This page builds a Notion-style editor: rich text blocks and marks, images, code blocks, markdown shortcuts, a slash menu, a selection toolbar, and the Notion theme. It mounts it in a SvelteKit page, reads the document as it changes and styles the result.

<Steps>
  <Step title="Pick the plugins">
    Every block kind and mark comes from a plugin. `<Edytor>` already includes rich text (paragraphs, headings, lists, to-dos, toggles, callouts, quotes, dividers and the text marks), images and keyboard block moves. Add the others for menus, code and shortcuts; a menu's markup is yours, a snippet you pass it.
  </Step>
  <Step title="Give it a document">
    Pass the initial content as `value`, a JSON tree of blocks.
  </Step>
  <Step title="Mount it in the browser">
    Render the editable editor after the page has hydrated, so the server never renders it.
  </Step>
  <Step title="Read the changes">
    Use `onChange`, or bind the editor instance with `bind:edytor` and read `edytor.value`.
  </Step>
  <Step title="Style it">
    Import the Notion theme, or target the `data-edytor-*` attributes the editor renders.
  </Step>
</Steps>

## The editor

```svelte title="src/lib/Editor.svelte" check
<script lang="ts">
	import {
	Edytor,
	createCodePlugin,
	createSlashMenuPlugin,
	createToolbarPlugin,
	createMarkdownShortcutsPlugin,
	richTextPlaceholder,
	type EdytorInstance,
	type JSONDoc,
	type SlashMenuController,
	type ToolbarController
} from 'edytor';
	import 'edytor/themes/notion.css';

	// Rich text, images and arrow moves are included by default.
	const plugins = [
		createCodePlugin(),
		createMarkdownShortcutsPlugin(),
		createSlashMenuPlugin({ menu }),
		createToolbarPlugin({ toolbar })
	];

	const value: JSONDoc = {
		children: [
			{ type: 'heading', data: { level: 'h1' }, content: [{ text: 'Meeting notes' }] },
			{
				type: 'paragraph',
				content: [
					{ text: 'Type ' },
					{ text: '/', marks: { code: true } },
					{ text: ' to turn a line into another block.' }
				]
			},
			{ type: 'todo-item', data: { checked: false }, content: [{ text: 'Send the recap' }] }
		]
	};

	let edytor = $state<EdytorInstance>();

	const onChange = (next: JSONDoc) => {
		console.log('changed', next.children);
	};
</script>

<!-- The slash menu: its rows are the commands, its keys and ARIA the controller's. -->
{#snippet menu(slash: SlashMenuController)}
	<ul class="menu" {@attach slash.popup}>
		{#each slash.commands as command, index (command.id)}
			<li {...slash.option(index)} onclick={() => void slash.run(command)}>{command.label}</li>
		{/each}
	</ul>
{/snippet}

<!-- The selection toolbar: a button per mark. -->
{#snippet toolbar(bar: ToolbarController)}
	<div class="bar" {@attach bar.popup} {@attach bar.keys}>
		{#each bar.marks as { mark, label, icon } (mark)}
			<button aria-label={label} aria-pressed={bar.isActive(mark)} onclick={() => bar.toggleMark(mark)}
				>{icon}</button
			>
		{/each}
	</div>
{/snippet}

<div class="edytor-notion">
	<Edytor {plugins} {value} {onChange} bind:edytor class="editor" placeholder={richTextPlaceholder} />
</div>

<style>
	.menu,
	.bar {
		margin: 0;
		padding: 4px;
		border-radius: 8px;
		background: #fff;
		box-shadow: 0 4px 16px rgb(0 0 0 / 0.12);
		list-style: none;
	}
	.menu :global([data-selected='true']) {
		background: #f1f1ef;
	}
</style>
```

The `edytor-notion` class applies the imported theme to the document, and `richTextPlaceholder` shows Notion's placeholders ("Heading 1", "To-do", "Type '/' for commands"…). The menus are your markup: the plugins place them, open and close them, and give them their keys and ARIA through the controller (`popup`, `keys`, `option(index)`). Block handles (a `+` and a drag grip beside each block) and a block menu on the grip are two more plugins drawn by your snippets, `createBlockHandlesPlugin({ handle })` and `createBlockMenuPlugin({ menu })`. The demo's complete Notion-style chrome, every surface with its styles, is in the repository's [`src/routes/chrome`](https://github.com/beynar/edytor/tree/master/src/routes/chrome): copy it to start from Notion's look.

What each plugin adds:

| Plugin | Adds |
| --- | --- |
| `createRichTextPlugin()` (default) | The rich text block kinds and marks, their keyboard shortcuts (<kbd>Mod</kbd>+<kbd>B</kbd>, <kbd>Mod</kbd>+<kbd>Alt</kbd>+<kbd>1</kbd>, …) and HTML import rules. List, to-do and toggle items continue on <kbd>Enter</kbd>. |
| `createImagePlugin()` (default) | An image block: embed from a link (or your upload, with `createImagePlugin({ upload })`), with an editable caption. |
| `createArrowMovePlugin()` (default) | <kbd>Mod</kbd>+<kbd>Shift</kbd>+<kbd>↑</kbd> / <kbd>↓</kbd> move the caret's block; <kbd>Mod</kbd>+<kbd>↑</kbd> / <kbd>↓</kbd> move selected blocks. |
| `createCodePlugin()` | A `code` block (an island of `codeLine` children) with syntax highlighting. |
| `createMarkdownShortcutsPlugin()` | Typing `# `, `- `, `1. `, `[] `, `" `, `> `, `---` or ```` ``` ```` at the start of a block converts it; `**bold**`, `*italic*` and friends format inline. |
| `createSlashMenuPlugin({ menu })` | A menu of block kinds, opened by typing `/`. |
| `createToolbarPlugin({ toolbar })` | A floating toolbar over a text selection: Turn into, link, marks and colors. |
| `createBlockHandlesPlugin({ handle })` | A `+` and a drag grip beside each block: drag and drop, keyboard moves. |
| `createBlockMenuPlugin({ menu })` | The menu of a block handle's grip: Turn into, Duplicate, Move, Delete. |

Plugin order matters: when two plugins define the same block kind, mark or command, the first one wins. Rich text is added after your plugins so they can override it; `defaultPlugins={false}` turns the defaults off. See [Plugins](/docs/plugins#default-plugins).

Every menu, toolbar, handle and panel takes the snippet that draws it, and draws nothing without one. See [Menus and handles](/docs/customization/menus).

## Mount it in a page

An editable editor is client-only: mount it once the page has hydrated. The page shell around it still renders on the server.

```svelte title="src/routes/+page.svelte" check
<script lang="ts">
	import { onMount } from 'svelte';
	import Editor from '$lib/Editor.svelte';

	let mounted = $state(false);
	onMount(() => {
		mounted = true;
	});
</script>

<main>
	<h1>Notes</h1>
	{#if mounted}
		<Editor />
	{/if}
</main>
```

:::note[Editable editors are client-only]
An editable editor's content and selection belong to the browser: with a room, the latest state is in IndexedDB or on the server, not in your server render. Server-rendering an editable `<Edytor>` is not tested and not supported; mount it after hydration as above, or turn SSR off for the route (`export const ssr = false;` in its `+page.ts`). To server-render a document, use a `readonly` view. See [SvelteKit](/docs/getting-started/sveltekit#editable-editors-mount-after-hydration).
:::

## Read the document

`onChange` receives the whole document after every committed change: local edits, remote edits and undo. Its argument is a `JSONDoc`, `{ data?, children }`, the type `value` takes, so you can store it and open it again as `value`.

With the instance bound, `edytor.value` returns the same JSON and is reactive, so it works in `$derived`. Pass the bound instance to a component of yours, `<BlockCount {edytor} />`:

```svelte title="src/lib/BlockCount.svelte" check
<script lang="ts">
	import type { EdytorInstance } from 'edytor';

	let { edytor }: { edytor?: EdytorInstance } = $props();
	const blockCount = $derived(edytor?.value.children?.length ?? 0);
</script>

<p>{blockCount} blocks</p>
```

`edytor.value` returns the same object until the next change. Clone it before you mutate it. Computing it serializes the whole document, so prefer `onChange` (or a debounced save) over reading it in many places.

`value` is the initial content only. Updating the prop later does not replace the document, and `value` is not bindable (`bind:value` fails type-checking). To change content after mount, use [commands](/docs/editor/commands).

## Style the editor

The Notion theme above styles every bundled kind; its colors and fonts are custom properties you can override (see [Styling](/docs/customization/styling#notion-theme)). To style the editor yourself instead, drop the import and the `edytor-notion` class.

The editor renders a `div` with `data-edytor` (and your `class`). Each block is an element with data attributes you can target:

| Selector | Matches |
| --- | --- |
| `[data-edytor]` | The editable root. |
| `[data-edytor-block]` | Every block element. |
| `[data-edytor-type="heading"]` | Blocks of one kind. `data-edytor-id` holds the block id. |
| `[data-edytor-selected]` | Blocks in a block selection. |
| `[data-edytor-focused]` | Blocks the text selection is in. |
| `[data-edytor-void]` | Void blocks, and chrome marked non-editable. |
| `[data-edytor-text]` | Text segments. `data-edytor-text-empty="true"` when empty. |
| `[data-edytor-mark="bold"]` | A mark element (`<strong>`, `<em>`, `<a>`, …). |
| `[data-edytor-inline-block]` | Inline blocks. |
| `[data-placeholder]::before` | The placeholder of an empty block. |
| `[data-edytor-overlay]` | The layer after the root that holds your handles and menus, and remote carets. |

The block element's tag comes from its kind: list items render `li`, a toggle `details`. A `heading` is a `div` holding its text in an `h1`–`h3`, and a `quote` holds its text in a `blockquote`; their nested blocks follow that tag. A few styles to start from:

```css title="src/app.css"
.editor {
	outline: none;
	line-height: 1.6;
}
.editor :is(p, blockquote) {
	margin: 0;
}
.editor [data-edytor-type='quote'] {
	border-left: 3px solid currentColor;
	padding-left: 12px;
}
.editor [data-edytor-selected] {
	background: #e8e6df;
	border-radius: 3px;
}
```

The placeholder is drawn by a `::before` rule the library ships, at 45% opacity. Override `[data-edytor-text][data-placeholder]::before` to restyle it.

To change a kind's markup rather than its styles, override its snippet (see [the component page](/docs/editor/edytor-component#snippets)) or define your own kind in [Custom blocks](/docs/customization/blocks).
