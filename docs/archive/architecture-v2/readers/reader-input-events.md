## 1. Required behavior (no implementation names)

Tags: [user-visible] [collab-invariant] [browser-constraint] [test-only]. Test citations are the pins that make the guarantee non-negotiable.

### A. Capturing intent
1. [user-visible] Every editing intent the browser announces produces exactly one effect on the document, or a named no-op; never native mutation + model mutation for the same keystroke (e.g. `mobile-beforeinput.spec` "repairs native DOM drift after non-cancelable paste", "…block merge deletion").
2. [user-visible] Unsupported intents are refused with zero document and zero DOM change, collapsed and ranged (`unsupported-beforeinput.spec` — 14 input types × 2 shapes).
3. [browser-constraint] When an engine does not announce a structural intent (Enter, Shift+Enter, Backspace/Delete at a text/block boundary, a range delete), the key's intent still executes against the document, using the selection as it was **at the key press**, not the selection after the browser drifted it (`beforeinput-fallback.spec` "routes structural Backspace/Delete/Enter/Shift+Enter … when beforeinput is missing").
4. [browser-constraint] When the engine misreports the intent, the key's intent wins: Android Backspace reported as a paragraph insertion deletes backward (`mobile-beforeinput.spec:1334`); a text insertion whose data is `\n`/`\r` is a line break/paragraph.
5. [user-visible] Intents that originate inside a nested foreign editable region, a native form control, a void block's own editable element, or a plugin chrome control are not captured by the editor (`composition.spec` nested-control guards; drop onto native controls swallowed).
6. [user-visible] A browser-declared target that lies wholly or partly outside the editor is refused without mutation and without disturbing the previous valid selection (`input.spec:698-766`).
7. [user-visible] An undo/redo request that belongs to a focused control outside the editor is not consumed from the document history (`undo-scope.spec` 3 tests); an undo/redo that arrives only through the post-mutation notification still runs editor history (`input.spec:1109,1151`).
8. [user-visible] Read-only editors accept navigation, copy, select-all; every mutating intent and key is refused and the document never changes (the observer ignores DOM mutations while read-only rather than healing them) (`beforeinput.fixtures` "keeps readonly editors unchanged").

### B. Resolving where the edit applies
9. [user-visible] The edit applies at the browser-declared target when it is inside the editor, even if the editor's cached selection is stale (`input.spec:766,945,985`, shadow-root `input.spec:907`); element-node boundary points around inline atoms normalize to the neighbouring text (`input.spec:803`).
10. [user-visible] Safety filter on declared targets: a declared deletion range is adopted only when it stays inside one text and is non-degenerate; a cross-text declared delete range is ignored so the structural delete (merge) still runs (`input.spec:1266,1306`); an insertion over a live multi-block selection keeps the selection the user made (triple-click block range is not widened by the browser's own range).
11. [user-visible] Unit deletes: when the platform declares a word/line range, that range IS the unit (`del.unit.adopted-range`); with no usable range, words are runs of `[\p{L}\p{N}_]` (`del.unit.model-boundary`); soft/hard line = the current block's content start/end.
12. [user-visible] A collapsed character delete removes one grapheme cluster (`advanced-delete.spec:214-356`, `del.caret.char`).
13. [user-visible] With a block selection, typing/composition replaces the selected blocks with one empty default block and inserts there; a drop while blocks are selected inserts at the drop point instead (`drop-beforeinput.spec:337`); a printable key over a selected inline atom replaces the atom with the character.

### C. Content semantics
14. [user-visible] Marks of typed text: an explicitly pending mark set (toggled at a collapsed caret) wins; replacing a range inherits only the marks common to every replaced part (`mobile-beforeinput.spec:1093,1130`; `composition.spec:1276`); otherwise the text inherits the marks of the character before the caret, else after; typing at the end of a link follows the link-boundary rule (`input.spec:480`).
15. [user-visible] Deleting (natively) inside a run whose marks are uniform keeps those marks pending for the next insertion (`dom-mutation.spec:596`).
16. [user-visible] Composition: the committed value is the final IME value (final composition insertion, a commit-time text insertion, or compositionend data — whichever arrives), inserted exactly once at the place composition started, with the marks captured when it started; intermediate previews are replaced, never appended; an empty final value cancels and removes the preview without an undo entry (`composition.spec` 40 tests, `composition-cancellation.spec` 8 tests); the first phantom Enter/(WebKit) Backspace after commit is ignored, later ones are not (`composition.spec:1521-1766`).
17. [collab-invariant] Remote edits during a composition never rewrite the composing DOM node; a remote insert before the composition shifts the commit point; remote text absorbed inside the composition region is replaced at commit (`composition-remote-lock.spec` 7 tests).
18. [user-visible] Structural keys follow the delete contract (`docs/editor-delete-contract.md`): Enter splits / inserts before at block start / at the end of a parent that has children lifts the parent's content above the children (`input.spec:1346,1391`); Shift+Enter inserts one soft break (inside code lines it splits the line, caret at the new line start); Backspace at block start unnests a nested last child, selects a void predecessor, is a no-op at an island's first child or the document start, otherwise merges; Delete at block end selects a void successor or merges forward; Backspace/Delete at a text-part boundary removes the adjacent inline atom; Backspace on a trailing soft-break marker removes only the break.
19. [user-visible] Paste/drop payload precedence: internal editor fragment → plugin claim (HTML, files) → files unclaimed insert nothing → `text/uri-list` becomes a link when a link mark exists → plain text; Shift-paste forces plain; internal drags never become drops; mid-composition paste/drop is left to the browser (`drop-beforeinput.spec` 12 tests, `clipboard.spec`).
20. [user-visible] Plugin-defined text triggers (the mention `@`) behave the same whether the character arrived through a cancelable event or through a native DOM change (`beforeinput.fixtures` "routes non-cancelable hotkey pending @ through mention insertion").
21. [user-visible] Double-space auto-period replaces only the previous space (`input.spec:517`); a Tab text insertion follows Tab semantics (`input.spec:607,666`).

### D. Adopting or reverting browser-made DOM changes
22. [browser-constraint] Text changes the browser makes inside one text element (non-cancelable insertion/deletion, spell-check replacement, transpose/yank, missing-event mutations, type-over records, wrapper replacement, text-node splits) are adopted into the document exactly once, the caret lands where the browser put it (or where the diff implies), the undo step records the pre-edit caret, and plugins observe the insertion (`input.spec:2042-2746`, `dom-mutation.spec:519-881,1071,1118`).
23. [browser-constraint] Structural DOM changes the browser makes around a model-owned command (created paragraphs, `<br>`, merged text, removed survivor blocks) are discarded; the document's result stands and the caret is restored (`mobile-beforeinput.spec:894-1707`).
24. [user-visible] Foreign DOM damage heals: foreign attributes on editor-exclusive nodes are stripped, owned attributes restored, spoofed identity markers neutralised, injected elements removed (injected text inside a text element is adopted or reverted exactly once), removed managed nodes restored, WebKit converted spaces become spaces, flipped/cloned mark DOM re-rendered; repair is bounded (`dom-mutation.spec:906-1276`, DST `foreignMutation` oracle in `docs/editor-dst.md`).
25. [user-visible] Repair never steals focus or selection the user moved elsewhere (outside gesture, nested editable, plugin chrome) and never replaces an atomic (block / inline atom) selection with a text caret.
26. [browser-constraint] Nothing repairs or re-renders the node an IME is composing into; deferred repair runs after composition, and a composition abandoned by the browser is cancelled after an idle bound.

### E. Caret after the edit
27. [user-visible] After every command the DOM caret equals the document caret, including when the destination text mounts later, when the browser jumps the selection after an IME commit, and Android's post-delete +1 echo (`composition.spec:565`, `android-caret-restore.test`).
28. [user-visible] A newer user gesture supersedes any deferred caret write (delete contract "Selection ownership and lifecycle").
29. [user-visible] Native navigation keys update the document selection, with a fallback when an engine did not move the caret across a boundary (`navigation-selection-sync.spec` 9 tests).

### F. History
30. [user-visible] Undo boundaries: paragraph insertion, paste, drop, cut and every delete (except composition-text deletes) start a new undo step; a browser-owned deletion followed by an empty-typed input is its own step (`input.spec:1023`); undo selection snapshots hold the pre-edit caret.
31. [user-visible] Undo/redo during composition is swallowed (both announcement channels).

### G. Placeholder
32. [user-visible] A block whose content is one empty text shows the placeholder; it disappears as soon as visible text exists in the DOM (even before the document knows), stays hidden during composition, returns when content is deleted, and never appears twice (`placeholder-repair.spec` 9 tests).

### H. Test harness contracts
33. [test-only] Headless command programs drive the real command dispatch with an `{inputType, data}` descriptor against the document selection (`command-simulation/programs/canary.test.tsx`, `command-peer-set.ts`) — the DOM event object is inessential to the contract.
34. [test-only] Observable counters used by oracles: phantom-key suppressions (`postCompositionGuardSwallows`), placeholder repair stats, `flushNow()` of the mutation queue.

## 2. Real constraints

### Browser (contenteditable, Input Events, IME, Selection, MutationObserver)
- **B1 — cancelability is per engine and per input type.** Chromium implements Input Events Level 2: composition insertions are not cancelable, and Android Chrome delivers many text/delete intents non-cancelable (keyCode 229). WebKit follows the Level 1 composition model (`deleteCompositionText` / `insertFromComposition` around the commit), which the editor treats as model-owned commands. Both "model writes the preview" (`beforeInputCommands.ts:167-215`) and "browser writes, editor adopts" paths are therefore forced. Android Chrome can also report a non-cancelable `deleteContentBackward` and then do nothing (`onBeforeInput.ts:474-516`, pinned by `mobile-beforeinput.spec:706`).
- **B2 — declared targets are ephemeral and untrustworthy.** `getTargetRanges()` exists only during dispatch, can be empty, can use element-node (child-index) boundary points, and can straddle the editor boundary (`input.spec:698-803`). Forces: resolve the target at admission time, with a containment check and a boundary-point normalisation.
- **B3 — some engines skip `beforeinput` for structural keys and drift the DOM selection before any event.** Forces a keydown-time selection snapshot and a deferred keydown fallback (`edytor.svelte.ts:1379-1452`); the only evidence of intent may be the keydown.
- **B4 — IME ordering differs per engine and the IME owns its node.** WebKit sends the final `insertFromComposition` before `compositionend`; Firefox sends `compositionend` before the last `input`; WebKit/Chromium can deliver a phantom Enter/Backspace keydown right after commit; synthesized sessions can start and never end. Re-rendering or replacing the text node under composition corrupts the IME (gap analysis G2). Forces: a composition session with its own lifetime, commit idempotent across several possible commit signals, an idle cancel, and a render pin on the composing node.
- **B5 — MutationObserver records carry no provenance.** Records are delivered in a microtask after the mutating task; the editor's own renderer produces exactly the same record kinds as the browser and foreign scripts. `characterDataOldValue` is needed to see type-overs, `attributeOldValue` to recover a stripped identity attribute (`domTextMutationObserver.ts:1542-1555`).
- **B6 — selection events are asynchronous and echo.** `selectionchange` is task-queued, fires for the editor's own writes, can be skipped by WebKit when a write equals the current selection; carets can be element-node positions; Firefox can report multiple ranges; shadow roots need `getComposedRanges`.
- **B7 — after `preventDefault()` the browser does not move the caret.** The editor must write the DOM caret itself, after its own render has produced the target text node.
- **B8 — native editing clones DOM, including editor attributes.** A native paragraph split or mark continuation clones inline wrappers and `data-*` identity markers into new nodes (`input.spec:459`, `dom-mutation.spec:854`). Identity by attribute is therefore spoofable by the browser itself, not only by extensions.
- **B9 — WebKit writes `span.Apple-converted-space` with NBSP** for spaces typed natively.
- **B10 — clipboard events carry no modifier state** (Shift-paste must be inferred from key events); **drop points** need `caretPositionFromPoint` or the legacy `caretRangeFromPoint`.
- **B11 — undo-scope walk.** Chromium/WebKit re-dispatch `historyUndo`/`historyRedo` at the editable root when a foreign focused control exhausts its own stack.

### Svelte 5 runes
- **S1 — rendering is batched.** Model writes update `$state`; the DOM changes in a later flush (microtask / `tick()`). Between the write and the flush the DOM disagrees with the model, and a caret write must wait for the flush.
- **S2 — Svelte owns its node ranges.** `{#each}`/`{#if}` keep empty text-node anchors; removing or re-parenting nodes Svelte owns corrupts its bookkeeping (`domTextMutationObserver.ts:315-319`: removing anchors makes keyed-each reconciliation "spin forever"). Foreign structural damage must be healed by restoring the exact removed nodes or by a keyed remount of an owner whose anchors survived, not by arbitrary DOM surgery.
- **S3 — a keyed remount destroys the node.** `{#key editorDomRevision}` and `domVersion` in content keys remount spans; during composition these must be deferred (`edytor.svelte.ts:444-462`, `text.svelte.ts:618-626`).
- **S4 — runes see model state, not DOM state.** A fact that exists only in the DOM (natively typed text before adoption) is invisible to `$derived` unless mirrored into `$state`; this is why the placeholder reads a DOM-fed `hasDomText` (`Text.svelte`).
- **S5 — actions bind after insertion and unbind on destroy.** Node↔wrapper maps (`nodeToText`, `nodeToInlineBlock`) are maintained by actions and can lag the DOM inside one flush.

### Vendored Yjs v14
- **Y1 — insertions are unformatted unless the caller names every mark.** `insertContent` sets every currently active format the caller did not pass to `null` (`src/lib/crdt/vendor/yjs/src/ynode.js:340-346`). The editor must decide the marks of **every** insertion (typed, composed, pasted, adopted from DOM). This is the only reason a "marks for insertion" rule exists at all.
- **Y2 — offsets do not survive concurrency; anchors do.** Relative positions with an `assoc` sign keep insertion affinity through remote edits. Any fact that must survive an async window with collaboration (composition region, deferred caret target) must be an anchor, not a number.
- **Y3 — undo grouping is time-based.** The undo manager merges transactions inside `captureTimeout`; `stopCapturing()` is the only way to force a boundary, so each boundary rule is an explicit call site.
- **Y4 — transactions carry origin.** Local vs remote changes are distinguishable at mirror time (`text.svelte.ts` `_setItems`: `change.origin !== this.edytor.transaction`).
- **Y5 — composition previews are ordinary document writes.** `insertCompositionText` writes the preview into the document (`beforeInputCommands.ts:194-208`), so previews replicate like any content and every commit/cancel must replace or remove exactly those atoms.

## 5. Distinctions that must stay explicit

| # | Distinction | Bug if merged |
|---|---|---|
| D1 | **Announced intent vs executed effect** (prepared intent vs execution attempt). A non-cancelable `beforeinput` announces an intent; whether the browser performed it is only known later. | Treat "announced + non-cancelable" as "done": Android's no-op Backspace never deletes (`mobile-beforeinput.spec:706`). Treat "we ran the model op" as "browser did nothing": double deletion / duplicated paste (`mobile-beforeinput.spec:1638`). |
| D2 | **Browser-owned change (adopt) vs drift around a model-owned change (revert).** The same `characterData` record on the same node means opposite things depending on who owned the attempt. | Adopt drift → duplicated merged text after a non-cancelable block merge (`mobile-beforeinput.spec:1288`); revert a browser-owned insert → the user's keystroke disappears. |
| D3 | **Observation vs guarantee**: DOM text/caret vs document text/caret. The DOM is ahead of the model for browser-owned input and behind it after a model op until the render flush (S1). | DOM-as-truth during the render window → a stale native re-anchor reverts the caret (the reason `setAtTextOffset` verifies writes); model-as-truth for the placeholder → placeholder painted beside natively typed text. |
| D4 | **Keydown-time target vs declared event-time target vs post-mutation caret.** Three moments, three legitimate sources, each for a different intent class. | WebKit structural Backspace applied at the drifted selection (cross-browser note 7); adoption caret taken from keydown time → caret lands before the adopted text. |
| D5 | **Composition preview (replaceable attempt state) vs committed text (durable progress) vs cancellation (reversal of an effect that already replicated, Y5).** | Preview treated as committed → appended previews (`composition.spec:788`); cancel treated as "forget local state" → preview atoms stay in the shared document. Today the two abandonment exits disagree: the dangling-blur reset keeps the atoms (`edytor.svelte.ts:1471-1484`), the idle cancel deletes them (`domTextMutationObserver.ts:1516-1540`). Keep-or-delete is a product decision; it must be one decision. |
| D6 | **Region identity (anchors) vs numeric offsets.** | Numbers used as identity: `Text.deleteAt` silently redirects any delete whose `(offset, length)` coincides with the region to the anchor-resolved region (`text.svelte.ts:843-862`), and `_resolveCompositionOffset` remaps any insert at an offset equal to `startOffset` (`:500-541`). Anchors dropped: a remote insert before the composition moves the commit (`composition-remote-lock.spec:169`). |
| D7 | **Renderer-produced record vs browser/foreign record** (provenance). | Measured (jsdom, §7-C1): a model-owned composition preview produces two `data-edytor-focused` attribute records written by the editor itself; queued during composition they arm the idle timer and, after 750 ms without `compositionend`, the live session is ended and its preview deleted from the document. Liveness heuristics exist only because this distinction is not represented. |
| D8 | **Event occurrence vs handler binding.** One keydown occurrence must be handled once regardless of how many listeners see it. | Measured (§7-C2): a plugin hotkey that does not call `prevent` runs twice per keydown. |
| D9 | **Caret write accepted vs caret projected.** `setAtTextOffset` resolves after falling back to a model-only write when the node never connects (`selection.svelte.ts:3087-3135`). | Callers cannot tell which happened, so each adds its own retry cadence (F13); a caller that assumes projection sends the next native keystroke to the old DOM position (the delete contract's former UNRESOLVED-2 class). |
| D10 | **Capability vs permission.** `contenteditable` (the browser lets the user type) is not the editor's permission to route the input: void captions and plugin chrome are capable but not editor-owned; readonly removes capability but events still arrive. | Using `isContentEditable` as permission captures caption typing into the document selection, or processes paste in readonly. Healing must keep restoring void-text capability (`contenteditable` on texts inside voids) as a render fact, not a permission. |
| D11 | **Document undo scope vs a foreign control's undo scope.** | Undo-scope walk consumes document history for another control's intent (`undo-scope.spec`). |
| D12 | **Mark toggle state vs mark value.** Pending marks built at a collapsed caret inherit only marks whose value is `true` (`text.utils.ts:282-286`, `richTextOperations.ts:285-291`). | Valued marks (link `href`, color) vanish from the next typed character after any collapsed toggle inside them, while the adjacency rule (`beforeInputCommands.ts:141-155`) would have kept them — two meanings of "marks at the caret". |
| D13 | **Spontaneous post-commit selection jump vs user gesture** (gesture serial). | Deferred restores either fight the user or fail to repair the browser's jump (`composition.spec:565`). Already represented; keep it the only admission criterion instead of per-site guards. |

## 6. Representation candidates

### R1 — One *input attempt* value, produced by every source, consumed by one dispatcher
**Represent** (instead of 3 event vocabularies, a 25-field snapshot, 6 timed flags and 7 event fabrication sites):
```ts
type Intent =
  | { kind: 'insert'; payload: string | ClipboardPayload }            // typed, paste, drop, quotation
  | { kind: 'delete'; dir: 'back' | 'fwd'; unit: 'char' | 'word' | 'softLine' | 'hardLine' | 'selection' }
  | { kind: 'break'; soft: boolean }
  | { kind: 'history'; op: 'undo' | 'redo' };
type Attempt = {
  id: number;                          // occurrence identity (D8)
  intent: Intent;                      // admitted meaning — immutable after admission
  target: AnchoredRange | AtomicSelection; // resolved once: declared range, keydown snapshot, or model selection (D4); anchors when execution crosses an async boundary (Y2)
  owner: 'model' | 'browser';          // D2 — decided once (F1)
  expect?: { text: TextRef; before: string }; // browser-owned only (F16)
  deadline?: number;                   // missing-event / no-op-event fallbacks (B1, B3)
  historyStep: boolean;                // derived from intent kind (F14)
};
```
Sources: `beforeinput` (one inputType→intent table, including the misreport overrides), keydown bindings (keys map to intents; the structural fallback is an attempt with a deadline that a later `beforeinput` for the same occurrence *confirms* instead of re-running), paste/drop (payload intent + drop-point target), Emacs chords, plugin overrides (attach to `(intent, target)`, not to key strings). One `dispatch(attempt)` applies the history boundary, plugin interception, the command, and a caret-projection request.

**Machinery that disappears** (xloc): the fabrication sites — `edytor.svelte.ts:1417-1437`, `onInput.ts:366-390`, `onPaste.ts:44-82` (37), `onDrop.ts:113-139` (21), `hotkeys.ts:304-311`, `CodePlugin.svelte:87-101`, `beforeInputCommands.ts:23-70,316-326` (~60) ≈ 150; inputType predicate families + two routers + `shouldRefreshDomAfterModelCommand` + `NON_COMPOSITION_INSERT_TYPES` (41+49+25+19) → one table of ~35; `beforeInputSnapshot.ts` (109); the suppression flag family and repair-target plumbing (~240, §4.4) replaced by `owner`/`expect`/`deadline` on the attempt; ~8 scattered `stopCapturing()` decisions; duplicated admission (~130 of 214); the double keydown run.
**Invariant that replaces it:** *each user occurrence yields at most one attempt; its intent, target and owner are fixed at admission; only the dispatcher maps intents to document operations; nothing downstream re-reads the DOM event.*
**Where the language must be tested:** a plugin that issues an intent from inside another intent's execution (code-line Enter → normalization split) must be a sub-operation of the running attempt, not a new attempt/history step; a deadline attempt confirmed late by a real `beforeinput` must not run twice; an empty target (block selection emptied by a remote delete before the deadline) must yield a named no-op result, not `selectBlocks(dead)`; a failed command (plugin `prevent(cb)` whose `cb` throws) must leave the attempt in a `failed` phase so the observer treats native drift as model-owned and re-renders instead of adopting.

### R2 — Composition is one *session* whose region is two anchors, with exactly `preview`, `commit`, `cancel`
**Represent:**
```ts
type CompositionSession = {
  host: TextRef;                 // resource ownership: the DOM node the IME owns (render pin)
  startTarget: AnchoredRange;    // replaced selection at compositionstart (admitted meaning)
  marks: Marks;                  // captured once at start
  region: { start: Anchor /*left*/; end: Anchor /*right*/ } | null; // replaceable attempt state lives here
  phase: 'started' | 'previewing' | 'committed' | 'cancelled';
};
```
Every commit signal (final composition insertion, a text insertion while composing, `compositionend`, a commit-time `input`) calls `commit(value)`, which is idempotent on `phase`; every abandonment (empty final data, blur, idle) calls `cancel()`, whose single semantics (delete or keep the replicated preview atoms, D5) is decided once. Offsets are derived from the anchors on read.

**Machinery that disappears:** `beforeInputCommands.ts:160-305` (128) → ~40 of session code; `edytor.svelte.ts:1600-1752` `onCompositionEnd` (128) → a `commit(event.data ?? preview)` call; `getFinalCompositionMarks` (`edytor.svelte.ts:1665-1688`, 20; marks are captured at start); `text.svelte.ts:471-541` `_syncCompositionRegion` + `_resolveCompositionOffset` (51) and the region branch of `deleteAt` (`:843-862`, 22) — the numeric-coincidence reinterpretation (D6); the 9 reset sites of F7 and `hasHandledCompositionInput` / `compositionStartReplacementState` / `NON_COMPOSITION_INSERT_TYPES`; the observer's own cancel (`domTextMutationObserver.ts:1516-1540`, 25). The render pin stays (B4) but keys off `session.host` + `phase`.
**Invariant:** *at most one session exists; only the session writes composition state; each session ends through exactly one of `commit`/`cancel`, exactly once; region positions are anchors, never cached numbers.*
**Where it breaks:** host block deleted remotely mid-composition (anchors resolve to the seam — commit there or cancel? must be specified next to `conc.delete-wins-block`); Firefox's duplicated committed input after `compositionend` (`composition.spec:935`) must arrive as drift of a *committed* session (model-owned → revert), not a new adoption; a remote split moving the region's atoms to another wrapper keeps the pin on `host` (resource) while `commit` writes through the anchors (meaning) — the current code handles this by keeping the commit on the host (`edytor.svelte.ts:264-301`), which must remain an explicit rule.

### R3 — Provenance at the source: the renderer's own DOM writes are never classified; the DOM caret is a projection
**Represent:** a render bracket owned by the dispatcher and the remote-apply path: *(1)* before applying any document change, flush pending observer records (so browser/foreign records are processed first, never discarded); *(2)* after the change, force the render (`flushSync`) and discard `observer.takeRecords()` — the ProseMirror (`DOMObserver.stop/start` around view updates) and Lexical (disconnect during reconciliation) discipline. Every record that reaches classification is then browser-made or foreign **by construction**, and is handled by location only: character content inside a text element → adopt or re-render according to the pending attempt's `owner` (R1); anything else → invert (attributes from `oldValue`; childList by exact re-insertion/removal in reverse order, which S2 requires) or remount the smallest owning unit. The caret: commands return a model target; one projector writes the DOM caret after the flush that rendered it, and re-applies only when the DOM selection moved without a gesture (D13).

**Machinery that disappears:** liveness inference ≈ 297 (`domTextMutationObserver.ts:72-116,277-343,345-394,396-652`); attribute spec tables + healing ≈ 297 (`:1080-1492`) → ~15 of `oldValue` inversion; caret capture/restore after repair 106 (`:897-1078`); the blanket observation suppression in `transact()` (`edytor.svelte.ts:401-407`) and the observer's suppressed/retry branch (~35); `removeStalePlaceholders.ts` (192) and the two per-node MutationObservers in `Text.svelte` (~80): once own records are never restored and browser text is adopted in the same microtask, the placeholder is a pure render of model state; the caret retry cadences of F13 (~260 across files); `domTextOffset.ts` (43) and the observer's third point→offset copy (37).
**Invariant:** *no record produced by the editor's own rendering is ever classified; every classified record is reverted or adopted by its location and the pending attempt's owner; the DOM caret is written only by the projector.*
**Preconditions (the honest cost):** Svelte 5 exposes no pre-DOM-write hook, so the bracket must force `flushSync` at the end of each dispatched attempt, each remote apply and each history command; renders triggered outside the bracket would look foreign — including selection-driven attribute writes such as `data-edytor-focused` (the exact record that cancels a live composition in §7-C1), so selection-state changes must render inside the bracket too; plugin chrome must stay inside declared plugin-owned subtrees excluded from observation, and plugins lose the ability to decorate text elements' attributes. Without R3, the observer keeps its classification design (floor ≈ 1,100 instead of ≈ 300, see §8).

## 7. Falsifying counterexamples

Measured ones were run in the repo's jsdom lane with a scratch vitest config (`scratchpad/arch/exp/*.exp.test.ts`, repo files untouched).

**C1 — IME pause (composed × own renderer).** *Measured.* `Hello|`, `compositionstart`, preview `に`, then no event for 850 ms (a user reading IME candidates). Result: `isComposing=false`, `compositionState=null`, document `Hello` — the live preview was deleted and the session ended while the IME still owns it. After the observer went quiet for 1.2 s beforehand, the only records during the session were two `attributes:data-edytor-focused` records on the block element, written by the editor itself; queued during composition, they armed the 750 ms idle cancel (`domTextMutationObserver.ts:1557-1569,1642-1653,1516-1540`), which also calls `refreshFromModel()` on the now-unpinned host — in a browser, the IME's node is remounted mid-composition. By the same code path, any record (a peer's edit in another paragraph, an extension's attribute write) re-arms the timer. Falsifies "records need no provenance" and the split commit/cancel ownership (D5, D7).

**C2 — one keystroke, several executions (occurrence identity).** *Measured.* A plugin binding `mod+alt+k` that does not call `prevent` runs **2×** per keydown (node-capture and document listeners both call `onKeyDown`, `edytor.svelte.ts:2048-2055`). A non-preventing `enter` binding runs **3×** per Enter press (2 keydown listeners + the `beforeinput`→synthetic-keydown bridge `beforeInputCommands.ts:40-53`), while the paragraph splits once (`["he","llo"]`). Falsifies "a hotkey binding is an intent handler" — today it is invoked per routing path, not per occurrence.

**C3 — fact changes between observation and use (concurrent × keydown fallback).** *Measured.* `he[ll]o` selected, Backspace keydown with no `beforeinput` (the fallback path WebKit needs), a non-local insert `XX` at offset 0 lands before the fallback timer. The live selection correctly rode the insert (`4..6`), but the fallback replayed its numeric keydown snapshot (`edytor.svelte.ts:1381-1411`, `setAtRange(startText, 2, endText, 4)`) and deleted `he`: result `XXllo`, intended `XXheo`. Falsifies "keydown-time target = numbers" (Y2); the snapshot must be anchors.

**C4 — foreign rewrite of a long paragraph (adoption × marks × collab).** *Measured on `diffText`.* 1100-char text, middle 700 chars replaced (autotranslate / extension): `diffText` returns `[{delete:1100},{insert:<1100 chars>}]`; the prefix/suffix diff returns `retain 200, delete 700, insert 700`. Adoption then deletes and re-inserts every atom — local and remote carets lose their anchors, concurrent remote inserts into the untouched prefix/suffix are deleted, and every inserted character gets the marks at offset 0 (`onInput.ts:309-315`). Falsifies "any diff is fine for adoption": identity-preserving prefix/suffix is the requirement.

**C5 — Android no-op Backspace under collaboration (announced intent vs effect).** *Derived from code.* The 150 ms fallback (`onBeforeInput.ts:495-515`) proves "the browser did not delete" by `text.stringContent === initialValue` and an unchanged numeric caret. Any remote edit to the same text within 150 ms makes both checks fail, so neither the browser nor the fallback deletes: the keystroke is lost. The check conflates "someone changed the text" with "our deletion happened" (D1); the attempt should test whether the atom before its anchored caret still exists.

**C6 — generated value needed after a boundary.** *Derived from code.* Enter at the end of a parent that has children creates `new Text(...)` before insertion and later looks it up by the pre-insertion id with a fallback to the detached wrapper (`beforeInputCommands.ts:536-545`); adoption may rename ids (`text.svelte.ts:674-702`), so correctness depends on the pending-alias mechanism. Commands should return a model-space target (block id + offset/anchor) resolved after the render boundary, never a wrapper created before it.

**C7 — failure midway.** *Derived from code.* In `onBeforeInput` the suppression windows are armed (`:716-723`) before plugins and the command run; a plugin `prevent(cb)` whose `cb` throws, or a command that throws after partial writes, exits with those windows armed and no model result — for a non-cancelable event the browser's native mutation is then treated as drift of a model-owned command and reverted, losing the user's input. The attempt needs an explicit `failed` phase that decides adopt-vs-revert.

**C8 — same intent, two channels.** *Derived from code.* Shift+Enter in a code line: on desktop the code plugin's key binding fabricates a cancelable `insertParagraph` (`CodePlugin.svelte:87-101`); on Android the non-cancelable `insertLineBreak` skips the bridge (`beforeInputCommands.ts:42-44`) and reaches `insertLineBreak`, where code-line normalization happens to split the line. Parity rests on normalization coincidence plus two separate browser specs (`structural-keys.spec:39`, `mobile-beforeinput.spec:1448`). Any new plugin override bound to a key string silently does not exist on Android.

**C9 — nested editable inside a void inside a list item (nesting in nesting).** Admission decides "not the editor's event" in 11+ places with different subsets (F18): `onPaste` refuses during composition but `onCut` does not (`onCut.ts:30-40`); `reconcileFocusedDomText` checks nested editables but `restoreSelectionAfterRepair` checks them separately with its own rule. An editable caption inside a void image block nested in a list item, with a plugin-chrome control beside it, is the smallest document that exercises every subset at once; any disagreement routes one of its events into the document selection.

**C10 — empty collection.** The keydown fallback stores `Array.from(selectedBlocks)` (`edytor.svelte.ts:1387`) and replays `selectBlocks(...)` after the timer; if a remote delete removed those blocks in between, the replay selects dead blocks and the fallback delete runs on them. Expected by contract: a named no-op or the seam rule (`sel.seam.*`).
