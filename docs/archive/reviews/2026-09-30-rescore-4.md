### XW-01 — A text range from a collapsed toggle's header past its hidden body deletes the hidden children

- **Area:** Editing behaviors
- **Severity:** medium
- **Effort:** M
- **Where:** `src/lib/events/beforeInputDeleteCommands.ts:30`. The root cause is in `src/lib/crdt/rangeDelete.ts`: the `between` slice goes into `doomed` with no view-state check.
- **Failure:** The document is [toggle 'title' -> [p 'body'] (closed), p 'after'] with the caret at title:5.
  - Shift+ArrowRight is handled by the editor's own navigation, which gives the range title:5 to after:0.
  - Backspace then gives [toggle 'titleafter'] with no children. Typing 'X' gives [toggle 'titleXafter'], also with no children.
  - The hidden content disappears with nothing shown on screen. Undo recovers it only if the user notices.
  - This contradicts hotkeys.mdx:37: "A closed toggle is one unit".
- **Fix:** When a surviving closed toggle's header starts the range, keep its hidden descendants out of `doomed` (they stay its children). Alternatively, clamp the range so the closed toggle is treated as a unit. Apply the same rule to `replaceRange`, which covers typing, paste and insertParagraph over a range.
- **Done when:** notion-parity has passing rows for Shift+Right then Backspace, Shift+Right then typing, and a range from mid-header to mid-'after', each keeping 'body'. There is also one Undo row.

### XW-02 — A read-only socket's `saved` stays false forever (reload with a local store, second tab, relayed delete, empty room)

- **Area:** Collaboration
- **Severity:** medium (raised from low by the refuter)
- **Effort:** S
- **Where:** `src/lib/crdt/providers/websocket.ts:521` (`_updateHandler`) and `:593-601` (`_track`)
- **Failure:** Any update whose origin is not the provider is tracked as this actor's own write. That includes the local store's replay and BroadcastChannel relays. A read-only socket's writes are refused and never acked. Reproduced cases:
  1. A viewer with a stable `actor` (which the docs recommend) and the default local store reloads. The previous session's `c/<old>` record is replayed and counted as its own, giving saved=false and unsaved=1 permanently.
  2. The same happens when the viewer opens a second tab.
  3. The same happens when a peer's delete-only edit reaches the viewer over the channel before the socket copy does.
  4. It should also happen for a viewer on an empty room, because the seed is counted as its own write. This case was not re-run in workerd.

  The effects: a permanent "Saving…" state, a `beforeunload` prompt on every close, and `_faults` never resetting. This contradicts websocket.mdx:185.

- **Fix:** On the first `permission-denied 'read-only'`, clear `_pending` and stop tracking. Otherwise, filter dictionary-record structs from `written()` for every origin, and skip delete-only updates from relay or store origins.
- **Done when:** There are passing rows for a viewer reload with a store, a viewer with a second tab, a relayed delete, and a viewer on an empty room (workerd). Each one reaches `saved`.

### XW-03 — The FW-01 line rule flattens every island that declares a `defaultChild`, and the public docs are silent about it

- **Area:** CRDT correctness
- **Severity:** medium
- **Effort:** M
- **Where:** `src/lib/crdt/text/runs.ts:539` (`typeOf`). Also `src/lib/crdt/edytor-doc.ts:810` (`roles.line = defaultChildOf`) and `src/lib/crdt/placement/model.ts:467-510`.
- **Failure:** Any island that declares a `defaultChild` is affected, not just code.
  - A custom callout island `K:callout[H:heading, P:paragraph[Q]]` shows as `K:callout[H:paragraph,P:paragraph] Q:paragraph`, and `insertBlock({parent:'P'})` returns `refused`.
  - A table island `table→row→cell` shows as `T:table[R1:row] c1:cell c2:cell`.
  - `toJSON()` returns the flattened tree, so exports keep the wrong structure.
  - The rule is written down only in AGENTS.md:79 and editor-delete-contract.md `conc.island-lines`. customization/blocks.mdx:59-82 and concepts/blocks.mdx:58-89 do not mention it.
- **Fix:** Make the line rule opt-in, for example with a `lines: true` role on code, or apply it only when the defaultChild kind declares no children. At minimum, document it in the `island` and `defaultChild` option rows and in concepts/blocks.mdx, and add a DEV warning when an island's defaultChild kind is a container.
- **Done when:** A two-level custom island row (table→row→cell) keeps its structure, or the documented rule and the DEV warning ship with a row that pins the flattening.
