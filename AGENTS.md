# Edytor Repository Guide

For coding agents and maintainers who need to work on the repo without rediscovering its structure.

Edytor is a small editing engine with a Svelte rendering layer, on a Yjs v14 document. It is not a component library with a thin editor wrapper. Almost every bug that "looks random" from the DOM or selection side comes from changing behavior in the wrong layer, or from giving one fact a second owner. Read "One owner per fact" before changing anything in `session/`, `surface/` or `events/`.

## Project identity

- Name `edytor`, version `0.1.0-next.16` (a pre-release: the `0.0.11` on npm has another API), work in progress.
- Docs: the site (`site/content/docs`) is the single source for API and behavior; the README is a landing page that links to it.
- Install: `pnpm add edytor@next`, the name every install instruction gives, the landing page's Copy install included (`src/tests/docs-drift.test.ts` checks it; a bare `edytor` is the old `0.0.11`). Release: bump the version, run the lanes locally, deploy the site, push `master`, then push an annotated `v<version>` tag: `.github/workflows/publish.yml` publishes it (npm trusted publishing with provenance, no token; `next` for a pre-release, else `latest`; it runs lint, `check` and `check:worker`, not the timing-sensitive test lanes). The docs live at `https://edytor.dev` (the `edytor-docs` Worker's custom domain, `site/wrangler.jsonc`; the workers.dev URL still answers and the room allows both origins) and redeploy on every push to `master` through Workers Builds (the `edytor-docs` Worker's trigger "Deploy docs on master": `pnpm install --frozen-lockfile`, then `cd site && KEEP_LIVE=1 pnpm run deploy`, so a served version keeps its live tarball; `cf builds triggers`/`cf builds list` manage and inspect it). Workers Builds forces every `wrangler deploy` of a build onto the connected Worker's name (`WRANGLER_CI_OVERRIDE_NAME`): the room's `deploy` script unsets it, or the room would replace the docs (it did once: `site/wrangler.jsonc`'s `v2` migration deletes the class that left). The site also hosts each packed tarball: `site/scripts/pack-edytor.sh` (run by the site's `deploy`) stages it in `site/public/` under its versioned name, which the site serves at its root (earlier installs by URL). A served tarball URL is permanent (lockfiles pin the URL and its hash): `pnpm run deploy` in `site/` refuses new bytes under a version the site already serves (`FORCE=1` overrides) and re-serves every version in `site/scripts/served-versions.txt` from the live bytes, so whenever the packed code changes, bump the pre-release version (`next.N`) and append it to that list (never remove one). The deploy then reinstalls the site and the demo room `site/room` from the new pack and refuses to build unless both hold it (`site/scripts/installed-edytor.sh`: the landing's live editor and the room bundle the installed copy, not the tarball), deploys the docs to the beynar Cloudflare account (`CLOUDFLARE_ACCOUNT_ID`, as `site/room/wrangler.jsonc`) and the room (it runs the same packed `edytor/cloudflare`), and ends with `site/scripts/smoke.sh`, which rechecks both installs and also dials a closed demo room from the docs origin and requires a `4404` close (`site/scripts/probe-room.mjs`).
- Stack: Svelte 5, SvelteKit, TypeScript, **vendored Yjs v14** (`@y/y@14.0.0-rc.26`, an owned fork under `src/lib/crdt/vendor/yjs/`, patches listed in `UPSTREAM.md`; the `yjs` npm package is a dev dependency for migration tests only), Vitest, Playwright.
- The architecture below is the result of the arch-v2 plan (`docs/architecture-v2/plan.md`); `docs/architecture-v2/execution-ledger.md` records every checkpoint, the lane results and the measured numbers.

## The top-level model

Five contexts, each with one job and a lifetime:

| Context     | Lives in                                                                  | Lifetime               | Job                                                                                                                                                                          |
| ----------- | ------------------------------------------------------------------------- | ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **doc**     | `src/lib/crdt/` (not `vendor/`, `providers/`, `protocols/`, `migration/`) | the engine doc         | The replicated document and everything derived from it: block registry, placements, streams, one index, prepared operations, anchors, attribution. DOM-free and Svelte-free. |
| **sync**    | `src/lib/crdt/{providers,protocols,migration}/`, `src/lib/collaboration/` | provider / document    | Transport: the generation envelope, the room lifecycle and join rule, IndexedDB + websocket providers, awareness, presence, v13→v14 migration.                               |
| **session** | `src/lib/session/`                                                        | the view               | DOM-free per-view state: the selection value, the command dispatcher, input attempts, the composition session, history, keymap, navigation, moves, handles.                  |
| **surface** | `src/lib/surface/`, `src/lib/components/`, `src/lib/events/`              | one mount              | The only code that touches the host DOM: render cells, the compare-to-truth observer, the selection projector, the IME pin, the overlay, the event adapters.                 |
| **plugins** | `src/lib/plugins.ts`, `src/lib/plugins/`, `src/lib/kinds.ts`              | the editor (immutable) | Kind, mark and atom records, hooks, commands, bindings.                                                                                                                      |

`src/lib/edytor.svelte.ts` (`Edytor`) is the composition root: it builds one of each per view and wires them. It should hold wiring, not rules.

### Worker-safe CRDT boundary (maintainer constraint)

The CRDT engine and the sync layer also run server-side in a Cloudflare Durable Object that coordinates clients over WebSockets (a central coordinator, not P2P). `src/lib/crdt/**` (vendor included), `src/lib/utils/json.ts`, `src/lib/utils.ts` and `src/lib/constants.ts` must stay importable and runnable without Svelte and without browser globals:

- never import `svelte`, `$app/*`, `*.svelte(.ts|.js)` or a view layer (`components`, `selection`, `surface`, `session`, `events`, `block`, `text`, `plugins`, `clipboard`, `collaboration`, `edytor*.ts`) from there;
- feature-detect browser APIs (IndexedDB, `navigator.locks`, `BroadcastChannel`, page events); no module-level timers.

Three checks enforce it: `pnpm lint` (`WORKER_SAFE` + `edytor/worker-safe-imports` in `eslint.config.js`), `pnpm check:worker` (bundles `src/lib/crdt/index.ts` and `src/lib/cloudflare/index.ts` for a Worker target) and `src/tests/crdt/arch-v2/do-coordinator.test.ts` (a reference coordinator with the browser globals removed and timers forbidden). The coordinator's public surface — `bindCrdt(Y)` (`.sync` readers/writers and `applyRemote`, `.admission`, `.doc`), the frame contract, the message types (incl. `messageSaved`, `messageChunk`), the chunk codec, the lib0 frame helpers and the instance-free awareness codec (`readAwarenessEntries`/`writeAwarenessEntries`) — is section 8 of `src/lib/crdt/index.ts`. Do not remove anything that test or the room imports. The site's `server/protocol` and `server/room` pages have the contract.

The shipped room is `edytor/cloudflare` (`src/lib/cloudflare/`): `DocumentRoom` (the Durable Object) and `routeDocumentSocket` (authorize before the upgrade, forward only `X-Edytor-User/Replica/Access`, the user percent-encoded; a denied dial (`null`, or an invalid identity: a `userId` empty, not a string, over 256 characters or with a lone surrogate, or an invalid `replica`) is accepted and closed `4403`, an invalid document id `4400` (empty, `.`/`..`, over 256 characters, a lone surrogate: `validRoomId`, which the provider and `createWebsocketSync` enforce by throwing at construction; `<Edytor server room>` never throws: a readonly view or the server render builds no provider, an editable view reports `4400` through `onSyncRefused` without dialing), so the provider stops; the provider sends the room id percent-encoded as one path segment, and a host Worker decodes it, closing a segment that does not decode `4400`; a host Worker refusing a dial itself answers `closedSocket(code, reason)`, never an HTTP error, which the browser reports as `1006`). It is in the Worker-safe set and is the only module allowed to import `cloudflare:workers`; `src/cloudflare-workers.d.ts` (outside `src/lib`, never shipped) types that runtime for `pnpm check`, while `tests/do` checks it against `@cloudflare/workers-types`. Rules it owns: identity bound in the socket attachment; a client id belongs to the user whose socket dials or binds it as its `replica` (another user's dial is closed `4409`); new structs under another user's id, or an id the room holds part of, are stripped from the frame and the sender stays (an id the room holds nothing of is stored unowned, `relayed`; the frame's deletes are kept except those of map entries the stripped structs replace, held or not (`replacedEntries` resolves an unheld origin through the frame; unknown counts as an entry); a delete of an item the room lacks is stored as a `pending` row (capped at `MAX_WAITING_DELETES` ranges: a frame past it has those deletes dropped, a `waiting` refusal, left out of its ack; `settleDeletes` re-checks after applying, so deletes of the frame's own waiting items and in-memory replaced entries are capped too; compaction keeps only the ones still waiting, apart, and reclaims those of ids no user registered and no socket holds, in memory too (deletes of a registered id's items are kept, so a writer can still fill the cap: `dropWaitingDeletes()`, also over RPC, empties it, in-memory ones too; a stored waiting delete arms `onSave`, and a seed from the `onSave` copy stores the ones it carries as a `pending` row again), applied when the item arrives, echoed to the sender that released it, all dropped when a frame's release discards a forged stamp), except the entry a rewrite of the same frame that still waits replaces (it waits with it, in memory; a struct the engine left a Skip for counts as waiting)); only undecodable bytes are `1008 malformed`, room faults close `1011`; `authorize` may return `{ expired: true }` (close `4401`, retried); read-only sockets get the read-only notice (auth subtype `1`, `writeReadOnly`: no event, the provider's `readOnly` turns true) when they join and `permission-denied` (`read-only`) per refused write, and stay (the provider then tracks nothing, so `saved`, and sends the socket only its document's own local edits, never what a tab or a store delivered; that denial never emits `failed`); every sync message is answered with `messageSaved` after the write (the provider's `saved`/`unsaved`; its deletes are the message's stored ones, applied or in a `pending` row, and the provider settles a delete only when an ack names it), and a frame that releases waiting structs broadcasts one, with the deletes that waited, to the other sockets (a relayer's waiting rewrite, e.g. `lastChangedBy`, is stored when the author returns); frames above `EDYTOR_MAX_FRAME_BYTES` go out as `messageChunk` sequences; compaction is `mergeUpdates` after `EDYTOR_COMPACT_AFTER` records, run after the message is acknowledged (a failure is logged as a `storage` refusal and retried; nobody is disconnected); every entry point runs under `noTimers`. Restore and registry: `onLoad` returns JSON, a bare v14 update or `{update, replicas}` (`LoadedDocument`); nothing is stored until it settles; `null` is provisional (asked again at every start); a throw closes sockets `1011 room unavailable` and is retried; a refused payload, a torn record or a container of another generation sets `failure` and refuses every socket `1008 refused: container` (`reset()` is the generation cutover). `onSave` receives `{value, update, replicas}` (`ReplicaOwner[]`; an alarm that finds the rows unreadable restarts the room, else re-arms with backoff); after a bare-update restore each id with content is claimed by its first dial (an `orphan` note). `refusals` keeps the newest `MAX_REFUSALS` (100), `refusalCounts` counts all. The room echoes an accepted presence entry to its sender, so a lone client is never silent for 30 s. Server `transact` edits obey the `semantics` option (default `defaultSemantics`; `semantics: {}` checks nothing) and are one transaction, not a rollback, like every client-side `transact`: a throw from `fn` keeps the writes made before it (stored and relayed; all or nothing is one `prepare.*` plan), a failed append throws the storage error and rebuilds from the rows keeping what the engine holds waiting (a rebuild replaces `doc` and `facade`: their subscriptions end); a room-side write straight through `facade` whose append failed is dropped (`heal`) at the next entry point or the next read of `facade` or `doc` while the room is idle (never mid-transaction, mid-frame or mid-event, `afterAllTransactions` included: the frame handler faults its sender); a room `transact` inside another transaction or its change events (a `facade.onChange` subscriber, of a client's frame or of the room's own `transact`; only a call inside `fn` joins) throws without writing, as its write could not be stored before it returns (defer it with `queueMicrotask`); client updates are relayed as they are.

## Doc

- **Shape.** `JSONDoc = {children: JSONBlock[]}`, `JSONBlock = {type, id?, data?, content?, children?}`, `content` = `JSONText {text, marks?}` and `JSONInlineBlock {type, id?, data?}` (`src/lib/utils/json.ts`). A block owns its inline `content` and its nested `children`; the model is not a DOM mirror.
- **Streams (text ownership).** Each block's text is a stream in a backing text, delimited by boundary items. A split writes one boundary; a merge adds a claim. Split and merge never copy text. `docs/crdt-v14-text-ownership-adr.md` and the plan §2.1 have the details.
- **Text delete marks.** A text delete writes the writer's mark (root `textdel`, in the history's scope); an undo restores text through `restoreFilter`/`onApply` (fork patch P11) only where no other writer's mark holds it and no copy shows it, copying the character's newest incarnation; the writer's replica hides a concurrent restoration of what its mark holds, deduplicates its own copies (leftmost wins) and restores what it withheld once the holds are gone. Restoration records (root `restored`) give every copy its root and origin. Never restore or delete text behind the history's back: go through the facade.
- **Preserve what was not removed (2026-09-28, `docs/editor-delete-contract.md`).** A block delete removes only its members (`del.blocks.promote`: unselected children take the slot; `deleteBlock(id, { keepChildren: false })` is the explicit subtree delete) and a block selection is exactly its members (`sel.blocks.exact`; a selected block that shows only its children — a list, a code block — stands for its subtree: what acts on content — delete, cut, copy, paste, typing, marks, Turn into, `onDeleteSelectedBlocks` — reads `selection.selectedMembers`, while `selectedBlocks`/`getSelectedBlocksInDocumentOrder` are the blocks as clicked, one block to the block menu's Copy link, Move, Duplicate and Escape, GX-02/HX-01; marks still skip a closed toggle's hidden body in it). An undo never deletes a block its step created (`hist.undo.withdraw`, P12): the block is withdrawn and shows while it holds another writer's content. An emptied document writes nothing: each view shows a virtual paragraph (`doc.empty.virtual`) that the first edit in it creates, in the edit's plan. A text range delete that would leave nothing to hold the caret keeps its head block, emptied, with its id, type and data (`del.range.whole-doc`), so peers deleting the whole document keep the same block; it never writes a new one. A range inside one `lines` island (a code block's whole text) keeps its head the same way (`del.range.island-kept`); other islands keep `del.range.empty-container`. A block-set delete and the block menu's Delete share `caretAfterBlockDelete` (`replaceSelection.ts`): the start of a promoted child that takes the set's place, else the end of the nearest line before, else the start of the nearest line after; Escape ends the first selected block's `shownText` (`selectedBlocksExit`; the one shown-line walker, also behind `setAtBlockRange` and leaving a block selection). Never `firstEditableText` (it stops at an inline atom).
- **Operations are two-phase.** Every facade op is `apply(prepare.op(…))`. `prepare` writes nothing and returns a plan of named steps with its effect (or `refused`); `apply` writes it in one transaction and returns `OpResult {status: 'applied' | 'noop' | 'refused', ids}`. Range delete (`prepare.deleteRange`/`replaceRange`/`deleteBlocks`) and paste/drop placement (`prepare.insertFlow`) are single plans whose rules are rows in `docs/editor-delete-contract.md` (`del.range.*`, `flow.*`). A pasted line whose kind joins no text (a list, a code block, a void) is placed as a block, never joined, so no text lands where nothing shows it (`flow.apart`, GX-01; assert it in DOM tests with `expectNoHiddenContent` from `src/tests/fixtures/dom/invariants.ts`), and a code line takes a flow as plain lines (`flow.lines`). A new structural case means a new contract row, not a caller flag.
- **One index, one report.** `facade.onChange(cb)` delivers one `DocChange` per commit that changed the visible document (`added`, `removed`, `moved`, `meta`, `content`, `order`). Nested transactions publish once; a transaction that nets out publishes nothing. Its callbacks (and `onWritableChange`'s) run inside the engine's `update` emit: one that throws is logged, never rethrown (an error escaping that emit wedges the doc: no later transaction emits `update` again).
- **Roles.** `void` (structurally isolated, not editable by the core flow) and `island` (editable, sealed from its neighbours) drive merge, unnest, delete and navigation. They are not cosmetic. A document learns them from its views' plugins or from `createDocument({semantics})` (`defaultSemantics` for the bundled kinds); without either, a headless document checks no roles. The bundled rows live in `crdt/semantics.ts`: change them there, not in the plugins. An island whose role also says `lines: true` (code → `codeLine`, opt-in) holds only lines and a line holds no children, even a deleted one's children take the island's slot; the display enforces this against undo and concurrency (`displaySlotOf`, the index's `typeOf`, line kinds from the roles via `EdytorDocConfig.kinds`; `docs/editor-delete-contract.md` `conc.island-lines`). Any other island keeps its structure (a retype to an ordinary kind re-kinds only a lines island's lines, as `typeOf` does). Nothing merges into a block that renders no content (`canMerge`: a code block's first line, a list's first item, a row's first cell), and a container (no content, not an island: a list, a row) never merges as a whole: the key merges and text ranges act on its items, no key, block delete or move leaves one with no child, an outdent splits it rather than handing its later items to a paragraph (the list keeps the items after the outdented ones; a new list takes those before), nothing is retyped into a kind that renders no content, and a peer's item promoted out of a removed one shows as its new parent's default child at read time. One predicate owns what a container holds, `fits(parent, kind)`: a container whose default child is its own kind (a list's `list-item`, a columns layout's `column`) holds only those and containers of them, one whose default child is the document's (a column) holds anything; moves are refused where blocks do not fit (`canPlace`), Tab nests under a container's last item (`nestParent`, also `moves.ts` `inside`), outdents/lifts are refused where they would not fit, and a plain (default-kind) block shed or pasted into a list becomes its item, while any other kind keeps its kind and data, as read-time promotion does (`settledKind`/`fitted`); the move command's `out` step asks `prepare.unNestBlocks`, not `canPlace`; explicit `insertBlocks`/retypes are not refitted, though a plain block stored directly in a list shows as its item at read time (`typeOf`'s `itemOf`, AW-04: no race leaves a bare paragraph in a list; a Turn into racing an outdent may leave another kind, such as a heading, there, as a merge can — a documented residual) (`isContainer`, `fits`, `settle`, `emptiable`/`emptying` in the facade — `rangeDelete.ts` uses the same ones; `container` reset in `displaySlotOf`/`typeOf`; `del.merge.container`).
- **Read-time display.** A deleted block's unmarked children, and a child a peer adds, moves or splits under it concurrently, show in its slot (`displaySlotOf`, rank `promotedRank`); nothing hides with a deleted subtree (`del.blocks.promote`). A void kind displays no children: a retype to void moves them right after it, and a child that lands under one concurrently is shown in its slot, from the document's roles (`DisplayOwnership.childless`, fed by the runs index from `roleOf`), so replicas must hold the same roles.
- **Seeds.** A seed is written under a writer id hashed from the value, in a band below 2^26; live writers are uint53, so a seed never displaces a live block. Two different seeds sharing an id resolve by hash order (irreversible), so never seed a changing snapshot beside a room. The derived own-text writer is a different id space (53-bit `hash53`); never widen the seed writer.
- **Anchors** are `DocAnchor = {b, a}` (see the anchor contract below).
- **Properties (data).** A block's, an atom's and the document's (root `docdata`, in the history's scope) `data` is one attr per JSON leaf, `d/` + RFC 6901 pointer (`crdt/data.ts`): per-leaf LWW, a primitive leaf under which leaves exist reads as the object. Arrays are fine-grained (`Y.Array` semantics, no Y types): a `[]` marker leaf plus items, item `id`'s value under segment `~id` (`~` + a letter is never an escape) and its rank (`placement/rank.ts`) at `~id#`, a move's at `~id>`; an item lives while its creation rank `~id#` does, so a remove beats a concurrent inner edit or move (orphan leaves are skipped); an insert after an item this client ranked goes in its run there (`between`: the item's rank + a `RUN` segment tied by the client, YATA's origin rule, so its later inserts there stay together even across commands; elsewhere a plain `rankBetween`); a whole-array assignment keeps the items a longest common subsequence keeps equal and pairs the rest by position (`arrange`); `order` re-ranks only what leaves the longest increasing run. Patches address items by index or id (`~…`), resolved at prepare time (the plan's leaf writes name ids; a gone id is refused); `facade.dataItemIds(target, path)` lists them, and the proxy names an item it hands out by id, so a held item (a keyed `{#each}` row) stays on it. An array assigned where no item is (a new node's data, an exploded legacy array, a whole assignment) takes ids/ranks derived from its index and its value's hash (`~l<i>.<hash>`, tie = hash: identical concurrent assignments and seeds write the same items, different ones stay apart); inserts into an array with items use `randOf(doc)`. Legacy bases (the whole `data` attr, a next.6 atomic array leaf) are shadowed by the leaves at, above and under their paths (`effective`): a patch writes its leaves over them while they still read right, else explodes them (`patchWrites` reads the result back to decide). One write path: `prepare.patchData(target, ops)` (`target` a block id, `{block, atom}` or `null`; ops `{path, value?}`, `{path, splice}`, `{path, order}`; `setBlockData`/`setInlineData`, `setBlock`'s data and a flow's `redata` are root patches); no schema generation bump (mixed-version clients read only the legacy attr). The index folds leaf attrs as `meta`; the doc root's change is `DocChange.data`. `JSONDoc.data` is seeded (joins the seed hash only when present; hashed and built from the key-sorted form, so key order never splits a seed) and exported by `toJSON` only when non-empty. View: `block.data`/`atom.data`/`edytor.data` are `propsProxy` (`session/props.ts`): reads live through the cell (blocks, atoms) or `edytor.docData()`, writes are the `patchData` command (an array mutator is one `splice`/`order`/reassignment patch, an index write a path into that item) (hooks see every data write, `setBlock`'s included, as a `patchData` step); the dispatcher lets a `patchData` setting only strings at the same target and paths continue the previous one's undo step when each new string inserts or deletes one run in the previous one (`typedFrom`: typing into a bound field); a flag, number, delete, object, or a string set to another value (`'todo'` → `'done'`) is its own step. A kind's own control inside the host (any native form control, whatever its type, or a nested foreign editable, never the root or a text element: `isKindControl`) owns every event on its composed path (`ownsEvent`, DR-props-2): keys, `beforeinput`, paste, copy, cut, drops (a file is swallowed) and selection, whatever the selection, a block selection included. `onKeyDown` (before the readonly and hotkey paths), `onBeforeInput` (`isBrowserOwnedNativeInput`, before the selection sync), `onPaste`, `copySelection`, `onDrop` and the projector ask that one predicate; never add a per-type or per-handler check beside it.

## Sync

- Every frame is `varuint GENERATION | varuint messageType | payload`; `GENERATION = PROTOCOL_VERSION * 1000 + SCHEMA_VERSION` (schema generation 4). Anything else is refused before decode; `applyRemote` refuses updates that forge the schema stamp.
- One room lifecycle and join rule (`providers/room.ts`): hello = Step1 + presence; a Step1 is answered with Step2, plus our own Step1 when the asker holds something we lack.
- `createIndexeddbSync(name)` / `createWebsocketSync({server, room, params?, maxBackoffTime?, connectTimeout?, onExpired?, WebSocketPolyfill?, disableBc?, persist?, persistName?})` are `EdytorSync` factories for `<Edytor {sync}>` or `document.attachSync` (`serverUrl`/`roomName` are deprecated aliases of `server`/`room`); the document keeps one provider per transport target. `createWebsocketSync` attaches a local IndexedDB store by default (`edytor:<server>/<room>`, skipped without `indexedDB`) as a provider of its own through the payload's `attach`, so the document's readiness rules apply to each leg unchanged; while the store exists it carries the cross-tab channel (the socket's BroadcastChannel leg is off).
- Readiness bound: `createWebsocketSync` sets `bound: Infinity` and arms the 1 s bound through `EdytorSyncPayload.armBound()` from the socket's open or its first failed dial, so a cold room hydrates instead of racing the seed. Known gap: a server that opens and then takes over 1 s to send its state is read as empty. A dial that neither opens nor fails is closed after `connectTimeout` (10 s default, `Infinity` = no limit), which arms the bound (up to about 11 s). A `4401` before the first sync holds the bound (`armBound`'s counterpart `holdBound()`) until that provider syncs or is released.
- Refusals: a close with `1008` or `4xxx` is terminal: the provider stops dialing and emits `refused` (`SyncRefusedError {code, reason}`); an empty document never seeds over it and exposes `document.syncRefusal` / `onSyncRefused` until that provider is released or syncs again; one that already holds content is hydrated at the refusal. `4401` (expired credentials) is not terminal: `expired` fires (`onExpired` option, `<Edytor onSyncExpired>`) and the provider redials with the re-read `params`; `<Edytor onSyncRefused>` reports refusals (the one standing at mount too, isolated like the later ones). Releasing a refused provider decides with the providers still attached (none: stays pending), and a view never seeds a refused document on mount. `1006` (an HTTP refusal looks the same) keeps redialing: backoff `100 ms × 2ⁿ` capped at `maxBackoffTime`, the cap doubling to 30 s after 8 dials that never synced, each emitting `unreachable`; the count resets when a connection syncs. A room fault (`1011`) after a sync also grows the backoff and emits `unreachable` (`attempts`: faults in a row), until the room acknowledges every local update again (`saved`, which counts only clocks of client ids the actor dictionary binds to the document's actor, so another user's stripped edits never hold it). Provider and awareness events isolate their listeners (`protocols/observable.ts`): a throwing one is logged and the provider keeps going. A text `ping` goes out after 15 s of silence; a text `pong` counts as liveness.
- Presence lost with a transport is removed under the `LOCAL_PRESENCE_LOSS` origin: that tab only, sibling tabs keep their remote carets. `beforeunload` only announces the departure (an unsaved-changes prompt may keep the page); `pagehide` of a page leaving for good destroys the providers.
- `<Edytor>` releases a view-owned document in `onDestroy`, which also runs after a server render.
- Presence: `selections[viewKey] = serialize(value) + t`, through the view's `PresenceWriter`: `share` (`caret`, `block`: `{ blocks: [focus block] }`, `none`) and `throttle` (ms, leading write then one trailing write of the newest; a named timer cleared by `destroy()`). A view writes only its own key. Peers resolve the freshest valid entry per client, text (a caret) or a block set (a bar beside the blocks' own rows).

## Session

- **Selection value** (`SelectionValue`, by `kind`): `none`, `text {anchor, focus, pending?}`, `atom {blockId, atomId, from}`, `blocks {ids}`. Everything a command reads (endpoints as (block, display offset), direction, collapsed, covered blocks, edge flags, marks, content) is `project(value, doc)`, memoized per (value, index version). `selection.state` is a read-only compatibility getter over the projection. Pending marks are `value.pending` (`selection.pending`, `selection.stage(marks)`).
- **`select(value, cause)`** is the one writer. No text endpoint rests in a block that renders no content (a divider, a list, a code block): `select` moves it to the nearest shown line (`#shown`: a container's first item, else the next line, else the one before; none: the value stays), and the post-flush repair does the same after a peer's change (FX-01). Over a block selection the navigation keys (`move` in `session/navigation.ts`) and Escape/Enter (`selectedBlocksLine`) read each member's own line, a line-less member's (list, code block) subtree, never an unselected child's (`shownText` in `selection/replaceSelection.ts`); voids alone stay selected except under the document keys; never patch a key instead. It applies the effects once (selected/focused sets and hooks, suggestions), emits `onSelectionChange` and publishes presence only when the value changed, and asks the projector to display (causes `model`/`history`), or not (`dom`).
- **Dispatcher** (`edytor.dispatcher`): admission (readonly, `document.writable`) → prepare → `onBeforeOperation` on the command and on each planned step under its documented name, all before any write → one transaction → normalization requests drained once inside it (also when the transaction threw: its writes stay) → `last.status` (`refused | noop | applied | failed`) → `onAfterOperation` once. A veto refuses the whole command; `prevent(cb)` replaces it. `prevent()` is caught only in the dispatcher; never call `stopCapturing()` or catch `PreventionError` elsewhere. Plugin command API: `dispatcher.dispatch`, `lead` (a markdown or slash trigger removal leading a conversion in one plan) and `caret` (the command's result selection); `Plan`/`Prepared` are exported types.
- **Undo policy is the dispatcher's.** Do not hand-place `dispatcher.cut(…)` before block or text operations. An operation outside a user command is its own step (it cuts before it writes) unless it is `insertText` or `addInlineBlock` continuing at the caret the last step left, when that step was text editing (`history.continues`: the dispatcher records per step, as it writes, whether it was an insertion, a composition or a text deletion, `inserts` → `history.wrote`; a resize, a data write, a paste or a conversion ends it); a led operation (markdown or slash conversion) and `inlineMarkdown` are always their own step, so undo gives back the typed trigger. To make a multi-operation gesture one step, wrap it in `edytor.transact` (always one step) or `dispatcher.run(kind, body)` (also a prevention scope; it cuts no step between its synchronous commands, but each commits alone, so the capture window groups them: `captureTimeout: 0`, a slow body or commands after an `await` split it). `dispatcher.cut` remains only for writes the dispatcher never sees: raw facade writes, browser-owned attempts, a composition's first write.
- **Data writes are commands.** `block.data.x =` (the proxies), `block.setData`, `atom.setData` (all `patchData`) and `block.type =` (`setBlock`) go through the dispatcher: refused when readonly, shown to hooks, recorded in `last`, their own undo step. `block.model.setData` is the raw write. `edytor.clear()`, `historyUndo()` and `historyRedo()` check the same admission (`dispatcher.permits()`): a readonly view never wipes or rewinds the shared document.
- **Selection-touched blocks and hidden bodies.** `src/lib/selection/replaceSelection.ts` owns `getSelectionBlocks` (blocks a selection touches; a closed toggle's hidden body is not touched), `outermost`, `revealing` (a move never hides a block the user saw) and `revealed` (wraps the block move commands `nestBlock`/`unNestBlock`/`moveBlock`/`moveBlocks`, so every caller reveals); caret walkers use `shown(block, step, { removed })`, which skips hidden bodies unless their toggle is being removed. The visibility rule itself (`HIDDEN`, `hidden`, `shown`, `viewOf`, `rangeCovers`, `selectedTextSpans`) has one owner, `src/lib/selection/visibility.ts`; editor code imports it from there, and `selection.hidden`/`selection.shown` re-expose the same functions to extensions. Keep one definition of each here; plugins import them from these modules.
- **Input attempt** (`edytor.attempts`): one per occurrence (a `beforeinput`, a keydown whose `beforeinput` never came, paste, drop, a native line break). Intent, anchored target (the selection value) and owner (model performs, or browser performs and the model adopts) are fixed at admission. An intent with no target is refused there (`targetless`: a text, delete or break intent while the value is `none` and the host holds no caret a gesture placed, `projector.placed`): prevented at its keydown and at its `beforeinput`, never adopting the declared range (Chromium's parked caret at the host's start), and that caret stays parked (`projector.parked`) until a press, an adopted move or a display. A model-owned attempt owns the DOM drift around it until its deadline.
- **Composition session** (`edytor.composition`): one IME composition, `live → tail → gone`. The start target is replaced by an ordinary command at the first write (over a block or atom selection, which shows no DOM range, at `compositionstart`, with the DOM caret parked in its place by `projector.park`, EW-01); the pin keeps the host's render as the IME found it until the first preview (a write before it collapses the IME's range to the node's start; before it `imeBuffer()` reads nothing, so an abandon writes nothing, FX-02), and a range across texts (across blocks, or across an inline atom in one block) shows the rest its first write merged into the host, with the host's new segments, after the IME's own write (`pin.merge`, FX-08, GX-04); previews are mechanical tracked writes in one capture group (one undo step); it ends exactly once (`commit`, `cancel`, `abandon`, or D-20 when a commit re-places the host's block). No timer ever ends a session. While live, the host's segment list is frozen by the pin and the projector writes no DOM selection.
- **History**: `edytor.historyUndo()/historyRedo()` are the bare engine calls — never inside a transaction and with no tracked write after them (that would empty the redo stack), so nothing normalizes after them. The issuing view restores its recorded value, and each call sets `dispatcher.last` (`applied`, `noop` on an empty stack, `refused`).
- **Handles**: `Block`, `Text`, `InlineBlock` are id-only handles (`edytor.idToBlock` is the `Handles` registry). Getters read the document index (inside a command they see its writes); mutators issue commands. They are **not reactive** (their `data` proxy excepted: it reads through the cell): templates read the snippet's view object or the cells. A `Text` is the `ordinal`-th segment of its block and has no identity across commits; key extension state by block id and anchor. Liveness is `block.isInTree`, `text.isInDocument`, `atom.isInDocument`.

## Surface

- **Cells** (`edytor.cells`): one frozen cell per visible block, patched from each change report; a patch replaces exactly the cells it names. Components render from cells only (`Edytor` → `Block` → `Content` → `Text`/`Mark`/`InlineBlock`). The core renders the block element from the kind's `element`; snippets render inner markup and receive view objects (`BlockView`, `InlineBlockView`), not handles. The block element wraps the children too, so a kind that holds children never declares a heading or text-level `element`; it declares `contentElement`, which the core wraps around `content()` (snippet overrides keep it): the rich text heading and quote are `div`s whose `h1`–`h3`/`blockquote` holds only their text, children in a sibling `div` (`heading-children-structure.test.tsx`).
- **Nesting indent.** Every kind that renders children puts them in ONE `div[data-edytor-children]` (a rich text snippet's `nested`; the unknown-kind fallback in `Block.svelte`), indented once by `padding-inline-start: var(--edytor-nest-indent, 24px)` (`Block.svelte`'s global style, `themes/notion.css`); a kind that indents through a marker column (Notion theme: lists, to-dos, callouts) zeroes it, a toggle aligns it with its text — never add a second indent (`children-container-20260930.test.tsx`, `nest-indent.spec.ts`). Text segments are keyed causally (by the atom before them), so typing never remounts the caret's node.
- **Compare-to-truth observer** (`edytor.surface`): records carry no provenance; they only say what to compare. The pre pass (root `$effect.pre`) inverts a record that removed registered elements and snapshots an edit the flush would overwrite; the compare pass (root `$effect`, after every DOM write) compares each named content with its cell. Text inside a content is adopted through the dispatcher unless an expectation claims its host (the composition tail, a pending structural key, a model-owned drift — then the cell is restored); structure is restored; the live IME host is the IME's; read-only divergence is inverted at the flip back. The root, text elements and core mark elements are strict containers. **D-25:** a block's own text/atom run is a strict region only the editor writes; tolerance covers only a kind's own markup around the content and children slots (and attributes the table does not own).
- **Projector** (`edytor.projector`): the only DOM-selection writer. After every flush it writes the current value when asked, or when the render epoch moved, and only if the live DOM selection differs. It never takes focus from outside the editor (a form control or foreign editable focused in a kind's chrome counts as outside: a field bound to `block.data` keeps its focus while each keystroke commits) and never writes while a composition is live, except `park`: the one caret a composition over a block or atom selection gets before the IME writes. It classifies every `selectionchange` (echo, drift, composition, foreign, intent). Two named, time-bounded browser rules are the only signatures: the Android post-delete snap-back and the IME post-commit jump. The caret a browser parks when the editor focuses its own host (`takeKeys` in `events/onFocus.ts`, after a block drop, a column resize release or a grip click no menu answers, so the history and block-selection keys act at once) is drift until the next gesture, never adopted; a `none` value asked for (a history step) shows no DOM range.
- **View state** (a kind's declared `viewState`, `open` on a toggle's `details`): the browser and the user own it; `Block.attach` carries it to a re-rendered element (a moved toggle stays open). A collapsed toggle is one unit: `hidden(block)`/`shown(block, step)` let Backspace, Delete, Tab and the block-selection arrows skip its hidden body; never walk `blockBefore`/`blockAfter` alone for a key the user sees. A text range never reaches a hidden body either: `prepareDeleteContent` passes `{ hidden(id, removed?) }` to `prepare.deleteRange`/`replaceRange`, and range deletion asks it with the blocks that die, so a dying head's body goes and a dying tail's revealed body can take the caret (`del.range.hidden-body`, which Backspace/Delete next to a closed toggle reuse as one plan), and copy, marks, the toolbar and typed-over marks ask `rangeCovers`/`selectedTextSpans` (`src/lib/selection/visibility.ts`: a hidden block is covered exactly when the range's delete removes it; the live block selection covers exactly its members, a selected list or code block with its shown subtree: `selectedMembers`, FX-07, GX-02), never `state.texts` directly. Cut deletes like Backspace (not a replacement), and `prepare.insertFlow` takes the same `viewOf(edytor)` so a split closed header keeps its body.
- **Overlay** (`edytor.overlay`): `add(measure)` and `mount(component, props, name, zIndex, measure)` share one read-then-write contract: `measure(host, origin)` reads layout and returns its style writes (a closing menu returns its close as a write). Handles, drop indicator (Notion's plain 4px bar: centered between siblings; for `inside`, where the child lands, indented to the child's column), the nest backdrop (`[data-edytor-drop-backdrop]`, one per drag: a tint over the own row of the block a drop nests into — `inside`'s target or its `nestParent`, or a before/after's new non-root parent — `--edytor-drop-backdrop-color`; never a style on the block), menus and remote carets live in `[data-edytor-overlay]` beside the host, positioned layer-relative once per frame. Never add chrome inside the host. Block handles are lazy: a handle mounts only for a block near the viewport (an `IntersectionObserver`; every block when there is none), hovered, selected, focused or dragged (hovered: the pointer over the block or its own handle host, which sits flush with it; a handle over a column gap spans the gap, its `+` at the gap's left edge and its grip flush with its block, and its box takes the pointer at its block's whole row, hovered or not — the one hit rule, owned by `BlockHandles.svelte`; the column resize band sits above it at the gap's middle (`columns/gaps.ts`: `gapBefore` and `bandOf`, the one measurement both read), so wherever its guide shows a press resizes), and drop targets register only while our own drag runs. Every handle drag sets a custom drag image, never the grip alone (`blockHandles/dragPreview.ts`): clones of the group's block elements, stripped of editable/view-only/live-node attributes, in a wrapper carrying the root's and its ancestors' classes, unrestyled (only `scale(0.8)`, sized to the scaled box; the count badge for several), cloned at drag start and removed by the drag library (`drag-preview-20260930.test.tsx`, `drag-preview.spec.ts`). Drop zones (`zones`, on Atlassian's `@atlaskit/pragmatic-drag-and-drop-hitbox` list-item hitbox, loaded through `src/lib/dnd/pragmatic.ts`'s CJS entries for SSR): the hitbox splits the own row of the block under the pointer (`rowAt`: beside a nested block, over its ancestors' indent, that block's row) into reorder-before/reorder-after halves, `blocked` when the document refuses the whole half (then the other half's placements, `data-blocked` on the indicator); combine is never offered, the pointer's x nests: past one nest step (`--edytor-nest-indent`, else 24px) right of the text start, inside. PDD's tree rules: an expanded block's (children shown, not a closed toggle, not a container) lower half is its first child's slot, never after its subtree; the last block of a nested group reparents to the ancestor level whose text column is nearest the pointer, down to the root. A dragged block's own row and subtree offer nothing (released there, a drag is a no-op). The handle column left of the editor's blocks (the drag's handle width; `margin` on the page target) is the row at the pointer's height, by its halves, before or after only (never inside; over an item of a container the dragged blocks do not fit in, the container is the row, by its whole box's halves: `reorder`), the bar held between rows: a drag straight down the handles reorders, never a beside band (those start past it); a block target there refuses the pointer (`canDrop`), so the page target's rule always applies. Handles other than the source take no pointer during a drag (they sit over ancestor columns) (`dnd-nest-backdrop.test.tsx`). Auto-scroll: a handle drag registers Atlassian's auto-scroll for the window and every scrolling ancestor of the host (the host included), for our drags only, at drag start and releases it at the drop (`blockHandles/autoScroll.ts`); `dnd/pragmatic.ts` binds the package's `makeApi` to our adapter's `monitorForElements`, since its own entry requires the core by bare path, which a browser bundle resolves to a second adapter that never sees our drags. Never measure every block: reading a block inside a collapsed (`display: none`) subtree forces a layout each time.
- **Placeholder** is the `data-placeholder` attribute on the empty text element, drawn by a shipped `::before` rule.
- **Suggestions** (`edytor.suggestions`, `session/suggestions.svelte.ts`; site `editor/suggestions`): a view's proposed content at a position (`after`/`before`/`inside`/`end`/`replace`, by block id or a range's anchors), session state only: never in the document, history, presence or another view until `accept()`, one dispatcher command (`acceptSuggestion`, CUT `both`) placing it as a paste does (`prepare.insertFlow` at `{slot}`/`{replace}`/the text's end, `flow.place`; a text range: `replaceRange` then the flow at its caret). It survives selection changes and is dropped (`prune`, from the commit) when its block dies. A block suggestion renders in the host as one view-only group (`components/Suggestion.svelte`: `[data-edytor-suggestion]`, `contenteditable=false`, the kinds' own rendering through `Block`'s `preview` cells, no handle, no ids, no text elements), registered with the observer as `preview` (never compared or healed) and skipped by the truth oracle, selection mapping (`SUGGESTION` in `selection.utils.ts`), chrome presses and the drag clone; an `end` suggestion is the ghost text (`[data-edytor-text-suggestion]`); replaced blocks carry the owned `data-edytor-suggestion-replaced`, a replaced range is overlay rectangles (`components/SuggestionRanges.svelte`). The bar and keys are `suggestionsPlugin` (a default).
- **DOM selection exceptions.** Besides the projector (`post`, `park` and its own clear when focus leaves), only these write the DOM selection directly: `selection/domSelection.ts` replaces a multi-range selection (in practice Firefox's) with its bounding range when a snapshot reads it, and these clear it: `events/onFocus.ts` (focusout after focus moved outside), `edytor.svelte.ts` (attach teardown), `selection/selection.svelte.ts` (two sites), `block/inlineBlock.svelte.ts` (atom selection). Do not add more.
- **BI2-5 lint**: DOM mutation calls in `src/lib` are allowed only in the host writers (`components/`, the handles' attachments, `surface/observer`, `surface/attributes`, `surface/overlay`, `plugins/`, `collaboration/`). Never write imperatively into owned text or mark elements.

### Selection contracts that must not regress

(Normative spec: `docs/editor-delete-contract.md`, "Anchor contract", "Selection ownership and lifecycle", "Responsibility map".)

- A caret anchor is `{b, a}`: `b` the home block of the backing text, `a.i` the bound item (causal identity), `a.a`'s sign the insert affinity. Text ownership is streams delimited by boundary items: a left caret at a split-born block's start binds that block's boundary item, so the containing stream and the side are two facts in two fields (no owner facet since arch-v2 D12). Never let a caret migrate into a surviving neighbour block because that neighbour received text at the shared gap.
- Logical recovery destination and DOM readiness are separate: a live destination with no mounted node stays the selection value and is displayed by the projector's pass after the flush that mounts it (a value that no longer projects runs the seam repair; a text mount or the observer's records re-run a waiting pass). Do not "fix" this by treating unmounted text as unrecoverable, or by weakening `firstEditableText`'s mounted-node requirement (container phantom slots must stay skipped).
- `surface/projector.svelte.ts` is the only DOM-selection writer (`post`, and `park` under a live composition; the named exceptions are under Surface): after every Svelte flush it writes the current value, so no older request can overwrite a newer gesture. Commands and input attempts decide the value and `select()` it in their own turn (`edytor.attempts.caret` only records the drift-repair caret); the three named writes that still select after a wait (the adoption caret, the root-heal redisplay, the drift repair's caret) check the gesture serial after it and yield to a newer gesture. Do not bring back tick/timeout re-assert loops. While a requested display has not landed, a `selectionchange` with no intent gesture since the request (`Edytor.intentSerial`, the one gesture serial; `input` events do not bump it) is not adopted.

## Plugins

`Plugin = (editor) => definitions & operations` (`src/lib/plugins.ts`). A plugin contributes:

- kind records (`blocks`): `snippet`, `element`, `viewState`, `void`, `island`, `rendersContent`, `defaultChild`, `continues` (list-like Enter), `container` (a header over its children: toggle, callout, quote), `presets` (slash menu, markdown, "turn into"), `empty`, `html`/`plain` export, `parse` (HTML import), `transformText`, `normalizeContent`/`normalizeChildren`, focus/select hooks;
- mark records (`marks`): `tag` + `attributes(value)` (the one element the core renders and the clipboard exports, P2.7), an optional `snippet` (custom markup inside a core span), `parse` (HTML import), `void`, `edge` (`inclusive | exclusive | side-dependent`), `toolbar`; atom records (`inlineBlocks`);
- `hotkeys` (typed `HotKeyCombination`: up to three modifiers in any order; unknown tokens fail types and warn in DEV), `commands`, and hooks (`onBeforeOperation`, `onAfterOperation`, `onBeforeInput`, `onCopy`/`onCut`/`onPaste`, `onDeleteSelectedBlocks`, attach hooks that may return a cleanup, `placeholder`).

Duplicate definitions and commands: **first wins** (an extension that extends another's definition lists itself first). Extensions read the document through handles and view objects, never Yjs types. Bundled and exported: rich text, code (TanStack Highlight, JSX only; tokens are its `transformText`), image (`imagePlugin`/`createImagePlugin({ upload })`: void `figure`, `data.src` filtered by `safeImageSrc` to http(s)/blob/`data:image/`, "Add an image" link panel, Upload only with `upload`, editable caption), block handles, block menu, slash menu, toolbar, markdown shortcuts, arrow move. The mention plugin is a reference implementation only (not exported). The bundled chrome follows Notion (2025 light theme); the matching document stylesheet is `src/lib/themes/notion.css`, shipped as `edytor/themes/notion.css` and scoped under `.edytor-notion`. The demo route (`src/routes/+page.svelte`) and the site's live editor use that theme, `richTextPlaceholder` and the shipped plugins, including the block menu (the demo route builds it with `createBlockMenuPlugin({ linkTo })`). HTML import (P4.1, `clipboard/htmlFlow.ts`): external `text/html` paste and drop are parsed by the browser (`DOMParser`) into a flow; the tag tables are the kind and mark records inverted (a preset's export/element tag, a mark's `tag`, each record's `parse` hook first) — never a tag switch. Paste order: internal MIME, embedded fragment, a plugin's `onPaste`, HTML import, `text/plain`.

Default plugins: `<Edytor>` (`withDefaults` in `components/Edytor.svelte`) adds `arrowMovePlugin`, `suggestionsPlugin`, `imagePlugin` and `richTextPlugin` after the app's `plugins` (its kinds and keys win), each unless the list already has it (any `createImagePlugin` / `createSuggestionsPlugin` instance counts, via `isImagePlugin` / `isSuggestionsPlugin`); `defaultPlugins={false}` opts out. Block handles are added separately (`blockHandles`). The `Edytor` class itself adds nothing (`createTestEdytor` lists its plugins), and the DOM harnesses (`EdytorHarness.svelte`, `SiblingEdytors.svelte`, `/test/dom`) pass `defaultPlugins={false}` so each test's plugin set is exact.

Editing behavior (Enter and Backspace by role: plain, continuing, container, void, island) has one canonical description, the site's `customization/hotkeys#enter-and-backspace-by-role` table; `src/tests/docs-drift.test.ts` catches known stale phrasings. The code is `insertParagraph` in `events/beforeInputCommands.ts` (`continues`, `container`, the `<details>` open state read from `block.node`), `resetKindAtStart` in `events/beforeInputDeleteCommands.ts` (`del.start.kind`) and `prepareSplit`/`prepareSplitKeepingChildren` (a container header's mid split: the children stay) in `block/block.utils.ts`. Change the rule there and in that table, nowhere else. The slash menu opens only at a text start or after whitespace and matches each query word, in order, as a word prefix of a label or keyword (`matchesQuery` in `kinds.ts`, shared with the block menu's search, so `/to do` stays open); a replacing kind (`empty`) converts in place only a block holding nothing but the query (`holdsNothing` reads `dispatcher.pendingLead`), else it is inserted after the block. Emptiness is one rule: `block.isEmpty` (and `holdsNothing`) count inline atoms, so a block holding only a mention is never treated as empty (a public change, listed in `reference/migration.mdx` under the upgrade from the previous pre-release). Enter or Shift+Enter over a block selection removes nothing: it leaves the selection for the caret at the end of the first selected block's line, as Escape does (`selectedBlocksLine` in `selection/replaceSelection.ts`, Notion; Escape over voids alone goes to the next shown line, else the one before, through `selectedBlocksExit`, never into a divider's phantom text); Mod+Enter only opens/closes toggles and checks to-dos (Notion), each shown block it is in (`shownSelectionBlocks`, `flipToggles`), never splits.

UI snippets: the chrome plugins take snippets and keep their behaviour (keys, placement, commands). `createSlashMenuPlugin({ item?, menu? })` (`SlashMenuItem` `{command, selected, icon, run, select}` / `SlashMenuController`), `createToolbarPlugin({ toolbar? })` (`ToolbarController`; placement measures `[data-edytor-toolbar-bar]`, else the first element), `createBlockMenuPlugin({ linkTo?, menu? })` (`BlockMenuController`; placement measures `[data-edytor-block-menu]`, else the first element; a custom menu owns its keys, the built-in ones live on the default search field), and `BlockHandlesOptions.handle` (`BlockHandleSnippetPayload` `{block, grip, add, readonly, draggable}`; `grip` is `BlockHandleController.grip(block)`, the one attachment for drag source, click-to-activate and Alt+arrow keys, used by the default handle too). `slashMenuPlugin`, `toolbarPlugin`, `blockMenuPlugin` are the factories called without options. The contract tests are `src/tests/fixtures/dom/custom-ui.test.ts` (fixture `src/tests/dom/CustomUi.svelte`).

Block handles and the block menu:

- Each handle is a `+` (dispatches `BLOCK_ADD_EVENT`; the slash menu answers it and adds nothing until a row is picked — typing goes to the menu's query, a custom `menu` snippet is wrapped in a focused element for that, and Escape, a press outside, focus leaving or readonly close it with the selection given back — then `BlockAddition.insert` adds the parent's default kind below, Alt above, and runs the command in ONE transaction and undo step; a command that answers `false` or is refused with nothing applied is taken back inside that transaction, which the history then does not capture (undo and redo stacks untouched, selection given back); an empty default-kind block is converted instead; unanswered, the `+` inserts the empty block at once. The `+` menu lists only commands whose `isEnabled` holds for the block being added (`additionView` in `SlashMenuController`: a view whose caret is in a stand-in of that block), so commands read the selection from their argument; its field is its one keyboard owner (rows are no Tab stops); a `+` clicked over a grip's menu first gives back the pre-grip selection (`BlockHandleController.ungrip`)) and the ⋮⋮ grip. A grip click selects the block (an atomic block selection; a block selection already holding it stays, and the block menu then acts on all of it; over a text range across blocks, the blocks it covers), then calls `onActivate`, or, when none is set, dispatches `edytor-block-activate` (`BLOCK_ACTIVATE_EVENT`, `{ block, anchor }`) on the editor node. `blockMenuPlugin` listens for that event; a consumer `onActivate` replaces it.
- The block stays selected while the block menu is open. Its actions return a text caret with `selection.setAtTextOffset(text, offset)`, which replaces the atomic selection (the old `setCollapsedStateAtTextOffset` alias is removed), then focus the editor. A DOM range alone cannot replace an atomic selection.
- Moves go through `edytor.canMoveBlocks`/`edytor.moveBlocks` everywhere (drag and drop, handle keys, arrow move, the block menu). A handle's drag, Alt+arrows and click take the selection's blocks through one resolver, `BlockHandleController.dragBlocks` (the outermost of `movable(...)` over a block selection's blocks as clicked — never `selectedMembers`, so a selected list's item drags alone — or a text range's `getSelectionBlocks`, when the handle's block is among them, else that block alone; Mod+Shift+↑/↓ over a text range takes the same blocks, and over a block selection its `outermost`; after a move `selectMoved` keeps the moved blocks' selected descendants selected — only when the block selection held the whole group, else the moved blocks alone, the drag's rule; a handle's Alt+arrow over a text range covering its block keeps the range, as Mod+Shift+↑/↓ does; a drag's undo step restores the selection held before its start, `history.began`); a drag's placement is sticky across gaps, and below the document's last block all the way down (the pointer's x still picking the level; out of the editor's width it clears), never over another block's own row — a drop target sticks while it or a target inside it holds the placement, since PDD keeps an inner target only while every outer one of its chain sticks, and a left target hands the placement to the innermost one still current (`onDragLeave`); a drag fixes that group at its start, shows its count on the preview and the indicator, and drops it as ONE `moveBlocks` call (any parents; a refused group moves nothing). `moveBlocks` itself opens a closed toggle the blocks land in or that adopts blocks (`revealing`); callers do not wrap it. An `in`/`out` step over siblings moves each run of adjacent ones on its own (`dispatcher.each`), as Tab does, so it never reorders the text. A move refused before any command runs (readonly, `canMoveBlocks` false) still sets `dispatcher.last` to `refused`; inside one `dispatcher.run`, a step that applied is never overwritten by a later refused or no-op step.
- List containers (`rendersContent: false`, not void/island — `block.isContainer`) are never converted (`convertible` is false; `convertedBlocks` in kinds.ts skips them, so the items selected with them convert) and never count as touched by a text range that starts or ends in them (`getSelectionBlocks` skips those, so Tab/Shift+Tab over a range move the same blocks as the rows block-selected; a list the range runs through stays in, so it moves in order with its neighbours, and `moveRoots` groups them by parent while `edytor.moveBlocks` (`parts` in moves.ts) moves each run of adjacent siblings on its own, so no key reorders text). Turn into and the horizontal rule place the new kind through one helper, `placing` in kinds.ts, prepared from the payload hooks leave (a rewritten kind is placed for that kind, its `normalizeContent` runs on it, and the caret follows it; `dispatchPlan`'s `then`): `facade.prepare.liftOut` lifts the item out of every list it does not fit (`facade.landingOf`; a divider or code block inserted after an item: the list splits after it), composed with the retype as ONE plan (never a loop of dispatched lifts: a veto must keep everything); a block's own kind (a data-only change) never lifts it. `liftOut` and `unNestBlocks` split a list with one routine, `splitOut`. What a split, a first-item lift, an outdent or a merge moves out of a block, and the blocks `splitBlock`/`insertFlow` at a position create, is ranked by where it came from (`exitRanks`/`pieceRanks`/`sourceRank` in the facade: side of the gap, then path, or text after the split point), never at random in the gap: two peers' concurrent splits keep the text order whatever their client ids, one gesture each between syncs (CW-01, DR-crdt-6/7; residuals in the delete contract). Only those paths rank by source: inserts beside a block (Enter at a block's start or end, Duplicate, +; a container header's Enter, whose tail becomes a plain first child; a `whole` or `replace` `insertFlow`: a block-selection paste, a paste or typing over selected blocks), several gestures by one peer before sync (Turn into over several blocks is one plan per block, Shift+Tab one per run of adjacent blocks) and moves (drag, handle Alt+↑/↓/→, Mod+Shift+↑/↓, block-menu Move, Tab) take plain ranks and are not claimed (`order-scope.test.ts` pins them; do not widen source ranking without passing `rank-growth.test.ts`, EW-02). A source rank's first part segment is followed by one tied by the client's clock, so one client never mints one twice in a gap (DW-05) and a later gesture's blocks never interleave an earlier one's (FX-06); `rankBetween` stops descending once its prefix is below the right bound (FX-04). A command over several parts (Turn into over several blocks, Tab over several runs, code-line Tab/Shift+Tab over several lines, formatting across blocks, Duplicate) runs through `dispatcher.each`: a refused or vetoed part is skipped and the others apply; a block-selection delete (keyboard — every Backspace/Delete chord, word and line deletes too: `wordAndLineDeletes` in bindings.ts at keydown, and `runBeforeInputDeleteCommand` for any delete intent's `beforeinput` — cut or block menu) goes through `deleteSelectedBlocks`, which runs `onDeleteSelectedBlocks` and then one `deleteBlocks` plan. Every path that removes a block selection asks `keepsSelectedBlocks` (replaceSelection.ts) first — that delete, typing and composition (`replaceSelectedBlocksWithEmptyBlock`) and paste (`pasteFlow`); Enter and Shift+Enter remove nothing (`selectedBlocksLine`) and never ask — and a kept selection refuses the gesture (`dispatcher.last` = `refused`). A composition over a block selection replaces it at `compositionstart` (`Composition.#rangeless`, over a selected atom too: the new block is rendered with `flushSync` and the DOM caret parked in it by `projector.park` before the IME writes, as a block selection shows no DOM range and the IME would write at the editable's start); refused, the IME writes into `selectedBlocksExit`'s line, which the tail restores. `#release` clears the D-20 baseline (`#where`/`#order`), so that replacement's commit never ends the new session. Enter in an empty item leaves the list through `unNestBlock`. Enter keys off `block.list`, so an item outdented into its outer item keeps outdenting; a container's `itemKind` (`numbered-list-item` for `ordered-list`) is the kind its items show as, so converting to it is a no-op and `rowOf` names items by it.

## Where to fix what

- A structural edit is wrong → the document op (`crdt/edytor-doc.ts` prepare functions, `crdt/rangeDelete.ts`, `crdt/flow.ts`) and its contract row, then the view command in `block/block.utils.ts`.
- A text edit is wrong → `text/text.utils.ts`, `session/editing/text.ts` (marks).
- A keystroke is wrong in the browser → `events/onBeforeInput.ts` + `events/beforeInputCommands.ts` / `beforeInputDeleteCommands.ts`, the attempt (`session/attempt.ts`), the binding (`session/bindings.ts`).
- The caret lands wrong → the command's result selection (`Dispatcher.caret`) or the seam (`crdt/anchors.ts`); the projector only displays the value.
- The DOM differs from the model → the observer's classification (`surface/observer.svelte.ts`) or the cell (`surface/cells.ts`). Never patch the DOM from a command.
- IME → `session/composition.svelte.ts` and `surface/pin.svelte.ts`.
- Rendering is wrong while the model is right → components and kind records.

## Practical rules

- Change behaviour in its owner. If a change needs a flag, timer, retry or a second place that decides the same thing, stop: a contract row or an owner rule is missing.
- Timers are named, counted browser rules only (`pnpm census` reports them); no `tick()` polling, no re-assert loops.
- Keep `src/lib/crdt` Worker-safe; run `pnpm check:worker` when touching it.
- Verify engine APIs in the vendored source (`src/lib/crdt/vendor/yjs/src`), not from Yjs v13 examples; fork changes go through `UPSTREAM.md`.
- Public API and behavior changes update the site in the same change: the page that documents it, and `reference/migration.mdx` ("Complete list of changes", the canonical record; the README links it and keeps no copy). The ledger records gates and measurements.
- The composition root's `readonly edytor = this` is load-bearing: `batch()` binds operations onto the `Edytor` too. `edytor.container` is gone; the host element is `edytor.node`. Focus and pointer ownership listeners live in `events/onFocus.ts` (`attachFocus`).
