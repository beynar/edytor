### YW-01 — A resent waiting rewrite has its replaced-entry delete stored, so the block ends up with no type

- **Area:** Durable Object server
- **Severity:** medium
- **Effort:** S
- **File:** `src/lib/cloudflare/DocumentRoom.ts:1415` (also `heldClock` :357-361, `isEntry` :406-408)
- **Failure:** The `stay` rule compares struct clocks against `heldClock`, the end of the last stored struct. v14 integrates a client's later structs past a waiting one and leaves a Skip, and `heldClock` counts past that Skip. Sequence reproduced in workerd:
  1. The room is restored from a lagging snapshot.
  2. Bob retypes a block, and his rewrite waits on Ada's lost entry.
  3. Bob types once more.
  4. The room is evicted and Bob redials. His handshake resends the rewrite, and the delete of Ada's type entry is stored as a `pending` record.
  5. The room is evicted again and Ada returns.

  The room's `read()` and Ada's `toJSON()` throw "block seed has no type"; in production the type is `''`. It recovers only when Bob reconnects, and never if his local copy is gone. authorization.mdx:142 promises the opposite.

- **Fix:** Decide "still waiting" by integration, not by the end of the store. Compare against `stateVector(doc).get(client)`, or treat a missing or Skip `storedStruct` as waiting. In `isEntry`, treat a held Skip as unknown instead of setting `entry = false`.
- **Done when:** A workerd row covering waiting rewrite → later same-client struct stored → evict → resend → evict → author returns expects type `heading`, and the room and every client agree.

### YW-02 — Delete next to a list or table container that renders no content dissolves the container, and Backspace at the first item does nothing

- **Area:** CRDT correctness (medium), Editing behaviors (low)
- **Severity:** medium
- **Effort:** M
- **File:** `src/lib/crdt/edytor-doc.ts:1153` (`canMerge`), `mergeUnnesting` :1780-1787, `mergeForward` :1804-1807; view side `src/lib/events/beforeInputDeleteCommands.ts:61,147`
- **Failure:**
  - Merging into a no-content container: DR-crdt-2 refuses it.
  - Merging such a container into its neighbour: still allowed.
  - Delete at the end of the paragraph above `[unordered-list[a, b]]` gives `[p, list-item a, list-item b]` at the root, with no `<ul>` and no text joined. `ordered-list` behaves the same.
  - In a table island, `mergeForward('c1')` removes row R2 and leaves its cell directly under the table.
  - Backspace at the start of a first list item that has siblings is a silent no-op.

  No text is lost and one undo restores the tree.

- **Fix:** Extend DR-crdt-2 to the source side. When `fromId` is not an island and renders no content, target its first content-rendering descendant, so Delete above a list pulls the first item's text up and leaves the list in place. Otherwise refuse. Island merges such as code keep their current behaviour. In the view, Backspace at the start of a first item or cell lifts it out of its container.
- **Done when:** p1 rows pass for lists and the table island, and notion-parity rows cover Delete above a list and Backspace at the first item (for both list kinds).

### YW-03 — Mod+A in a multi-line code block, then Backspace, Delete or cut, removes the whole code block

- **Area:** Editing behaviors
- **Severity:** medium
- **Effort:** S
- **File:** `src/lib/crdt/rangeDelete.ts:129` (`emptied()`); `src/lib/events/onCut.ts:10`
- **Failure:** The code plugin's Mod+A selects every line, from L1:0 to the end of the last line. The range delete dooms every line, then dooms the `code` container because it renders no content. `[p a, code[x,y], p z]` becomes `[p a, p z]` with the caret at a:1. Cut used to leave an empty code block; it now does the same, because wave 7 moved `onCut` from the replace path to the delete path. Typing over the same selection keeps the block.
- **Fix:** Exempt a `lines` island from the empty-container rule by keeping its first line, emptied, as the head. Or have the code plugin turn a whole-island text range delete into a `replaceRange` that keeps the head.
- **Done when:** notion-parity rows for Mod+A followed by Backspace, Delete and cut in a two-line code block each leave `code['']` with the caret at L1:0.

### YW-04 — After deleting a block selection, or pressing Escape, the caret lands in the middle of a neighbour that holds an inline atom

- **Area:** Editing behaviors
- **Severity:** medium
- **Effort:** S
- **File:** `src/lib/selection/replaceSelection.ts:126` (`deleteSelectedBlocks`); `src/lib/session/bindings.ts:315-323` (Escape)
- **Failure:** Both paths place the caret at the end of `firstEditableText`, which in a block like `'hello @m world'` is only `'hello '`. After block-selecting the next paragraph and pressing Backspace, typing `Z` gives `hello Z@m world`. The block menu's Delete (XW-06) uses `lastEditableText` and lands correctly, so the two paths disagree. Escape contradicts hotkeys.mdx:49 ("caret at the end of the first selected block"). For Escape, use the first selected block in document order and its `lastEditableText`. - **Done when:** Rows with a mention in the neighbouring block pass for Backspace, Delete and Escape, and the keyboard and block-menu Delete land on the same caret.

### YW-05 — Room ids containing `/`, `%`, `#` or `?` never connect or land in the wrong room

- **Area:** Documentation clarity and accuracy (the provider code is also affected)
- **Severity:** medium
- **Effort:** S
- **File:** `site/content/docs/server/quick-start.mdx:51`; also authorization.mdx:75-78, extending.mdx:22-24, `site/pages/_home/CodePreview.astro:23-25`, `src/lib/crdt/providers/websocket.ts:613-618`
- **Failure:** The provider dials `server + '/' + room` without encoding it. The documented route matches a single path segment, calls `decodeURIComponent` with no guard, and answers a non-match with HTTP 404. Results:

  | Room id        | What happens                                       |
  | -------------- | -------------------------------------------------- |
  | `acme/roadmap` | 404 → 1006 → redials forever as `unreachable`      |
  | `100% done`    | URIError → 500 → 1006 → redials forever            |
  | `notes#2`      | lands in room `notes`, shared with other documents |
  | `a?b`          | lands in room `a` and loses `?replica=`            |

  The docs describe any id from 1 to 256 characters as valid. room.mdx:22 itself says a Worker should never refuse with an HTTP error.

- **Fix:** Wrap the room in `encodeURIComponent` in the provider's `get url()`. Make the four snippets decode inside a try/catch like the demo's `roomOf`, and refuse with `closedSocket(4400/4404)`.
- **Done when:** A test dials `a/b`, `100%`, `a#b` and `a?b` through the quick-start route and reaches the matching room. The drift test keeps the snippets and `roomOf` aligned.

### YW-06 — `dispatcher.last` stays `'refused'` after an undo or redo that applies

- **Area:** API ease of use (medium), Code organization (low)
- **Severity:** medium
- **Effort:** S
- **File:** `src/lib/edytor.svelte.ts:326`
- **Failure:** `#replay` writes `last` only when it refuses, and `History.#run` never writes it. Sequence: type, go readonly, `historyUndo()` (refused), go editable, `historyUndo()`. The undo applies but `last` still reads `{undo, refused}`. The docs say "every command sets `dispatcher.last`" (commands.mdx:85), and readonly.mdx:34 and troubleshooting.mdx:73-75 recommend a `last?.status === 'refused'` check after these calls. - **Done when:** The SW7-selection-4 row asserts `last` after the editable undo and after an applied redo.

### YW-07 — The view's Enter (`liftContent`) writes an explicit empty type during a half-delivered retype

- **Area:** CRDT correctness
- **Severity:** low
- **Effort:** S
- **File:** `src/lib/events/beforeInputCommands.ts:225`; `src/lib/crdt/edytor-doc.ts:1719-1721`
- **Failure:** `liftContent` always passes the tail `{ type: block.type }`, and `Block.type` is `''` while the type attribute is missing. The facade uses any explicit tail type, so the `kindToCopy` fallback never runs. - **Done when:** A view row next to DR-crdt-1's presses Enter at the end of a typeless block with children and gets the parent's default child type.

## Refuted

- **A multi-line paste into an open toggle's header moves its children to the last pasted block, unlike Enter** (Editing behaviors, reported as low, `src/lib/crdt/flow.ts:112`). The mechanics are accurate, but the behaviour is intended:
  - The normative spec, docs/editor-delete-contract.md:237-251 (`flow.split`), sends shown children to the tail and keeps only hidden children with the head.
  - The flow.ts header comment says the same.
  - wave7-delete-review.test.tsx:231 pins exactly this scenario.
  - d7-flow.test.ts:141 pins the general rule.

  Whether an open toggle should follow the Enter container rule is a product decision, not a defect. Leftover docs nit: clipboard.mdx:59 does not say where a block's children go on a multi-line paste.
