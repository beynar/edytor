`<Edytor />` is deliberately small: rich text, no menus, no handles. `edytor/starter` is the other end: one component with everything on.

```svelte title="src/routes/+page.svelte" check
<script lang="ts">
	import { StarterEditor } from 'edytor/starter';
</script>

<StarterEditor />
```

That is a full editor:

- **Every useful bundled plugin**: rich text, code, tables, columns, images, files, video and audio, embeds, bookmarks, equations, mentions, a table of contents, markdown shortcuts, find, the marquee selection and block moves from the keyboard, with nesting on. Page links join when you give it `pages`.
- **The ready-made menus**: the slash menu, the block handles and block menu, the selection toolbar and its link card, the table's grips and menus, the code header and its language list, the callout icon picker, the equation panel, the image toolbar, the empty media panel, the find bar, the marquee box and the suggestion bar.
- **The page around the blocks**: a cover image, a page icon, a large title and [typed page properties](/docs/starter/properties), all stored in the document's data, so they sync in a room and undo like the blocks.
- **The Notion theme**, which a `theme` object or CSS variables change ([Customizing](/docs/starter/customizing)).

## A real page

The props `<Edytor>` takes pass through, so a document comes and goes as usual, and each part is a prop:

```svelte title="src/lib/Page.svelte" check
<script lang="ts">
	import type { JSONDoc } from 'edytor';
	import { StarterEditor, type StarterProperty } from 'edytor/starter';

	let { value, save }: { value: JSONDoc; save: (value: JSONDoc) => void } = $props();

	const properties: StarterProperty[] = [
		{
			id: 'status',
			name: 'Status',
			type: 'select',
			options: [
				{ value: 'todo', label: 'To do', color: 'gray' },
				{ value: 'done', label: 'Done', color: 'green' }
			]
		},
		{ id: 'due', name: 'Due', type: 'date' }
	];
	const upload = async (file: File) => {
		const response = await fetch('/api/upload', { method: 'POST', body: file });
		return (await response.json()).url as string;
	};
</script>

<StarterEditor {value} onChange={save} {properties} {upload} plugins={{ equation: false }} />
```

- `upload` stores what a user adds: an image, a file, a video or an audio block, and the cover or the icon they upload. Without it those accept links only.
- `plugins` turns a bundled plugin off (`false`) or configures it ([Props](/docs/starter/props#plugins)).
- The page's data rides in the document: `value.data.title`, `value.data.cover`… ([Page parts](/docs/starter/page)).

## Edge cases

- **It is opt-in.** `edytor/starter` is its own entry point: only an app that imports it ships it, and `<Edytor />` from `edytor` does not grow by a byte.
- **The name.** `StarterEditor` is one export: import it under the name your app uses (`import { StarterEditor as NotesEditor } from 'edytor/starter'`).
- **It renders on the server** from `value` (or `snapshot`) and hydrates with the same markup; the controls that add a cover, an icon or a property appear once the view is live.
- **Your own editor instead.** The same chrome, as plugins for your `<Edytor>`, is [Ready-made menus](/docs/customization/ready-made-menus).
