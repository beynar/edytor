# Elegance / code-quality review — vendored engine + edytor layers

Date: 2026-09-23. Review only; no product code was changed. Seven parallel
review passes covered `src/lib/crdt` (core, model layers, providers/protocols/
migration), `src/lib/selection` + `src/lib/events`, the editor runtime +
components + plugins, the vendored engine + binding, and cross-cutting test
coverage. Every HIGH finding below was independently verified against the
tree before inclusion; lower findings carry their reviewers' confidence
marks (CONFIRMED = caller/absence verified by grep, LIKELY = mechanism
verified, SUSPECT = needs a reproduction).

Review standard: the five sloppy-code classes (duplication, dead code,
needless abstraction, boundary violations, missing tests) plus the Elegance
principles (one fact one authority, resolve once, share structure, precise
ownership, validate at real boundaries, observations aren't requirements,
semantics ≠ packaging, capability ≠ authority, one semantic rule per real
consumer, abstractions must pay).

## Verdict

The v14 stack is genuinely good at its core: the admission boundary is a
real single gate, refusal preserves data, the maintained view is one
authority, and the recent hardening landed real fixes. The problems are
**accretion**, not design: each hardening round added a mechanism beside
the previous one rather than consolidating, so the selection/restore layer
now carries ~8 deferred re-assert mechanisms with ~7 distinct ownership
tokens, the four `setAt*` writers have divergent guards, and the providers
share ~200 lines of duplicated room protocol.

There are also a small number of outright defects: a guaranteed mount
crash in the shipped component's default value, a `moveBlocks` throw on an
equal-rank seam, a marks-derivation bug on every native derive, a document
that can latch `pending` forever on provider failure, and grouped drags
bypassing the plugin interception layer.

## Boundary violations / misplaced responsibilities

- **Undo-ownership repair lives inside the facade file** — ~260 lines of `store.clients`/`keep`/`redone`/`insertSet`/`changed`/`_transaction` internals in `edytor-doc.ts:675-932`. Correct and tested, but the deepest private-field coupling in the codebase; belongs in its own module so the blast radius is visible.
- **Schema gate sits in provider dispatch, not the protocol seam** — `readSyncStep2`/`readUpdate`/`readSyncMessage` in `sync.ts` apply ungated and _throw_ on unknown types, while both providers re-implement the dispatch gated+staged+emitting. The exported/documented path is the unsafe one; a third transport on it gets no schema protection.
- **`sync.ts` header claims "verbatim port"** but ~240 lines are EdytorDoc-aware staging replicating engine-private state — correctness-critical code in a file advertising pure parity.
- **`doc.rand` monkey-patched onto vendor `Doc` instances** (`peer-set.ts`; read at `placement/model.ts:717`) — a WeakMap or namespaced key avoids shape-extending foreign objects.
- **`_attachHistory` monkey-patches `manager.destroy`** (`document.ts:715-721`) — works and is tested, but rewrites an engine method; a `'destroy'` listener would not.
- **Plugins re-enter below the operation layer**: `CodePlugin` calls `edytor.onBeforeInput` recursively inside `onBeforeOperation` and runs `insertChildren` sub-ops that re-fire hooks to all plugins (ordering depends on plugin array order); mention plugin uses tick+setTimeout caret restores — symptomatic of a missing post-commit caret primitive.
- **`getTextById`/`getBlockByIdOrContent` dispatch on `id.startsWith('t'/'b')`** — the view layer is coupled to id-minting formats; adjacent APIs have inconsistent failure contracts (throw vs `undefined`).
- **Module-globals `internalDragSource`/`shiftPasteModifierHeld`** — page-wide mutable state shared across every Edytor instance; mostly survives but is unowned.
- **`createDomSelectionSnapshotFromMultiRange` mutates the live selection** inside a getter named `…Snapshot` — a read with a side effect.
- **`engine-boundary.test.ts` scans only `*.ts`** — a `.js` file under `src/lib/crdt` bypasses the deep-import gate.
- **`EdytorDocument.transact`/`facade` reachable post-destroy** (see D14).

## Well-designed (keep, don't churn)

1. **Single admission boundary** — `checkSchema`/`assertUsableDoc`/`assertAdmission` is the one ordered gate shared by document create/load/attach/sync AND transport staging; refusal preserves data everywhere (staged applies, non-destructive IDB refusal, blocked compaction, aborted-upgrade probes).
2. **`M.view` + `modelState` injection** — one maintained replicated-state authority; `undoRepairAttached` module-scope dedupe; pure shared traversal functions across fresh/maintained paths.
3. **The `syncSettleMs` fix** resolves a real ambiguity correctly (foreign empty SyncStep2 ≠ own handshake) without breaking empty-room cold start.
4. **`createBeforeInputSnapshot`** — one prepared-intent authority for ~25 derived fields; commands consume, never re-derive.
5. **`domSelection.ts`** — the single owner of DOM-selection semantics (shadow/composed ranges, direction-aware dedupe, focused-only scroll).
6. **Events layer purity** — zero `facade`/`model` references; everything flows through the operation surface.
7. **Vendor manifest** — `UPSTREAM.md` pinned commit+sha, executable diff recipe, vendored upstream suite runs against the patched engine (331 tests of free regression coverage).
8. **History's two-layer capture** — identity-tracked origins + engine-marked non-local integration; can't be bypassed by an un-stamped provider.
9. **Error-channel discipline** — every refusal mode emits `'message-error'`/`'schema-mismatch'` observably; same-tab BC sync delivery guarded.
10. **Interval-ownership replaced dense in production** — the dense algorithm survives only as the test oracle (the right place for a second implementation).

## Recommended repair order

1. **Kill the mount crash** (D1): `defaultValue` → `{children:[]}` or a `defaultType` block; move the demo fixture to `src/routes`. One line, biggest user-visible win.
2. **Fix the throw + the silent-wrong-value bugs** (D2, D3, D6, D8): `moveBlocks` tie guard, `currentMarks` range, `undoRepairClaims` key, atomic inline-block target clearing — all small, each with a pinned test.
3. **Add the sync failure channel** (D4): `EdytorSync.failed(reason)` → `settle()`; reject `whenSynced` on destroy (D22); `connectBc` enforce `_hydrationRefused` (D10).
4. **Unify the selection writers** (D7, S4): one `SelectionWriter` owner (resolve→guard→write→dedupe→derive→verify) + one `buildSelectionState` factory; then consolidate the ~8 re-assert mechanisms onto one epoch/intent token (S3) — this is where the flake surface lives.
5. **Extract `bindRoomProtocol`** (S1) — one owner for envelope dispatch, gated `messageSync`, awareness sequences; providers keep only socket-vs-storage edges. Absorbs D24.
6. **Consolidate the ownership contest + view derivations** (S2, S7, S13, S14): `gatherClaims`, shared range cache, `ProjectedBlock` single materializer, `facade.isVisibleBlock` as the one oracle.
7. **Route grouped drags + text primitives through the op pipeline** (D5 + events' `insertAt`/`deleteAt` bypass) — one interception contract.
8. **Dead-code sweep** (one commit): the dead-surface list above, `onDeselect` either wired or removed, `serialize.ts` deleted, vendor `content-helper.js`/`ynode.js:940` cleaned at next refresh.
9. **Coverage pins** in the same order as the fixes; the HIGH test gaps (BC leg, auth, snippets, block hooks) are cheap and catch real regressions.
10. **Boundary hygiene last**: extract undo-repair to its own module, gate the exported `readSyncMessage` or drop it from the public surface, `engine-boundary` scan widened to `.js`, `doc.rand` → WeakMap, `status()` non-creating probe.

## Honest residuals

- The four `setAt*` writers' retry loops are duplicated _skeletons_ around genuinely different bodies — consolidation must keep per-write semantics; a naive shared loop would be worse.
- The `~200-line` provider duplication includes irreducible transport branches — extract the _decisions_ (gating, dispatch, awareness), not the plumbing.
- `disableBc:false` coverage needs a real BroadcastChannel environment — `fake-indexeddb/auto` gives IDB, but lib0's BC uses the real API; pin it via the existing `broadcastchannel` polyfill seam or a browser spec.
- D4's failure channel is a _contract_ change (`EdytorSync` gains a callback) — consumers' factories must opt in; until they do, an unreachable provider still means pending.
