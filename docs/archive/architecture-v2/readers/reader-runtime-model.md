## 1. Required behavior (guarantees, stated without implementation names)

Document shape and identity
- **G1 [user-visible]** A document is an ordered tree of blocks. Each block has a type, a JSON data payload, inline content (text runs with marks, plus atomic inline objects), and ordered children. Round-tripping through the canonical JSON (`{children:[{type,id?,data?,content?,children?}]}`) is lossless for JSON-typed payloads. Non-JSON payloads are coerced, with a dev-time warning.
- **G2 [user-visible]** Inline content always *presents* as text-first and text-last, with an editable text gap between any two atoms. Different text-part boundaries at the same gap are interchangeable. Opposite sides of an atom are not (anchor contract rule 6).
- **G3 [user-visible][collab-invariant]** Blocks have stable ids. A block keeps its id through move, nest, unnest, type/data change and undo. A split mints the id for the tail. A merge keeps the surviving block's id. Deleting with `keepChildren` preserves the children's ids.
- **G4 [user-visible]** The document is never empty. The root always holds at least one block of the parent-appropriate default type, and deleting everything leaves exactly one empty block (`del.range.whole-doc`).

Structural editing
- **G5 [user-visible]** Operations: insert blocks; split at a position (the tail takes the *parent-appropriate* default type with empty data); merge backward/forward in document order (an empty first block merges forward); nest under the previous sibling; unnest to after the parent; move one or many blocks before/after/inside a target as **one** undo step with identity kept; delete with or without the children; replace type/data/content/children; clear.
- **G6 [user-visible]** Permission rules: a void block takes no children and never merges. An island subtree is sealed (nothing moves in or out, and it cannot be nested or unnested across its boundary). A block never moves into its own subtree. The answer must be the same when asked in advance (drag affordance) and at execution; plugins may still veto at execution.
- **G7 [user-visible]** Range deletion follows the `del.range.*` rules: the head keeps its prefix; when the tail is cut (`yEnd>0`) its suffix merges into the head; the head dies iff its prefix is empty; a range ending at the tail's start leaves the tail untouched; a nested tail is promoted when its container dies; the caret lands on the documented seam.
- **G8 [collab-invariant]** Deleting a block deletes everything it displays. No atom it displayed may re-appear in another block, whether the delete came from this view, the headless document API or a remote peer. Together with `conc.delete-wins-block`, this also covers atoms inserted concurrently into the doomed block.

Text editing and marks
- **G9 [user-visible]** Insert text, replace a range, delete by grapheme cluster (never half a surrogate pair or ZWJ sequence), and set, toggle or clear marks over a range.
- **G10 [user-visible]** At a collapsed caret, marks toggled with no range apply to the *next* insertion only. They are neither replicated nor undoable.
- **G11 [user-visible]** One insertion-mark rule for every input channel: explicit, then pending, then the mark of the character before, then the mark of the character after. Composition commits and selection replacement keep the marks common to the replaced text. Render-only decorations (for example code tokens from a text transform) never leak into stored marks.

History
- **G12 [user-visible]** Every user action is one undo step. Contiguous typing coalesces. A split is separate from the typing around it. A paste is its own step. A new edit clears redo. The initial seed is never an undo step.
- **G13 [user-visible]** Undo/redo restores the caret or selection recorded for that step, in the view that issued the command only. Sibling views and remote peers treat it as an ordinary change, and their carets ride it.
- **G14 [collab-invariant]** Undo is actor-local and never reverts remote work (`conc.undo.actor-local`). Undone text returns to the block that displayed it before the delete, identically on every replica.

Selection survival
- **G15 [collab-invariant]** Carets and ranges survive remote and programmatic change. They ride inserts according to affinity, follow merged atoms, and land on the documented seam when their content dies. They never migrate into another surviving block because it received text at a shared gap (anchor contract rules 1–6).
- **G16 [user-visible]** A caret destination that exists in the model but is not mounted yet is completed once it mounts. A block whose renderer does not show its own content (a container) is never a caret destination.
- **G17 [user-visible]** A deferred caret write (composition commit, history, structural-key repair) never overrides a newer user gesture, even when the gesture picks the same offset. Programmatic and remote writes never scroll the page.

IME and browser input
- **G18 [browser-constraint]** While an IME composition is live, the DOM node that hosts it is never re-rendered or re-mounted. Remote edits still reach the model, but that node sees them only after the composition ends. The commit replaces exactly the atoms the preview occupies, including remote text absorbed inside the region, and never duplicates or clobbers neighbors.
- **G19 [browser-constraint]** Phantom post-composition keys are not executed: WebKit fires Enter/Backspace after `compositionend`. An abandoned composition (no `compositionend`) is unlatched after blur or a timeout, without swallowing later keys.
- **G20 [browser-constraint]** Input the browser applies itself is reconciled into the model exactly once: non-cancelable Android input, autocorrect, and text-local fast paths. Input the model applied is not re-applied from the resulting DOM mutation.

Publication, plugins, views
- **G21 [user-visible]** One change callback fires per committed transaction (local, remote or undo) with the whole document. The reactive value export tracks commits, and computing it is skipped when nobody consumes it.
- **G22 [user-visible]** Plugins can contribute block, mark and inline definitions and snippets; a user snippet override replaces only the renderer and keeps plugin semantics. Plugins can intercept an operation: the first non-void return replaces the payload, and `prevent` aborts. They can also observe afterwards, normalize children and content with a bounded number of passes, pick the default block type per parent, hook DOM attach, and register commands.
- **G23 [user-visible]** Several views may render one document, each with its own selection. A view that borrows a document never destroys it. Conflicting block-role declarations fail construction without half-applying state.
- **G24 [collab-invariant]** A view never seeds content that a provider is about to hydrate. A failed provider hands the seeding decision back. History capture starts only after the content decision.
- **G25 [user-visible]** A keystroke costs O(edited block), not O(document), at 5k blocks. A content-only commit updates only the touched blocks.
- **G26 [user-visible]** The placeholder shows only for the lone empty text of an empty block, never while text is visible or a composition is live, and never twice.
- **G27 [test-only]** Wrapper-object stability: a block kept alive or moved by a commit is the same JS object (`mirror-incremental.test.tsx`). Also test-only: `project()` call counts (`scoped-text-refresh.test.tsx`), `_items` array identity, `_normalizationDepth`, `postCompositionGuardSwallows`, placeholder-repair `stats`. The user-visible requirement behind wrapper stability is only "no DOM remount under the caret"; object identity itself is not required.
- **G28 [collab-invariant]** Presence payloads carry anchors plus legacy `startTextId`/`yStart` for older peers. The legacy text id must mean the same position on every replica, which is why it is `t:{blockId}:{segmentOrdinal}`. That fact belongs to the wire format, not to the runtime objects.

## 2. Real constraints

Browser (contenteditable / events / selection)
- **B1** In contenteditable the browser writes the DOM itself for part of the input: Android non-cancelable `beforeinput`, autocorrect and spellcheck replacement, text-local fast paths, composition previews. The DOM can therefore drift from the render tree. A DOM→model reconcile path (MutationObserver/`input` diff) and an occasional forced re-render are real needs.
- **B2** IME: replacing or re-keying the text node that hosts a composition aborts or duplicates the composition, so every serious editor locks that node (browser gap analysis G2). Event order differs per engine. WebKit fires `compositionend` before the terminating keydown. Firefox fires `compositionend` before `input`. Synthesized or abandoned compositions may never send `compositionend` (the phantom-key guard and dangling reset).
- **B3** Selection API: `selectionchange` is async and coalesced, and every programmatic `addRange` echoes one. Gecko clamps a caret on a shortened node while Blink keeps the offset. Android shifts the caret after cross-paragraph deletes. A caret write needs a mounted node. This forces "logical destination" and "DOM-ready destination" apart (delete contract, "Selection ownership").
- **B4** Some structural keys produce no `beforeinput` on some engines, so a keydown-driven fallback that synthesizes the command is needed. `historyUndo`/`historyRedo` can arrive as `beforeinput` from the native undo stack.
- **B5** An empty inline element cannot hold a caret, and a trailing `\n` is invisible. A zero-width filler and an extra trailing span are required, and both must be excluded from model offsets.
- **B6** Adjacent same-mark elements must be merged for rendering. Otherwise a browser mutation inside one mark element leaves siblings behind, and the framework skips "unchanged" text writes (the 'lead!!' regression in `deltas.ts`).

Svelte 5
- **S1** `$state` class fields hold proxies, and `structuredClone` throws `DATA_CLONE_ERR` on them. Payloads therefore cross the boundary through a JSON clone (`cloneJson`).
- **S2** Memo keys that are not reactive (`facade.version`) are invisible to `$derived`/`$effect`. A reactive counter must be read alongside them (`valueRevision`).
- **S3** A keyed `{#each}` reuses DOM by key and `{#key}` destroys the subtree. A remount while composing kills the IME (hence the deferred `refreshEditorDom`). A remount also re-runs `use:` actions, so a subscription whose lifetime is tied to `attach` silently dies (runtime-cutover defect 4).
- **S4** Svelte flushes DOM on a microtask (`tick`). A model change is visible in the DOM only after `tick`, so every caret write after an op waits (`getTextNode` polls `tick` up to 10 times).

Vendored Yjs v14 and the edytor schema
- **Y1** `doc.transact` joins an enclosing transaction and cannot change its origin. `update` fires once at transaction cleanup, and observers run after `beforeObserverCalls`.
- **Y2** Maintained run views sync at commit. A mid-transaction read needs a transaction-aware path: facade `contentItems`/`project` keyed on the facade-owned `version`, which bumps on every write. Read-your-writes has a cost, so it must be asked for explicitly.
- **Y3** A block's displayed content is a *projection*: backing texts plus replicated slice claims, with ownership resolved by generation, start and stamp. Display offsets (UTF-16 units + 1 per inline atom) are the only local write addressing. A split shares the backing text, so atoms typed at a split tail's head sit inside the predecessor's claim window (`removeBlock-claim-release.test.tsx`).
- **Y4** Relative positions (assoc < 0 = left) are the causal identity of a position. A bound item that has not been integrated resolves to `null` until it arrives. An anchor bound to a tombstone resolves to the gap's edge, so offsets inside a deleted run collapse.
- **Y5** `UndoManager` captures by transaction origin, coalesces by `captureTimeout`, is shared by all views of a document (`stack-item-*` events reach every view), and resurrects deleted atoms as **new** items linked only by a local `redone` pointer (the undo-ownership ADR).
- **Y6** The wire's UTF-8 encoding turns unpaired surrogates into U+FFFD. Strings must be normalized before they enter replicated state (`sanitizeWireString`).

## 6. Representation candidates

The root problem is that one object plays two roles with incompatible consistency models. The `Block`/`Text`/`InlineBlock` wrapper is:
- the **operation handle**, which must be read-your-writes inside an open transaction, and
- the **render cell**, which is reactive, commit-consistent and identity-stable for keyed DOM.

To make the first role true, every structural op runs `flushMirror()`, a full `facade.project()` plus a whole-tree reconcile, **mid-transaction** (16 op-level call sites: block.utils.ts ×12, block.svelte.ts ×4). The commit then re-applies the same change incrementally. Everything else (pending adoption, carriers, aliases, divergence preflight, `_live` flags, offset re-mapping) is bookkeeping to keep one object valid under both models. The three candidates below change *what is represented*. Most of the machinery listed as H in §4 follows from them.

### RC1 — A position is `(blockId, displayOffset)` followed by an anchor; text segments carry no identity

Represent every text position (caret, range endpoints, composition region, undo snapshot, op arguments and op results) as a document display position, plus an anchor when it must survive edits. Text segments become an anonymous render slicing: `deriveContentParts(items)[k]`. Pending marks move to the caret.

- **Disappears.** Positional text ids `t:{b}:{ord}` and their three constructions. Also gone: `idToText` aliasing, `_pendingAliases`, the deferred rename under the pin, and every `getTextById(x.id) ?? x` rediscovery (four call sites). The seven offset mappers go (`segStart`, `partOffsetOf`, `atomOffsetOfPartIndex`, `displayLength`, the `resolveTextAnchor` inverse walk, the `deleteParts` span, and contentRange's text-only coordinates), leaving one "segment containing offset" helper used only for DOM writes. `history/historySelectionSnapshot.ts` goes because the anchor-first restorer needs no id/path fallback, and so do the `addInlineBlock` pending-mark migration and the positional `compositionState.textId`. **≈ 330 xloc in this domain** (plus the selection-side mirror of the same machinery).
- **Replacing invariant.** *A text position is identified by `(block id, display offset)` and followed through edits by a document anchor. Content segments are a pure function of the block's content items and have no identity.* This is anchor rule 6 ("text-part boundaries at one gap are interchangeable") made structural.
- **Constraint kept.** The presence wire still carries `startTextId` for older peers (G28). Derive it at publish time from `(blockId, ordinal of the segment containing the offset)` and parse it back on receive. It stays a wire format, not a runtime identity.

### RC2 — The document is the only tree: stateless operation handles plus commit-only render cells

Split the two roles:
- **Operation handles** are stateless getters over the document (the existing `DocBlock` in `crdt/nodes.ts`, extended with a segment view derived from `contentItems`). They are read-your-writes by construction because every read goes through the facade's version-keyed view. Plugins keep `block.children`, `block.content`, `text.stringContent` and `text.insertAt(...)`; the getters delegate to the document.
- **Render cells** are one reactive object per visible block id, created and disposed only when a commit's DocChange says so. `added` builds the subtree, `removed` disposes it, `order` replaces child-id lists, `meta` sets type/data, and `content` sets items, from which segments are `$derived`. The DocChange is self-contained and is diffed against the facade's own previous snapshot, so the cell tree cannot diverge. A full rebuild from `project()` remains only as a guard for a missed subscription.

- **Disappears.** Mid-transaction `flushMirror` (16 op-level sites) and the `_projectedTree` memo. Also gone: the full `reconcileChildren` path, the preflight/fallback in `applyMirrorChange`, and pending adoption (`_pendingBlocks`, `_pendingParts`, the carrier second pass). The detached/spec mode goes too: the three-mode constructors, `_toSpec`, `spliceTextItems`/`formatTextItems`/`_sliceFrom`, InlineBlock `_spec`, `groupContent`, and every `if (!this._bound)` branch. So do the `_live`/`_bound`/`_blockId` flags, `_dropPrev`/`_dropNext` (seam neighbors come from the previous order list of the removing DocChange), the mid-transaction `refreshFromProject`, the `Block.value` second serializer and its shim, and the view-side re-derivations of document order and permission (`closestNextBlock`, `insideIsland`, `canMoveBlockTo`). **≈ 1,000 xloc net**, after adding back roughly 50 for cell patching and 40 for segment handles.
- **Measured payoff (probe P9/P9b).** Deleting 1,000 selected blocks takes **10.6 s** through the view path versus **7 ms** directly on the document in one transaction. A range delete over N blocks triggers 2N+1 full reconciles: 250 blocks 0.5 s, 500 blocks 2.0 s, 1,000 blocks 11 s, 2,000 blocks 62 s. That is a user-visible freeze today.
- **Replacing invariant.** *Operations read and write only the document. A render cell exists exactly for each visible block id and changes only when a commit's DocChange is applied. No object is both an operation handle and a render cell.*
- **Also removed with it.** P5 and P2 become impossible by construction once range delete is a document operation governed by the document's merge rules.

### RC3 — One input-attempt record and one composition record (owned by the input pipeline)

- An **attempt** is `{serial, inputType, owner: 'model' | 'browser' | 'structural-fallback', repairAt: Anchor | null, horizon}`. It is opened by the gesture, consulted by `onInput`, the mutation observer and the `beforeinput` repair, and closed by the next gesture or the horizon. It replaces seven flags, four timers and the `consume`/`suppress`/`repair`/`clear` functions (edytor.svelte.ts:302–321, 1298–1378).
- A **composition** is `{hostNode, start: Anchor(right), end: Anchor(left), marks, preview, baseRender, startIntent}`. Offsets are derived by resolving the two anchors. It replaces the offsets + `regionLength` + `value.length` fallbacks, `textId`, `_compositionHostText`, the three-way `compositionText` fallback, and the Text-side `_syncCompositionRegion`, `_reanchorCompositionRegion` and `_resolveCompositionOffset` resync.
- **Disappears.** **≈ 250 xloc** from this domain. About 70 xloc of attempt handling reappears in `events/` as a smaller record, so that part is *moved, not deleted*.
- **Replacing invariants.** *At most one input attempt is open per view, and every observed DOM mutation is attributed to it.* *The composition region is exactly the atoms between two anchors, and its host is the DOM node the IME owns.*

### Ownership moves that ride along (not new concepts)

1. **Delete ⇒ delete what is displayed.** This belongs in document ownership resolution: a deleted block's claims keep winning over a covering claim for atoms inside its window. It fixes P3/P3b, where headless and concurrent deletes leak today, and removes the view-side tombstoning.
2. **Permission and document order are document-only.** `canMoveBlocks` should ask the facade (fixes P1/P2 drift).
3. **Phantomness is declared, not observed.** A block definition says whether it renders its own content. `firstEditableText` then needs no `node != null` test, and `firstText`/`lastText` stop returning phantom slots (F30).
4. **One history restorer.** Keep the issuing view's `stack-item-popped` handler (anchor-first). Delete the id/path restorer (fixes P4).
5. **One default-type rule, always resolved against the new block's actual parent,** with no implicit selection-derived argument. The facade's split and merge-reset use the same rule (fixes P10 and P12). Do not copy type/data and then reset them (F16).
6. **Readiness is a document state machine.** Views subscribe and never self-decide (F25).
7. **The placeholder is CSS on the empty block** (or an overlay outside `contenteditable`), so `removeStalePlaceholders.ts` (192) and all repair scheduling disappear (F27).

Honesty adjustments:
- **Moved, not deleted.** About 70 xloc of input-attempt handling reappears in `events/`, and about 40 of range-delete and delete-ownership support in `crdt/` (ownership moves 1 and 5). System-wide, this domain's responsibilities cost ≈ 2,640, a **≈ 48 %** reduction. The placeholder costs a few lines of CSS in `components/Text.svelte`, which itself sheds its per-placeholder observers (not counted here).
- **Range: 2,300–2,850 (−44 % to −55 %).** The upper bound applies if:
  1. the selection domain keeps `Text` object identity, which halves RC1's ~330 because segment handles would need stable identity again;
  2. plugin-API shims for detached `new Block({block})` and wrapper-identity comparisons (`state.startText === x`) must stay (~+100); or
  3. composition timing constraints need more of the current C code than estimated.
- **Measurement caveat.** About 250 xloc in both columns are `export type` bodies that `xloc.mjs` counts (see the header). They survive in any design.
- **Tests to rewrite (G27, test-only).** `mirror-incremental.test.tsx` (registry and `_pendingBlocks` invariants), `scoped-text-refresh.test.tsx` (`project()` counts, `_items` identity, `reconcileContent` spies, the `flushMirror` return value) and the normalization-depth tests all pin today's mechanism, not a user guarantee. The product guarantees behind them (G25 cost, G15 caret ride) need new oracles against the document, which P9/P9b already sketch.
- **Overlap.** The per-candidate figures in §6 (~330 / ~1,000 / ~250) overlap; for example, detached-mode code is claimed by both RC1 and RC2. This table is the non-overlapping per-file count.
- **Bundle.** These are source-line counts. Bundle size was not measured, and fewer lines do not prove a smaller bundle. The runtime evidence is different: P9/P9b show per-operation cost dropping from O(N·doc) to O(changed), and five `SvelteMap` registries fall to two.
- **Extension cost after the change.** A new structural op is one document operation plus one handle method. No `flushMirror` placement, no result re-lookup, no pending-adoption registration, no per-op normalize call list, and no separate permission re-check in the view. Today each op needs all five.
