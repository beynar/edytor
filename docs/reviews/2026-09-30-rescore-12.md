## Open units of work

### FX-01 — Word-navigation keys over a block selection put the caret in a void's or container's hidden text, and typed text is saved invisibly

- **Areas:** Code organization, Editing behaviors, API ease of use (found separately by all three)
- **Severity:** medium
- **Effort:** S
- **File:** src/lib/session/navigation.ts:133
- **Failure:** In `move()`, the branch for no Shift, not collapsed, and a unit other than line or doc runs `select(edytor, to, to)`, where `to = dir > 0 ? end : start`. A block selection's projected start and end can be the hidden content text of a divider, a list container or a code block (`edgeText` falls back to `content[0]`, selection.svelte.ts:229). The Shift variant anchors the range there too. The wave-14 `edge()` guard covers only the line and doc units.
  - Repro: doc [first, before, divider d, after]. Put the caret at the start of "after" and press Backspace, which selects d. Press Ctrl+→ or Ctrl+← (Alt+←/→ on Mac) and type "Z". The divider now has content [{text:'Z'}]. Ctrl+Shift+→ gives the same result.
  - Container cases: `selectBlocks(a, L)` on an unordered-list, or on a whole code block C, then Ctrl+→ and "Z", writes the text into L's or C's hidden content.
  - Real browsers, per the Behaviors reviewer:
    - Chromium writes into the divider, or into the start of the first paragraph.
    - Firefox and WebKit drop the typed character.
  - This contradicts the SW14-keys-1 row title ("no key puts the caret in a lone selected divider's phantom text", wave14-ime-escape.test.tsx:514), selection.mdx:118 ("a divider holds no caret") and migration.mdx:139–140.
  - Root cause: the block-selection projection (session/selection.ts:287) points start and end into each block's own content. Each consumer guards against this separately (`edge`, `selectsBlocks`, `lineOf`, `firstText`) instead of the projection guarding once.
- **Fix:** Over a block selection, pick the endpoint with the same rule Escape uses: `selectedBlocksExit` / `caretBeside`, or the displayed edges (`firstText`, `lastShownText`). If there is no shown line, keep the block selection. Better, fix it at the source: have the projection never point at a void's or container's hidden text. Give the Shift variant the same treatment.
- **Done when:** The SW14-keys-1 DOM table and wave14-block-exit.spec.ts have rows for Mod+←/→ and Alt+←/→, with and without Shift, over:
  - a lone divider
  - [paragraph, divider]
  - a list selected by its grip
  - a whole code block

  Each row asserts that no block which renders no content ends up with content, and all rows pass in jsdom and in Chromium, Firefox and WebKit.

### FX-02 — A composition over a text range, abandoned before its first preview, rewrites the selected text (marks lost, extra undo step)

- **Area:** Code organization. This is a wave-14 regression from SW14-ime-1.
- **Severity:** low
- **Effort:** S
- **File:** src/lib/surface/pin.svelte.ts:85
- **Failure:** `acquire` sets `preview: { text: '', native: true }`, so `imeBuffer()` (:118) reads the untouched selected text as the IME's buffer. `abandon()` (composition.svelte.ts:190) then commits it through `#end`. Repro: "f" + bold "ir" + "st", select [1,4], compositionstart, then ArrowLeft (or a pointer gesture, blur, or a new compositionstart) before any compositionupdate. Content becomes [{text:'first'}]: the bold is gone, the characters get new ids, and the undo stack goes from 0 to 1. At c96abec this wrote nothing.
- **Fix:** Keep "no preview yet" separate from "native". For example, leave the preview null until the first `show()` and have `imeBuffer()` return null while it is null.
- **Done when:** A DOM row passes: compositionstart over a range with mixed marks, then abandon, leaves the document and the undo stack unchanged.

### FX-03 — `transact(fn)` that throws skips the unstored check, so after a failed append the room serves and acknowledges the unstored edit

- **Area:** Durable Object server
- **Severity:** low
- **Effort:** S
- **File:** src/lib/cloudflare/DocumentRoom.ts:820
- **Failure:** `this.unstored` is checked only after `facade.transact` returns normally. Yjs emits `update` from its finally block even when fn throws, so a failed append sets `unstored`, and fn's error then propagates past the rebuild. Repro in workerd:
  1. Add a RAISE(ABORT) trigger on update inserts.
  2. Run `r.transact(f => { f.insertText(...,'UNSTORED '); throw })`.
  3. Drop the trigger and connect a new client.

  `read()` and the new joiner see the unstored text, the joiner gets an ack, and the stored rows lack it. This contradicts room.mdx:42. It heals on the next client frame, which closes that client's socket with 1011. It needs a double fault.

- **Fix:** Run the unstored check and `rebuild()` in a `finally` around `facade.transact`, and let the storage error win over fn's error.
- **Done when:** A tests/do case (trigger plus a throwing fn) passes: the room rebuilds from the stored rows, and no joiner is served or acknowledged the unstored edit.

### FX-04 — `rankBetween` keeps descending after the lock, so ranks grow linearly under concentrated edits

- **Area:** CRDT correctness. Pre-existing: the same numbers hold at c96abec.
- **Severity:** low
- **Effort:** S
- **File:** src/lib/crdt/placement/rank.ts:210 (the cause is :161, `rSeg = rightOpen ? undefined : R[i]`, which ignores `locked`)
- **Failure:** `rankBetween([100,5,7],[100,6,3])` returns `[100,5,7,0]`. The mid-document Enter walk reaches a max rank of 144, 432 and 896 characters (41 KB, 139 KB, 752 KB) at 100, 300 and 1000 steps. A walk of splits only reaches 1.3–1.7 MB. With the patch, the Enter walk gives 144/240/592 characters. rank-growth.test.ts:66 ("Measured: 432") and its bound of 480 are calibrated on the unpatched growth, so the guard pins that growth instead of catching it. Order and convergence are unaffected.
- **Fix:** Change :161 to `const rSeg = rightOpen || locked ? undefined : R[i]`, then re-measure and tighten the rank-growth bounds.
- **Done when:** rank-growth.test.ts has tightened bounds and a 1000-step row asserting sublinear growth (for example rank@1000 ≤ 2 × rank@300), and the order lanes stay 212/212.

### FX-05 — A Turn into over several list items is several plans and reverses the text on half the client-id pairs, but no not-claimed list names it

- **Area:** CRDT correctness
- **Severity:** low
- **Effort:** M
- **File:** src/lib/kinds.ts:232
- **Failure:** `convertBlocks` runs `dispatcher.each`, which issues one `convertToKind`/`liftOut` plan per block. Seed [p, ul>[a,b,c,d,e], q]. Ada turns a and b into headings while Bob outdents c: the result is "pacbdeq" on 120/240 pairs. Converting b and c while Bob outdents d gives "pabdceq" on 120/240 pairs. The same probe with `unNestBlocks([b,c])` keeps the order on every pair. concurrent-editing.mdx:128 lists "Turn into on a list item" as ordered, which invites the wrong inference.
- **Fix:** Either lift each run of adjacent selected items of one list in one plan (`splitOut` already takes several ids), or add "Turn into over several blocks" to the site's "Several gestures before a sync" bullet, the contract's not-claimed list and document-api.
- **Done when:** Either the multi-item Turn into holds the order on 240/240 pairs, or the docs name it and an order-scope row pins {pabcdeq, pacbdeq}, with a drift phrase guarding it.

### FX-06 — The DW-05 clock tie on the last part segment lets a later split interleave a restored multi-line paste

- **Area:** CRDT correctness
- **Severity:** low
- **Effort:** S
- **File:** src/lib/crdt/placement/model.ts:484
- **Failure:** `t: i === 0 ? clientId : i === last ? clock : SOURCE_TIE`. For `pieceRanks`, the tie lands on the per-block index. Repro:
  1. Ada pastes ['', 'one', 'two'] at the end of X, then sync.
  2. Bob deletes 'one' and 'two', then sync.
  3. Ada presses Enter at the end of X and types "new", then sync.
  4. Bob undoes.

  The result is P|hello|one|new|two|Q on 24/24 pairs. At c96abec the new line tied with 'one' instead.

- **Fix:** Put the clock in its own segment right after the client-tied first segment: `[d@client, clock, i…]`.
- **Done when:** An order-scope DW-05 row for this variant passes with the pasted lines contiguous, and the existing DW-05 rows still pass.

### FX-07 — Formatting over a block selection that runs past a closed toggle also formats its hidden, unselected body

- **Area:** Editing behaviors
- **Severity:** low
- **Effort:** S
- **File:** src/lib/plugins/richtext/richTextOperations.ts:80
- **Failure:** `formatSelectedTextRange` uses `selectedTextSpans`, which calls `rangeCovers` on the projected range. Doc [a, toggle(closed){h}, z]: `selectBlocks(t, z)` then Mod+B makes "head", "h" and "z" bold. `selectBlocks(t)` alone makes only "head" bold. A Backspace over the same selection keeps h and promotes it. The toolbar's active-mark state (ToolbarController.svelte.ts:70/144) probably over-reaches the same way; this was not checked.
- **Fix:** For a selection of kind "blocks", build the spans from each selected block's own line (`lineOf`), or have `rangeCovers` treat a block selection as exact.
- **Done when:** Rows for [t], [t, z] and [a, t] pass with h never formatted, and the toolbar state matches.

### FX-08 — While composing over a range across blocks, the text after the range end disappears from the screen until commit

- **Area:** Editing behaviors. Pre-existing, not a wave-14 regression.
- **Severity:** low
- **Effort:** M
- **File:** src/lib/session/composition.svelte.ts:158
- **Failure:** The pin's frozen tail is cut at `startText.length` when the range spans texts, so the remainder merged in from the end block is not rendered. CDP repro: [first, second, last], select fi[rst … la]st, compose "に". The model holds ["fiにst"] and the screen shows ["fiに"] until commit, when both read "fi日st". This contradicts the SW14-ime-1 docstring, "what the screen shows equals the document at every step".

- **Done when:** A CDP row asserting domTexts equals the model at every step of a live composition over a cross-block range passes.
