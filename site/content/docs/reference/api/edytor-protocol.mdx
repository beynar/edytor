## AdmissionResult

Non-throwing admission result — the audit/read-side counterpart of
`assertAdmission`.

```ts
export type AdmissionResult = {
    admitted: true;
    verdict: AdmissionVerdict;
} | {
    admitted: false;
    error: SchemaMismatchError;
};
```

## AdmissionVerdict

What an admitted doc carries — the `sync()` readiness decision:

- `'fresh'` — no schema claim and an empty block registry; seeding
  (`facade.init`) is legal. Foreign/unrelated ROOTS may still exist —
  they are not schema claims and coexist next to the seeded schema.
- `'initialized'` — supported schema content is committed; the doc is
  adopted as-is (`hydrated`), never seeded.

```ts
export type AdmissionVerdict = 'fresh' | 'initialized';
```

## assertAdmission

The document-level admission gate — runs the ordered checks and throws
the typed refusal:

- `SchemaMismatchError` `'unversioned' | 'unsupported' |
  'foreign'` — a schema claim this build cannot own.

PURE READS — a refusal leaves the doc byte-identical (the reads may
materialize empty root SHARE entries in the doc's share map, which do
not encode into updates). Returns the `AdmissionVerdict` for the
readiness decision.

```ts
declare const assertAdmission: (doc: EngineDoc, docName?: string) => AdmissionVerdict;
```

## assertSchema

Hard gate — throws `SchemaMismatchError` when `checkSchema` reports a
problem. Used by migration and by `Edytor.sync()` before
mutating a synced document.

```ts
declare const assertSchema: (doc: EngineDoc, docName?: string) => void;
```

## createChunkReader

The receiving half of `chunkFrame`, one per connection: feed it
each chunk frame's body (after the message type); it returns the whole
frame on `end`, `null` before. An out-of-order or oversized sequence
throws and resets; a sequence announcing more than `maxBytes` throws
`ChunkError` at its start, before anything is buffered. A
sequence is assembled into ONE buffer of its announced size, allocated
at its start (`buffered`), never into parts copied at its end.
`admit(total)` is asked at each start, before that allocation: it may
throw to refuse the sequence, or return `false` to skip it (its parts
are read and dropped, and its end returns `null`).

```ts
declare const createChunkReader: (maxBytes?: number, admit?: (total: number) => boolean) => ChunkReader;
```

## EngineNode

Structural minimum of the vendored `Y.Node` (v14) used by the placement
model. A real `YNode` satisfies this at runtime; typed consumers cast once
at the boundary (`doc as unknown as EngineDoc`).

```ts
export interface EngineNode {
    readonly name: string;
    readonly doc: unknown | null;
    readonly length: number;
    readonly _item: EngineItemRef;
    getAttr(key: string): unknown;
    setAttr(key: string, value: unknown): unknown;
    deleteAttr(key: string): void;
    forEachAttr(f: (value: unknown, key: string, node: EngineNode) => void): void;
    attrKeys(): IterableIterator<string>;
    insert(index: number, content: unknown): void;
    delete(index: number, length?: number, into?: EngineNode | null, fresh?: unknown, propose?: {
        into: EngineNode;
        sort: (client: number, clock: number) => number;
    } | null): void;
    hold(ids: number[]): void;
    move(index: number, ids: number[], side?: number, part?: number, at?: ReadonlyArray<{
        client: number;
        clock: number;
    }> | null): void;
}
```

- `name`: Node name ('block' | 'content' | 'at' | 'inline' in our schema).
- `doc`: The doc this node is integrated into; `null` while detached.
- `length`: Sequence length (invalid read on detached nodes — track offsets instead).
- `_item`: The item this node is attached to (identity anchor for `crdtId`).
- `delete`: Delete `length` live units at `index`.
- `hold`: Append one hold record of `ids` (`client, clock, len` triples) to this records list: they read as deleted while it lives.
- `move`: Move the units `ids` names (`client, clock, len` triples, in order) to live index `index` of this sequence: one move record there (the fork's `ContentMove`); `side` is its class among the items of its origin (`0` after, `1` before), `at` the chain it stands at for the sort of two records at one origin — the units from the root sequence down to the unit it stands at, outermost first (`null`: the first unit it names) — and `part` its order among the records standing there.

## SchemaProblem

A document's relationship to this build's schema:

- `unversioned` — registry state exists but `meta.v` is absent. Someone
  wrote replicated content without running the schema path (a rogue or
  v13-era write). This state must NEVER be persisted/broadcast as a
  document update by a provider.
- `unsupported` — `meta.v` names a version this build does not speak
  (e.g. `99` written by a future build). Content still applies (a replica
  cannot refuse structs it already shares a protocol with), but providers
  surface a `schema-mismatch` signal so operators can detect skew.
- `foreign` — `meta.v` is the supported version but `meta.schema` is
  missing or names a DIFFERENT manifest (`'not-edytor'`, a next-gen name,
  an app-local doc kind). A valid version number alone does not make the
  payload an edytor document — the manifest name is part of the contract
  (the version-only check let foreign `meta.schema` values
  cross the staging boundary).

```ts
export type SchemaProblem = {
    kind: 'unversioned' | 'unsupported' | 'foreign';
    version?: number;
    schema?: unknown;
};
```

- `version`: The observed `meta.v` (undefined for `unversioned`).
- `schema`: The observed `meta.schema` (undefined when absent).

## WebsocketProviderEvents

```ts
export type WebsocketProviderEvents = {
    status: (event: {
        status: 'connected' | 'disconnected' | 'connecting';
    }) => void;
    access: (access: 'write' | 'suggest' | 'comment' | 'read', provider: unknown) => void;
    synced: (state: boolean) => void;
    'connection-close': (event: CloseEvent | null, provider: unknown) => void;
    'connection-error': (event: Event, provider: unknown) => void;
    'protocol-mismatch': (mismatch: ProtocolMismatch, provider: unknown) => void;
    'message-error': (error: unknown, provider: unknown) => void;
    'schema-mismatch': (detail: SchemaMismatchDetail, provider: unknown) => void;
    saved: (state: {
        saved: boolean;
        unsaved: number;
    }, provider: unknown) => void;
    'permission-denied': (reason: string, provider: unknown) => void;
    refused: (refusal: SyncRefusedError, provider: unknown) => void;
    expired: (state: {
        reason: string;
        attempts: number;
        nextRetryMs: number;
    }, provider: unknown) => void;
    unreachable: (state: {
        attempts: number;
        nextRetryMs: number;
    }, provider: unknown) => void;
    failed: (error: unknown, provider: unknown) => void;
};
```

- `access`: What the room says this connection's user may do, as it joins (and at a change in place).
- `'message-error'`: Fired when a v14-tagged frame could not be decoded (truncated/corrupt frame or an unknown message type), or when a sync payload failed to apply.
- `'schema-mismatch'`: A received update wrote a foreign schema stamp and was refused (SchemaMismatchDetail).
- `saved`: The count of local updates the room has not yet acknowledged as persisted changed (store-before-ack: a `messageSaved` frame carries the room's state vector after it stored what it holds).
- `'permission-denied'`: Server refused access — the auth reply carried a denial reason.
- `refused`: The server closed the socket with a refusal code (`1008`, `4xxx`): the provider stopped dialing.
- `expired`: The server closed the socket with `4401`: the credentials expired.
- `unreachable`: A dial ended before its connection synced (refused upgrade, dropped handshake, server down, not open within `connectTimeout`): `attempts` in a row, the next in `nextRetryMs`.
- `failed`: Terminal sync failure: the provider never synced — destroyed before any handshake completed, refused, or the server denied permission.

## WebsocketProviderOptions

```ts
export type WebsocketProviderOptions = {
    connect?: boolean;
    awareness?: Awareness;
    params?: Record<string, string>;
    WebSocketPolyfill?: WebsocketPolyfill;
    resyncInterval?: number;
    maxBackoffTime?: number;
    connectTimeout?: number;
    disableBc?: boolean;
    maxFrameBytes?: number;
};
```

- `params`: Query parameters (auth tokens), read at every dial.
- `resyncInterval`: Re-send a Step1 every `resyncInterval` ms on the live socket (off by default): heals frames a test harness drops; the join rule needs no timer.
- `maxBackoffTime`: Max reconnect backoff (exponential backoff is used).
- `connectTimeout`: ms a dial may take to open before it is closed like a failed one (default 10 000; `Infinity` waits for as long as the browser does).
- `disableBc`: Opt out of cross-tab sync over the BroadcastChannel (on by default).
- `maxFrameBytes`: Largest frame sent whole (default 32 MiB, Cloudflare's WebSocket message limit): a larger one — a reconnect's backlog, a big paste — goes out as a chunk sequence the room reassembles.
