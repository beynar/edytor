# Data model

The replicated document (`src/lib/crdt/`, the doc context): its shape, streams, marks, deletes, operations, the index, roles, seeds, anchors and properties. Layouts and tables have their own file, [layouts-and-tables.md](layouts-and-tables.md); who owns each fact is in the owners table of [AGENTS.md](../../AGENTS.md).

- **Shape.** `JSONDoc = {children: JSONBlock[]}`, `JSONBlock = {type, id?, data?, content?, children?}`, `content` = `JSONText {text, marks?}` and `JSONInlineBlock {type, id?, data?}` (`src/lib/utils/json.ts`). A block owns its inline `content` and its nested `children`; the model is not a DOM mirror.
- **Streams (text ownership).** Each block's text is a stream in a backing text, delimited by boundary items. A split writes one boundary; a merge adds a claim. Split and merge never copy text. `docs/crdt-v14-text-ownership-adr.md` has the details.
- **Marks are paired operations (fork patch YP13).** A mark write is one operation: a start (value, Lamport timestamp, id, side) and an end naming its start; a character shows per mark the open operation with the greatest timestamp (`crdt/text/marks.ts`, `mark.*` rows). Writes stay adjacent to their YATA origins; the integration orders one origin's items left-side marks, content, right-side marks, so a mark's `edge` (document semantics `marks`) decides where a concurrent insert at its ends lands. Local insertions get exactly `marksForInsertion`'s marks (`fitMarks`). Never write a plain format item into an edytor document.
- **Text delete marks.** A text delete writes the writer's mark (root `textdel`, in the history's scope); an undo restores text through `restoreFilter`/`onApply` (fork patch YP11) only where no other writer's mark holds it and no copy shows it, copying the character's newest incarnation; the writer's replica hides a concurrent restoration of what its mark holds, deduplicates its own copies (leftmost wins) and restores what it withheld once the holds are gone. Restoration records (root `restored`) give every copy its root and origin. Never restore or delete text behind the history's back: go through the facade.
- **Preserve what was not removed (2026-09-28, `docs/editor-delete-contract.md`).** A block delete removes only its members (`del.blocks.promote`: unselected children take the slot; `deleteBlock(id, { keepChildren: false })` is the explicit subtree delete) and a block selection is exactly its members (`sel.blocks.exact`; a selected block that shows only its children — a list, a code block — stands for its subtree: what acts on content — delete, cut, copy, paste, typing, marks, Turn into, `onDeleteSelectedBlocks` — reads `selection.selectedMembers`, while `selectedBlocks`/`getSelectedBlocksInDocumentOrder` are the blocks as clicked, one block to the block menu's Copy link, Move, Duplicate and Escape; marks still skip a closed toggle's hidden body in it).
  - An undo never deletes a block its step created (`hist.undo.withdraw`, fork patch YP12): the block is withdrawn and shows while it holds another writer's content.
  - An emptied document writes nothing: each view shows a virtual paragraph (`doc.empty.virtual`) that the first edit in it creates, in the edit's plan.
  - A text range delete that would leave nothing to hold the caret keeps its head block, emptied, with its id, type and data (`del.range.whole-doc`), so peers deleting the whole document keep the same block; it never writes a new one.
  - A range inside one `lines` island (a code block's whole text) keeps its head the same way (`del.range.island-kept`); other islands keep `del.range.empty-container`.
  - A block-set delete and the block menu's Delete share `caretAfterBlockDelete` (`replaceSelection.ts`): the start of a promoted child that takes the set's place, else the end of the nearest line before, else the start of the nearest line after; Escape ends the first selected block's `shownText` (`selectedBlocksExit`; the one shown-line walker, also behind `setAtBlockRange` and leaving a block selection).
  - Never `firstEditableText` (it stops at an inline atom).
- **Module layout.** `crdt/edytor-doc.ts` is the facade's wiring: each part is a `crdt/doc/` module over an explicit context, the parts before it (`reads`, `capability`, `funnel`, `events`, `history`, `anchors`, `steps`, then the op families `moves`, `layout`, `split-merge`, `delete`, `meta` and `content` over `OpsContext`). The index (`crdt/text/runs.ts`) is wired the same way from `crdt/text/index/` parts over one shared state object (`state.ts`): `claims`, `streams`, `anchored`, `layout`, `placement`, `records`, `cache`, `fold`, `report` and `checks`. A fix goes in the part that owns the fact, never in a second part.
- **Operations are two-phase.** Every facade op is `apply(prepare.op(…))`. `prepare` writes nothing and returns a plan of named steps with its effect (or `refused`); `apply` writes it in one transaction and returns `OpResult {status: 'applied' | 'noop' | 'refused', ids}`. Range delete (`prepare.deleteRange`/`replaceRange`/`deleteBlocks`) and paste/drop placement (`prepare.insertFlow`) are single plans whose rules are rows in `docs/editor-delete-contract.md` (`del.range.*`, `flow.*`). A pasted line whose kind joins no text (a list, a code block, a void) is placed as a block, never joined, so no text lands where nothing shows it (`flow.apart`; assert it in DOM tests with `expectNoHiddenContent` from `src/tests/fixtures/dom/invariants.ts`), and a code line takes a flow as plain lines (`flow.lines`). A new structural case means a new contract row, not a caller flag.
- **One index, one report.** `facade.onChange(cb)` delivers one `DocChange` per commit that changed the visible document (`added`, `removed`, `moved`, `meta`, `content`, `order`).
  - Nested transactions publish once; a transaction that nets out publishes nothing.
  - Its callbacks (and `onWritableChange`'s) run inside the engine's `update` emit: one that throws is logged, never rethrown (an error escaping that emit wedges the doc: no later transaction emits `update` again).
  - A read folds every transaction whose writes are in the document and whose commit fold has not run (the open one, and one an `update` listener or observer started, whose body runs before its observers), so a report or read in between never mixes their items with an index that has not seen them; such a write's effects can then appear in the report of the transaction whose cleanup started it.
  - Each backing text keeps a maintained row (`crdt/text/rows.ts`): an edit that writes or removes no boundary moves it by its units, never a rescan.
  - The claim graph, placements and children index are maintained too: a structural change re-decides the owners its claims reach, the placements of the blocks whose candidates (or whose parent's entry) changed, and the slots of the stored subtrees whose slot walk reads a changed block, patching only those parents' child lists (each replaced, never mutated under a reader) and re-running the layout rules only on the layouts it reaches; a cycle through a changed display edge, or any block that shows no argmax candidate, runs the global resolution whole.
- **Roles.** `void` (structurally isolated, not editable by the core flow), `island` (editable, sealed from its neighbours) and `layout` (items side by side, below) drive merge, unnest, delete and navigation.
  - They are not cosmetic.
  - A document learns them from its views' plugins or from its `semantics`: `createDocument`/`loadDocument` default to `defaultSemantics` (as the room does; `semantics: {}` checks none), `attachDocument` (a view's own document) to none.
  - The bundled rows live in `crdt/semantics.ts` (`richTextKinds`, `codeKinds`, `imageKinds`, `layoutKinds`, exported): change them there, not in the plugins.
  - An app's own kinds have one source the same way: one table spread into the kind records and passed to `semanticsOf` (which reads only a record's structural fields) and `mergeSemantics` (field by field, `SemanticConflictError` on a disagreement) for the room.
  - In development builds a document publishes `semanticsDigest` of its roles in its presence and the room logs the kinds it reads otherwise (`semanticsMismatch`, log entry `semantics`).
  - An island whose role also says `lines: true` (code → `codeLine`, opt-in) holds only lines and a line holds no children, even a deleted one's children take the island's slot; the display enforces this against undo and concurrency (`displaySlotOf`, the index's `typeOf`, line kinds from the roles via `EdytorDocConfig.kinds`; `docs/editor-delete-contract.md` `conc.island-lines`).
  - Any other island keeps its structure (a retype to an ordinary kind re-kinds only a lines island's lines, as `typeOf` does).
  - Nothing merges into a block that renders no content (`canMerge`: a code block's first line, a list's first item, a row's first cell), and a container (no content, not an island: a list, a row) never merges as a whole: the key merges and text ranges act on its items, no key, block delete or move leaves one with no child, an outdent splits it rather than handing its later items to a paragraph (the list keeps the items after the outdented ones; a new list takes those before), nothing is retyped into a kind that renders no content, and a peer's item promoted out of a removed one shows as its new parent's default child at read time.
  - One predicate owns what a container holds, `fits(parent, kind)`: a container whose default child is its own kind (a list's `list-item`, a columns layout's `column`) holds only those and containers of them, one whose default child is the document's (a column) holds anything; moves are refused where blocks do not fit (`canPlace`), Tab nests under a container's last item (`nestParent`, also `moves.ts` `inside`), outdents/lifts are refused where they would not fit, and a plain (default-kind) block shed or pasted into a list becomes its item, while any other kind keeps its kind and data, as read-time promotion does (`settledKind`/`fitted`); the move command's `out` step asks `prepare.unNestBlocks`, not `canPlace`; explicit `insertBlocks`/retypes are not refitted, though a plain block stored directly in a list shows as its item at read time (`typeOf`'s `itemOf`: no race leaves a bare paragraph in a list; a Turn into racing an outdent may leave another kind, such as a heading, there, as a merge can — a documented residual) (`isContainer`, `fits`, `settle`, `emptiable`/`emptying` in the facade — `rangeDelete.ts` uses the same ones; `container` reset in `displaySlotOf`/`typeOf`; `del.merge.container`).
- **Read-time display.** A deleted block's unmarked children, and a child a peer adds, moves or splits under it concurrently, show in its slot (`displaySlotOf`, rank `promotedRank`); nothing hides with a deleted subtree (`del.blocks.promote`). A void kind displays no children: a retype to void moves them right after it, and a child that lands under one concurrently is shown in its slot, from the document's roles (`DisplayOwnership.childless`, fed by the runs index from `roleOf`), so replicas must hold the same roles.
- **Seeds.** A seed is written under a writer id hashed from the value, in a band below 2^26; live writers are uint53, so a seed never displaces a live block. Two different seeds sharing an id resolve by hash order (irreversible), so never seed a changing snapshot beside a room. The derived own-text writer is a different id space (53-bit `hash53`); never widen the seed writer.
- **Anchors** are `DocAnchor = {b, a}` (see the anchor contract in [selection-and-input.md](selection-and-input.md#selection-contracts-that-must-not-regress)).
- **Properties (data).** A block's, an atom's and the document's (root `docdata`, in the history's scope) `data` is one attr per JSON leaf, `d/` + RFC 6901 pointer (`crdt/data.ts`): per-leaf LWW, a primitive leaf under which leaves exist reads as the object.
  - Arrays are fine-grained (`Y.Array` semantics, no Y types): a `[]` marker leaf plus items, item `id`'s value under segment `~id` (`~` + a letter is never an escape) and its rank (`placement/rank.ts`) at `~id#`, a move's at `~id>`; an item lives while its creation rank `~id#` does, so a remove beats a concurrent inner edit or move (orphan leaves are skipped); an insert after an item this client ranked goes in its run there (`rankAfter` in `placement/rank.ts`: the item's rank and one segment of the run band, or the next member of the client's run; a run of the earlier marker form is still extended; YATA's origin rule, so its later inserts there stay together even across commands; elsewhere a plain `rankBetween`); a whole-array assignment keeps the items a longest common subsequence keeps equal and pairs the rest by position (`arrange`; `common` is linear: the equal prefix and suffix, then an exact Hunt–Szymanski run while at most `PAIRS_BOUND` pairs of equal values compare, else the middle pairs by position; never a full LCS table); `order` re-ranks only what leaves the longest increasing run.
  - Patches address items by index or id (`~…`), resolved at prepare time (the plan's leaf writes name ids; a gone id is refused); `facade.dataItemIds(target, path)` lists them, and the proxy names an item it hands out by id, so a held item (a keyed `{#each}` row) stays on it.
  - An array assigned where no item is (a new node's data, an exploded legacy array, a whole assignment) takes ids/ranks derived from its index and its value's hash (`~l<i>.<hash>`, tie = hash: identical concurrent assignments and seeds write the same items, different ones stay apart); inserts into an array with items use `randOf(doc)`.
  - Legacy bases (the whole `data` attr, a next.6 atomic array leaf) are shadowed by the leaves at, above and under their paths (`effective`): a patch writes its leaves over them while they still read right, else explodes them (`patchWrites` reads the result back to decide).
  - A kind's role may declare `atomic` paths (`data.atomic`: `BlockRole.atomic`, adopted with the role so every replica agrees): a write at or under one writes its whole value as one leaf (`collapse`) and deletes the leaves under it, so concurrent assignments never merge into a hybrid; an object leaf reads as its keys.
  - One write path: `prepare.patchData(target, ops)` (`target` a block id, `{block, atom}` or `null`; ops `{path, value?}`, `{path, splice}`, `{path, order}`; `setBlockData`/`setInlineData` and a flow's `redata` are root patches; `setBlock`'s data — a retype's, Turn into's — sets the leaves it names and removes none, `data.retype.keep`); no schema generation bump (mixed-version clients read only the legacy attr).
  - The index folds leaf attrs as `meta`; the doc root's change is `DocChange.data`.
  - `JSONDoc.data` is seeded (joins the seed hash only when present; hashed and built from the key-sorted form, so key order never splits a seed) and exported by `toJSON` only when non-empty.
  - View: `block.data`/`atom.data`/`edytor.data` are `propsProxy` (`session/props.ts`): reads live through the cell (blocks, atoms) or `edytor.docData()`, writes are the `patchData` command (an array mutator is one `splice`/`order`/reassignment patch, an index write a path into that item) (hooks see every data write, `setBlock`'s included, as a `patchData` step); the dispatcher lets a `patchData` setting only strings at the same target and paths continue the previous one's undo step when each new string inserts or deletes one run in the previous one (`typedFrom`: typing into a bound field); a flag, number, delete, object, or a string set to another value (`'todo'` → `'done'`) is its own step.
  - A kind's own control inside the host (any native form control, whatever its type, or a nested foreign editable, never the root or a text element: `isKindControl`) owns every event on its composed path (`ownsEvent`): keys, `beforeinput`, paste, copy, cut, drops (a file is swallowed) and selection, whatever the selection, a block selection included.
  - `onKeyDown` (before the readonly and hotkey paths), `onBeforeInput` (`isBrowserOwnedNativeInput`, before the selection sync), `onPaste`, `copySelection`, `onDrop` and the projector ask that one predicate; never add a per-type or per-handler check beside it.
