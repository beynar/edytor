Edytor ships as one npm package, `edytor`. It contains the `<Edytor>` component, the bundled plugins, the collaborative document API and its CRDT engine, and a Cloudflare Durable Object room.

:::warning[Early development]
Edytor is a pre-release (`0.1.0-next.41`) and is not ready for production. The API can change between releases without a compatibility layer.

These docs describe that release. The `edytor@0.0.11` that npm installs without a tag predates it and uses a different API; the [changelog](/docs/reference/migration) lists every change.
:::

## Requirements

- **Svelte 5.** `svelte` is a peer dependency (`^5.0.0`). The editor uses runes and snippets, so Svelte 4 is not supported.
- **A Svelte-aware bundler.** The root entry ships `.svelte` files. SvelteKit, or Vite with `@sveltejs/vite-plugin-svelte`, compiles them for you.
- **Node.js 22 or later** (the package's `engines` field).
- **A current browser.** Chrome, Edge, Firefox and Safari are tested; the code needs at least Chrome and Edge 111, Firefox 119 or Safari 16.4. Real phones and their keyboards are not tested yet. See [Platform support](/docs/reference/platform-support).

## Install

The pre-release is on npm under the `next` tag:

```package-install
pnpm add edytor@next
```

Name the tag: a bare `edytor` resolves to the old, incompatible `0.0.11`. Each pre-release is published from CI with npm provenance.

Earlier installs by URL keep working: this site still serves every pre-release tarball it hosted, each at its versioned URL, and the bytes under a URL never change, so a lockfile's URL and integrity hash stay valid. Switch to `edytor@next` when you upgrade.

If your project does not have Svelte yet, add it too:

```package-install
npm i -D svelte
```

Do not install `yjs` for Edytor. The collaboration engine (a fork of Yjs v14) is vendored inside the package and is available as [`edytor/crdt`](/docs/getting-started/entry-points). The `yjs` package on npm is v13, which cannot exchange updates with v14.

The package pulls in a few runtime dependencies on its own: Atlassian's Pragmatic Drag and Drop (block handles), TanStack Highlight (code block highlighting) and `lib0`.

## Build from source

To build the tarball yourself, from a clone of the repository (`master`):

```bash
cd edytor           # your clone
pnpm install
pnpm package        # builds dist/
pnpm pack           # writes edytor-0.1.0-next.41.tgz
```

Then, in your project, install the file:

```package-install
pnpm add ../edytor/edytor-0.1.0-next.41.tgz
```

## Verify the install

Render an editor. It needs no setup, but it is editable, so the page renders it in the browser only:

```svelte title="src/routes/+page.svelte" check
<script lang="ts">
	import { Edytor } from 'edytor';
</script>

<Edytor />
```

```ts title="src/routes/+page.ts" check
export const ssr = false; // an editable editor is client-only
```

Turning SSR off renders the whole page in the browser. To keep the rest of the page server-rendered, mount the editor after hydration instead, as the [quick start](/docs/getting-started/quick-start#mount-it-in-a-page) does; [SvelteKit](/docs/getting-started/sveltekit) explains why.

You should see one empty paragraph. Hover it to reveal its block handle (touch devices always show it). An empty document always starts with one block of the default type (`paragraph`). `<Edytor>` includes the rich text, image, arrow move and suggestions plugins by default, so this is already a working rich text editor.
