# Plugins and chrome

What a plugin contributes, the bundled plugins and their defaults, labels, block handles and the block menu, and the chrome the overlay draws beside the host (`src/lib/plugins.ts`, `src/lib/plugins/`, `surface/overlay.ts`).

## Plugins

`Plugin = (editor) => definitions & operations` (`src/lib/plugins.ts`). A plugin contributes:

- kind records (`blocks`): `snippet`, `element` and `contentElement` (a tag, `{tag, attributes}`, or `(data, id) => …`), `viewState`, `void`, `island`, `lines`, `layout`, `rendersContent`, `defaultChild`, `continues` (list-like Enter), `container` (a header over its children: toggle, callout, quote), `presets` (slash menu, markdown, "turn into"), `empty`, `html`/`plain` export, `parse` (HTML import), `transformText`, `normalizeContent`/`normalizeChildren`, focus/select hooks;
- mark records (`marks`): `tag` + `attributes(value)` (the one element the core renders and the clipboard exports), an optional `snippet` (custom markup inside a core span), `parse` (HTML import), `void`, `edge` (`inclusive | exclusive | side-dependent`), `copy` (`false`: copy and cut leave it out, `createEdytorClipboardFragment`; the comment anchor's), `toolbar` (`run`: the button calls it instead of toggling); atom records (`inlineBlocks`): `snippet`, `plain`, `html` (clipboard HTML) and `parse` (HTML import claims an element inside a line as the atom);
- `inputRules` (`{ find, replace(match, ctx) }`: text typed at the caret, a string or the rule's own writes through `ctx.remove(then)`, block offsets; no rule in a code block's lines) and `triggers` (`{ char, items(query), onPick }`: a menu at the caret, `TriggerMenu.svelte` in the overlay, keys through the plugin's `hotkeys` before its own; `onPick`'s first operation takes the trigger's removal as its lead; rows are keyed and named by position, so two may share a label; Enter during a pending search picks the answer's first row, never an older query's), both wired into the plugin's own hooks at its place in the list (`plugins/triggers/triggers.ts`, called once per plugin by the composition root); never parse typed text in a plugin's `onBeforeOperation` for these;
- `hotkeys` (typed `HotKeyCombination`: up to three modifiers in any order; unknown tokens fail types and warn in DEV), `commands`, and hooks (`onBeforeOperation`, `onAfterOperation`, `onBeforeInput`, `onCopy`/`onCut`/`onPaste`, `onDeleteSelectedBlocks`, attach hooks that may return a cleanup, `placeholder`).

- Duplicate definitions and commands: **first wins** (an extension that extends another's definition lists itself first).
- Extensions read the document through handles and view objects, never Yjs types.
- Bundled and exported:
  - rich text (with toggle headings, `toggle-heading`: a `details` whose `summary` holds the `h1`–`h3`, a container as the toggle, presets Toggle heading 1–3 reached from a heading by `> ` and from a toggle by `#`–`###` through `KindPreset.markdownFrom`; with the link UX, `link.*`: a URL typed before a space or pasted at a caret is linked as an undo step of its own after the text, `typedLink`/`linkText` in `richTextOperations.ts`; Mod+click opens a link, `openLink`; container bodies, `body.*`: an open toggle's or a callout's empty body shows a hint, `EmptyBody.svelte`, `data-edytor-empty-body`, chrome inside the kind's markup whose click is ONE command, `openBody`, and over which a handle drop goes `inside` (`overEmptyBody`); a childless block this view retypes into a toggle opens, from `onBeforeOperation`/`onAfterOperation` through `onBlockAttached`; a callout is an icon, a title (its own text, semibold) and a content (its children, `body: true`, so Enter at the title's end goes into it, `bodyShows`); its icon, `callout.icon`, is `data.icon`, the view's default from `createRichTextPlugin({ callout: { icon, icons, picker } })` when unset, none when `''`, picked in the overlay by the view's one `CalloutIconPicker` (`calloutIcons.svelte.ts`: `set`/`remove`, the `keys`/`popup` attachments and `option(i)` rows that the default `CalloutIconMenu.svelte` and an app's `picker` snippet share; the block menu's `callout.icon` row is the keyboard's way in); its HTML is `<div data-edytor-callout="💡">`, read back by its `parse` hook)
  - code (`createCodePlugin({ languages, defaultLanguage })`: a block's language is its `data.language`, JavaScript when unset, picked in the header: its button opens the view's one `LanguageMenu` (`code/languageMenu.svelte.ts`, rendered by `LanguageMenu.svelte` in the overlay: a search `combobox` over a `listbox`, a pick one `patchData`, the keys given back to the button when they opened it, else to the editor; Alt+F10 at a caret in a code line focuses the button; the first code plugin listed owns it); TanStack Highlight tokens are its lines' `transformText`, read from the parent's `data` through the cell, with each grammar loaded the first time a line of it renders: `code/languages.ts` owns `CODE_LANGUAGES`, the shared grammar map and `tokenizeCode`; JSX ships eagerly)
  - image (`imagePlugin`/`createImagePlugin({ upload })`, `src/lib/plugins/image/`: void `figure`, `data.src` filtered by `safeImageSrc` to http(s)/blob/`data:image/`, `data.alt`, `data.width` (px) and `data.align` (`left`/`center`/`right`), "Add an image" link panel, Upload only with `upload`, editable caption; with `upload` its `onPaste` claims pasted and dropped image files unless the HTML beside them shows text: `ImageUploads` places one empty image block per file as a paste (one step), shows the upload (view state), and fills `src` in `dispatcher.outside`; the chrome (`ImageControls`, `ImageChrome.svelte`) is in the overlay: resize handles writing `data.width` on release from a view-only preview, as the column resize does, an alignment toolbar and an alt field, on the hovered image, else the image that is the whole block selection; a press outside (`onPress`) or focus leaving closes the alt field; HTML import takes a bare `img`, and a void element inside a line ends it, `flow.html.void`, except an inline glyph image (an emoji-only alt, an emoji class, 32 px or under), which is its `alt` text, `flow.html.glyph`)

## Block handles and the block menu

- Each handle is a `+` (dispatches `BLOCK_ADD_EVENT`; the slash menu answers it and adds nothing until a row is picked — typing goes to the menu's query, a custom `menu` snippet is wrapped in a focused element for that, and Escape, a press outside, focus leaving or readonly close it with the selection given back — then `BlockAddition.insert` adds the parent's default kind below, Alt above, and runs the command in ONE transaction and undo step; a command that answers `false` or is refused with nothing applied is taken back inside that transaction, which the history then does not capture (undo and redo stacks untouched, selection given back); an empty default-kind block is converted instead; unanswered, the `+` inserts the empty block at once. The `+` menu lists only commands whose `isEnabled` holds for the block being added (`additionView` in `SlashMenuController`: a view whose caret is in a stand-in of that block), so commands read the selection from their argument; its field is its one keyboard owner (rows are no Tab stops); a `+` clicked over a grip's menu first gives back the pre-grip selection (`BlockHandleController.ungrip`)) and the ⋮⋮ grip.
  - A grip click selects the block (an atomic block selection; a block selection already holding it stays, and the block menu then acts on all of it; over a text range across blocks, the blocks it covers), then calls `onActivate`, or, when none is set, dispatches `edytor-block-activate` (`BLOCK_ACTIVATE_EVENT`, `{ block, anchor }`, cancelable) on the editor node.
  - `blockMenuPlugin` listens for that event and answers it with `preventDefault()` to keep the keyboard; unanswered, the controller focuses the editor so the keys act on the selected block; a consumer `onActivate` replaces it (and owns the focus).
  - Layouts and columns have no handle; a block in a column has its `+` (Alt+click: a new column right of its column, `moveBlocks` `right`) and grip in the gap, right of the resize band (`gaps.ts`).
- The block stays selected while the block menu is open. Its actions return a text caret with `selection.setAtTextOffset(text, offset)`, which replaces the atomic selection (the old `setCollapsedStateAtTextOffset` alias is removed), then focus the editor. A DOM range alone cannot replace an atomic selection.
- Moves go through `edytor.canMoveBlocks`/`edytor.moveBlocks` everywhere (drag and drop, handle keys, arrow move, the block menu).
  - A handle's drag, Alt+arrows and click take the selection's blocks through one resolver, `BlockHandleController.dragBlocks` (the outermost of `movable(...)` over a block selection's blocks as clicked — never `selectedMembers`, so a selected list's item drags alone — or a text range's `getSelectionBlocks`, when the handle's block is among them, else that block alone; Mod+Shift+↑/↓ over a text range takes the same blocks, and over a block selection its `outermost`; after a move `selectMoved` keeps the moved blocks' selected descendants selected — only when the block selection held the whole group, else the moved blocks alone, the drag's rule; a handle's Alt+arrow over a text range covering its block keeps the range, as Mod+Shift+↑/↓ does; a drag's undo step restores the selection held before its start, `history.began`); a drag's placement is sticky across gaps, and below the document's last block all the way down (the pointer's x still picking the level; out of the editor's width it clears), never over another block's own row — a drop target sticks while it or a target inside it holds the placement, since PDD keeps an inner target only while every outer one of its chain sticks, and a left target hands the placement to the innermost one still current (`onDragLeave`); a drag fixes that group at its start, marks its count as `data-count` (no badge), and drops it as ONE `moveBlocks` call (any parents; a refused group moves nothing).
  - `moveBlocks` itself opens a closed toggle the blocks land in or that adopts blocks (`revealing`); callers do not wrap it.
  - An `in`/`out` step over siblings moves each run of adjacent ones on its own (`dispatcher.each`), as Tab does, so it never reorders the text.
  - A move refused before any command runs (readonly, `canMoveBlocks` false) still sets `dispatcher.last` to `refused`; inside one `dispatcher.run`, a step that applied is never overwritten by a later refused or no-op step.
- List containers (`rendersContent: false`, not void/island — `block.isContainer`) are never converted (`convertible` is false; `convertedBlocks` in kinds.ts skips them, so the items selected with them convert) and never count as touched by a text range that starts or ends in them (`getSelectionBlocks` skips those, so Tab/Shift+Tab over a range move the same blocks as the rows block-selected; a list the range runs through stays in, so it moves in order with its neighbours, and `moveRoots` groups them by parent while `edytor.moveBlocks` (`parts` in moves.ts) moves each run of adjacent siblings on its own, so no key reorders text).
  - Turn into and the horizontal rule place the new kind through one helper, `placing` in kinds.ts, prepared from the payload hooks leave (a rewritten kind is placed for that kind, its `normalizeContent` runs on it, and the caret follows it; `dispatchPlan`'s `then`): `facade.prepare.liftOut` lifts the item out of every list it does not fit (`facade.landingOf`; a divider or code block inserted after an item: the list splits after it), composed with the retype as ONE plan (never a loop of dispatched lifts: a veto must keep everything); a block's own kind (a data-only change) never lifts it.
  - `liftOut` and `unNestBlocks` split a list with one routine, `splitOut`.
  - What a split, a first-item lift, an outdent or a merge moves out of a block, and the blocks `splitBlock`/`insertFlow` at a position create, is ranked by where it came from (`exitRanks`/`pieceRanks`/`sourceRank` in the facade: side of the gap, then path, or text after the split point), never at random in the gap: two peers' concurrent splits keep the text order whatever their client ids, one gesture each between syncs (residuals in the delete contract).
  - On top, the display reads pieces of one text that stand where they were made in the text's order between clients (`order.split.text`: `textRanker` in `placement/model.ts`, through `displaySlotOf`); never re-rank pieces in a command.
  - Only those paths rank by source: inserts beside a block (Enter at a block's start or end, Duplicate, +; a container header's Enter, whose tail becomes a plain first child; a `whole` or `replace` `insertFlow`: a block-selection paste, a paste or typing over selected blocks) take a plain rank, or, right after a block this client ranked, extend its run there (`order.insert.run`: `ranksFor(…, run)`, the data arrays' `rankAfter`, so one peer's consecutive lines never interleave with another's), several gestures by one peer before sync (Turn into over several blocks is one plan per block, Shift+Tab one per run of adjacent blocks) and moves (drag, handle Alt+↑/↓/→, Mod+Shift+↑/↓, block-menu Move, Tab) take plain ranks and are not claimed (`order-scope.test.ts` pins them; do not widen source ranking without passing `rank-growth.test.ts`).
  - A source rank's first part segment is followed by one tied by the client's clock, so one client never mints one twice in a gap and a later gesture's blocks never interleave an earlier one's; `rankBetween` stops descending once its prefix is below the right bound.
  - A command over several parts (Turn into over several blocks, Tab over several runs, code-line Tab/Shift+Tab over several lines, formatting across blocks, Duplicate) runs through `dispatcher.each`: a refused or vetoed part is skipped and the others apply; a block-selection delete (keyboard — every Backspace/Delete chord, word and line deletes too: `wordAndLineDeletes` in bindings.ts at keydown, and `runBeforeInputDeleteCommand` for any delete intent's `beforeinput` — cut or block menu) goes through `deleteSelectedBlocks`, which runs `onDeleteSelectedBlocks` and then one `deleteBlocks` plan.
  - Every path that removes a block selection asks `keepsSelectedBlocks` (replaceSelection.ts) first — that delete, typing and composition (`replaceSelectedBlocksWithEmptyBlock`) and paste (`pasteFlow`); Enter and Shift+Enter remove nothing (`selectedBlocksLine`) and never ask — and a kept selection refuses the gesture (`dispatcher.last` = `refused`).
  - A composition over a block selection replaces it at `compositionstart` (`Composition.#rangeless`, over a selected atom too: the new block is rendered with `flushSync` and the DOM caret parked in it by `projector.park` before the IME writes, as a block selection shows no DOM range and the IME would write at the editable's start); refused, the IME writes into `selectedBlocksExit`'s line, which the tail restores.
  - `#release` clears the re-placement baseline (`#where`/`#order`), so that replacement's commit never ends the new session.
  - Enter in an empty item leaves the list through `unNestBlock`.
  - Enter keys off `block.list`, so an item outdented into its outer item keeps outdenting; a container's `itemKind` (`numbered-list-item` for `ordered-list`) is the kind its items show as, so converting to it is a no-op and `rowOf` names items by it.

## Input rules and block colours

- Input rules (`inputRules`): first match that writes wins; one command, the matched text's removal leading it, its own undo step even when the match is the typed text alone (`dispatcher.alone`); never a paste or a drop (`dispatcher.command`); refused or declined: typed as typed.
- Block colours: `colorAttributes` is the one reading (the core's block element and the attribute table; `colorClasses`/`colorsOfClasses` the copy's and the paste's Notion classes, `block-color-red`) and `setBlockColor` the one write (the block menu's Color, its search and the slash menu's `/red`; `colorable` says who takes one).

## Chrome in the surface

- **Overlay** (`edytor.overlay`): `add(measure)` and `mount(component, props, name, zIndex, measure)` share one read-then-write contract: `measure(host, origin)` reads layout and returns its style writes (a closing menu returns its close as a write).
  - Handles, drop indicator (Notion's plain 4px bar: centered between siblings; for `inside`, where the child lands, indented to the child's column), the nest backdrop (`[data-edytor-drop-backdrop]`, one per drag: a tint over the own row of the block a drop nests into — `inside`'s target or its `nestParent`, or a before/after's new non-root parent — `--edytor-drop-backdrop-color`; never a style on the block), menus and remote carets live in `[data-edytor-overlay]` beside the host, positioned layer-relative once per frame.
  - Never add chrome inside the host.
  - While a text selection runs (`selection.dragging`, a press in the host until its release, reactive), the handles and the column resize bands take no pointer (`data-selecting`), so the native selection is computed against the host.
  - Block handles are lazy: a handle mounts only for a block near the viewport (within a screen above or below: `nearTop`, a binary search over the top-level blocks' boxes on the overlay's frames, and the blocks inside them; every block where there is no layout; a block the band gains mounts its handle in a task queued from that frame, after its paint, browser rule `handles.after-paint`, so a key that adds blocks paints its text first), hovered, selected, focused or dragged (hovered: the pointer over the block or its own handle host, which sits flush with it; a handle over a column gap spans the gap, its `+` at the gap's left edge and its grip flush with its block, and its box takes the pointer at its block's whole row, hovered or not — the one hit rule, owned by `BlockHandles.svelte`; the column resize band sits above it at the gap's middle (`columns/gaps.ts`: `gapBefore` and `bandOf`, the one measurement both read), so wherever its guide shows a press resizes), and drop targets register only while our own drag runs.
  - Every handle drag sets a custom drag image, never the grip alone (`blockHandles/dragPreview.ts`): clones of the group's block elements, stripped of editable/view-only/live-node attributes, in a wrapper carrying the root's and its ancestors' classes, unrestyled (only `scale(0.8)`, sized to the scaled box; no count badge), cloned at drag start and removed by the drag library (`drag-preview.test.tsx`, `drag-preview.spec.ts`).
  - Drop zones (`zones`, on Atlassian's `@atlaskit/pragmatic-drag-and-drop-hitbox` list-item hitbox, loaded through `src/lib/dnd/pragmatic.ts`'s CJS entries for SSR): the hitbox splits the own row of the block under the pointer (`rowAt`: beside a nested block, over its ancestors' indent, that block's row) into reorder-before/reorder-after halves, `blocked` when the document refuses the whole half (then the other half's placements, `data-blocked` on the indicator); combine is never offered, the pointer's x nests: past one nest step (`--edytor-nest-indent`, else 24px) right of the text start, inside.
  - PDD's tree rules: an expanded block's (children shown, not a closed toggle, not a container) lower half is its first child's slot, never after its subtree; the last block of a nested group reparents to the ancestor level whose text column is nearest the pointer, down to the root.
  - A dragged block's own row and subtree offer nothing (released there, a drag is a no-op).
  - The handle column left of the editor's blocks (the drag's handle width; `margin` on the page target) is the row at the pointer's height, by its halves, before or after only (never inside; over an item of a container the dragged blocks do not fit in, the container is the row, by its whole box's halves: `reorder`), the bar held between rows: a drag straight down the handles reorders, never a beside band (those start past it); a block target there refuses the pointer (`canDrop`), so the page target's rule always applies.
  - The drop reach (`dnd.reach`, one zone function: `marginAt` in `blockHandles/geometry.ts`): within the editor's height, past the handle column on the left and past the content's right edge, up to `--edytor-drop-reach` (240px default, `dropReach`), the page target answers for the row the content's near edge shows at that height (a layout's first column on the left, its last on the right): the first 120px (`BESIDE_MARGIN`) are the beside bands' when the document has a layout kind (a refused band shows nothing, a row offering none reorders), the rest reorders: left as the handle column, right as the row's own right edge offers (`atRightEdge`: its halves, inside past one nesting step, so nothing jumps leaving the content); past the reach nothing. A block target holding the pointer (its slop) answers first; never add a second margin rule elsewhere.
  - Handles other than the source take no pointer during a drag (they sit over ancestor columns) (`dnd-nest-backdrop.test.tsx`).
  - Auto-scroll: a handle drag registers Atlassian's auto-scroll for the window and every scrolling ancestor of the host (the host included), for our drags only, at drag start and releases it at the drop (`dnd/autoScroll.ts`, shared with the table's row and column drags); `dnd/pragmatic.ts` binds the package's `makeApi` to our adapter's `monitorForElements`, since its own entry requires the core by bare path, which a browser bundle resolves to a second adapter that never sees our drags.
  - Never measure every block: reading a block inside a collapsed (`display: none`) subtree forces a layout each time.
- **Accessibility** (site `editor/accessibility`): the root is the `textbox`, named by the view's `aria-label`/`aria-labelledby`/`aria-describedby`/`id` props (`Edytor.svelte`). A popup's ARIA has one writer: the markup rendering it publishes `{ id, haspopup?, active?, keys?, opener? }` to `edytor.popups` once it is in the page, through its controller's `popup` attachment (default and custom markup alike); the root renders the newest, a handle's `+`/grip reads `openedBy` for `aria-expanded` (the textbox takes none, WAI-ARIA 1.2). The keyboard's owner names the highlighted row: the root for a typed `/`, the menu's own field for the `+` (a `combobox`) and the block menu. The toolbar is reached with Alt+F10 (roving tab stop; Escape is `controller.release`), every key in it stopped from the editor. A column band is a focusable `separator` (`resize.key`, one `transact` per press; the caret's layout shows its bands). `edytor.announcer` is the polite live region (`[data-edytor-live]`, overlay). A block's `dir` is `blockDir` of its own text (first strong character, none: inherit), owned by the attribute table: on the block, never the text element (engines move the caret by the paragraph's direction). The list kinds' `li`/`ul`/`ol` are `role="none"` (items are sibling blocks). Chrome text grays are `#73726e` (AA). `tests/editor-dom/a11y.spec.ts` is the axe audit (WCAG 2.2 A/AA; `target-size` a known gap: the 18px grip), `tests/editor-dom/bidi.spec.ts` the bidi rows.
- **Suggestions** (`edytor.suggestions`, `session/suggestions.svelte.ts`; site `editor/suggestions`): a view's proposed content at a position (`after`/`before`/`inside`/`end`/`replace`, by block id or a range's anchors), session state only: never in the document, history, presence or another view until `accept()`, one dispatcher command (`acceptSuggestion`, CUT `both`) placing it as a paste does (`prepare.insertFlow` at `{slot}`/`{replace}`/the text's end, `flow.place`; a text range: `replaceRange` then the flow at its caret). It survives selection changes and is dropped (`prune`, from the commit) when its block dies. A block suggestion renders in the host as one view-only group (`components/Suggestion.svelte`: `[data-edytor-suggestion]`, `contenteditable=false`, the kinds' own rendering through `Block`'s `preview` cells, no handle, no ids, no text elements), registered with the observer as `preview` (never compared or healed) and skipped by the truth oracle, selection mapping (`SUGGESTION` in `selection.utils.ts`), chrome presses and the drag clone; an `end` suggestion is the ghost text (`[data-edytor-text-suggestion]`); replaced blocks carry the owned `data-edytor-suggestion-replaced`, a replaced range is overlay rectangles (`components/SuggestionRanges.svelte`). The bar and keys are `suggestionsPlugin` (a default).
- The block handles' drag: `BlockHandleController` decides where a drop lands (the hitbox, the margins, the beside bands, `placement`); `DropIndicator` (`blockHandles/dropIndicator.ts`) draws it (the bar, the nest backdrop, in the overlay, measured per frame); `blockHandles/geometry.ts` holds what both read (a placement's shape, a block's own row and first text line, one nesting step, the drop reach's zones).
