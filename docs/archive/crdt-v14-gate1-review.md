# CRDT v14 — Gate 1 Adversarial Review

**Scope:** the vendored-Yjs v14 engine layer — placement model
(`src/lib/crdt/placement/model.ts`, `rank.ts`), text ownership
(`src/lib/crdt/text/model.ts`), maintained runs
(`src/lib/crdt/text/runs.ts`), plus the test harness and random corpus that
are supposed to prove them. Review method: source inspection + targeted
executable probes under `src/tests/crdt/gate1/`, not scenario-reading alone.

**Baseline:** before probes, `pnpm test:crdt` was green (the pre-existing
lanes). After adding the durable regression probes the lane fails by design —
13 expected failures concentrated in three files, all pinned below.

**Verdict: GATE 1 DOES NOT PASS.** There is one blocker (silent convergent
content loss via display-parent cycles), one major production defect (nested
insert id collision destroys an existing block), and one major test-oracle
gap that made the blocker invisible to the existing suite.

> **Resolution status (post-hardening): all findings addressed** — see
> [Resolution](#resolution-post-hardening). `pnpm test:crdt` green with the
> probes active (904 passed / 0 failed); the formerly-failing probes are now
> durable regression guards.

## Attack items verified clean

Probed and held — these are _positive_ results, not just absence of a found
bug (each is backed by an executable probe now kept under `gate1/` or by
existing scenario coverage re-verified during review):

- **Invalid local moves are true no-ops**: move-into-self, move-into-own-
  descendant, missing block, missing parent, deleted block — all return
  `false` and emit **0 update bytes** (`model.ts:607-621`, `612` guard).
- **Move/split/merge identity**: `crdtId` stable across move, nest, unnest,
  split, merge (corpus `lost-identity` = 0 for model adapter across 150
  seeds; move ADR evidence consistent).
- **Concurrent move determinism**: both delivery orders converge; repeated
  concurrent moves leave ≤4 live candidates/peer after 50 rounds.
- **Undo selectivity**: split-undo after a remote tail edit preserves the
  remote edit (`b1` = `hello world!!` after undo reclaimed `s1`);
  merge-undo resurfaces the claimed block even after a remote move;
  delete-undo restores a subtree with remote edits inside it intact;
  merge-undo + remote split of the claimed region converges with atoms
  partitioned across both blocks — no duplication, no loss.
- **Runs view isolation**: editing block A fires no subscriber on B and B's
  run snapshot stays `toBe`-identical; remote update touching only b2 does
  not recompute subscribed b1; a claimed-region edit correctly fires the
  _owner_ block's subscriber.
- **`decorateRuns` is write-free**: 0 update bytes emitted; decorations ride
  on the run objects only.
- **Detached-node delta guard**: `runs()`/`blockText` on a missing id
  returns `[]`/null without throwing or poisoning the integrated `.delta`
  cache (text/model.ts `itemsOfRange` deliberately uses `toDelta()` on
  detached nodes).
- **Inline atoms**: seam split at an atom's left edge moves it whole to the
  sibling (unique id, no split); a mark range spanning an atom splits the
  surrounding text runs but keeps the atom a single un-marked inline run;
  undo of an inline insert removes exactly the atom; concurrent inserts on
  both sides of an atom converge with the atom whole.
- **Ownership claim cycles**: the `owner()` map itself resolves concurrent
  `A→B`/`B→A` claims to the max-stamp edge (per text-ownership ADR:77-79;
  scenario coverage at active-text). The blocker is only the _composition_
  of this map with placement parents.
- **Deleted-anchor fallback**: covered by active-text.ts:389 (TX06c) —
  slice coverage survives its bound atom being deleted.
- **Wire growth**: 500 sequential moves = 53.3B/move, doc state 3.5KB, live
  `at` candidates = 3; 200 same-gap inserts → max rank length 16; 200
  splits = 168.9B/split; concurrent-move rounds leave 4 live candidates.
  Consistent with the move-ADR "~71B/move" claim and the O(record) intent.
- **Scenario registry honesty**: active/pending accounting is real —
  pending §8 ids render as `it.todo` in the separate pending lane
  (`pnpm test:crdt:pending` = 12 todo), and the registry asserts every §8
  id is either active or explicitly pending.

## Coverage limitations (honest)

- **No DOM/selection/input verification** — SE01–SE03, IN01 pending; the
  review covered the engine layer only.
- **Persistence/provider/migration unverified** — SY02, CO01–CO03 pending.
  In particular, `reload('snapshot'|'log')` dropping pending items (the
  `unrecoverable-loss` evidence class) was tolerated, not adjudicated.
- **Corpus evidence classes are tolerated, not proved**: `lost-edit`×~126
  seeds on the model adapter is evidence ("a later delete may have eaten
  the tag"), not a correctness proof. Combined with finding #3, the corpus
  passing is weak positive evidence.
- **Corpus nondeterminism** (finding #4): per-run clientIds change which
  ops resolve, so percentages are approximate (~19% of seeds showed
  vanished blocks in one sweep; set varies).
- **Runs/rich-text**: isolation, atoms, marks, decorations verified;
  _not_ verified — undo of format ops across merges, long-session run-cache
  behavior, `runs.bench` performance claims (bench is `skipIf`-gated).
- **Wire growth** measured only at the op level (updates emitted), not
  whole-doc sync payload or awareness traffic.
- The composed-cycle oracle (`vanishedIds`) treats `hidden-ancestor` as
  legitimately hidden; a bug that hides blocks via a different mechanism
  could escape that specific check.

One probe assertion was corrected rather than the engine:
`display-cycle.test.ts` "concurrent merge×move" asserted
`blockText(b1) === 'hello world'` after `mergeBlocks(b2 → b1)` — but the
merge _claim_ legitimately makes `b1` display b2's content
(`'hello worldsecond block'` is the U04 contract: claimed content reachable
through the claimer). The assertion now checks both halves are reachable
through `b1` — the defect it guarded (unreachable content) is covered by
the reachability assertion above it.

## Suggested fix sequencing

1. `mergeBlocks` display-ancestry guard + composed-cycle detection in the
   projector (finding 1) — this makes display-cycle + reachability green.
2. `checkStructurallyValid` registry-completeness check (finding 3) — do it
   _with_ #1 so the corpus gate actually watches for this class.
3. `insertBlock` spec-id prevalidation (finding 2).
4. Pin clientIds in `createPeerSet` (finding 4) so failure artifacts
   reproduce.
5. Adapter return fix + vacuous-assertion cleanup (findings 5, 6).
