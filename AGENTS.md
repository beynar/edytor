# Edytor Repository Guide

For coding agents and maintainers who need to work on the repo without rediscovering its structure.

Edytor is a small editing engine with a Svelte rendering layer, on a Yjs v14 document. It is not a component library with a thin editor wrapper. Almost every bug that "looks random" from the DOM or selection side comes from changing behavior in the wrong layer, or from giving one fact a second owner. Read "One owner per fact" before changing anything in `session/`, `surface/` or `events/`.

## Project identity

- Name `edytor`, version `0.1.0-next.0` (a pre-release: the `0.0.11` on npm has another API), work in progress.
- Docs: the site (`site/content/docs`) is the single source for API and behavior; the README is a landing page that links to it.
- Stack: Svelte 5, SvelteKit, TypeScript, **vendored Yjs v14** (`@y/y@14.0.0-rc.26`, an owned fork under `src/lib/crdt/vendor/yjs/`, patches listed in `UPSTREAM.md`; the `yjs` npm package is a dev dependency for migration tests only), Vitest, Playwright.
- The architecture below is the result of the arch-v2 plan (`docs/architecture-v2/plan.md`); `docs/architecture-v2/execution-ledger.md` records every checkpoint, the lane results and the measured numbers.

## The top-level model

Five contexts, each with one job and a lifetime:

| Context     | Lives in                                                                  | Lifetime               | Job                                                                                                                                                                          |
| ----------- | ------------------------------------------------------------------------- | ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **doc**     | `src/lib/crdt/` (not `vendor/`, `providers/`, `protocols/`, `migration/`) | the engine doc         | The replicated document and everything derived from it: block registry, placements, streams, one index, prepared operations, anchors, attribution. DOM-free and Svelte-free. |
| **sync**    | `src/lib/crdt/{providers,protocols,migration}/`, `src/lib/collaboration/` | provider / document    | Transport: the generation envelope, the room lifecycle and join rule, IndexedDB + websocket providers, awareness, presence, v13→v14 migration.                               |
| **session** | `src/lib/session/`                                                        | the view               | DOM-free per-view state: the selection value, the command dispatcher, input attempts, the composition session, history, keymap, navigation, moves, handles.                  |
| **surface** | `src/lib/surface/`, `src/lib/components/`, `src/lib/events/`              | one mount              | The only code that touches the host DOM: render cells, the compare-to-truth observer, the selection projector, the IME pin, the overlay, the event adapters.                 |
| **plugins** | `src/lib/plugins.ts`, `src/lib/plugins/`, `src/lib/kinds.ts`              | the editor (immutable) | Kind, mark and atom records, hooks, commands, bindings.                                                                                                                      |

`src/lib/edytor.svelte.ts` (`Edytor`) is the composition root: it builds one of each per view and wires them. It should hold wiring, not rules.

### Worker-safe CRDT boundary (maintainer constraint)

The CRDT engine and the sync layer also run server-side in a Cloudflare Durable Object that coordinates clients over WebSockets (a central coordinator, not P2P). `src/lib/crdt/**` (vendor included), `src/lib/utils/json.ts`, `src/lib/utils.ts` and `src/lib/constants.ts` must stay importable and runnable without Svelte and without browser globals:

- never import `svelte`, `$app/*`, `*.svelte(.ts|.js)` or a view layer (`components`, `selection`, `surface`, `session`, `events`, `block`, `text`, `plugins`, `clipboard`, `collaboration`, `edytor*.ts`) from there;
- feature-detect browser APIs (IndexedDB, `navigator.locks`, `BroadcastChannel`, page events); no module-level timers.

Three checks enforce it: `pnpm lint` (`WORKER_SAFE` + `edytor/worker-safe-imports` in `eslint.config.js`), `pnpm check:worker` (bundles `src/lib/crdt/index.ts` and `src/lib/cloudflare/index.ts` for a Worker target) and `src/tests/crdt/arch-v2/do-coordinator.test.ts` (a reference coordinator with the browser globals removed and timers forbidden). The coordinator's public surface — `bindCrdt(Y)` (`.sync` readers/writers and `applyRemote`, `.admission`, `.doc`), the frame contract, the message types (incl. `messageSaved`, `messageChunk`), the chunk codec, the lib0 frame helpers and the instance-free awareness codec (`readAwarenessEntries`/`writeAwarenessEntries`) — is section 8 of `src/lib/crdt/index.ts`. Do not remove anything that test or the room imports. The site's `server/protocol` and `server/room` pages have the contract.

The shipped room is `edytor/cloudflare` (`src/lib/cloudflare/`): `DocumentRoom` (the Durable Object) and `routeDocumentSocket` (authorize before the upgrade, forward only `X-Edytor-User/Replica/Access`). It is in the Worker-safe set and is the only module allowed to import `cloudflare:workers`; `src/cloudflare-workers.d.ts` (outside `src/lib`, never shipped) types that runtime for `pnpm check`, while `tests/do` checks it against `@cloudflare/workers-types`. Rules it owns: identity bound in the socket attachment; a client id belongs to the first user who writes under it (a socket's `replica` is registered at the upgrade), and new structs under another user's id are refused 1008; read-only sockets get `permission-denied` per write and stay; every sync message is answered with `messageSaved` after the write (the provider's `saved`/`unsaved`); frames above `EDYTOR_MAX_FRAME_BYTES` go out as `messageChunk` sequences; compaction is `mergeUpdates` after `EDYTOR_COMPACT_AFTER` records, run after the message is acknowledged (a failure is logged as a `storage` refusal and retried; nobody is disconnected); every entry point runs under `noTimers`. Restore and registry: `onLoad` returns JSON, a bare v14 update or `{update, replicas}` (`LoadedDocument`); nothing is stored until it settles; `null` is provisional (asked again at every start); a throw closes sockets `1011 room unavailable` and is retried; a refused payload, a torn record or a container of another generation sets `failure` and refuses every socket `1008 refused: container` (`reset()` is the generation cutover). `onSave` receives `{value, update, replicas}` (`ReplicaOwner[]`); after a bare-update restore each id with content is claimed by its first authenticated writer (an `orphan` note). `refusals` keeps the newest `MAX_REFUSALS` (100), `refusalCounts` counts all. The room echoes an accepted presence entry to its sender, so a lone client is never silent for 30 s. Server `transact` edits obey the `semantics` option (default `defaultSemantics`; `semantics: {}` checks nothing); client updates are relayed as they are.

## Doc

- **Shape.** `JSONDoc = {children: JSONBlock[]}`, `JSONBlock = {type, id?, data?, content?, children?}`, `content` = `JSONText {text, marks?}` and `JSONInlineBlock {type, id?, data?}` (`src/lib/utils/json.ts`). A block owns its inline `content` and its nested `children`; the model is not a DOM mirror.
- **Streams (text ownership).** Each block's text is a stream in a backing text, delimited by boundary items. A split writes one boundary; a merge adds a claim. Split and merge never copy text. `docs/crdt-v14-text-ownership-adr.md` and the plan §2.1 have the details.
- **Text delete marks.** A text delete writes the writer's mark (root `textdel`, in the history's scope); an undo restores text through `restoreFilter`/`onApply` (fork patch P11) only where no other writer's mark holds it and no copy shows it, copying the character's newest incarnation; the writer's replica hides a concurrent restoration of what its mark holds, deduplicates its own copies (leftmost wins) and restores what it withheld once the holds are gone. Restoration records (root `restored`) give every copy its root and origin. Never restore or delete text behind the history's back: go through the facade.
- **Preserve what was not removed (2026-09-28, `docs/editor-delete-contract.md`).** A block delete removes only its members (`del.blocks.promote`: unselected children take the slot; `deleteBlock(id, { keepChildren: false })` is the explicit subtree delete) and a block selection is exactly its members (`sel.blocks.exact`). An undo never deletes a block its step created (`hist.undo.withdraw`, P12): the block is withdrawn and shows while it holds another writer's content. An emptied document writes nothing: each view shows a virtual paragraph (`doc.empty.virtual`) that the first edit in it creates, in the edit's plan. A text range delete that would leave nothing to hold the caret keeps its head block, emptied, with its id, type and data (`del.range.whole-doc`), so peers deleting the whole document keep the same block; it never writes a new one.
- **Operations are two-phase.** Every facade op is `apply(prepare.op(…))`. `prepare` writes nothing and returns a plan of named steps with its effect (or `refused`); `apply` writes it in one transaction and returns `OpResult {status: 'applied' | 'noop' | 'refused', ids}`. Range delete (`prepare.deleteRange`/`replaceRange`/`deleteBlocks`) and paste/drop placement (`prepare.insertFlow`) are single plans whose rules are rows in `docs/editor-delete-contract.md` (`del.range.*`, `flow.*`). A new structural case means a new contract row, not a caller flag.
- **One index, one report.** `facade.onChange(cb)` delivers one `DocChange` per commit that changed the visible document (`added`, `removed`, `moved`, `meta`, `content`, `order`). Nested transactions publish once; a transaction that nets out publishes nothing.
- **Roles.** `void` (structurally isolated, not editable by the core flow) and `island` (editable, sealed from its neighbours) drive merge, unnest, delete and navigation. They are not cosmetic. A document learns them from its views' plugins or from `createDocument({semantics})` (`defaultSemantics` for the bundled kinds); without either, a headless document checks no roles. The bundled rows live in `crdt/semantics.ts`: change them there, not in the plugins.
- **Read-time display.** A deleted block's unmarked children, and a child a peer adds, moves or splits under it concurrently, show in its slot (`displaySlotOf`, rank `promotedRank`); nothing hides with a deleted subtree (`del.blocks.promote`). A void kind displays no children: a retype to void moves them right after it, and a child that lands under one concurrently is shown in its slot, from the document's roles (`DisplayOwnership.childless`, fed by the runs index from `roleOf`), so replicas must hold the same roles.
- **Seeds.** A seed is written under a writer id hashed from the value, in a band below 2^26; live writers are uint53, so a seed never displaces a live block. Two different seeds sharing an id resolve by hash order (irreversible), so never seed a changing snapshot beside a room. The derived own-text writer is a different id space (53-bit `hash53`); never widen the seed writer.
- **Anchors** are `DocAnchor = {b, a}` (see the anchor contract below).

## Sync

- Every frame is `varuint GENERATION | varuint messageType | payload`; `GENERATION = PROTOCOL_VERSION * 1000 + SCHEMA_VERSION` (schema generation 4). Anything else is refused before decode; `applyRemote` refuses updates that forge the schema stamp.
- One room lifecycle and join rule (`providers/room.ts`): hello = Step1 + presence; a Step1 is answered with Step2, plus our own Step1 when the asker holds something we lack.
- `createIndexeddbSync(name)` / `createWebsocketSync({server, room, params?, maxBackoffTime?, WebSocketPolyfill?, disableBc?, persist?, persistName?})` are `EdytorSync` factories for `<Edytor {sync}>` or `document.attachSync` (`serverUrl`/`roomName` are deprecated aliases of `server`/`room`); the document keeps one provider per transport target. `createWebsocketSync` attaches a local IndexedDB store by default (`edytor:<server>/<room>`, skipped without `indexedDB`) as a provider of its own through the payload's `attach`, so the document's readiness rules apply to each leg unchanged; while the store exists it carries the cross-tab channel (the socket's BroadcastChannel leg is off).
- Readiness bound: `createWebsocketSync` sets `bound: Infinity` and arms the 1 s bound through `EdytorSyncPayload.armBound()` from the socket's open or its first failed dial, so a cold room hydrates instead of racing the seed. Known gaps: a server that opens and then takes over 1 s to send its state is read as empty; a dial that neither opens nor fails keeps an empty document pending.
- Refusals: a close with `1008` or `4xxx` is terminal: the provider stops dialing and emits `refused` (`SyncRefusedError {code, reason}`); an empty document never seeds over it and exposes `document.syncRefusal` / `onSyncRefused`. `1006` (an HTTP refusal looks the same) keeps redialing: backoff `100 ms × 2ⁿ` capped at `maxBackoffTime`, the cap doubling to 30 s after 8 dials that never synced, each emitting `unreachable`; the count resets when a connection syncs. A text `pong` counts as liveness.
- Presence lost with a transport is removed under the `LOCAL_PRESENCE_LOSS` origin: that tab only, sibling tabs keep their remote carets.
- `<Edytor>` releases a view-owned document in `onDestroy`, which also runs after a server render.
- Presence: `selections[viewKey] = serialize(value) + t`. A view writes only its own key. Remote carets resolve the freshest valid text entry per client.

## Session

- **Selection value** (`SelectionValue`, by `kind`): `none`, `text {anchor, focus, pending?}`, `atom {blockId, atomId, from}`, `blocks {ids}`. Everything a command reads (endpoints as (block, display offset), direction, collapsed, covered blocks, edge flags, marks, content) is `project(value, doc)`, memoized per (value, index version). `selection.state` is a read-only compatibility getter over the projection. Pending marks are `value.pending` (`selection.pending`, `selection.stage(marks)`).
- **`select(value, cause)`** is the one writer. It applies the effects once (selected/focused sets and hooks, suggestions), emits `onSelectionChange` and publishes presence only when the value changed, and asks the projector to display (causes `model`/`history`), or not (`dom`).
- **Dispatcher** (`edytor.dispatcher`): admission (readonly, `document.writable`) → prepare → `onBeforeOperation` on the command and on each planned step under its documented name, all before any write → one transaction → normalization requests drained once inside it → `last.status` (`refused | noop | applied | failed`) → `onAfterOperation` once. A veto refuses the whole command; `prevent(cb)` replaces it. `prevent()` is caught only in the dispatcher; never call `stopCapturing()` or catch `PreventionError` elsewhere. Plugin command API: `dispatcher.dispatch`, `lead` (a markdown or slash trigger removal leading a conversion in one plan) and `caret` (the command's result selection); `Plan`/`Prepared` are exported types.
- **Undo policy is the dispatcher's.** Do not hand-place `dispatcher.cut(…)` before block or text operations. An operation outside a user command cuts by the `CUT` table, never the continuation heuristic: structural operations and deletions are one step each; a led operation (markdown or slash conversion) and `inlineMarkdown` are always their own step, so undo gives back the typed trigger. To make a multi-operation gesture one step, wrap it in `dispatcher.run(kind, body)` (also a prevention scope) or `edytor.transact`. `dispatcher.cut` remains only for writes the dispatcher never sees: raw facade writes, browser-owned attempts, a composition's first write.
- **Data writes are commands.** `block.setData`, `block.type =` and `atom.setData` go through the dispatcher (`setBlock`, `setInlineData`): refused when readonly, shown to hooks, recorded in `last`, their own undo step. `block.model.setData` is the raw write.
- **Input attempt** (`edytor.attempts`): one per occurrence (a `beforeinput`, a keydown whose `beforeinput` never came, paste, drop, a native line break). Intent, anchored target (the selection value) and owner (model performs, or browser performs and the model adopts) are fixed at admission. A model-owned attempt owns the DOM drift around it until its deadline.
- **Composition session** (`edytor.composition`): one IME composition, `live → tail → gone`. The start target is replaced by an ordinary command at the first write; previews are mechanical tracked writes in one capture group (one undo step); it ends exactly once (`commit`, `cancel`, `abandon`, or D-20 when a commit re-places the host's block). No timer ever ends a session. While live, the host's segment list is frozen by the pin and the projector writes no DOM selection.
- **History**: `edytor.historyUndo()/historyRedo()` are the bare engine calls — never inside a transaction and with no tracked write after them (that would empty the redo stack), so nothing normalizes after them. The issuing view restores its recorded value.
- **Handles**: `Block`, `Text`, `InlineBlock` are id-only handles (`edytor.idToBlock` is the `Handles` registry). Getters read the document index (inside a command they see its writes); mutators issue commands. They are **not reactive**: templates read the snippet's view object or the cells. A `Text` is the `ordinal`-th segment of its block and has no identity across commits; key extension state by block id and anchor. Liveness is `block.isInTree`, `text.isInDocument`, `atom.isInDocument`.

## Surface

- **Cells** (`edytor.cells`): one frozen cell per visible block, patched from each change report; a patch replaces exactly the cells it names. Components render from cells only (`Edytor` → `Block` → `Content` → `Text`/`Mark`/`InlineBlock`). The core renders the block element from the kind's `element`; snippets render inner markup and receive view objects (`BlockView`, `InlineBlockView`), not handles. Text segments are keyed causally (by the atom before them), so typing never remounts the caret's node.
- **Compare-to-truth observer** (`edytor.surface`): records carry no provenance; they only say what to compare. The pre pass (root `$effect.pre`) inverts a record that removed registered elements and snapshots an edit the flush would overwrite; the compare pass (root `$effect`, after every DOM write) compares each named content with its cell. Text inside a content is adopted through the dispatcher unless an expectation claims its host (the composition tail, a pending structural key, a model-owned drift — then the cell is restored); structure is restored; the live IME host is the IME's; read-only divergence is inverted at the flip back. The root, text elements and core mark elements are strict containers. **D-25:** a block's own text/atom run is a strict region only the editor writes; tolerance covers only a kind's own markup around the content and children slots (and attributes the table does not own).
- **Projector** (`edytor.projector`): the only DOM-selection writer. After every flush it writes the current value when asked, or when the render epoch moved, and only if the live DOM selection differs. It never takes focus from outside the editor and never writes while a composition is live. It classifies every `selectionchange` (echo, drift, composition, foreign, intent). Two named, time-bounded browser rules are the only signatures: the Android post-delete snap-back and the IME post-commit jump.
- **Overlay** (`edytor.overlay`): `add(measure)` and `mount(component, props, name, zIndex, measure)` share one read-then-write contract: `measure(host, origin)` reads layout and returns its style writes (a closing menu returns its close as a write). Handles, drop indicator (Notion's plain 4px bar: centered between siblings; for `inside`, where the child lands, indented to the child's column), menus and remote carets live in `[data-edytor-overlay]` beside the host, positioned layer-relative once per frame. Never add chrome inside the host. Block handles are lazy: a handle mounts only for a block near the viewport (an `IntersectionObserver`; every block when there is none), hovered, selected, focused or dragged, and drop targets register only while our own drag runs. Never measure every block: reading a block inside a collapsed (`display: none`) subtree forces a layout each time.
- **Placeholder** is the `data-placeholder` attribute on the empty text element, drawn by a shipped `::before` rule.
- **DOM selection exceptions.** Besides the projector, only these clear the DOM selection directly: `events/onFocus.ts` (focusout after focus moved outside), `edytor.svelte.ts` (attach teardown), `selection/selection.svelte.ts` (two sites), `block/inlineBlock.svelte.ts` (atom selection). Do not add more.
- **BI2-5 lint**: DOM mutation calls in `src/lib` are allowed only in the host writers (`components/`, the handles' attachments, `surface/observer`, `surface/attributes`, `surface/overlay`, `plugins/`, `collaboration/`). Never write imperatively into owned text or mark elements.

### Selection contracts that must not regress

(Normative spec: `docs/editor-delete-contract.md`, "Anchor contract", "Selection ownership and lifecycle", "Responsibility map".)

- A caret anchor is `{b, a}`: `b` the home block of the backing text, `a.i` the bound item (causal identity), `a.a`'s sign the insert affinity. Text ownership is streams delimited by boundary items: a left caret at a split-born block's start binds that block's boundary item, so the containing stream and the side are two facts in two fields (no owner facet since arch-v2 D12). Never let a caret migrate into a surviving neighbour block because that neighbour received text at the shared gap.
- Logical recovery destination and DOM readiness are separate: a live destination with no mounted node stays the selection value and is displayed by the projector's pass after the flush that mounts it (a value that no longer projects runs the seam repair; a text mount or the observer's records re-run a waiting pass). Do not "fix" this by treating unmounted text as unrecoverable, or by weakening `firstEditableText`'s mounted-node requirement (container phantom slots must stay skipped).
- `surface/projector.svelte.ts` is the only DOM-selection writer: after every Svelte flush it writes the current value, so no older request can overwrite a newer gesture. Commands and input attempts decide the value and `select()` it in their own turn (`edytor.attempts.caret` only records the drift-repair caret); the three named writes that still select after a wait (the adoption caret, the root-heal redisplay, the drift repair's caret) check the gesture serial after it and yield to a newer gesture. Do not bring back tick/timeout re-assert loops. While a requested display has not landed, a `selectionchange` with no intent gesture since the request (`Edytor.intentSerial`, the one gesture serial; `input` events do not bump it) is not adopted.

## Plugins

`Plugin = (editor) => definitions & operations` (`src/lib/plugins.ts`). A plugin contributes:

- kind records (`blocks`): `snippet`, `element`, `viewState`, `void`, `island`, `rendersContent`, `defaultChild`, `continues` (list-like Enter), `container` (a header over its children: toggle, callout, quote), `presets` (slash menu, markdown, "turn into"), `empty`, `html`/`plain` export, `parse` (HTML import), `transformText`, `normalizeContent`/`normalizeChildren`, focus/select hooks;
- mark records (`marks`): `tag` + `attributes(value)` (the one element the core renders and the clipboard exports, P2.7), an optional `snippet` (custom markup inside a core span), `parse` (HTML import), `void`, `edge` (`inclusive | exclusive | side-dependent`), `toolbar`; atom records (`inlineBlocks`);
- `hotkeys` (typed `HotKeyCombination`: up to three modifiers in any order; unknown tokens fail types and warn in DEV), `commands`, and hooks (`onBeforeOperation`, `onAfterOperation`, `onBeforeInput`, `onCopy`/`onCut`/`onPaste`, `onDeleteSelectedBlocks`, attach hooks that may return a cleanup, `placeholder`).

Duplicate definitions and commands: **first wins** (an extension that extends another's definition lists itself first). Extensions read the document through handles and view objects, never Yjs types. Bundled and exported: rich text, code (TanStack Highlight, JSX only; tokens are its `transformText`), image (`imagePlugin`/`createImagePlugin({ upload })`: void `figure`, `data.src` filtered by `safeImageSrc` to http(s)/blob/`data:image/`, "Add an image" link panel, Upload only with `upload`, editable caption), block handles, block menu, slash menu, toolbar, markdown shortcuts, arrow move. The mention plugin is a reference implementation only (not exported). The bundled chrome follows Notion (2025 light theme); the matching document stylesheet is `src/lib/themes/notion.css`, shipped as `edytor/themes/notion.css` and scoped under `.edytor-notion`. The demo route (`src/routes/+page.svelte`) and the site's live editor use that theme, `richTextPlaceholder` and the shipped plugins, including the block menu (the demo route builds it with `createBlockMenuPlugin({ linkTo })`). HTML import (P4.1, `clipboard/htmlFlow.ts`): external `text/html` paste and drop are parsed by the browser (`DOMParser`) into a flow; the tag tables are the kind and mark records inverted (a preset's export/element tag, a mark's `tag`, each record's `parse` hook first) — never a tag switch. Paste order: internal MIME, embedded fragment, a plugin's `onPaste`, HTML import, `text/plain`.

Default plugins: `<Edytor>` (`withDefaults` in `components/Edytor.svelte`) adds `arrowMovePlugin`, `imagePlugin` and `richTextPlugin` after the app's `plugins` (its kinds and keys win), each unless the list already has it (any `createImagePlugin` instance counts, via `isImagePlugin`); `defaultPlugins={false}` opts out. Block handles are added separately (`blockHandles`). The `Edytor` class itself adds nothing (`createTestEdytor` lists its plugins), and the DOM harnesses (`EdytorHarness.svelte`, `SiblingEdytors.svelte`, `/test/dom`) pass `defaultPlugins={false}` so each test's plugin set is exact.

Editing behavior (Enter and Backspace by role: plain, continuing, container, void, island) has one canonical description, the site's `customization/hotkeys#enter-and-backspace-by-role` table; `src/tests/docs-drift.test.ts` catches known stale phrasings. The code is `insertParagraph` in `events/beforeInputCommands.ts` (`continues`, `container`, the `<details>` open state read from `block.node`), `resetKindAtStart` in `events/beforeInputDeleteCommands.ts` (`del.start.kind`) and `prepareSplit` in `block/block.utils.ts`. Change the rule there and in that table, nowhere else.

UI snippets: the chrome plugins take snippets and keep their behaviour (keys, placement, commands). `createSlashMenuPlugin({ item?, menu? })` (`SlashMenuItem` `{command, selected, icon, run, select}` / `SlashMenuController`), `createToolbarPlugin({ toolbar? })` (`ToolbarController`; placement measures `[data-edytor-toolbar-bar]`, else the first element), `createBlockMenuPlugin({ linkTo?, menu? })` (`BlockMenuController`; placement measures `[data-edytor-block-menu]`, else the first element; a custom menu owns its keys, the built-in ones live on the default search field), and `BlockHandlesOptions.handle` (`BlockHandleSnippetPayload` `{block, grip, add, readonly, draggable}`; `grip` is `BlockHandleController.grip(block)`, the one attachment for drag source, click-to-activate and Alt+arrow keys, used by the default handle too). `slashMenuPlugin`, `toolbarPlugin`, `blockMenuPlugin` are the factories called without options. The contract tests are `src/tests/fixtures/dom/custom-ui.test.ts` (fixture `src/tests/dom/CustomUi.svelte`).

Block handles and the block menu:

- Each handle is a `+` (inserts the parent's default kind below, Alt above, and types `/` so the slash menu opens; an empty default-kind block takes the `/` itself) and the ⋮⋮ grip. A grip click selects the block (an atomic block selection), then calls `onActivate`, or, when none is set, dispatches `edytor-block-activate` (`BLOCK_ACTIVATE_EVENT`, `{ block, anchor }`) on the editor node. `blockMenuPlugin` listens for that event; a consumer `onActivate` replaces it.
- The block stays selected while the block menu is open. Its actions return a text caret with `selection.setAtTextOffset(text, offset)`, which replaces the atomic selection (the old `setCollapsedStateAtTextOffset` alias is removed), then focus the editor. A DOM range alone cannot replace an atomic selection.
- Moves go through `edytor.canMoveBlocks`/`edytor.moveBlocks` everywhere (drag and drop, handle keys, arrow move, the block menu).

## Where to fix what

- A structural edit is wrong → the document op (`crdt/edytor-doc.ts` prepare functions, `crdt/rangeDelete.ts`, `crdt/flow.ts`) and its contract row, then the view command in `block/block.utils.ts`.
- A text edit is wrong → `text/text.utils.ts`, `session/editing/text.ts` (marks).
- A keystroke is wrong in the browser → `events/onBeforeInput.ts` + `events/beforeInputCommands.ts` / `beforeInputDeleteCommands.ts`, the attempt (`session/attempt.ts`), the binding (`session/bindings.ts`).
- The caret lands wrong → the command's result selection (`Dispatcher.caret`) or the seam (`crdt/anchors.ts`); the projector only displays the value.
- The DOM differs from the model → the observer's classification (`surface/observer.svelte.ts`) or the cell (`surface/cells.ts`). Never patch the DOM from a command.
- IME → `session/composition.svelte.ts` and `surface/pin.svelte.ts`.
- Rendering is wrong while the model is right → components and kind records.

## Practical rules

- Change behaviour in its owner. If a change needs a flag, timer, retry or a second place that decides the same thing, stop: a contract row or an owner rule is missing.
- Timers are named, counted browser rules only (`pnpm census` reports them); no `tick()` polling, no re-assert loops.
- Keep `src/lib/crdt` Worker-safe; run `pnpm check:worker` when touching it.
- Verify engine APIs in the vendored source (`src/lib/crdt/vendor/yjs/src`), not from Yjs v13 examples; fork changes go through `UPSTREAM.md`.
- Public API and behavior changes update the site in the same change: the page that documents it, and `reference/migration.mdx` ("Complete list of changes", the canonical record; the README links it and keeps no copy). The ledger records gates and measurements.
- The composition root's `readonly edytor = this` is load-bearing: `batch()` binds operations onto the `Edytor` too. `edytor.container` is gone; the host element is `edytor.node`. Focus and pointer ownership listeners live in `events/onFocus.ts` (`attachFocus`).
