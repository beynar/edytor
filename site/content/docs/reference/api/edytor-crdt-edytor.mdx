## AnchorAffinity

Selection-endpoint affinity — which side of a position the anchor binds
to (see `T.atomAnchorAt`):

- `'left'` — bound to the atom BEFORE the position; resolves right after
  it, so a concurrent insert exactly at the position lands to the
  anchor's right. Used for carets and range ENDS.
- `'right'` — bound to the atom AT the position; resolves right before
  it, so a concurrent insert lands to the anchor's left — outside a
  range starting here. Used for range STARTS.

```ts
export type AnchorAffinity = 'left' | 'right';
```

## BlockRole

Structural role of a block type (plugin-side policy, resolved per op).

```ts

    island?: boolean;
    lines?: boolean;
    layout?: boolean;
    table?: boolean;
```

## DocBlock

Typed handle over one document block. Handles are dead-safe: constructing
one for an absent/merged id is legal — ops are `refused` (the underlying
facade ops guard the same way).

Read members are getters — every access re-derives from current doc state,
so a handle obtained before a mutation sees the mutation afterwards
(including within the same transaction).

```ts
export type DocBlock = {
    readonly id: BlockId;
    readonly document: DocumentOperations;
    readonly attribution: BlockAttribution | undefined;
    readonly items: readonly ContentItem[];
    readonly length: number;
    readonly runs: readonly ContentRun[];
    childIds(): BlockId[];
    insertText(offset: number, text: string, marks?: Record<string, unknown>): OpResult;
    deleteText(offset: number, length: number): OpResult;
    format(offset: number, length: number, marks: Record<string, unknown>): OpResult;
    setMark(offset: number, length: number, name: string, value: unknown): OpResult;
    unsetMark(offset: number, length: number, name: string): OpResult;
    clearMarks(offset: number, length: number): OpResult;
    insertInline(offset: number, spec: InlineSpec): OpResult;
    removeInline(inlineId: string): OpResult;
    setInlineData(inlineId: string, data: Record<string, unknown>): OpResult;
    insertChild(index: number, spec: BlockSpec): OpResult;
    moveTo(dest: {
        parent: NodeRef;
        index: number;
    }): OpResult;
    nestUnder(parent: DocBlock | BlockId): OpResult;
    unNest(): OpResult;
    split(offset: number, newId: BlockId, tail?: SplitTail): OpResult;
    mergeBackward(): OpResult;
    mergeForward(): OpResult;
    mergeFrom(other: DocBlock | BlockId): OpResult;
    delete(opts?: {
        keepChildren?: boolean;
    }): OpResult;
    setType(type: string): OpResult;
    setData(data: Record<string, unknown>): OpResult;
    set(value: Parameters<DocumentWrites['setBlock']>[1]): OpResult;
    duplicate(freshId: (oldId: string, kind: 'block' | 'inline') => string): OpResult;
};
```

- `id`: Stable caller-assigned block id.
- `document`: The owning document — cross-node and document-level ops live here.
- `attribution`: Compact per-block attribution (`{createdBy, contributors, lastChangedBy}` as durable actor ids), or `undefined` for system/foreign blocks carrying no record.
- `items`: Resolved content items of this block's display (\{kind:'text'\} runs and \{kind:'inline'\} atoms in display order, unmerged across streams).
- `length`: Display length in atoms (UTF-16 text units + 1 per inline atom).
- `runs`: The maintained run view for this block — frozen, structurally shared run arrays refreshed at transaction commit.
- `childIds`: Ordered visible child ids.
- `format`: Multi-mark format over `[offset, offset+length)`; `null` values unset.
- `clearMarks`: Remove every mark present anywhere in the range.
- `insertChild`: Insert a fresh-identity child spec; `ids`: the new block.
- `moveTo`: Relocate this block — identity preserved; island/void rules apply.
- `nestUnder`: Move to the last position under `parent`.
- `unNest`: Move beside the parent (index = parent index + 1).
- `split`: Split content at display `offset` into a new sibling `newId`; `ids`: the new block.
- `mergeBackward`: Baseline merge into the previous block in document order (a list's first item lifts out instead); `ids`: the survivor.
- `mergeForward`: Baseline merge pulling the next block in document order into this (a list passes its first item).
- `mergeFrom`: Engine merge primitive — `other`'s content+children claim into this.
- `delete`: Delete (per-writer marks on this block and what it displays); the children take its slot unless `keepChildren: false`.
- `set`: Baseline `setBlock` — type/data update in place; content/children replace (all-or-nothing).
- `duplicate`: Fresh-identity copy of this subtree right after it; `freshId` names each copied block and inline atom (an unanswered atom id is minted, an unanswered block id refuses); `ids`: the copy.

## DocChange

One committed transaction's semantic diff — the payload `EdytorDoc.onChange`

of the document (each view over it, its cells included) receives the same
object, so it is read-only.

```ts

};
```

- `origin`: Transaction origin (local origin object, remote marker, …).
- `local`: `transaction.local` — false for remote-applied updates.
- `version`: Monotonic event counter per facade.
- `added`: Newly visible blocks → full projected subtree (incl.
- `removed`: Ids no longer visible (deleted, merged-away, or hidden with subtree).

- `order`: Parents (`null` = root) whose visible child list changed → new order (frozen — shared with the retained snapshot baseline).
- `data`: The document's own data (`docData()`), when this commit changed it.

## DocumentReadiness

How the document's content state was decided — the distinction the
readiness contract requires:
- `pending` — undecided (created without a value or attached before
  `sync()`; a provider may still hydrate — nothing bootstrapped,
  nothing broadcast). Reads/attaches/`sync()` legal, `history`
  refuses;
- `local` — seeded locally (`createDocument({value})`, or `sync()` on a
  still-fresh doc — seed-if-empty bootstrap included). Full surface
  legal;
- `hydrated` — the doc was already initialized when `sync()` ran:
  provider-applied remote state or a `loadDocument` restore (schema
  asserted, content untouched). Full surface legal.

`sync()` is the only transition out of `pending`, and it is the
document-side admission re-check: a doc that arrived in a problem
state (unversioned/unsupported/foreign/legacy — e.g. via raw
`applyUpdate` bypass writes) refuses there with a typed error, stays
`pending`, and preserves the state — never silently becoming `local`.

```ts
export type DocumentReadiness = 'pending' | 'local' | 'hydrated';
```

- `attribution`: The attribution surface — compact per-block records, the replicated actor dictionary (`u/` profiles, `c/` replica bindings), and a `legacy()` read over any pre-existing `a/` per-edit records written by earlier builds.
- `transaction`: The document's own local-edit transaction origin — headless edits via `transact` carry it so history capture attributes them.
- `requireHydration`: `DocumentOptions.requireHydration`: an empty document waits for a provider's `synced`.
- `clientID`: The replica id (`doc.clientID`) — identifies the replica, not the actor.

- `readiness`: `pending` | `local` | `hydrated` — distinguishes a locally-seeded ready from a provider-hydrated/restored ready (the contract consumers need to tell "I decided this content" from "sync brought it").

- `rendersContent`: Whether kind `type` renders its own content slot (undeclared kinds do).
- `adoptSemantics`: Contribute document-level semantics — the seam views use to seed the structural roles implied by their plugin block definitions.
- `sync`: The readiness transition — decide the document's content state.
- `history`: The default local history (registry-scoped `Y.UndoManager` — `undo`/`redo`/`stopCapturing`/stacks).
- `trackOrigin`: Track a local-edit transaction origin for history capture — the seam views use to enroll their own `TRANSACTION` instance in this document's history.
- `untrackOrigin`: Release a previously-tracked origin — the view-teardown counterpart of `trackOrigin`.
- `clearHistory`: Drop the undo/redo stacks.
- `transact`: Local document transaction — headless edits, one undo step per call (`origin`: another origin, which the document's history tracks only when it is tracked).
- `onReady`: Subscribe to the readiness transition — fires once, synchronously, inside `sync` when `_readiness` leaves `'pending'` (every decision path goes through `sync()`: provider `synced`, local seed, explicit call).
- `syncPending`: Whether an attached provider has neither settled nor reached its bound.
- `syncRefusal`: The server's refusal of a provider (a `1008`/`4xxx` close — see `SyncRefusedError`), the latest still standing: that provider stopped.
- `onSyncRefused`: Subscribe to provider refusals (`syncRefusal`).
- `attachSync`: Attach a provider sync factory to this document (headless `EdytorSync` path — the same contract views use).
- `encode`: Full replicated state as a v14 update — `loadDocument` restores it on a fresh replica.
- `retain`: Acquire one more attach reference and return its ONE-SHOT release capability.
- `destroy`: Release ONE attach reference.

## tableBlock

A table block in the document JSON: `rows × columns` cells, the table's
`columns` and each cell's `column` set. It names no block id, so a value
holding it seeds the same table every time.


## TableBlockOptions

What `tableBlock` builds.

```ts
export type TableBlockOptions = {
    rows?: number;
    columns?: number;
    cells?: readonly (readonly (string | readonly JSONText[])[])[];
    headerRow?: boolean;
    headerColumn?: boolean;
    widths?: readonly (number | undefined)[];
};
```

- `rows`: Rows (default: the rows of `cells`, else 2).
- `columns`: Columns (default: the widest row of `cells`, else 2).
- `cells`: Each cell's text, by row then column (a string, or rich text).
- `headerRow`: The first row is a header row.
- `headerColumn`: The first column is a header column.
- `widths`: Column widths in pixels, by position (absent: the default width).
