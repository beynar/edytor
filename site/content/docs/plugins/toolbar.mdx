`createToolbarPlugin({ toolbar })` shows a formatting toolbar above a text selection, Notion's `[Kind ⌄] | Link | B I U S </> | A ⌄` in the demo. The bar is your `toolbar` snippet: the plugin ships when it shows, its placement, its keys and every action, and no markup (see [Markup](#markup)). The mark buttons come from the mark definitions: every mark with a `toolbar` entry is in `controller.marks`.

```svelte title="Toolbar.svelte" check
<script lang="ts">
	import { Edytor, createToolbarPlugin, type ToolbarController } from 'edytor';

	const plugins = [createToolbarPlugin({ toolbar })];
</script>

{#snippet toolbar(controller: ToolbarController)}
	<div class="bar" {@attach controller.popup} {@attach controller.keys}>
		{#each controller.marks as { mark, label, icon } (mark)}
			<button aria-label={label} aria-pressed={controller.isActive(mark)} onclick={() => controller.toggleMark(mark)}
				>{icon}</button
			>
		{/each}
		<button onclick={() => controller.setColor('highlight', '#fbf3db')}>Highlight</button>
	</div>
{/snippet}

<Edytor {plugins} />
```

It formats through [`richTextOperations`](/docs/plugins/rich-text#formatting-from-code), so it relies on the rich text plugin (on by default), or on your own plugin that defines the `link`, `color` and `highlight` marks if you want the link and color panels to work.

## What it offers

What the controller offers, as the demo's bar shows it, from left to right:

1. **The kind button**, labeled with the block's kind ("Heading 2", "Text"…): the preset sharing the most data with the block, or drawn with the same tag (a stored `h5` heading, drawn as an `h3`, is "Heading 3"). It opens a "Turn into" panel listing the kinds that keep content, with ✓ on the current one. Picking one converts every block the selection touches, nested ones included, as one undo step, and keeps the selection; a list's items leave the list ([Containers](/docs/concepts/blocks#containers)). A closed toggle's hidden body is not touched, as in Notion; an open toggle's children are.
2. **Link** opens a link panel: a URL field (`data-testid="toolbar-link-input"`) showing the selection's current link, with Apply and Remove. The field takes the focus when the panel opens. <kbd>Enter</kbd> in the field applies and closes the panel; <kbd>Escape</kbd> closes it. Both give the editor its focus back with the text still selected. Applying an empty field removes the link.
3. **One button per mark** whose definition has `toolbar: { label, icon }`, in registration order. With the rich text plugin: bold, italic, underline, strike and code. A button toggles its mark over the selection, and shows pressed (`aria-pressed="true"`, in blue) when the mark covers the whole selection.
4. **A ⌄** (Color) opens Notion's colors: ten text colors and ten background colors. A text color sets the `color` mark, a background the `highlight` mark, and Default removes that mark: `controller.setColor('color' | 'highlight', value)` takes any CSS colour, so the palette is your markup's (the demo's is Notion's, `palette.ts`).

One panel is open at a time; clicking its button again closes it. Panels drop below the bar, over the text.

| Color   | Text      | Background |
| ------- | --------- | ---------- |
| Default | none      | none       |
| Gray    | `#7d7a75` | `#f0efed`  |
| Brown   | `#9f765a` | `#f5ede9`  |
| Orange  | `#d27b2d` | `#fbebde`  |
| Yellow  | `#cb9434` | `#f9f3dc`  |
| Green   | `#50946e` | `#e8f1ec`  |
| Blue    | `#387dc9` | `#e5f2fc`  |
| Purple  | `#9a6bb4` | `#f3ebf9`  |
| Pink    | `#c14c8a` | `#fae9f1`  |
| Red     | `#cf5148` | `#fce9e7`  |

The values are stored in the marks as written, so documents keep them if you restyle the editor.

Add a button for your own mark by declaring `toolbar` on it:

```ts
marks: {
	keyboard: { tag: 'kbd', toolbar: { label: 'Keyboard', icon: '⌨' } }
}
```

The `icon` is text: a letter, a symbol or an emoji. With `run`, the button calls it instead of toggling the mark: the [comments plugin](/docs/plugins/comments)'s `comment` mark declares `toolbar: { label: 'Comment', icon: '💬', run }`, which opens a thread on the selection.

## When it shows

The toolbar shows when all of these hold:

- the editor is not readonly (turning it readonly hides the toolbar; it shows again over the same selection when the editor is editable);
- the selection is a non-collapsed text range;
- no whole block and no inline atom is selected;
- the selection is not inside a void or an island block (such as a code block).

It follows the selection as it changes, and repositions on scroll, resize and edits. While it shows, the editor's root names it (`aria-controls`) and the key that reaches it (`aria-keyshortcuts="Alt+F10"`): <kbd>Alt</kbd>+<kbd>F10</kbd> moves the focus to its first button, <kbd>←</kbd>/<kbd>→</kbd>, <kbd>Home</kbd> and <kbd>End</kbd> walk the bar (one tab stop), and <kbd>Escape</kbd> gives the focus back to the editor over the same selection ([Accessibility](/docs/editor/accessibility#the-toolbar-from-the-keyboard)). Buttons keep the selection: clicking one does not move the caret, and the selection is restored after the format is applied. A press anywhere on the toolbar, its background included, never takes the editor's focus: typing after it goes on in the editor, replacing the selected text. Only its fields (the link panel's URL field) take focus.

## Keyboard

<kbd>Mod</kbd>+<kbd>K</kbd> opens the link panel, its field focused (`link.mod-k`, Notion): over the selected text, or, at a caret inside a link, over that whole link, which it selects first. At a caret outside any link, and wherever the toolbar does not show (a code block, a void, a readonly view), the key is not claimed.

## Link card

With a `card` snippet, hovering a link shows a card just below it (`link.card`, Notion), in the overlay with `data-edytor-link-card-host` (`z-index: 61`): in the demo, the link's URL, then three buttons.

| Button | Calls              | Action                                                                                         |
| ------ | ------------------ | ---------------------------------------------------------------------------------------------- |
| Open   | `openHovered()`    | Opens the link in a new tab (`noopener`, `noreferrer`), as <kbd>Mod</kbd>+click does           |
| Edit   | `editHovered()`    | Selects the whole link and opens the link panel on it, its field focused                       |
| Remove | `removeHovered()`  | Removes the link from the whole link (the characters around it linked to the same URL), one undo step; the selection stays |

The card stays while the pointer moves from the link onto it, and goes when the pointer leaves both. A press on it never takes the editor's focus. A readonly view shows no card. Without a `card`, no card shows.

A URL typed in the link panel goes through the same sanitization as every link: a `javascript:` or other unsafe scheme is ignored. Colors go through `setMarkValueAtRange` and `removeMarkAtRange` (see [Formatting from code](/docs/plugins/rich-text#formatting-from-code)).

## Placement

The toolbar mounts in the editor's overlay, in a `position: fixed` host with the attribute `data-edytor-toolbar-host` and `z-index: 60`. It is centered above the selection, or placed below it when there is no room above, and kept inside the viewport. Its look is yours: the demo's Notion-style bar is `Toolbar.svelte` (and the card `LinkCard.svelte`) in the repository's [`registry/edytor/chrome`](https://github.com/beynar/edytor/tree/master/registry/edytor/chrome) (the `edytor-chrome` registry item, in your app after `shadcn-svelte add`).

The example at the top of this page uses `popup` and `keys`. The plugin cancels the `mousedown` of every press in its host but in a field (an `input`, a `textarea`, a `select`), so your buttons keep the selection and the editor's focus without a `mousedown` handler of their own. The plugin places the host by the element marked `data-edytor-toolbar-bar` (`popup` marks your bar; else your snippet's first element), so a panel that opens below the bar does not push the bar up. See [Menus and handles](/docs/customization/menus) for the other menus.
