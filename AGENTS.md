# Edytor Repository Guide

For coding agents and maintainers who need to work on the repo without rediscovering its structure.

Edytor is a small editing engine with a Svelte rendering layer, on a Yjs v14 document. It is not a component library with a thin editor wrapper. Almost every bug that "looks random" from the DOM or selection side comes from changing behavior in the wrong layer, or from giving one fact a second owner. Read "One owner per fact" before changing anything in `session/`, `surface/` or `events/`.

## Project identity

- Name `edytor`, version `2.0.0` (`latest` on npm; the API report is the reviewed surface: a change to it is semver-major unless it only adds).
- Stack: Svelte 5, SvelteKit, TypeScript, **vendored Yjs v14** (`@y/y@14.0.0-rc.26`, an owned fork under `src/lib/crdt/vendor/yjs/`, patches listed in `UPSTREAM.md`; the `yjs` npm package is a dev dependency for the v13 boundary tests only), **vendored Pragmatic drag and drop** (the parts the drags use, under `src/lib/dnd/vendor/pragmatic/`, changes listed in its `UPSTREAM.md`), Vitest, Playwright.
- The architecture below is the result of the arch-v2 plan (`docs/archive/architecture-v2/plan.md`); `docs/archive/architecture-v2/execution-ledger.md` records every checkpoint, the lane results and the measured numbers.
- Docs, install, the packed tarball and the release process: [`docs/agents/release.md`](docs/agents/release.md).

## The top-level model

Five contexts, each with one job and a lifetime, plus the shared leaves and the composition root:

| Context     | Lives in                                                                                                                                                                                                  | Lifetime               | Job                                                                                                                                                                                                                                      |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **doc**     | `src/lib/crdt/` (not `vendor/`, `providers/`, `protocols/`)                                                                                                                                               | the engine doc         | The replicated document and everything derived from it: block registry, placements, streams, one index, prepared operations, anchors, attribution. DOM-free and Svelte-free.                                                             |
| **sync**    | `src/lib/crdt/{providers,protocols}/`, `src/lib/cloudflare/`, `src/lib/collaboration/` (not the remote carets, not `history/`)                                                                            | provider / document    | Transport: the generation envelope, the room lifecycle and join rule, IndexedDB + websocket providers, awareness, presence state, the room.                                                                                              |
| **session** | `src/lib/session/`, `src/lib/block/`, `src/lib/text/`, `src/lib/clipboard/`, `src/lib/selection/{replaceSelection,visibility}.ts`, `src/lib/kinds.ts`                                                     | the view               | DOM-free per-view state: the selection value, the command dispatcher, input attempts, the composition session, history, keymap, navigation, moves, the handles, the clipboard's flows, the kind catalogue.                               |
| **surface** | `src/lib/surface/`, `src/lib/components/` (not `Edytor.svelte`), `src/lib/events/`, `src/lib/selection/` (the rest), `src/lib/dnd/`, `src/lib/collaboration/{remoteSelection.ts,RemoteSelections.svelte}` | one mount              | The only code that reads or writes the host DOM: render cells, the compare-to-truth observer, the selection projector, the IME pin, the overlay, the event adapters, the DOM selection's adopter (`EdytorSelection`), the remote carets. |
| **plugins** | `src/lib/plugins.ts`, `src/lib/plugins/`, `src/lib/export/`, `src/lib/collaboration/history/`                                                                                                             | the editor (immutable) | Kind, mark and atom records, hooks, commands, bindings, and the chrome's controllers (headless: the app draws every menu, handle and panel; the version history's controller).                                                           |

Outside the package, `registry/` is the shadcn-svelte registry an app copies with `npx shadcn-svelte add https://edytor.dev/r/<item>.json` (`registry.json`: the `edytor-chrome` item, `registry/edytor/chrome/`, the Notion-style chrome in shadcn components; the `starter` item, `registry/edytor/starter/`, `StarterEditor` and its page parts; `registry/ui/` and `registry/utils.ts` are this repository's shadcn-svelte install, `components.json`, the registry's dependencies, never served). It imports the package by its published name (`edytor`, resolved to `src/lib` by `vite.config.ts` and `registry/edytor.d.ts`), the shadcn components as `$registry/ui/…`, which the registry build rewrites to the app's aliases. Nothing in `src/lib` imports it (`pnpm check:deps`, `registryImports`). Built into `site/public/r/` (`pnpm registry:build`, served at `https://edytor.dev/r/`); `pnpm check:registry` fails on a stale build; `tests/registry-install/run.sh` installs it into a fresh SvelteKit app.

The shared leaves (`src/lib/utils/`, `src/lib/utils.ts`, `src/lib/constants.ts`, `src/lib/labels.ts`) import nothing of the contexts. `src/lib/edytor.svelte.ts` (`Edytor`) is the composition root (with the mount `components/Edytor.svelte` and the entry `index.ts`): it builds one of each per view and wires them. It should hold wiring, not rules.

**Import direction.** The contexts form no import cycle between them. The session never value-imports the surface, the chrome or the root, and the surface never value-imports the chrome or the root (`import type` is free). What the session asks of the surface and of the input commands is a port it declares (`session/ports.ts`: `SurfacePort` — the projector's `park`, `placed` and `parked`, the observer's `flush`, clearing the DOM selection, a DOM point's text and offset — and `InputPort`, the intents a binding runs) and the root implements (`edytor.ports`). The handles' attachments (the host writers) still register their nodes with the observer, and the composition session drives the pin and reads the cells, through the view. Three checks: `edytor-contexts/context-imports` in `eslint.config.js` (`pnpm lint`), `pnpm check:deps` (`scripts/deps.mjs`: Tarjan's strongly connected components over the value imports of `src/lib`, vendor excluded; `--cross`, `--between`, `--edges` show what to invert) and `src/tests/deps.test.ts` (no cycle crosses contexts, every module has one, no forbidden import). The assignment is data, `CONTEXTS` and `FORBIDDEN` in `scripts/contexts.mjs`: a new directory gets a row there and here. A module that seems to need an import against the direction is in the wrong context, or the owner is missing a port.

## Where to fix what

- A structural edit is wrong → the document op (the `crdt/doc/` prepare families over `crdt/doc/steps.ts`, `crdt/rangeDelete.ts`, `crdt/flow.ts`) and its contract row; the view dispatches it under the same name (`Dispatcher.operate`), so there is no view-side copy to fix.
- A text edit is wrong → the text ops (`crdt/doc/content.ts`), `session/editing/text.ts` (marks: `marksForInsertion`, `insertionMarksAt`).
- A keystroke is wrong in the browser → `events/onBeforeInput.ts` + `events/beforeInputCommands.ts` / `beforeInputDeleteCommands.ts`, the attempt (`session/attempt.ts`), the binding (`session/bindings.ts`).
- The caret lands wrong → the command's result selection (`Dispatcher.caret`) or the seam (`crdt/anchors.ts`); the projector only displays the value.
- The DOM differs from the model → the observer's classification (`surface/observer.svelte.ts`) or the cell (`surface/cells.ts`). Never patch the DOM from a command.
- IME → `session/composition.svelte.ts` and `surface/pin.svelte.ts`.
- A table shows wrong (a cell out of its column, an empty row, a stray cell) → the index's table rules (`tableVisit`, `cellRank` in `crdt/text/index/layout.ts`) and the `table.*` rows, never the table plugin; a table op writes wrong → `plugins/table/ops.ts` (plans composed of the document's `patchData`, `insertBlocks`, `deleteBlocks`, `moveBlocks`; a wrong step is theirs); the grid's chrome → `plugins/table/chrome.svelte.ts`.
- A layout shows wrong (an empty column, a one-column layout, a block beside the columns) → the index's layout rules (`crdt/text/index/layout.ts`, `displaySlotOf`) and the `layout.*` rows, never the columns plugin; a beside drop lands wrong → `besideAt`/`placeBeside`; the gap's chrome overlaps → `plugins/columns/gaps.ts`.
- Rendering is wrong while the model is right → components and kind records.

## Practical rules

- Change behaviour in its owner. If a change needs a flag, timer, retry or a second place that decides the same thing, stop: a contract row or an owner rule is missing.
- Browsers: Baseline 2024 and later (Chrome/Edge 120, Firefox 125, Safari/iOS 17.4, Android Chrome 120; site `reference/platform-support`, held by `docs-onboarding.test.ts`: no shipped feature newer than them). No code path or feature detection for an older engine; a path one supported engine still needs names it, and an engine workaround names its still-open bug. An API every supported engine has but jsdom lacks is stubbed in `src/tests/dom/setup.ts` rather than detected in `src/lib`.
- Timers are named, counted browser rules only (`pnpm census` reports them); no `tick()` polling, no re-assert loops.
- Keep `src/lib/crdt` Worker-safe; run `pnpm check:worker` when touching it.
- Verify engine APIs in the vendored source (`src/lib/crdt/vendor/yjs/src`), not from Yjs v13 examples; fork changes go through `UPSTREAM.md`.
- Public API and behavior changes update the site in the same change: the page that documents it, and `reference/migration.mdx`, the user changelog: a note under `### Unreleased` (right after `## Upgrading between pre-releases`; a release sorts its notes into `#### Breaking changes`, `#### New` and `#### Fixed` under `### From <previous version>` and opens a new, empty `### Unreleased` ("Nothing yet.") above it, a note that asks apps or tests to act under breaking changes), and the "Complete list of changes", the canonical record by area (the README links it and keeps no copy). The changelog is written for users: no ticket code, contract row id or repository path (`src/tests/docs-drift.test.ts` rejects them). The ledger records gates and measurements.
- Engine privates (`_map`, `_start`, `_length`, `store`, `gc`/`gcFilter`, transaction events, undo stacks) and engine functions called with edytor's structural views (`EngineDoc`, `StoreStruct`, `IdSetLike`) go through the typed accessors of `src/lib/crdt/structs.ts` (`asEngineDoc`, `attrItems`, `firstItem`, `keepFromCollection`, `onTransaction`, `engineOps(Y)`, …): a new reach into the engine is an accessor there, never a cast at the call site (`pnpm census` counts `as unknown as` and `as never`). Each edytor document carries the fork's keep-replaced rule (`keepingReplaced`, `crdt/incarnations.ts`) before it integrates anything; the engine's class default stays upstream's. `.github/workflows/upstream.yml` diffs and tests a newer `@y/y` weekly.
- The public surface is curated: `src/lib/index.ts` lists every name (no `export *`), the wire vocabulary lives only in `edytor/protocol` (`src/lib/crdt/protocol.ts`), and a member only the editor's own layers call carries `@internal` in its JSDoc (`stripInternal` drops it from the published `.d.ts`). The committed report `api/*.api.md` (`pnpm api:report`) is the reviewed surface: `src/tests/api/public-surface.test.ts` (unit lane) fails until a change to it is regenerated, so review its diff like code. It also fails when a reported declaration's JSDoc names an internal ticket code (`R4`, `UW-22`): public JSDoc says what a code means instead. A removed name goes at once, with its row in the changelog's Breaking changes; an untyped caller still passing a removed view option or prop is ignored, without a warning (no compatibility shims).
- The view's writes are the document's operation names, defined on the `Edytor` by its constructor from `DOCUMENT_WRITES` (`interface Edytor extends DocumentWrites`); a new write is a document operation, never a handle method. `edytor.container` is gone; the host element is `edytor.node`. Focus and pointer ownership listeners live in `events/onFocus.ts` (`attachFocus`), the press among them (the chrome press included): a `pointerdown`, or a trusted primary `mousedown` no `pointerdown` came before (WebKit sends none for the first press after a native drag, bugs 202287/222632/279749), a pair counted once. A press inside the host is handled there, not by a `pointerdown` listener of its own. Chrome outside the host reads the same fact, never a second classification: a press listener installed after the attach (a menu's press outside) is `onPress(edytor, target, listener)`, and an overlay element's own `mousedown` asks `isLonePress(edytor, event)` (the column resize band starts its drag from it, tracking the mouse on the window).
