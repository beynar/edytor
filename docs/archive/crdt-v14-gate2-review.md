# CRDT v14 — Gate 2 Adversarial Review

**Scope:** U06 (assembled document model — `src/lib/crdt/edytor-doc.ts`,
`placement/model.ts`, `text/model.ts`, `text/runs.ts`) and U07 (providers —
`src/lib/crdt/providers/{indexeddb,websocket}.ts`; protocols —
`src/lib/crdt/protocols/{envelope,sync,awareness,auth}.ts`; migration —
`src/lib/crdt/migration/{migrate,legacy-schema}.ts`), plus the public package
boundary (`package.json` exports, `src/lib/index.ts`, `tests/packed-consumer`).

**Review method:** source inspection + targeted executable probes under
`src/tests/crdt/gate2/`, run via the CRDT lane
(`pnpm exec vitest run --config ./vitest.crdt.config.ts src/tests/crdt/gate2/`),
plus packed-tarball consumer verification in `tests/packed-consumer`. No
production files were modified; no git state was touched.

**Baseline:** the pre-existing CRDT lanes were green. After adding the gate-2
probes the lane fails _by design_ — **16 expected failures**, each pinning a
verified defect; every other test (1161) passes.

**Verdict: GATE 2 DOES NOT PASS.** Four blockers: (1) `migrate()` destroys a
live v14 generation via unconditional `updates.clear()`; (2) legacy rows with
missing CRDT deps are silently dropped and the migration still activates;
(3) disposing one facade kills the doc-shared RunView for every other facade —
including silently dropping block content from `toJSON()`; (4) the shipped
package installs and re-exports a live v13 engine alongside the vendored v14.
The documented consumer surface (`bindCrdt`, providers, Awareness) is
additionally unreachable through package exports — the U07 provider/API
contract that U08 depends on does not exist for external consumers.

## Verified clean (executable evidence)

Probed and held — positive results, not merely absence of failure:

- **Wire-protocol version gate**: a real `yjs@13`-encoded sync frame on the BC
  room and on the websocket path is dropped with `protocol-mismatch`
  (`{expected:14, found:0}`), never reaches `applyUpdate`, and the synchronous
  same-tab `bc.publish` does **not** throw into the publisher's stack.
- **Malformed/truncated/mis-versioned frames**: 10 of 11 attack frames produce
  `protocol-mismatch` or `message-error`; none mutate the doc; none escape into
  the publisher (`_bcSubscriber` catch → `message-error`). The one silent case is
  finding 12.
- **Provider lifecycle**: `whenSynced` resolves on hydration and is left pending
  (never settles) when destroyed before open; `destroy()` is idempotent;
  internally-owned awareness is destroyed with the provider while an injected
  awareness survives; BC disconnect broadcasts an awareness-removal the remote
  peer observes; destroy-before-connect stops the reconnect loop without
  throwing.
- **Websocket reconnect**: reconnect re-syncs (`synced` false→true, SyncStep1
  resent); `resyncInterval` re-sends SyncStep1 on the live socket; a WS-received
  update is persisted by the IDB provider on the same doc (cross-provider relay).
- **Compaction**: >500 updates trigger the debounced trim; a snapshot + later
  interleaved rows reload in order; post-reload doc is byte-equal and ops
  continue working.
- **Schema manifest**: `init()` on partial state does not clobber existing
  content; a replica that only ever applied updates learns `meta.v`; concurrent
  `init()` produces exactly one bootstrap root.
- **DocChange mirror**: a pure-JSON mirror driven only by DocChange events stays
  `toEqual(ed.toJSON())` across local structural edits, remote updates, undo,
  and update-only document construction.
- **Projector/read purity**: `project()`/`toJSON()`/`runs()`/`snapshot()`/
  `childrenIds()`/`positionOf()` emit zero update bytes; run marks are frozen;
  deep-frozen input specs are accepted without in-place normalization.
- **Undo — clean half**: provider-applied (remote/untracked-origin) updates
  never enter the undo stack; registry-scoped UM attached _after_ init cannot
  reach the bootstrap.
- **Migration — clean half**: sequential/concurrent claims converge to one
  generation; a lease-expired reclaim leaves exactly one snapshot row and both
  callers `active`; rollback preserves the legacy DB byte-identical and leaves
  the generation readable (empty); a non-legacy doc is rejected by the reader.

## Coverage limitations (honest)

- **fake-indexeddb + in-process BC only.** Real IndexedDB transaction
  interleaving across browser tabs, real BroadcastChannel cross-context
  delivery, and real websocket servers (binary frames, mid-connection auth
  expiry, network partitions) are not exercised — the WS path is tested through
  a `FakeWS` polyfill.
- **Pending-dep probe covers one dependency shape** (insert dependent on absent
  parent/left structs). `pendingDs` (delete-set-only pending) and GC'd-missing
  variants are not probed.
- **Lease arbitration** is verified under fake-indexeddb's serial scheduling;
  genuinely concurrent IDB transactions in two browser contexts may interleave
  differently.
- **Undo probes** cover doc-scope and registry-scope; per-subtree scopes and
  `trackedOrigins` configurations under interleaved local+remote traffic are
  partially covered.
- **Migration fixtures** are the four CO01 fixtures plus generated v13 docs —
  production v13 stores with real edit history depth are unexercised.
- **Packed-consumer** verifies node-ESM resolution of the tarball; bundler
  (vite/webpack/rollup) condition resolution was not re-verified.
- **No DOM/selection/input** — outside this gate's scope per AGENTS.md.

## U08 gate decision

**FAIL — do not cut over yet.** The application cutover (U08) writes Edytor's
real document layer onto this substrate. Doing so while `migrate()` can destroy
a live generation (finding 1), silently drop pending offline work (finding 2),
a routine `dispose()` can silently truncate `toJSON` output for surviving
facades (finding 3), and the package still ships+re-exports the v13 engine
(finding 4) would bake silent data-loss paths into the cutover. The provider
corruption-observability gap (6), absent schema gate (7), and the three
migration edge dead-ends (8, 9) are fix-once-cheaply items that must land
before or as part of the cutover commit. Findings 5, 10, 11 define explicit
contract decisions U08 must implement (exports map, undo scope, clone policy).

Suggested minimum bar to re-review for PASS: findings 1-4 resolved with the
retained probes green; findings 6-9 resolved or explicitly accepted with the
probes updated to pin the accepted behavior; finding 5's exports decision
landed so the provider doc's consumer example actually runs.
