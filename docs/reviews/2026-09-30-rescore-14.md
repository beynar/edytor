## Open units of work

### HX-01 — Block menu treats a grip-selected list or code block as a multi-block selection

- **Area:** Code organization, API ease of use (user-visible behavior)
- **Severity:** medium
- **Effort:** S
- **File:** src/lib/plugins/blockMenu/BlockMenuController.svelte.ts:156 (root cause src/lib/selection/replaceSelection.ts:21)
- **Failure:** GX-02 aliased `getSelectedBlocksInDocumentOrder` to `selectedMembers`, which adds a list's or code block's whole subtree. `open()` (:156-157) then sets `blocks = [L, one, two]` for a single grip click. As a result:
  - "Copy link to block" disappears (`blocks.length === 1` at :94). The demo passes `linkTo`.
  - Escape, Move up/down and Duplicate go through `restore()` (:252-262) and `selectBlocks(...live)`. They leave an explicit block selection of the whole subtree instead of a text caret, and ArrowUp/Down then do nothing (bindings.ts:95).
  - With a closed toggle inside the list, Escape followed by Mod+B bolds the hidden body, which breaks DR-behavior-4.
  - Duplicate (`duplicateAll`) and Turn into (`convertBlocks` over list and items) also take the multi-block branch.
- **Fix:** Base the menu's one-block-versus-several decision (`open`, the link row, `restore`) on the raw `edytor.selection.selectedBlocks`, sorted. Expand with `selectedMembers` only when an action runs (delete, copy, Turn into). An alternative is to retire the alias and call `selectedMembers` at each of the ~12 call sites, so every caller opts in explicitly. Also check the Duplicate and Turn-into branches, and update block-menu.mdx:63/87/117.
- **Done when:** DOM rows exist for a list grip and a code-block grip that show the link row present, Escape, Move and Duplicate returning a caret or a single-member selection, and Mod+B after Escape leaving a closed toggle's body unformatted. block-menu.mdx matches the code.

### HX-02 — Documented "delete the selected blocks" example destroys a grip-selected list's bullets

- **Area:** Documentation
- **Severity:** medium
- **Effort:** S
- **File:** site/content/docs/editor/commands.mdx:73 (also block-handles.mdx:165-180, selection.mdx:129)
- **Failure:** `edytor.deleteBlocks({ blocks: [...edytor.selection.selectedBlocks] })` on a grip-selected list L (selectedBlocks = {L}) promotes the items to paragraphs. That is the GX-02 outcome wave 16 fixed for the built-in gestures, where Backspace removes the whole list. The block-handles custom-menu example's `convertToKind(edytor, L, heading2, true)` returns false and changes nothing. No public API exposes the members a selection stands for: neither `selectedMembers`, `getSelectedBlocksInDocumentOrder` nor `deleteSelectedBlocks` is exported from src/lib/index.ts.
- **Fix:** Export a members accessor (for example `edytor.selection.selectedMembers`) or `deleteSelectedBlocks`, and use it in commands.mdx:73. Fix or annotate the block-handles custom-menu example. In selection.mdx:129, say that `selectedBlocks` holds the blocks as clicked and that a selected list stands for its items through the accessor. This can share the naming work of HX-01.
- **Done when:** On [p a, ul L>[one,two], p b] with L grip-selected, the documented snippet gives [a, b]. The custom-menu Turn into converts the items. A docs-drift phrase guards the snippet.

### HX-03 — A room read from `doc.on('afterAllTransactions')` heals mid-frame and acknowledges an unstored edit

- **Area:** Durable Object server
- **Severity:** low
- **Effort:** S
- **File:** src/lib/cloudflare/DocumentRoom.ts:1258
- **Failure:** `heal()` skips only while `_transactionCleanups` is non-empty. The engine empties that list before it emits `afterAllTransactions` (Transaction.js:345-346), still inside `sync.applyRemote`. A listener there that reads `r.facade`, calls `read()` or calls `transact` runs `rebuild(true)`, which clears `unstored`. `onSync` (:1566) then acknowledges the frame from the destroyed doc. Reproduced in workerd: the socket was not closed and the ack advanced to clock 4, but live and stored both read 'hello'. The client believes '!' is saved, and no peer received it.
- **Fix:** Set a `handling` flag around `applyRemote`/`settleDeletes` in `onSync`, and check it in `heal()` and in `transact`'s refusal. Alternatively, fault the sender when `this.doc !== doc` after the apply.
- **Done when:** A tests/do row next to the SW16 it.each, using an `afterAllTransactions` listener (both facade-read and transact variants), asserts a 1011 fault and no ack.

### HX-04 — Room `transact` in a subscriber of the room's own `transact` joins instead of throwing

- **Area:** Collaboration, Durable Object server, Documentation
- **Severity:** low
- **Effort:** S
- **File:** src/lib/cloudflare/DocumentRoom.ts:833 (docs site/content/docs/server/extending.mdx:205, JSDoc :826-830, AGENTS.md:38)
- **Failure:** `if (this.transacting) return fn(this.facade)` runs before the DR-rest-1 refusal (:837). `transacting` stays true through the outer commit's cleanup, so a `facade.onChange` subscriber reacting to the room's own write joins it and writes. When that nested append fails:
  - The outer call throws the storage error, although its own write was stored and broadcast. A caller that retries writes it twice.
  - The nested call returns 'ok' for a write that heal() dropped.
  - An unconditional writer recurses until 'Maximum call stack size exceeded'.
- **Fix:** Join only while `fn` runs. For example, when `this.transacting && doc._transaction === null`, fall through to the `_transactionCleanups` refusal. Otherwise, document that changes made by the room's own `transact` are joined, and state the failed-append semantics.
- **Done when:** A gx-dr row covers a subscriber of a room-originated change, with and without a failing append, and asserts the documented outcome. extending.mdx, the JSDoc and AGENTS.md match the code.

### HX-05 — Paste at a line's start whose first line stands apart uses random ranks

- **Area:** CRDT correctness
- **Severity:** low (downgraded from medium)
- **Effort:** S for the docs route, M for the code route
- **File:** src/lib/crdt/flow.ts:205-207
- **Failure:** The wave-16 `flow.apart` branch at `o === 0` places the blocks with `c.ranksFor(parent, index, n)`, a client-id-ordered random rank. The mid-line path (:237) and the end-of-line path (:222) use source-ranked `pieceRanks`. The race: Alice pastes [ul>[one], p x] at B:0 while Bob splits the line above ('hello|world'). On 123 of 240 client-id pairs the result reads 'hello' | ul 'one' | ' world' | 'xbody text'. Two list pastes (one at P's end, one at B:0) swap on 123 of 240 pairs. The replicas converge and no text is lost. This is the same shape as the already-documented Enter-at-line-start residual, and the contract's catch-all covers it. concurrent-editing.mdx and document-api.mdx:101 do not name it.
- **Fix:** Docs route: name "a paste at the start of a line whose first line is a list, code block, divider or image" in the concurrent-editing.mdx "A new block next to a line" bullet and in document-api.mdx:101. Code route (optional): rank the placed blocks by source (`exitRanks`, or the previous sibling's end piece rank).
- **Done when:** An order-scope or cw01 sweep row pins the chosen behavior for `flow.apart` at B:0 against a split of the line above, and against a paste at P's end. The docs name the residual, or the sweep shows serial order on all pairs.

## Refuted

No finding was refuted outright. Verification narrowed these:

- **CRDT, paste-at-line-start race (HX-05):** downgraded from medium to low. At `o = 0` nothing is split. The result has the same shape and the same 117/123 split as the documented Enter-at-line-start residual, and the contract's catch-all ("every other placement takes a plain rank") covers it. The DW-01 medium was about a far more common, undocumented gesture.
- **Code, parallel helpers (HX-13):** the failure scenario is refuted. A same-tick `setAtBlockRange(list)` selecting into a just-created, unmounted item matches `caretBeside` and the documented dead-endpoint recovery. Keyboard End needs a mounted DOM, so users never see the two diverge. Switching `#shown` to `shownText` would make the range branch inconsistent with the caret branch. `placedEnd` works on `BlockSpec` JSON in the CRDT layer and cannot reuse a `Block` walker. Only the organization nit stands.
- **Behaviors, container paste (HX-10):** the paragraph example is not a mismatch, because Enter also moves the children there, and blockquote is not a container in this build. Only the callout and open-toggle cases contradict "as Enter splits".
- **API, onDeleteSelectedBlocks contract (HX-07):** the claim that "a list is never named" is overstated. That clause is about an unselected container left empty. The real drift is that a selected list's items are named and deleted, not promoted.
- **CRDT, DR-rest-3 residual:** `close(f, folded)` is skipped for a partially written plan. It affects attribution only and needs a malformed plan, so it is not a finding.
- **Durable Object server, raw `doc.on('update')` throwing listener:** it can still wedge the engine, but that is generic Yjs behavior from before this wave, so it is not counted.
