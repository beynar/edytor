`createMentionPlugin` brings Notion's people mentions. Typing `@` opens a menu of the people your app's `items(query)` answers; the text typed after `@` filters it. Picking one replaces `@query` with a `mention` atom and puts the caret after it.

```svelte title="Editor.svelte" check
<script lang="ts">
	import { Edytor, createMentionPlugin, type MentionItem } from 'edytor';

	const people: MentionItem[] = [
		{ id: 'u1', label: 'Ada Lovelace', description: 'Engineering' },
		{ id: 'u2', label: 'Alan Turing', description: 'Research' }
	];

	const mentions = createMentionPlugin({
		items: (query) =>
			people.filter((person) => person.label.toLowerCase().includes(query.toLowerCase()))
	});
</script>

<Edytor plugins={[mentions]} />
```

It is not a default plugin: list it in `plugins`, in every view of a document that holds mentions (a view without it renders the atoms as unknown inline blocks).

## Options

<TypeTable
  type={{
    items: {
      type: "(query, ctx) => MentionItem[] | Promise<MentionItem[]>",
      required: true,
      description: "The people matching the text typed after @. Return a promise to search your server: the newest query's answer wins.",
    },
    char: { type: "string", description: "The character that opens the menu. Default @." },
    item: { type: "Snippet<[TriggerItemPayload<MentionItem>]>", description: "Replace each row of the menu." },
    labels: { type: "PartialLabels<'mention'>", description: "The menu's words over the English ones: `menu` (the listbox's name, People), `searching` (Searching…) and `noResults` (No results). See Localization." },
  }}
/>

A `MentionItem` is `{ id, label, description?, avatar? }`: `id` is the person's id in your app, `label` the name shown in the menu and in the mention, `description` a line beside it in the menu (an email, a role), and `avatar` an image URL (`http:`, `https:` or a `data:` image; anything else shows the name's initial).

A search over the network:

```ts title="mentions.ts" check
import { createMentionPlugin, type MentionItem } from 'edytor';

export const mentions = createMentionPlugin({
	items: async (query) => {
		const response = await fetch(`/api/people?q=${encodeURIComponent(query)}`);
		return (await response.json()) as MentionItem[];
	}
});
```

## The mention atom

A mention is an inline block of type `mention` whose data is `{ id, label }`:

```json
{ "type": "mention", "data": { "id": "u1", "label": "Ada Lovelace" } }
```

It renders `<span class="edytor-mention" data-edytor-mention data-mention-id="u1">@Ada Lovelace</span>` and copies as plain text as `@Ada Lovelace`. Like every atom it is selected, copied and deleted as one unit ([Inline blocks](/docs/customization/inline-blocks)). The label is the one stored when it was picked: to show a current name, render your own snippet for it (`mentionInlineBlock`, see [snippet overrides](/docs/customization/inline-blocks)) that looks the person up by `data.id`.

## Behavior

The menu is a [trigger](/docs/plugins/input-rules#triggers): it opens at the start of a text or after whitespace (`ada@example.com` opens nothing), <kbd>↑</kbd>/<kbd>↓</kbd> move the highlight, <kbd>Enter</kbd> or a click picks, <kbd>Escape</kbd> closes it and keeps the text. A query that matches nobody shows "No results" (`labels.noResults`), and a space after it closes the menu. It does not open in a code block or a readonly view.

The pick is one undo step, separate from the typing before it: undo gives back `@query`. A plugin that refuses the `addInlineBlock` operation, or the removal of `@query` (a `deleteContentAtRange` step), keeps the text, with the caret after it.

The menu's listbox is named "People"; while it is open the editor's root names it and its highlighted row ([Accessibility](/docs/editor/accessibility#menus-and-popups)). Its rows show an avatar (or an initial), the name and the description; replace them with `item`.

To link pages rather than people, see [Page link](/docs/plugins/page-link).
