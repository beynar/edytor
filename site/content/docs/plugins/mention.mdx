`createMentionPlugin` brings Notion's people mentions. Typing `@` opens a menu of the people your app's `items(query)` answers; the text typed after `@` filters it. Picking one replaces `@query` with a `mention` atom and puts the caret after it. The menu is your `menu` snippet (without it, nothing shows and <kbd>Enter</kbd> still picks the first person).

```svelte title="Editor.svelte" check
<script lang="ts">
	import {
		Edytor,
		createMentionPlugin,
		type MentionItem,
		type TriggerMenuController
	} from 'edytor';

	const people: MentionItem[] = [
		{ id: 'u1', label: 'Ada Lovelace', description: 'Engineering' },
		{ id: 'u2', label: 'Alan Turing', description: 'Research' }
	];

	const mentions = createMentionPlugin({
		items: (query) =>
			people.filter((person) => person.label.toLowerCase().includes(query.toLowerCase())),
		menu
	});
</script>

{#snippet menu(people: TriggerMenuController<MentionItem>)}
	<ul {@attach people.popup}>
		{#each people.items as person, index (person.id)}
			<li {@attach people.option(index)} onclick={() => void people.pick(person)}>{person.label}</li>
		{:else}
			<li role="presentation">{people.loading ? 'Searching…' : 'No results'}</li>
		{/each}
	</ul>
{/snippet}

<Edytor plugins={[mentions]} />
```

It is not a default plugin: list it in `plugins`, in every view of a document that holds mentions (a view without it renders the atoms as unknown inline blocks).

## Customize

This replaces the `menu` snippet: the people appear as cards with a coloured badge under the caret, drawn from the controller's `items`, `index`, `popup`, `option(index)` and `pick`.

```svelte title="MentionEditor.svelte" check
<script lang="ts">
	import {
		Edytor,
		createMentionPlugin,
		type JSONDoc,
		type MentionItem,
		type Plugin,
		type TriggerMenuController
	} from 'edytor';

	// The page's document and the rest of your editor's plugins.
	let { value, plugins = [] }: { value?: JSONDoc; plugins?: Plugin[] } = $props();

	const people: MentionItem[] = [
		{ id: 'u1', label: 'Ada Lovelace', description: 'Engineering' },
		{ id: 'u2', label: 'Alan Turing', description: 'Research' },
		{ id: 'u3', label: 'Grace Hopper', description: 'Compilers' },
		{ id: 'u4', label: 'Katherine Johnson', description: 'Orbits' },
		{ id: 'u5', label: 'Margaret Hamilton', description: 'Flight software' }

		items: (query) =>
```

## Options

<TypeTable
  type={{
    items: {
      type: "(query, ctx) => MentionItem[] | Promise<MentionItem[]>",
      required: true,
      description: "The people matching the text typed after @. Return a promise to search your server: the newest query's answer wins.",
    },
    char: { type: "string", description: "The character that opens the menu, and that the atom shows before its label. Default @." },
    kind: { type: "string", description: "The inline kind the atoms are, and the menu's name (controller.trigger.name). Default mention. List the plugin once per kind to mention several things." },
    menu: { type: "Snippet<[TriggerMenuController<MentionItem>]>", description: "The menu, at the caret while it is open (without it, nothing shows). Keep its ARIA with {@attach controller.popup} on the list and {@attach controller.option(index)} on each row. See Menus and handles." },
  }}
/>

A `MentionItem` is `{ id, label, description?, avatar? }`: `id` is the person's id in your app, `label` the name shown in the menu and in the mention, `description` a line beside it in your menu (an email, a role), and `avatar` an image URL for your row (the demo's draws an `http:`, `https:` or `data:` image, else the name's initial).

A search over the network:

```ts title="mentions.ts" check
import { createMentionPlugin, type MentionItem } from 'edytor';

export const mentions = createMentionPlugin({
	items: async (query) => {
		const response = await fetch(`/api/people?q=${encodeURIComponent(query)}`);
		return (await response.json()) as MentionItem[];
	}
});
```

## Several triggers

List the plugin once per thing to mention, each with its own `char` and `kind`: `@` for people, `$` for stock tickers. Each instance defines its own inline kind and opens its own menu; typing `$` never opens the people's menu.

```svelte title="MentionsAndTickers.svelte" check
<script lang="ts">
	import {
		Edytor,
		createMentionPlugin,
		type MentionItem,
		type TriggerMenuController
	} from 'edytor';

	const people: MentionItem[] = [{ id: 'u1', label: 'Ada Lovelace' }];
	const tickers: MentionItem[] = [
		{ id: 'AAPL', label: 'AAPL', description: 'Apple' },
		{ id: 'MSFT', label: 'MSFT', description: 'Microsoft' }
	];
	const matching = (rows: MentionItem[]) => (query: string) =>
		rows.filter((row) => row.label.toLowerCase().includes(query.toLowerCase()));

	const plugins = [
		createMentionPlugin({ items: matching(people), menu }),
		createMentionPlugin({ char: '$', kind: 'ticker', items: matching(tickers), menu })
	];
</script>

<!-- One snippet for both menus: `trigger.name` is the instance's kind. -->
{#snippet menu(controller: TriggerMenuController<MentionItem>)}
	<ul
		aria-label={controller.trigger.name === 'ticker' ? 'Tickers' : 'People'}
		{@attach controller.popup}
	>
		{#each controller.items as row, index (row.id)}
			<li {@attach controller.option(index)} onclick={() => void controller.pick(row)}>
				{row.label}
			</li>
		{/each}
	</ul>
{/snippet}

<Edytor {plugins} />
```

A ticker is `{ "type": "ticker", "data": { "id": "AAPL", "label": "AAPL" } }`: it renders `$AAPL` with `data-edytor-mention="ticker"` and copies as `$AAPL`. Two instances of one `kind` follow the first-listed rule: the first defines the kind (its `char` draws and copies the atoms), and each still opens its own menu. A document read with no view (a [room](/docs/server/quick-start), a headless document) needs nothing for a custom kind: a mention is an inline atom, which takes no structural role.

## The mention atom

A mention is an inline block of type `mention` whose data is `{ id, label }`:

```json
{ "type": "mention", "data": { "id": "u1", "label": "Ada Lovelace" } }
```

It renders `<span class="edytor-mention" data-edytor-mention="mention" data-mention-id="u1">@Ada Lovelace</span>` (the attribute's value is the `kind`, so `[data-edytor-mention]` styles every kind and `[data-edytor-mention="ticker"]` one) (`data-selected="true"` while the atom is selected; the [Notion theme](/docs/customization/styling#notion-theme) draws its muted colour and its selection) and copies as plain text as `@Ada Lovelace`, and as HTML as that span (pasted back into an editor with the plugin, it is the same mention again). Like every atom it is selected, copied and deleted as one unit ([Inline blocks](/docs/customization/inline-blocks)). The label is the one stored when it was picked: to show a current name, render your own snippet for it (a plugin listed first naming `inlineBlocks: { mention: snippet }`, see [Restyling a kind](/docs/editor/edytor-component#restyling-a-kind)) that looks the person up by `data.id`.

## Behavior

The menu is a [trigger](/docs/plugins/input-rules#triggers): it opens at the start of a text or after whitespace (`ada@example.com` opens nothing), <kbd>↑</kbd>/<kbd>↓</kbd> move the highlight, <kbd>Enter</kbd> or a click picks, <kbd>Escape</kbd> closes it and keeps the text. A query that matches nobody shows your menu's empty state (no rows), and a space after it closes the menu. It does not open in a code block or a readonly view.

The pick is one undo step, separate from the typing before it: undo gives back `@query`. A plugin that refuses the `insertInline` operation, or the removal of `@query` (a `deleteText` step), keeps the text, with the caret after it.

The menu's listbox is named "People"; while it is open the editor's root names it and its highlighted row ([Accessibility](/docs/editor/accessibility#menus-and-popups)). Its rows show an avatar (or an initial), the name and the description; replace them with `item`.

To link pages rather than people, see [Page link](/docs/plugins/page-link).
