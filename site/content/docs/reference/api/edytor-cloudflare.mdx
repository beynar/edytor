## AttachedDocument

One edytor document living in a Durable Object's storage: the room
logic, independent of the class that hosts it. Create it with
`attachRoom` (any Durable Object) or extend `DocumentRoom`.
The socket handlers ignore sockets without `SOCKET_TAG` and
return `false` for them.

```ts
export declare class AttachedDocument {
    readonly ctx: DurableObjectState;
    readonly maxRowBytes: number;
    readonly maxFrameBytes: number;
    readonly compactAfter: number;
    readonly saveAfter: number;
    readonly maxDocumentBytes: number;
    readonly documentWarning: number;
    readonly maxInboundFrameBytes: number;
    readonly maxBufferedBytes: number;
    readonly maxUpdatesPerSecond: number;
    readonly maxPresenceBytes: number;

    presence: Map<number, E.AwarenessEntry>;
    refusals: Refusal[];
    refusalCounts: Partial<Record<Refusal['reason'], number>>;

        kind: 'fresh';
    } | {
        kind: 'restored';
```

- `failure`: Why the stored container was refused (another generation, a torn record, `onLoad`…).
- `presence`: Latest presence entry per replica, for join snapshots (memory: refills after a wake).
- `refusals`: The newest `MAX_REFUSALS` refusals since this instance started (diagnostics; memory only).
- `refusalCounts`: Every refusal since this instance started, by reason.
- `origin`: How this instance came to be: a fresh container, or a restore of N stored records.
- `doc`: The live document; `null` when the stored container was refused.
- `facade`: The facade over the live document.
- `transact`: Manipulate: run `fn` on the facade in one transaction.
- `read`: The document as JSON.
- `alarm`: The room's one alarm (`room.alarm.tasks`): every task due at its time runs — the history slot (`room.history.slots`), `onSave`, the purge (`room.purge.timing`) — each re-arming itself or clearing its due row; then the alarm is set to the earliest due time left.
- `reset`: Generation cutover: drop the stored document (both tables) of a room whose storage belongs to another edytor generation, and start again from `onLoad` — reseed it from JSON.
- `records`: Reassembled logical records in write order (of one kind, with `only`); a torn record throws.
- `compressed`: Resolves once the snapshot compression in flight, if any, is stored: a compaction stores its snapshot raw, then compresses it in place.
- `compact`: Compaction: the rows become the generation record + one chunked snapshot of the live document's state (the healed state, deleted content collected but the text a replica may copy again — never a merge of the records, which keeps every keystroke's struct and every deleted character), atomically, + one `pending` record of the stored deletes still waiting.
- `lastUpdated`: When the room last stored a change (ms since the epoch), or `null` for a room that stored none since it records the time.
- `historyWritten`: Resolves once the versions the room is writing are stored (a slot a write closed is written in the background).
- `listHistory`: The room's versions, newest first: one per half-day slot that changed, for the retention (`room.history.slots`).
- `readHistory`: Version `key` as JSON (a preview), or `null` when this room holds no such version.
- `restoreHistory`: Restore version `key` as a forward edit (`room.history.restore`): one room transaction makes the visible document equal the version, keeping every id the registry holds and writing only what differs; stored, relayed to every socket, one step `undoRestore` undoes.
- `undoRestore`: Undo the last restore (`room.history.undo`): the history undo of exactly its transaction, edits made since kept.
- `listComments`: Every comment thread, oldest first, with the last change's sequence number (also over RPC).
- `comment`: One comments request by `actor` (also over RPC): add a thread, reply, resolve, reopen or delete, under the rules every store applies.
- `exportBlocks`: Export blocks `ids` for a move (`room.move`, step 1): their visible subtrees as JSON, the outermost only, in document order.
- `importBlocks`: Import a move's blocks (`room.move`, step 2) under `dest.parent` at `dest.index`, as one room transaction: each keeps its id unless this document holds it already (then `<id>~<n>`).
- `commitMove`: Commit a move (`room.move`, step 3), with the destination's acknowledgement: delete the exported blocks with their subtrees, as one room transaction, and watch them for late edits (`room.move.late`) for the grace period.
- `abortMove`: Drop an export that was not committed (`room.move`): the blocks stay.
- `lateEdits`: The late edits waiting to reach their destination (`room.move.late`), oldest first.
- `ackLateEdits`: The destination applied a move's late edits through `seq`: they are dropped here.
- `applyLateEdits`: Apply a batch of late edits of a move this room imported (`room.move.late`): each block's content and data merged three ways into what it holds now (what was written here since stays), as one room transaction.
- `purge`: The purge task, also over RPC (`room.purge.timing`): record an epoch (the state vector, now) when the document changed since the last one, purge what was deleted before the horizon — the newest epoch at least `purgeAfterDays` old — when it is newer than the last purged, and re-arm for the next epoch to pass it.
- `metrics`: The room's counters, also over RPC — see `RoomMetrics`.
- `dropWaitingDeletes`: Drop every waiting delete, stored or in memory (callable over RPC): the way out when a writer filled `MAX_WAITING_DELETES` with deletes of registered ids' items, which compaction keeps.
- `closeUser`: Revoke: close every socket of `userId` (also over RPC), `4403` (`access revoked`, final for the provider) unless you pass another `code` (`4401` redials with fresh `params`; `1011` redials too).
- `setAccess`: Change `userId`'s access on its open sockets (also over RPC): `'read'` downgrades each write socket in place (the read-only notice, then every write denied, the socket stays); `'write'` closes each read-only socket `1012` (`access changed`), which its provider redials, so `authorize` grants the new access; `'none'` closes every socket `4403` (`access revoked`), as `closeUser`.
- `owns`: Is `ws` one of this document's sockets?

## attachRoom

Attach an edytor room to any Durable Object (`attachRoom(this, opts)`,
in the constructor or a field). Its tables (`edytor_rows`,
`edytor_replicas`) live beside yours and its sockets carry
`SOCKET_TAG`. Each handler your class does not define —
`fetch`, `webSocketMessage`, `webSocketClose`, `webSocketError` and
`alarm` (a socket's credential may expire) — is installed on the
object; a class that
defines one delegates to the returned document's method (which returns
`false` for a socket that is not the document's).

```ts

```

## AttachRoomOptions

What `attachRoom` (and `DocumentRoom`) takes.

```ts
export type AttachRoomOptions = {
    onLoad?: () => Promise<LoadedDocument | null | undefined> | LoadedDocument | null | undefined;
    onSave?: (document: SavedDocument) => Promise<void> | void;
    saveAfter?: number;
    compactAfter?: number;
    maxRowBytes?: number;
    maxFrameBytes?: number;
    tablePrefix?: string;
    maxDocumentBytes?: number;
    documentWarning?: number;
    maxInboundFrameBytes?: number;
    maxBufferedBytes?: number;
    maxUpdatesPerSecond?: number;
    maxPresenceBytes?: number;
    maxPresencePerSecond?: number;
    maxPresenceFanout?: number;
    validate?: (frame: FrameValidation) => boolean | void;
    locks?: LockOptions;
    rooms?: () => MoveNamespace | undefined;
    log?: ((entry: RoomLogEntry) => void) | false;
    semantics?: DocumentSemanticsConfig;
    history?: HistoryOptions;
    purgeAfterDays?: number | false;
    now?: () => number;
    comments?: CommentOptions | false;
};
```

- `onLoad`: Retrieve: the document for a room that stores nothing yet.
- `onSave`: Save: mirror the document to your own store, `saveAfter` ms after the first unsaved change, on the object's alarm (a throw is retried by the platform).
- `saveAfter`: ms between the first unsaved change and `onSave` (default `DEFAULT_SAVE_AFTER`).
- `compactAfter`: Update records before the rows are merged into one snapshot (default `DEFAULT_COMPACT_AFTER`).
- `maxRowBytes`: Largest stored row; can only be lowered (default `DEFAULT_MAX_ROW_BYTES`).
- `maxFrameBytes`: Largest frame sent whole; can only be lowered (default 32 MiB).
- `tablePrefix`: Prefix of the document's SQL tables, beside your own (default `'edytor_'`).
- `maxDocumentBytes`: Largest document, in stored bytes (default `DEFAULT_MAX_DOCUMENT_BYTES`).
- `documentWarning`: The share of `maxDocumentBytes` past which the room logs the document's size (`size`, once per crossing), above 0 and at most 1 (default `DEFAULT_DOCUMENT_WARNING`, 0.8).
- `maxInboundFrameBytes`: Largest frame a socket may send, reassembled (default `DEFAULT_MAX_INBOUND_FRAME_BYTES`).
- `maxBufferedBytes`: The chunk sequences in flight on every socket together (default twice `maxInboundFrameBytes`, never less than it): a sequence that would pass it closes its socket `1011` (`room busy`), and its provider redials.
- `maxUpdatesPerSecond`: Sync messages per second a socket may send (default `DEFAULT_MAX_UPDATES_PER_SECOND`).
- `maxPresenceBytes`: Largest presence state a socket may publish, as JSON (default `DEFAULT_MAX_PRESENCE_BYTES`).
- `maxPresencePerSecond`: Presence messages per second a socket may send (default `DEFAULT_MAX_PRESENCE_PER_SECOND`).
- `maxPresenceFanout`: Presence frames per second the room sends over all its sockets (default `DEFAULT_MAX_PRESENCE_FANOUT`).
- `validate`: Accept, then compensate: after the room applied and stored a client frame that changed blocks, it is asked whether to keep it.
- `locks`: Per-block locks (`room.locks`): a block whose data names a user under `key` (default `lockedBy`) is that user's alone — a frame from anyone else touching it is denied and compensated, as `validate`'s denials are (`lockedBlocks`).
- `rooms`: The rooms blocks move to (`room.move`): with it, the room forwards the late edits of blocks it moved out to their destination itself, on its alarm; without it, they wait for the host's `forwardLateEdits`.
- `log`: The room's log: one entry per compaction, quota hit, denial or fault.
- `semantics`: The block roles `transact` edits obey — the document semantics your clients' plugins declare (`defaultType` also names the block an empty room is seeded with).
- `history`: Version history, in the store `HistoryOptions.store` names (a KV namespace, an R2 bucket or the room's own storage): the room writes its state twice a day — the morning's at local noon, the evening's at midnight, in `timeZone` — when it changed, for `retentionDays`; read and restore them with `listHistory`, `readHistory`, `restoreHistory` and `undoRestore` (or `routeDocumentHistory`).
- `purgeAfterDays`: Days after which deleted content is purged from the room and every replica (`room.purge.*`): default the history's `retentionDays`, else 30; `false` never purges.
- `now`: The room's clock, ms since the epoch (default `Date.now`): its slots, epochs and alarm read it.
- `comments`: Comment threads (`room.comments`): kept in the room's `threads` and `comments` tables, read and written through `routeDocumentComments` (or `listComments` and `comment` over RPC), each change sent to the sockets that subscribed.

## decideComment

Decide `request` by `actor`: the one rule of every comment store.

- A read-only actor changes nothing (`read-only`).
- `add` starts a thread under an id no thread holds (`exists`), with a
  first comment; `reply` adds one to a thread (`missing` without it).
- `resolve` and `reopen` are anyone's who may write (`noop` when the
  thread already is so).
- `delete` removes one comment, its author's or a moderator's
  (`forbidden`); the first comment, or no `comment`, removes the
  whole thread, its creator's or a moderator's.

Writes nothing: the store applies the change it returns.

```ts
declare const decideComment: (request: CommentRequest, actor: CommentActor, context: CommentContext) => CommentOutcome;
```

## DocumentRoom

The ready-made room: a Durable Object hosting one document, configured
by `vars` (`DocumentRoomEnv`). Subclass it to override `onLoad` and
`onSave`, and add your own RPC methods over `transact`/`read`. Its tables
are `rows` and `replicas` (no prefix).

```ts
export declare class DocumentRoom<Env = DocumentRoomEnv> extends DurableObject<Env> {
    readonly room: AttachedDocument;
    constructor(ctx: DurableObjectState, env: Env);
    protected onLoad(): Promise<LoadedDocument | null | undefined>;
    protected onSave(_document: SavedDocument): Promise<void>;
    protected validate(_frame: FrameValidation): boolean | void;
    protected onComment(_change: CommentChange): void | Promise<void>;
    protected log(entry: RoomLogEntry): void;
    protected semantics(): DocumentSemanticsConfig;
    protected history(): HistoryOptions | undefined;
    protected locks(): LockOptions | undefined;
    protected rooms(): MoveNamespace | undefined;
    protected now(): number;
    fetch(request: Request): Promise<Response>;
    webSocketMessage(ws: WebSocket, message: string | ArrayBuffer): void;
    webSocketClose(ws: WebSocket, code: number, reason: string): void;
    webSocketError(ws: WebSocket): void;
    alarm(): Promise<void>;
    listHistory(): Promise<HistoryEntry[]>;
    readHistory(key: string): Promise<JSONDoc | null>;
    restoreHistory(key: string, options?: {
        user?: string;
    }): Promise<RestoreResult>;
    undoRestore(options?: {
        user?: string;
    }): Promise<{
```

## HistoryStore

Where a room keeps its versions (`room.history.store`). Any object with
these members works; the room owns everything else: the keys (one room's
share a prefix), the values (compressed bytes, at most `maxValueBytes`),
the metadata, and the retention — it never lists or reads a version past
its `expiresAt`, and, unless the store expires values itself
(`nativeTtl`), its alarm deletes each one when it expires.

```ts
export type HistoryStore = {
    readonly maxValueBytes: number;
    readonly nativeTtl?: boolean;
    put(key: string, value: Uint8Array, options: {
        expiresAt: number;
        metadata: HistoryMetadata;
    }): Promise<void>;
    get(key: string): Promise<{
        value: Uint8Array;
        expiresAt: number | null;
    } | null>;
    list(prefix: string, cursor?: string): Promise<{
        entries: HistoryStoreRecord[];
        cursor?: string;
    }>;
    delete(key: string): Promise<void>;
};
```

- `maxValueBytes`: The largest value the store takes: a larger version is skipped (logged `history`), never split.
- `nativeTtl`: The store deletes a value at its `expiresAt` itself (KV's TTL): the room's alarm never deletes.
- `put`: Store `value` at `key` (replacing any value there) with its expiry and metadata.
- `get`: The value at `key`, with its expiry when the store knows it, or `null`.
- `list`: One page of the keys starting with `prefix`; `cursor` continues a listing, and is absent on its last page.
- `delete`: Delete `key` (a missing key is no error).

expiry. `maxValueBytes` (default `ROOM_HISTORY_MAX_VALUE_BYTES`)

## RoomMetrics

The room's counters, since this instance started (memory: a wake
starts them again), read with `metrics()` (also over RPC). Times are
what the runtime's clock reports: Workers advance it only across I/O, so
in production synchronous work (a compaction, a fold) often reads `0`;
sizes and counts are exact.

```ts
export type RoomMetrics = {
    documentBytes: number;
    documentLimit: number;
    storedBytes: number;
    records: number;
    rows: number;
    updateRecords: number;
    waitingBytes: number;
    sockets: number;
    buffered: {
        sequences: number;
        bytes: number;
    };
    compaction: Timing & {
        lastBytes: number;
    };
    fold: Timing;
    fanOut: {
        messages: number;
        bytes: number;
    };
    quotaHits: number;
    validationDenials: number;
    refusals: Partial<Record<Refusal['reason'], number>>;
    history: {
        written: number;
        skipped: number;
        lastKey: string | null;
    };
    purge: PurgeReport & {
        runs: number;
        horizon: number | null;
    };
    since: number;
};
```

- `documentBytes`: The document's size as the document quota measures it: its records, uncompressed.
- `documentLimit`: The document quota (`maxDocumentBytes`): writes past it are refused (`4413`).
- `storedBytes`: What its rows take in storage (a snapshot compressed).
- `records`: Logical records stored (the generation record included), and their rows.
- `updateRecords`: Update records since the last compaction (compaction runs at `compactAfter`).
- `waitingBytes`: Bytes of updates held waiting for a dependency (in memory, never stored).
- `sockets`: The document's open sockets.
- `buffered`: Chunk sequences in flight on every socket, and the bytes buffered for them (`maxBufferedBytes`).
- `compaction`: Compactions run, with their time.
- `fold`: Client sync frames folded (applied, indexed, stored and relayed), with their time.
- `fanOut`: Frames sent to other sockets (relays, presence, acknowledgements to others), and their bytes.
- `quotaHits`: Writes refused by a quota (`quota` refusals) and frames `validate` denied.
- `refusals`: Every refusal, by reason (as `refusalCounts`).
- `history`: Versions written to the history, skipped (`history` refusals), and the last key written.
- `purge`: Purges run and what they wrote, summed; the last horizon purged (ms since the epoch).
- `since`: When this instance started (ms since the epoch).

## routeDocumentComments

The host Worker's door to a document's comment threads, authorized as
`routeDocumentSocket` authorizes a dial, forwarding only the
verified identity:

- `GET <url>` → every thread and the last change's sequence number
  (`{ seq, threads }`), as JSON;
- `POST <url>` with a JSON body (`{ op: 'add' | 'reply' | 'resolve' |
  'reopen' | 'delete', thread, … }`) → what it did (`{ status:
  'applied', change }` or `{ status: 'noop', thread }`), as the
  verified user.

A refusal is an HTTP status: `400` (an invalid document id or request),
`401` (`{ expired: true }`), `403` (denied, a read-only identity's
write, another user's comment, an `Origin` that `options.allowedOrigins`
does not list), `404` (no such thread or comment, or the room keeps no
comments), `405` (another method), `409` (a thread or comment id taken),
`413` (a body over 64 KiB, too many threads or comments, or the room's
comment bytes full), `429` (the user past the room's comment rate).

```ts
export declare function routeDocumentComments(request: Request, rooms: DocumentNamespace, documentId: string, authorize: AuthorizeDocumentSocket, options?: RouteDocumentOptions): Promise<Response>;
```

## routeDocumentHistory

The host Worker's door to a document's version history,
authorized as `routeDocumentSocket` authorizes a dial, forwarding
only the verified identity:

- `GET <url>` → the versions, newest first (`listHistory`), as JSON;
- `GET <url>?key=<key>` → that version as JSON (`readHistory`), `404` when
  the room holds none;
- `POST <url>?restore=<key>` → restore it as a forward edit
  (`restoreHistory`, as the verified user), `404` when the room holds none;
- `POST <url>?undo` → undo the last restore (`undoRestore`).

A refusal is an HTTP status: `400` (an invalid document id), `401`
(`{ expired: true }`), `403` (denied, or a read-only identity's
restore, or an `Origin` that `options.allowedOrigins` does not list),
`404` (the room keeps no history), `405` (another method).

```ts
export declare function routeDocumentHistory(request: Request, rooms: DocumentNamespace, documentId: string, authorize: AuthorizeDocumentSocket, options?: RouteDocumentOptions): Promise<Response>;
```
