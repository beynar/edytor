## 3) Open units of work

Several findings were reported by more than one area. Each such pair is merged into one unit below. Each area still counts its own copy in its score.

### GX-01: A paste whose last line renders no content hides the rest of the host line

- **Area:** Editing behaviors
- **Severity:** high
- **Effort:** M
- **File:** `src/lib/crdt/flow.ts:140` (the mirror case for a first or only line is at `:128-133`)
- **Failure:**
  - `flow.split` makes the last pasted line the tail, `tail = lastType ? {type: lastType, ...} : c.tailOf(B)`. It never checks `rendersContent`, void or island.
  - Internal copy of `hello…two` from `[p hello, ul>[one,two], p 'keep this tail']`, pasted at `keep|`, gives `unordered-list(content ' this tail') > [one, two]`. The text ` this tail` is stored and synced but not shown.
  - HTML `<p>x</p><hr>` or `<p>x</p><pre><code>…</code></pre>` pasted at `hello| world` hides ` world` inside the divider or code block.
  - `flow.inline` has the same gap for a first or only line. `<hr>` alone is dropped. `<pre><code>` alone becomes a nested paragraph and loses the code kind.
  - After the list and code pastes, the caret lands at the first item instead of after the pasted content.
  - The defect predates wave 15 (flow.ts is unchanged since 9b31c14). Undo recovers the text.
- **Fix:**
  - When the last line's kind renders no content, or is void or an island, place that line as a middle block and use `c.tailOf(B)` for the tail, as Enter does.
  - Place a first or only line of such a kind as a block after the head, splitting B when `o < len`, instead of joining it into B.
  - Amend `flow.inline` and `flow.split` in `docs/editor-delete-contract.md`.
- **Done when:** DOM rows exist for list, code block and divider as the first, the last and the only pasted line, both mid-line and at the end of a line. The rows cover both the internal-fragment and HTML paths. Each row asserts that no block rendering no content holds text, that the kind is kept, and that the caret lands after the pasted content.

### GX-02: A list's own handle selects the container alone, so delete, cut and Mod+B go wrong

- **Area:** Editing behaviors
- **Severity:** medium
- **Effort:** M
- **File:** `src/lib/clipboard/createClipboardFragment.ts:99` (`nestMembers` at `:52`); `src/lib/plugins/blockHandles/BlockHandleController.svelte.ts:115`
- **Failure:**
  - A list container is movable, so it gets a handle. Clicking the handle gives `selectBlocks(L)`, which is L alone (`sel.blocks.exact`).
  - Backspace, Delete, the block menu's Delete and cut all give `[p 'one', p 'two', …]`: the bullets are gone and the items become paragraphs.
  - The cut fragment is `{blocks:[{type:'unordered-list'}], whole:true}`, with empty text/plain and `<ul></ul>` as HTML, so cut-and-paste does not move the list.
  - Mod+B formats nothing.
  - Navigation, Escape and Enter treat the same selection as the list's items (selection.mdx), so the behavior is inconsistent.
  - No text is lost, and one undo restores the list.
- **Fix:** Either the handle selects the container together with its items, or delete, copy, cut and `rangeCovers` expand a selected container (`isContainer`) to its subtree. State the rule in `sel.blocks.exact`.
- **Done when:** DOM rows over a grip-selected list pass for Backspace, Delete, cut plus paste elsewhere (the list moves intact) and Mod+B (the items are bolded).

### GX-03: `selectBlocks()` and `setAtBlockRange()` collapse over a list or code block and drop a leading divider

- **Area:** Code organization (low) and API ease of use (low); one defect reported twice
- **Severity:** low
- **Effort:** S
- **File:** `src/lib/selection/selection.svelte.ts:1319` (`#contentRange`), `:218-219` (`edgeText`), `:449-460` (`#shown`)
- **Failure:**
  - `edgeText` falls back to the hidden `content[0]` slot. `#shown` then moves both endpoints with the same rule, `caretBeside(blockAfter)`.
  - `setAtBlockRange(L)` gives the collapsed caret `i1:0…i1:0`, although selection.mdx says it gives "a range over the whole block".
  - `selectBlocks(a, L)` then `selectBlocks()` gives `a:0…i1:0`, which covers neither item.
  - `selectBlocks(d, after)` over a divider gives `after:0…after:5`, so the divider is no longer covered and survives a Backspace.
  - No built-in flow reaches this; only host code calling these public setters does.
- **Fix:**
  - Build `#contentRange` from `shownText(first,'first')` and `shownText(last,'last')`.
  - Make endpoint relocation depend on the endpoint's role: the start takes the subtree's first shown line and the end its last. Voids pass to their neighbours, as `move()` does.
  - Delete `edgeText`, and keep the current value when no line is shown.
- **Done when:**
  - `setAtBlockRange` over a list and over a code block returns a range across its items or lines.
  - Leaving a block selection of `[p, L]` spans L's items.
  - A void-led set still covers the void.
  - The JSDoc at `:1326-1327` and selection.mdx:76-78 agree with the result.

### GX-04: The FX-08 fix misses a composition range inside one block that crosses an inline atom

- **Area:** Code organization
- **Severity:** low
- **Effort:** S
- **File:** `src/lib/session/composition.svelte.ts:160`
- **Failure:**
  - `#across = shown === 'text' && startText?.parent !== endText?.parent` is false when both ends are in the same block, so `pin.merge` never refreshes `parts`.
  - Real Chromium: in `['first', @mention, 'last']`, select `fi[rst @ la]st` and compose. The screen shows `fiに@mention falsest` while the model holds `fiにst`.
  - The screen stays stale until commit or cancel, which contradicts the SW14-ime-1 claim that the screen equals the document at every step.
  - The divergence is visual only: the model is always correct.
- **Fix:** Change the check to `this.#across = shown === 'text' && startText !== endText`.
- **Done when:** A third CDP row sits next to the two FX-08 rows in `tests/editor-dom/ime-baseline.cdp.spec.ts`, for a range inside one block across an atom. It asserts that textContent equals `fi${step}st` at every composition step.

### GX-05: The public `moveBlocks` `out` and `unNestBlocks` reorder non-adjacent siblings, and the public docs do not say so

- **Area:** CRDT correctness (low) and Documentation (low); one defect reported twice
- **Severity:** low
- **Effort:** S
- **File:** `site/content/docs/editor/commands.mdx:170-182`; `document-api.mdx:88`; `src/lib/session/moves.ts:98-107`
- **Failure:**
  - `unNestBlocks(['a','c'])` on `[p, ul>[a..e], q]` gives `p|b|a|c|d|e|q`: the unselected b now reads before a.
  - Shift+Tab avoids this by splitting the selection into runs (`bindings.ts:138-148` `moveRoots`). The public command does not.
  - commands.mdx's own example passes `[...selectedBlocks]`, which can be non-contiguous. Only the internal contract (`:604-608`) states the reorder.
  - Per verification, `in` gathers non-adjacent groups the same way.
- **Fix:**
  - Docs route: add one line to commands.mdx under the direction table and to the unNestBlocks row in document-api.mdx. It should say that a direction group lands together, so unselected siblings between the moved blocks end up on one side, and that callers wanting the Tab and Shift+Tab behavior call once per run of adjacent siblings.
  - Code route (preferred): have `moves.ts place()` group into runs with `dispatcher.each`, as `moveRoots` does.
- **Done when:** Either the docs state this and a docs-drift phrase guards it, or the public command matches the keys. In both cases a row pins `[a,c]` out on `[a..e]`.

### GX-06: The block-selection navigation docs over-claim the macOS Ctrl keys, and hotkeys.mdx has an ambiguous parenthetical

- **Area:** API ease of use (low) and Documentation (low); one defect reported twice
- **Severity:** low
- **Effort:** S
- **File:** `site/content/docs/editor/selection.mdx:121`; `site/content/docs/customization/hotkeys.mdx:71`
- **Failure:**
  - Ctrl+B and Ctrl+F map to `'char'`, and `move()` returns false for `char` over a block selection (`navigation.ts:120`). The block stays selected, and the next typed key replaces it.
  - No `ctrl+` chord has a Shift variant (`navigation.ts:372`), yet the docs say the selection "grows with Shift".
  - hotkeys.mdx:71 reads as if a list's items are excluded, but End over a grip-selected list lands in its last item.
- **Fix:**
  - selection.mdx: name only Ctrl+A and Ctrl+E, with no Shift variant.
  - hotkeys.mdx: reword to "for a block with no line of its own (a list, a code block), its first or last nested line; never a divider".
- **Done when:** Both pages are corrected and a docs-drift phrase guards the Ctrl wording.

### GX-07: A throwing `edytor.transact` keeps its writes but skips normalization, and the docs do not say so

- **Area:** Documentation
- **Severity:** low
- **Effort:** S
- **File:** `site/content/docs/concepts/editor-instance.mdx:46`; `commands.mdx:146`; `customization/blocks.mdx:245`; code at `src/lib/edytor.svelte.ts:298-300`
- **Failure:**
  - `catch { this.dispatcher.drain(false); throw }` drops the queued normalizers.
  - Repro: `setBlock` followed by a throw leaves `normalizeContent` called 0 times, and `{y:2}` stays committed and synced.
  - This contradicts blocks.mdx's "peers never see the unnormalized state".
- **Fix:** State in all three pages that on a throw the earlier writes are kept without the normalization they requested. The alternative is to drain before rethrowing.
- **Done when:** A docs-drift phrase and a DOM row pin the chosen behavior.

### GX-08: `<Edytor server room actor>` names its local store from the raw `server` string

- **Area:** Collaboration
- **Severity:** low
- **Effort:** S
- **File:** `src/lib/components/Edytor.svelte:215`
- **Failure:**
  - Only the branch without an actor strips trailing slashes. The factory (`providers/index.ts:165-168`), the socket and the BroadcastChannel all normalize.
  - `wss://x/rooms/` and `wss://x/rooms` therefore open two different IndexedDB stores.
  - If an app changes the slash between releases, offline edits the room has not stored are stranded in the old store, and `clearDocument` can miss the store.
- **Fix:**
  - Compute `const base = server.replace(/\/+$/, '')` once and use it in both branches.
  - Say in persistence.mdx:36 that trailing slashes are removed. Optionally normalize the websocket.mdx:127 example.
  - Ship a migration note, because the fix itself renames the store for existing apps whose `server` prop has a trailing slash.
- **Done when:** A room-props row checks that an actor with a trailing-slash server resolves to the same store name as the same server without the slash, and the docs match.

### GX-09: After one failed direct `facade` write, later direct writes are silently dropped too

- **Area:** Durable Object server
- **Severity:** low
- **Effort:** S
- **File:** `src/lib/cloudflare/DocumentRoom.ts:1262` (update handler early return); `:809` (`facade` getter, which does not heal)
- **Failure:**
  - After a failed append, `unstored` stays set until the next `heal()` entry point.
  - Probe: RPC 1 writes A with the fail trigger on. RPC 2 writes B on healthy storage. Live content is `BAhello`, stored content is `hello`, and B raised no error.
  - extending.mdx:205 describes only the one failed write as dropped.
  - Writing through `transact` avoids this, since it heals first.
- **Fix:** Call `heal()` in the `facade` getter when not `transacting`. The alternative is to document that every later direct write is dropped until the room next serves or reads.
- **Done when:** A tests/do row runs a failed direct write followed by a direct write on healthy storage. It asserts that the second write is stored and broadcast, or, on the docs route, that it is dropped as documented.
