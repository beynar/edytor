`arrowMovePlugin` moves a block selection with the keyboard: <kbd>Mod</kbd> + <kbd>↑</kbd> moves the selected blocks up one step, <kbd>Mod</kbd> + <kbd>↓</kbd> down one step. <kbd>Mod</kbd> is <kbd>Cmd</kbd> on macOS and <kbd>Ctrl</kbd> elsewhere.

```svelte
<script lang="ts">
	import { Edytor, arrowMovePlugin, richTextPlugin } from 'edytor';
</script>

<Edytor plugins={[arrowMovePlugin, richTextPlugin]} />
```

It takes no options.

## Behavior

The keys act only while whole blocks are selected, for example after clicking a block handle or pressing <kbd>Mod</kbd> + <kbd>A</kbd> until the block is selected. With a text caret they keep their default meaning: moving the caret to the start or end of the document.

| Keys                          | Move                                                                       |
| ----------------------------- | -------------------------------------------------------------------------- |
| <kbd>Mod</kbd> + <kbd>↑</kbd>   | Before the previous sibling; from a first child, before the parent         |
| <kbd>Mod</kbd> + <kbd>↓</kbd>   | After the next sibling (never into its children); from a last child, after the parent |

- A group of selected siblings moves together, in document order. Selected blocks that are not siblings do not move.
- The moved blocks stay selected, so you can press the key again.
- A move never nests a block. To nest or outdent, use <kbd>Tab</kbd> and <kbd>Shift</kbd> + <kbd>Tab</kbd>, or a block handle's <kbd>Alt</kbd> + <kbd>→</kbd> and <kbd>Alt</kbd> + <kbd>←</kbd> (see [Block handles](/docs/plugins/block-handles#keyboard-moves)).
- Each move is one undo step, and it runs as a `moveBlock` or `moveBlocks` operation that plugins can refuse.

The plugin calls `edytor.moveBlocks({ blocks, direction })`, the same command block menus use. See [Commands](/docs/editor/commands).
