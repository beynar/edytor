# Re-score 2 — edytor (arch-v2)

This re-score follows four waves of fixes. Every NW unit from re-score 1 (NW-01 to NW-11) is resolved in code and pinned by tests. The Durable Object area went from 3.5 to 4.7, Behaviors from 3.0 to 4.3, and API from 4.0 to 4.7.
Three confirmed mediums remain:
- the display-only island reset (CRDT)
- a slash followed by a space that hijacks Enter (counted in both Code and Behaviors)
- the build-from-source path that clones master at 0.0.11 (Docs; the verifier raised it from low to medium)

Two areas moved down. CRDT goes from 4.4 to 4.3 because wave 4 introduced its medium. Docs goes from 4.5 to 4.3 because of the raised install-path finding.
Two of the reviewers' mediums were lowered to low on verification: 4401 seeding in CRDT and the build path's opposite, none. Two findings were refuted. The mean across the seven areas is 4.47. Four areas are still below 4.5.

### How each score was reached

Each score starts from the band for the verified findings, then applies the reviewer's adjustment only if its reason still holds after verification.

- **Collaboration: band 4.7, adjustment -0.1, final 4.6.** All 5 findings are lows. The -0.1 was argued for doc accuracy, and its reason still holds. Two confirmed lows break the rule documents.mdx:91 states, that a refusal never seeds (RW-05, RW-06). Two pages still describe the pre-NW-01 replica refusal (RW-16).
- **Durable Object: band 4.7, adjustment 0, final 4.7.** 3 lows. No adjustment was argued.
- **Code: band 4.3, adjustment +0.1, final 4.4.** 1 medium and 2 lows; the Mod+D low was refuted. The +0.1 reason still holds. The medium is query-matching logic in the slash controller that the Behaviors area shares, not a code-organization defect. The dispatcher undo policy is now one tested, documented table.
- **Behaviors: band 4.3, adjustment 0, final 4.3.** 1 medium and 1 low; the /divider low was refuted. No adjustment was argued.
- **API: band 4.7, adjustment 0, final 4.7.** 3 lows. The attachDocument low was narrowed to a docs example but is still confirmed. No adjustment was argued.
- **Docs: band 4.3, adjustment 0, final 4.3.** The verifier raised the build-from-source finding from low to medium, which leaves 1 medium and 5 lows. The reviewer argued no adjustment.

Some findings are counted in more than one area, because each reviewer reported them separately: the spaced slash, 4401 seeding, refusal release and seeding, the replica docs, and semanticsOf. Below they are merged into single units of work.

## Open units of work

Units are ordered most severe first.

### RW-01 — The island reset only changes the display: retyping a promoted block does nothing, moving it shows codeLine again, and island merges skip the reset
- **Area:** CRDT correctness
- **Severity:** medium
- **Effort:** M
- **Location:** `src/lib/crdt/text/runs.ts:497` (also `src/lib/crdt/placement/model.ts:456` and `src/lib/crdt/edytor-doc.ts:1660`)
- **Failure:** Ada deletes a code block, or merges it with Backspace or Delete, while Bob adds a line to it. Four things then go wrong, all reproduced:
  - `setBlockType` on the promoted block returns `applied`, but nothing changes on screen.
  - Moving it, pressing Tab or dragging it shows the stored `codeLine` outside any code block.
  - When the island is merged, the reset never happens and the result is `P:paragraph[L2:codeLine]`.
  - `splitBlock` without a tail copies the stored `codeLine`.
- **Fix:**
  - In `displaySlotOf`, also set `reset` for an island owned through a merge (`owner !== parent`).
  - Show the override only while the stored type is still the island's default child.
  - Write TYPE in facade operations that re-home or split a reset block (moveBlocks, nest/unnest, splitBlock without a tail).
  - Make the default tail in splitBlock use `blockTypeOf`.
  - Document the rule in the delete contract and in concurrent-editing.mdx.
- **Done when:** p1 rows for retype, move, Tab, split and "merge while a peer adds a line" converge to a correct type, and undoing the delete still restores `codeLine`.

### RW-02 — A slash followed by a space keeps the slash menu open, so Enter converts the block and erases text
- **Area:** Editing behaviors and Code organization
- **Severity:** medium
- **Effort:** S
- **Location:** `src/lib/plugins/slashMenu/SlashMenuController.svelte.ts:17` (also :20-28 and :199-205)
- **Failure:** Typing any of these and then pressing Enter converts the block:
  - "yes / no" becomes a callout.
  - "1 / 2" becomes a Heading 2.
  - "a / b" becomes a bulleted list.
  - "w / o" becomes a numbered list.
  - "yes / " and "x /-" swallow Enter and delete the slash text.

  Undo recovers each case. A longer following word such as "A / B testing" does not trigger it.
- **Fix:**
  - Close the menu, or never match, when whitespace directly follows the `/`.
  - Stop trimming leading whitespace from the query.
  - Treat a query that normalizes to empty (but was not empty) as no match.
- **Done when:** notion-parity rows for "yes / no", "1 / 2", "a / b", "yes / " and "x /-" followed by Enter keep the text, add a paragraph, and leave the menu closed.

### RW-03 — The documented build-from-source path clones GitHub master (0.0.11), and the edit links return 404
- **Area:** Documentation
- **Severity:** medium (raised from low on verification)
- **Effort:** S
- **Location:** `site/content/docs/getting-started/index.mdx:44`, `README.md:36-38`, `site/blume.config.ts:17-20`
- **Failure:** Until the package is published, building from source is the only install path. Its `git clone` has no branch, so it builds master at 0.0.11. The README's hard-coded `pnpm add ../edytor/edytor-0.1.0-next.0.tgz` fails, and following the site's advice to use the printed file name silently installs the incompatible 0.0.11. The "Edit this page" links point to `master:site`, which does not exist.
- **Fix:**
  - Push the arch-v2 branch and add `-b <branch>` to both clone commands, or merge to master first.
  - Point blume `github.branch` at the pushed branch until the merge.
  - Optionally, add a drift row that requires `-b` while the version is `-next` and master lags.
- **Done when:** a fresh clone following the README and the site produces `edytor-0.1.0-next.0.tgz`, and the edit links resolve.

### RW-04 — Expired credentials (4401) on a first visit let the readiness bound seed `value`, which then merges into the room
- **Area:** CRDT correctness and Collaboration
- **Severity:** low (the CRDT reviewer rated it medium; the verifier lowered it)
- **Effort:** S
- **Location:** `src/lib/crdt/providers/index.ts:184` (armBound, :158-185), `src/lib/crdt/providers/websocket.ts:86-87`
- **Failure:** An empty first visit (with persist:false or an empty IndexedDB) and an expired token turn the document `local` with the draft after about 2.4 s. Once the token refreshes, the document reads `['draft','room']`. The seed is non-undoable. It only shows when the client's `value` differs from the room's origin seed. A 4403 at the same point correctly never seeds.
- **Fix:**
  - Do not arm the bound on a 4401 close before the first sync, or feed 4401 into the same hold `_refusals` uses until that target syncs or is released.
  - Document that an expired token without a refresh leaves an empty document pending.
- **Done when:**
  - A readiness-bound row passes: 4401 for 3 s leaves the document pending, then an accepted dial is `hydrated` with only the room's content.
  - persistence.mdx:58 and the websocket.mdx 4401 row state the rule.

### RW-05 — A view mounted after a refusal seeds the refused, empty injected document
- **Area:** Collaboration (also the second half of the CRDT refusal low)
- **Severity:** low
- **Effort:** S
- **Location:** `src/lib/components/Edytor.svelte:192` (onMount at :188-193), `src/lib/crdt/document.ts:678`
- **Failure:** In `<Edytor document={doc}>` mounted after a 4403/4409/1008, onMount sees `!syncPending` and calls `document.sync(value)`. The document becomes `local` and editable, which breaks the documented rule that a refusal never seeds. With a local store attached, the seed can merge into the room later.
- **Fix:** Add `&& edytor.document.syncRefusal === undefined` to the onMount guard. An alternative is to route the view's decision through `_decide`.
- **Done when:** a DOM row mounts a view after a SyncRefusedError and the document stays `pending`.

### RW-06 — Releasing a refused provider next to a settled one leaves the empty document pending forever
- **Area:** Collaboration and CRDT correctness
- **Severity:** low
- **Effort:** S
- **Location:** `src/lib/crdt/document.ts:977`
- **Failure:** `release` calls `decide()`, which is `settle() && _decide()`. `settle()` already returned true at refusal time, so `_decide` never runs. With a settled companion provider (for example a separate createIndexeddbSync), the document ends in `{pending, syncRefusal: undefined, syncPending: false}`. That contradicts documents.mdx:91 and websocket.mdx:179.
- **Fix:** In `release`, when a refusal was deleted and at least one provider remains, call `this._decide(opts.value)`. Then reconcile the zero-provider case: the existing test expects `pending`, so either keep that behavior and reword the docs, or change the test.
- **Done when:** a readiness-bound row ("refused + settled companion, release the refused one → local") passes, and the docs match the chosen zero-provider behavior.

### RW-07 — The 10 s connect timeout seeds a slow cold room, while three pages promise an unlimited wait

### RW-08 — A second transient read fault after a rebuild, or one at cold start, makes the room refuse every client with 1008 for good
- **Area:** Durable Object server
- **Severity:** low
- **Effort:** S
- **Location:** `src/lib/cloudflare/DocumentRoom.ts:984` (start at :482-491, load at :652/:687)
- **Failure:** The retry path runs `start()`, which calls `load()` with `retryable=false`. A second read fault goes to `fail(error, false)`, and every dial then gets `1008 refused: container` until the object is evicted. That contradicts room.mdx:41.
- **Fix:** Pass `retryable` into `start()` when it re-runs from fetch or reset, or classify errors in `load()`: GenerationMismatchError and torn records are terminal, anything else is retryable.
- **Done when:** a workerd test with `failures = 2` gets 1011 and then recovers on a healthy dial.

### RW-09 — A persistent append or engine fault makes the affected clients redial about every 100 ms, with a full rebuild each time
- **Area:** Durable Object server
- **Severity:** low
- **Effort:** M
- **Location:** `src/lib/cloudflare/DocumentRoom.ts:802` (recover/fault at :788-809), `src/lib/crdt/providers/websocket.ts:216-219, :291-297`
- **Failure:** The trigger is a quota-exhausted SQLite store or bytes that decode but make the engine throw. Each provider holding edits the room lacks syncs, gets 1011 and redials after 100 ms, about 10 times a second, because hearing the room's Step2 resets the backoff. Each cycle serves a full Step2 and rebuilds from rows. There is no terminal signal and no `unreachable` event. Presence flickers for the other users.
- **Fix:** Reset the backoff only after an acknowledged save or a stable interval, and/or close with a distinct code after N identical faults on the server.
- **Done when:** a test with a permanent append trigger asserts that the dial count stays bounded.

## Refuted

- **Mod+D interleaves the copies (Code):** this is intended. The code comment, block-menu.mdx:90 and the editing-lows test all specify each copy after its own block. Grouping the copies would be a product decision.
- **/divider in an empty callout replaces the container (Behaviors):** this follows the documented rule that "a replacing kind converts in place only a block that holds nothing" (blocks.mdx:206, slash-menu.mdx:53, s6-kinds rows). One undo recovers it.

## Unresolved items

- **CRDT: "promoted children keep container-only kinds" (placement/model.ts:433).** Only partly fixed. The reset works only on display and misses the merge case. Tracked as RW-01.
- **CRDT: wellFormed/corpus note.** The corpus runner configures no roles (runner.ts:962), so void and island paths are never fuzzed. The p1 client ids sit inside the seed band. Not a defect in itself, but it is why RW-01 was not caught. Add roles to the corpus and move the p1 ids above 2^26.
- **Collaboration: DX refusal prop on `<Edytor>`.** This was optional and was not added. Component users must use `bind:edytor` to reach `syncRefusal` and `onSyncRefused`, and nothing surfaces `expired`. See RW-19.
- **API: two attachDocument exports, and the headless example omits semantics.** Unchanged. On verification the name clash is by design, and the docs example is what remains (RW-20).
