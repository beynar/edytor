The built-in chrome follows Notion: the slash menu, the mention and page link menus, the block menu, the selection toolbar and its link card, the menu a pasted URL opens, the image toolbar, the empty image and media blocks, a table's grips, menus and `+` bars, a code block's header and language list, the equation editor, the comment cards, the suggestion bar, the version history rows, the block handles and the marquee's rectangle. Each one takes a snippet that renders your markup instead. The plugin keeps the behavior: when the UI opens, where it is placed, the keys it claims, the commands it runs. Your markup keeps the keyboard and the ARIA of the built-in one through a few attachments the controller hands you.

## The pattern

Every element is customized the same way:

- **Where.** A snippet option in the plugin's factory options (`createBlockMenuPlugin({ menu })`), or a prop of the component (`<HistoryPanel item>`).
- **Naming.** A whole surface is named by what it is: `menu`, `toolbar`, `card`, `bar`, `empty`, `header`, `panel`, `box`; a control by what it is: `grip`, `add`. One row of a list is always `item`.
- **Typing.** A snippet takes one object argument whose type is exported from `edytor`: `Snippet<[BlockMenuController]>`, `Snippet<[SlashMenuItem]>`. A whole surface receives its controller: its state, its actions, its words (`labels`), `readonly`, and a way to close it. A row receives the shape every list shares, `MenuItemPayload`: `{ item, id, label, selected, run, select, option }`.
- **Accessibility.** The keyboard and the ARIA live on the controller as [attachments](https://svelte.dev/docs/svelte/@attach), never in the built-in markup only. The built-in markup uses the same attachments, so a snippet that uses them behaves exactly as it does.

| Attachment | Put it on | What it does |
| --- | --- | --- |
| `{@attach controller.popup}` | The list (`listbox` or `menu`), or the toolbar | Gives the element its id, and its role and name unless you set them; keeps the focus where it is on a press; publishes the popup to the editor's root (`aria-controls`, `aria-haspopup`, `aria-activedescendant` when the root holds the keyboard) while it is in the page, and withdraws it when it goes |
| `{@attach controller.keys}` | The element that holds the keyboard: the block menu's or the `+` menu's field, the toolbar, a table's grip menu, the code language list's search field | Takes the menu's keys (arrows, <kbd>Home</kbd>, <kbd>End</kbd>, <kbd>Enter</kbd>, <kbd>Escape</kbd>, …), focuses the element when it mounts, and makes it name the list and its highlighted row |
| `{...controller.option(index)}` | Each row | Its id, `role`, `aria-selected` (or `aria-checked`), `tabindex="-1"`, `data-selected`, and scrolls the keyboard's row into view. A row payload carries it as `option` |
| `{@attach controller.flyoutMenu}` | The block menu's open flyout | Its id, role, name and placement beside the menu |
| `{@attach controller.linkField}` | The toolbar's link field | Its id (unique per editor, for a `label`'s `for`), the focus when the panel opens, <kbd>Enter</kbd> applies, <kbd>Escape</kbd> closes |
| `{@attach controls.bar}`, `{@attach controls.altField}` | The image toolbar and its alt field | The toolbar's role and name; the alt field's focus, keys, and closing when the focus leaves |
| `{@attach empty.field}` | An empty block's link field | <kbd>Enter</kbd> embeds the link |
| `{@attach payload.grip}` | A table's row or column grip | The drag (the row or the column moves where it is dropped), the click that opens its menu, <kbd>↓</kbd> opens it too and <kbd>Escape</kbd> gives the keys back to the editor; its name, `aria-haspopup`, `aria-expanded` and `aria-controls` |
| `{@attach header.button}` | A code block's language button | Opens the language list on a click, <kbd>↓</kbd> or <kbd>↑</kbd> (<kbd>Alt</kbd>+<kbd>F10</kbd> at a caret in the block reaches it), <kbd>Escape</kbd> gives the keys back to the code; its name, `aria-haspopup`, `aria-expanded` and `aria-controls` |
| `{@attach editor.field}` | The equation editor's source field | The focus when the editor opens, the caret at the end; <kbd>Enter</kbd> and <kbd>Escape</kbd> close the editor (<kbd>Shift</kbd>+<kbd>Enter</kbd> is a newline in a block equation), and so does the focus leaving the panel |

Two rules hold for every snippet:

- **Keep the selection.** A press on a menu must not move the caret. `popup` cancels the `mousedown` of every press in its element but on a field; on anything else that acts on the text (a `+`, a button outside the list), call `preventDefault` on `mousedown`. The toolbar's host does it for every press but in a field.
- **Mark the element to place** when it is not your snippet's first element: the block menu measures `[data-edytor-block-menu]`; the toolbar's `popup` marks the bar `data-edytor-toolbar-bar` for you.

Each factory also takes `labels`, the words of its built-in markup, which its controller carries for yours (`controller.labels`): see [Localization](/docs/customization/localization). Your markup renders in the plugin's host without the built-in styles. `slashMenuPlugin`, `toolbarPlugin`, `blockMenuPlugin` and `blockHandlesPlugin` are the same plugins with the built-in markup.

A snippet declared at the top level of a component's markup can be used in its `<script>`, so you build the plugins there, as every example below does.

## Slash menu

`menu` replaces the whole menu; `item` replaces each row and keeps the built-in sections, empty state and footer. The menu opens on `/` (the editor's root keeps the keyboard: its <kbd>↑</kbd>/<kbd>↓</kbd>, <kbd>Enter</kbd> and <kbd>Escape</kbd> are the plugin's) or from a block handle's `+` (`controller.addition` is set: the menu holds the keyboard, through your field with `keys`). See [Slash menu](/docs/plugins/slash-menu#custom-markup).

```svelte title="SlashMenuEditor.svelte" check
<script lang="ts">
	import { Edytor, createSlashMenuPlugin, type SlashMenuController } from 'edytor';

	const plugins = [createSlashMenuPlugin({ menu })];
</script>

{#snippet menu(slash: SlashMenuController)}
	<div class="menu">
		{#if slash.addition}
			<!-- The `+` menu: this field holds the keyboard. -->
			<input
				role="combobox"
				aria-expanded="true"
				aria-controls={slash.listId}
				aria-label={slash.labels.filterLabel}
				placeholder={slash.labels.filter}
				value={slash.query}
				oninput={(event) => slash.search(event.currentTarget.value)}
				{@attach slash.keys}
			/>
		{/if}
		<ul {@attach slash.popup}>
			{#each slash.commands as command, index (command.id)}
				<li
					{...slash.option(index)}
					onmousemove={() => (slash.selectedIndex = index)}
					onclick={() => void slash.run(command)}
				>
					{command.label}
					{#if command.hint}<kbd>{command.hint}</kbd>{/if}
				</li>
			{:else}
				<li role="presentation">{slash.labels.noResults}</li>
			{/each}
		</ul>
	</div>
{/snippet}

<Edytor {plugins} />
```

An `item` row receives a `SlashMenuItem`: the shared row shape (`item` is the command, `run` runs it, removing the `/query` in the same step), with `command` and `icon` (the built-in line icon as a CSS `mask-image` value):

```svelte title="SlashRows.svelte" check
<script lang="ts">
	import { Edytor, createSlashMenuPlugin, type SlashMenuItem } from 'edytor';

	const plugins = [createSlashMenuPlugin({ item })];
</script>

{#snippet item({ command, label, icon, option, run, select }: SlashMenuItem)}
	<button {...option} class="row" onmousedown={(e) => e.preventDefault()} onmousemove={select} onclick={run}>
		{#if icon}<span class="icon" style:mask-image={icon}></span>{:else}<span>{command.icon}</span>{/if}
		{label}
	</button>
{/snippet}

<Edytor {plugins} />

<style>
	.row[data-selected='true'] {
		background: #f1f1ef;
	}
	.icon {
		width: 18px;
		height: 18px;
		background: currentColor;
		mask-size: contain;
	}
</style>
```

In a `+` menu, the plugin wraps your `menu` in a focused element that holds the keyboard with `keys` too: typing and <kbd>Backspace</kbd> edit `controller.query` when your snippet has no field. `controller.commands` holds only the commands that can run in the block being added; `controller.dismiss()` closes the menu with the selection given back.

## Mention, page link and other trigger menus

A [trigger](/docs/plugins/input-rules#triggers) (`@` for [mentions](/docs/plugins/mention), `[[` for [page links](/docs/plugins/page-link), or your plugin's own) takes `menu` (the whole menu, a `TriggerMenuController<T>`) and `item` (a row, a `TriggerItemPayload<T>`: the shared row shape, `pick` the same as `run`). The editor's root keeps the keyboard; `popup` names the list and its highlighted row from it.

```svelte title="MentionEditor.svelte" check
<script lang="ts">
	import {
		Edytor,
		createMentionPlugin,
		type MentionItem,
		type TriggerMenuController
	} from 'edytor';

	const people: MentionItem[] = [
		{ id: 'ada', label: 'Ada Lovelace' },
		{ id: 'alan', label: 'Alan Turing' }
	];
	const plugins = [
		createMentionPlugin({
			items: (query) => people.filter((person) => person.label.toLowerCase().includes(query)),
			menu
		})
	];
</script>

{#snippet menu(mentions: TriggerMenuController<MentionItem>)}
	<ul {@attach mentions.popup} aria-busy={mentions.loading}>
		{#each mentions.items as person, index (person.id)}
			<li {...mentions.option(index)} onclick={() => void mentions.pick(person)}>
				{person.label}
			</li>
		{:else}
			<li role="presentation">{mentions.loading ? mentions.searching : mentions.empty}</li>
		{/each}
	</ul>
{/snippet}

<Edytor {plugins} />
```

## Block menu

`menu` renders while `controller.isOpen`, beside the grip that opened it. Its field holds the keyboard: `keys` gives it the built-in keys (<kbd>↑</kbd>/<kbd>↓</kbd>, <kbd>Home</kbd>/<kbd>End</kbd>, <kbd>→</kbd> opens a row's flyout and <kbd>←</kbd> closes it, <kbd>Enter</kbd> runs the row, <kbd>Delete</kbd> removes the blocks while the query is empty, <kbd>Escape</kbd> closes the flyout, then the menu) and makes it name the menu, or the open flyout, and its highlighted row. `controller.rows` are the keyboard's rows (the actions, then the kinds and the colours a query names); `runSelected()` runs the highlighted one, `runFlyout()` the flyout's. See [Block menu](/docs/plugins/block-menu#custom-markup).

```svelte title="BlockMenuEditor.svelte" check
<script lang="ts">
	import { Edytor, createBlockMenuPlugin, type BlockMenuController } from 'edytor';

	const plugins = [createBlockMenuPlugin({ menu })];
</script>

{#snippet menu(blockMenu: BlockMenuController)}
	<div class="panel" data-edytor-block-menu>
		<input
			aria-label={blockMenu.labels.searchLabel}
			placeholder={blockMenu.labels.search}
			value={blockMenu.query}
			oninput={(event) => blockMenu.search(event.currentTarget.value)}
			{@attach blockMenu.keys}
		/>
		<div {@attach blockMenu.popup}>
			{#each blockMenu.rows as row, index (`${index}:${row.id}`)}
				<button
					type="button"
					{...blockMenu.option(index)}
					onmousemove={() => (blockMenu.selectedIndex = index)}
					onclick={() => {
						blockMenu.selectedIndex = index;
						blockMenu.runSelected();
					}}>{row.label}</button
				>
			{/each}
		</div>
		{#if blockMenu.flyout}
			<div class="flyout" {@attach blockMenu.flyoutMenu}>
				{#each blockMenu.flyoutRows as row, index (row.id)}
					<button
						type="button"
						{...blockMenu.option(index, true)}
						onclick={() => {
							blockMenu.flyoutIndex = index;
							blockMenu.runFlyout();
						}}>{row.label}</button
					>
				{/each}
			</div>
		{/if}
	</div>
{/snippet}

<Edytor {plugins} />
```

`option(index)` gives each row its role: `menuitem`, a kind's switch `menuitemcheckbox`, a colour `menuitemradio` with its ✓ as `aria-checked`, and a row that opens a flyout `aria-haspopup` and `aria-expanded`. Every action closes the menu and returns the caret to the block (a block holding no text stays selected).

## Toolbar and link card

`toolbar` renders while `controller.isVisible`, above the selection. On the bar, `popup` publishes it to the root (with <kbd>Alt</kbd>+<kbd>F10</kbd> as its shortcut) and marks it for the placement; `keys` makes it one tab stop: <kbd>Alt</kbd>+<kbd>F10</kbd> focuses it, <kbd>←</kbd>/<kbd>→</kbd>, <kbd>Home</kbd> and <kbd>End</kbd> walk its buttons, <kbd>Escape</kbd> gives the focus back to the editor over the same selection. `linkField` is the link panel's field. `card` replaces the card shown under a hovered link (`linkCard: false` shows none). See [Toolbar](/docs/plugins/toolbar#custom-markup).

```svelte title="ToolbarEditor.svelte" check
<script lang="ts">
	import { Edytor, createToolbarPlugin, type ToolbarController } from 'edytor';

	const plugins = [createToolbarPlugin({ toolbar, card })];
</script>

{#snippet toolbar(bar: ToolbarController)}
	<div class="frame">
		<div class="bar" {@attach bar.popup} {@attach bar.keys}>
			{#each bar.marks as { mark, label, icon } (mark)}
				<button aria-label={label} aria-pressed={bar.isActive(mark)} onclick={() => bar.toggleMark(mark)}
					>{icon}</button
				>
			{/each}
			<button aria-expanded={bar.panel === 'link'} onclick={() => bar.togglePanel('link')}
				>{bar.labels.link}</button
			>
		</div>
		{#if bar.panel === 'link'}
			<label for={bar.linkFieldId}>{bar.labels.linkUrl}</label>
			<input
				placeholder={bar.labels.linkPlaceholder}
				value={bar.linkUrl}
				oninput={(event) => bar.setLinkUrl(event.currentTarget.value)}
				{@attach bar.linkField}
			/>
		{/if}
	</div>
{/snippet}

{#snippet card(links: ToolbarController)}
	<div class="card" role="toolbar" aria-label={links.labels.card}>
		<span>{links.hoveredHref}</span>
		<button onclick={() => links.editHovered()}>{links.labels.edit}</button>
		<button onclick={() => links.removeHovered()}>{links.labels.remove}</button>
	</div>
{/snippet}

<Edytor {plugins} />
```

No press on the toolbar or the card takes the editor's focus (their hosts cancel each `mousedown` but in a field), so your buttons need no `mousedown` handler.

## URL paste menu

With the [embed](/docs/plugins/embed) or [bookmark](/docs/plugins/bookmark) plugin, a bare URL pasted on an empty line becomes a link and opens a menu: Link, Embed, Bookmark. `menu` replaces it (the view's one menu takes the first `menu` its embed and bookmark plugins pass). It renders while `controller.open`, under the line; the editor keeps the keyboard (<kbd>↑</kbd>/<kbd>↓</kbd>, <kbd>Enter</kbd> picks, <kbd>Escape</kbd> keeps the link).

```svelte title="PasteMenuEditor.svelte" check
<script lang="ts">
	import { Edytor, createEmbedPlugin, type UrlPasteController } from 'edytor';

	const plugins = [createEmbedPlugin({ menu })];
</script>

{#snippet menu(paste: UrlPasteController)}
	<ul {@attach paste.popup}>
		{#each paste.open?.options ?? [] as option, index (option.id)}
			<li
				{...paste.option(index)}
				onmousemove={() => (paste.index = index)}
				onclick={() => paste.pick(option)}
			>
				{option.icon} {option.label}
			</li>
		{/each}
	</ul>
{/snippet}

<Edytor {plugins} />
```

## Image toolbar

`toolbar` replaces the alignment buttons and the alt text field over the hovered (or selected) image; it renders at the image's top right while the chrome shows and no resize handle drags. The resize handles stay the plugin's. `bar` marks it so a press on it keeps the alt field open (its Alt button toggles it); `altField` focuses the field when it opens, closes it on <kbd>Enter</kbd> or <kbd>Escape</kbd> (the editor takes its keys back) and when the focus leaves it. See [Image](/docs/plugins/image).

```svelte title="ImageEditor.svelte" check
<script lang="ts">
	import { Edytor, createImagePlugin, type ImageControls } from 'edytor';

	const plugins = [createImagePlugin({ toolbar })];
</script>

{#snippet toolbar(image: ImageControls)}
	<div class="image-toolbar" {@attach image.bar}>
		<button aria-pressed={image.box?.align === 'left'} onclick={() => image.align('left')}
			>{image.labels.alignLeft}</button
		>
		<button aria-pressed={image.box?.align === 'center'} onclick={() => image.align('center')}
			>{image.labels.alignCenter}</button
		>
		<button aria-expanded={image.editing !== null} onclick={image.toggleAlt}>{image.labels.alt}</button>
		{#if image.editing !== null && image.editing === image.box?.id}
			<input
				aria-label={image.labels.alt}
				placeholder={image.labels.altPlaceholder}
				value={image.alt}
				oninput={(event) => image.setAlt(event.currentTarget.value)}
				{@attach image.altField}
			/>
		{/if}
	</div>
{/snippet}

<Edytor {plugins} />
```

## Empty image and media blocks

`empty` replaces an empty block's markup: the image's "Add an image" and its link panel, and the same for the [embed](/docs/plugins/embed), [bookmark](/docs/plugins/bookmark), [file](/docs/plugins/file), [video](/docs/plugins/video) and [audio](/docs/plugins/audio) blocks, a readonly view's placeholder included. It receives one controller per empty block: `open`, `draft` (bind your field to it), `failed` (why the last link or upload was not embedded), `embed(value?)`, `upload(file)` (with the plugin's `upload`, `canUpload`), and `readonly` (no control may write: show a placeholder). A media block's controller adds `kind`, `kindLabels`, `label`, `icon`, `accept`, and `pending`, the upload of a pasted or dropped file (`status`, `progress`).

```svelte title="EmptyBlocks.svelte" check
<script lang="ts">
	import {
		Edytor,
		createImagePlugin,
		createVideoPlugin,
		type ImageEmptyController,
		type MediaEmptyController
	} from 'edytor';

	const plugins = [
		createImagePlugin({ empty: emptyImage }),
		createVideoPlugin({ upload: (file) => upload(file), empty: emptyMedia })
	];
</script>

{#snippet emptyImage(image: ImageEmptyController)}
	{#if image.readonly}
		<p>{image.labels.image}</p>
	{:else}
		<input aria-label={image.labels.link} bind:value={image.draft} {@attach image.field} />
		<button onclick={() => image.embed()}>{image.labels.embed}</button>
		{#if image.failed === 'inline'}
			<small>{image.labels.tooLarge(image.inlineLimit, image.canUpload)}</small>
		{:else if image.failed}
			<small>{image.labels.invalid}</small>
		{/if}
	{/if}
{/snippet}

{#snippet emptyMedia(media: MediaEmptyController)}
	{#if media.pending?.status === 'uploading'}
		<progress value={media.pending.progress ?? undefined} max="1"></progress>
	{:else if media.readonly}
		<p>{media.icon} {media.label}</p>
	{:else}
		<input aria-label={media.kindLabels.placeholder} bind:value={media.draft} {@attach media.field} />
		<button onclick={() => media.embed()}>{media.kindLabels.submit}</button>
		{#if media.canUpload}
			<input
				type="file"
				accept={media.accept}
				onchange={(event) => {
					const file = event.currentTarget.files?.[0];
					if (file) void media.upload(file);
				}}
			/>
		{/if}
		{#if media.failed}<small>{media.failed === 'upload' ? media.labels.uploadFailed : media.kindLabels.invalid}</small>{/if}
	{/if}
{/snippet}

<Edytor {plugins} />
```

`upload` here is your own upload function. The markup renders inside the block (the block's own `contenteditable="false"` region), so its fields keep their keys and presses.

## Table grips, menu and `+`

The [table](/docs/plugins/table) plugin's chrome shows over the hovered table. `grip` replaces the grip of the hovered row (left of the table) and of the hovered column (above it): the plugin renders it centered where the grip stands, and `{@attach payload.grip}` gives it the drag, the click that opens its menu and the keys (<kbd>↓</kbd> opens the menu, <kbd>Escape</kbd> gives the keys back to the editor). A press on a grip is never prevented: that would stop the native drag.

`menu` replaces the grip's menu, under the grip while `chrome.menu` is set: `popup` and `keys` on its element make it a `menu` that takes the focus, its <kbd>↓</kbd>/<kbd>↑</kbd> walk the rows that can run, <kbd>Home</kbd>/<kbd>End</kbd> reach the ends, <kbd>Enter</kbd> runs the row, <kbd>Escape</kbd> closes it. `chrome.items` are the rows (Insert above, Insert below, Move up, Move down, Delete row, or the column's), each a `MenuItemPayload` with `disabled` (Move up on the first row, `aria-disabled`), `danger` and `icon`.

`add` replaces the `+` under the table (a row at its end) and beside it (a column): the plugin lays it along that edge, as wide (tall) as the table shows, and keeps the editor's selection on a press.

```svelte title="TableChrome.svelte" check
<script lang="ts">
	import {
		Edytor,
		createTablePlugin,
		type TableAddPayload,
		type TableChrome,
		type TableGripPayload
	} from 'edytor';

	const plugins = [createTablePlugin({ grip, menu, add: plus })];
</script>

{#snippet grip(handle: TableGripPayload)}
	<button type="button" class="grip" {@attach handle.grip}>{handle.kind === 'row' ? '⋮⋮' : '⋯'}</button>
{/snippet}

{#snippet menu(table: TableChrome)}
	<div class="menu" {@attach table.popup} {@attach table.keys}>
		{#each table.items as item (item.item.id)}
			<button
				type="button"
				{...item.option}
				class:danger={item.danger}
				onmousemove={item.select}
				onclick={item.run}>{item.label}</button
			>
		{/each}
	</div>
{/snippet}

{#snippet plus({ kind, label, add }: TableAddPayload)}
	<button type="button" class="add {kind}" aria-label={label} onclick={add}>+</button>
{/snippet}

<Edytor {plugins} />

<style>
	.grip {
		width: 20px;
		height: 20px;
		cursor: grab;
	}
	.menu [data-selected='true'] {
		background: #f1f1ef;
	}
	.add.row {
		width: 100%;
	}
	.add.column {
		height: 100%;
	}
</style>
```

`payload.toggle()` opens or closes a grip's menu, `payload.expanded` and `payload.dragging` say whether it is open or the grip is dragging; `chrome.close()` closes the menu with the keys given back to the editor.

## Code header and language list

The [code](/docs/plugins/code) plugin's `header` replaces the header above each code block (the language's button and Copy), inside the block's non-editable part. It receives the block's `CodeHeader`: `language` (its id) and `label`, the plugin's `languages`, `editable` (false in a readonly view and a suggestion's preview: show the label only), `expanded`, `setLanguage(id)`, `toggle()`, `copy()` and `copied` (true for a moment after a copy), and `labels`. `{@attach header.button}` makes your button open the view's language list under it, with the built-in keys and ARIA.

`menu` replaces that list (the first code plugin listed in a view owns it). It renders under the button while `menu.open` is set; `keys` on its search field makes it the `combobox` that holds the keys (<kbd>↓</kbd>/<kbd>↑</kbd> move the highlighted row, <kbd>Enter</kbd> picks it, <kbd>Escape</kbd> closes: the keys go back to the button when they opened the list, else to the editor), `popup` on the list makes it the `listbox` the root names, and each row of `menu.items` spreads its `option` (`current` marks the block's language).

```svelte title="CodeChrome.svelte" check
<script lang="ts">
	import { Edytor, createCodePlugin, type CodeHeader, type LanguageMenu } from 'edytor';

	const plugins = [createCodePlugin({ header, menu })];
</script>

{#snippet header(code: CodeHeader)}
	{#if code.editable}
		<button type="button" {@attach code.button}>{code.label} ▾</button>
	{:else}
		<span>{code.label}</span>
	{/if}
	<button type="button" onmousedown={(event) => event.preventDefault()} onclick={() => void code.copy()}
		>{code.copied ? code.labels.copied : code.labels.copy}</button
	>
{/snippet}

{#snippet menu(languages: LanguageMenu)}
	<div class="languages">
		<input
			placeholder={languages.labels.search}
			value={languages.query}
			oninput={(event) => languages.search(event.currentTarget.value)}
			{@attach languages.keys}
		/>
		<ul {@attach languages.popup}>
			{#each languages.items as item (item.item.id)}
				<li {...item.option} onmousemove={item.select} onclick={item.run}>
					{item.label}{#if item.current}&nbsp;✓{/if}
				</li>
			{/each}
		</ul>
		{#if languages.items.length === 0}<p role="status">{languages.labels.noResults}</p>{/if}
	</div>
{/snippet}

<Edytor {plugins} />
```

## Equation editor

The [equation](/docs/plugins/equation) plugin's `panel` replaces the editor that opens under an equation (its TeX source, KaTeX's error, Done). It renders while `editor.target` is set, under the equation (centered under a block one). It receives the view's `EquationEditor`: `expression` and `set(value)` (each keystroke one write, the typing one undo step), `display` (a block equation), `error`, `close()` and `labels`. `{@attach editor.field}` on the source's field gives it the focus when the editor opens and its keys: <kbd>Enter</kbd> and <kbd>Escape</kbd> close the editor (<kbd>Shift</kbd>+<kbd>Enter</kbd> is a newline in a block equation), as does the focus leaving the panel.

```svelte title="EquationPanel.svelte" check
<script lang="ts">

	const plugins = [createEquationPlugin({ panel })];

{#snippet panel(equation: EquationEditor)}
	<div class="panel" role="dialog" aria-label={equation.labels.editor}>
		<textarea
			aria-label={equation.labels.editor}
			placeholder={equation.labels.placeholder}
			rows={equation.display ? 3 : 1}
			value={equation.expression}
			oninput={(event) => equation.set(event.currentTarget.value)}
			{@attach equation.field}
		></textarea>
		{#if equation.error}<p role="status">{equation.error}</p>{/if}
		<button type="button" onmousedown={(event) => event.preventDefault()} onclick={() => equation.close()}

		>
	</div>
{/snippet}

```

## Block handle

`handle` replaces the `+` and the grip. `use:grip` gives any element the grip's behavior: dragging (every block the selection covers when it covers this one, with the count preview), a click that selects the block and opens the block menu (or calls `onActivate`), and the <kbd>Alt</kbd>+arrow moves. `add(alt?, anchor?)` is what the `+` does: it opens the slash menu under `anchor` (pass your button, `event.currentTarget`; else under the block), and adds nothing until a row is picked. `expanded` and `controls` say which menu the `+` or the grip opened while it is open (their `aria-expanded` and `aria-controls`), and `labels` are the handles' words (`labels.add(label)`, `labels.grip(label)`). Placement beside the block's first line and the hover fade stay the plugin's. Pass it with `blockHandles={{ handle }}`, alongside `draggable` and `onActivate`, or with `createBlockHandlesPlugin({ handle })`. See [Block handles](/docs/plugins/block-handles#custom-handle).

```svelte title="Handles.svelte" check
<script lang="ts">
	import { Edytor, type BlockHandleSnippetPayload } from 'edytor';

	const keep = (event: MouseEvent) => event.preventDefault();
</script>

{#snippet handle({
	label,
	grip,
	add,
	readonly,
	expanded,
	controls,
	labels
}: BlockHandleSnippetPayload)}
	{#if !readonly}
		<button
			class="add"
			aria-label={labels.add(label)}
			aria-expanded={expanded.add || undefined}
			aria-controls={controls.add}
			onmousedown={keep}
			onclick={(event) => add(event.altKey, event.currentTarget)}>+</button
		>
		<button
			class="grip"
			use:grip
			aria-label={labels.grip(label)}
			aria-expanded={expanded.grip || undefined}
			aria-controls={controls.grip}>⠿</button
		>
	{/if}
{/snippet}

<Edytor blockHandles={{ handle }} />
```
