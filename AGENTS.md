# Edytor Repository Guide

For coding agents and maintainers who need to work on the repo without rediscovering its structure.

Edytor is a small editing engine with a Svelte rendering layer, on a Yjs v14 document. It is not a component library with a thin editor wrapper. Almost every bug that "looks random" from the DOM or selection side comes from changing behavior in the wrong layer, or from giving one fact a second owner. Read "One owner per fact" before changing anything in `session/`, `surface/` or `events/`.

## The top-level model

Five contexts, each with one job and a lifetime, plus the shared leaves and the composition root:

| Context     | Lives in                                                                                                                                                                                                  | Lifetime               | Job                                                                                                                                                                                                                                      |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **doc**     | `src/lib/crdt/` (not `vendor/`, `providers/`, `protocols/`, `migration/`)                                                                                                                                 | the engine doc         | The replicated document and everything derived from it: block registry, placements, streams, one index, prepared operations, anchors, attribution. DOM-free and Svelte-free.                                                             |
| **sync**    | `src/lib/crdt/{providers,protocols,migration}/`, `src/lib/cloudflare/`, `src/lib/collaboration/` (not the remote carets, not `history/`)                                                                  | provider / document    | Transport: the generation envelope, the room lifecycle and join rule, IndexedDB + websocket providers, awareness, presence state, v13→v14 migration, the room.                                                                           |
| **session** | `src/lib/session/`, `src/lib/block/`, `src/lib/text/`, `src/lib/clipboard/`, `src/lib/selection/{replaceSelection,visibility}.ts`, `src/lib/kinds.ts`, `src/lib/edytor.utils.ts`                          | the view               | DOM-free per-view state: the selection value, the command dispatcher, input attempts, the composition session, history, keymap, navigation, moves, the handles, the clipboard's flows, the kind catalogue.                               |
| **surface** | `src/lib/surface/`, `src/lib/components/` (not `Edytor.svelte`), `src/lib/events/`, `src/lib/selection/` (the rest), `src/lib/dnd/`, `src/lib/collaboration/{remoteSelection.ts,RemoteSelections.svelte}` | one mount              | The only code that reads or writes the host DOM: render cells, the compare-to-truth observer, the selection projector, the IME pin, the overlay, the event adapters, the DOM selection's adopter (`EdytorSelection`), the remote carets. |
| **plugins** | `src/lib/plugins.ts`, `src/lib/plugins/`, `src/lib/collaboration/history/`                                                                                                                                | the editor (immutable) | Kind, mark and atom records, hooks, commands, bindings, and the chrome built on them (the version history panel).                                                                                                                        |

The shared leaves (`src/lib/utils/`, `src/lib/utils.ts`, `src/lib/constants.ts`, `src/lib/labels.ts`) import nothing of the contexts. `src/lib/edytor.svelte.ts` (`Edytor`) is the composition root (with the mount `components/Edytor.svelte` and the entry `index.ts`): it builds one of each per view and wires them. It should hold wiring, not rules.

**Import direction.** The contexts form no import cycle between them. The session never value-imports the surface, the chrome or the root, and the surface never value-imports the chrome or the root (`import type` is free). What the session asks of the surface and of the input commands is a port it declares (`session/ports.ts`: `SurfacePort` — the projector's `park`, `placed` and `parked`, the observer's `flush`, clearing the DOM selection, a DOM point's text and offset — and `InputPort`, the intents a binding runs) and the root implements (`edytor.ports`). The handles' attachments (the host writers) still register their nodes with the observer, and the composition session drives the pin and reads the cells, through the view. Three checks: `edytor-contexts/context-imports` in `eslint.config.js` (`pnpm lint`), `pnpm check:deps` (`scripts/deps.mjs`: Tarjan's strongly connected components over the value imports of `src/lib`, vendor excluded; `--cross`, `--between`, `--edges` show what to invert) and `src/tests/deps.test.ts` (no cycle crosses contexts, every module has one, no forbidden import). The assignment is data, `CONTEXTS` and `FORBIDDEN` in `scripts/contexts.mjs`: a new directory gets a row there and here. A module that seems to need an import against the direction is in the wrong context, or the owner is missing a port.

## Where to fix what

- A structural edit is wrong → the document op (the `crdt/doc/` prepare families over `crdt/doc/steps.ts`, `crdt/rangeDelete.ts`, `crdt/flow.ts`) and its contract row, then the view command in `block/block.utils.ts`.
- A text edit is wrong → `text/text.utils.ts`, `session/editing/text.ts` (marks).
- A keystroke is wrong in the browser → `events/onBeforeInput.ts` + `events/beforeInputCommands.ts` / `beforeInputDeleteCommands.ts`, the attempt (`session/attempt.ts`), the binding (`session/bindings.ts`).
- The caret lands wrong → the command's result selection (`Dispatcher.caret`) or the seam (`crdt/anchors.ts`); the projector only displays the value.
- The DOM differs from the model → the observer's classification (`surface/observer.svelte.ts`) or the cell (`surface/cells.ts`). Never patch the DOM from a command.
- IME → `session/composition.svelte.ts` and `surface/pin.svelte.ts`.
- A table shows wrong (a cell out of its column, an empty row, a stray cell) → the index's table rules (`tableVisit`, `cellRank` in `crdt/text/index/layout.ts`) and the `table.*` rows, never the table plugin; a table op writes wrong → `crdt/doc/table.ts`; the grid's chrome → `plugins/table/chrome.svelte.ts`.
- A layout shows wrong (an empty column, a one-column layout, a block beside the columns) → the index's layout rules (`crdt/text/index/layout.ts`, `displaySlotOf`) and the `layout.*` rows, never the columns plugin; a beside drop lands wrong → `besideAt`/`placeBeside`; the gap's chrome overlaps → `plugins/columns/gaps.ts`.
- Rendering is wrong while the model is right → components and kind records.

## Testing

Lanes (green at every gate; the rows expected to fail are declared `it.fails` and counted in the latest ledger row). CI (`.github/workflows/ci.yml`) runs the static checks and the unit, `test:crdt`, `test:dom` and `test:do` lanes on every push, Playwright Chromium (four shards) on every pull request; `nightly.yml` runs Firefox, WebKit, mobile, cdp and DST; only the pull request run's gate job is named `CI passed` (any other run's is `CI passed (<event>)`, as it skips Chromium); CONTRIBUTING.md has the lanes, the PR checklist and the branch protection ruleset to apply (not applied yet); `src/tests/ci-gates.test.ts` keeps the workflows, CONTRIBUTING.md and the gate rows in step (no retries, no measured time asserted):

- `playwright.config.ts` takes `PW_PORT` (default 4173; a local, untracked `playwright.arch.config.ts` takes `PW_PORT` too) and `playwright.dst.config.ts` takes `DST_PORT` (default 4183), so parallel worktrees do not collide.
- **No wall clock in a gate lane.** A row that says "stays fast" counts the index's work (`facade.runsView.debug`: `folds`, `foldedPairs`, `foldedStructs`, `recomputes`, `itemsWalked`) and states a scaling contract (ten times the blocks: the same recomputes, at most eleven times the fold input; a keystroke's work the same at 5,000 blocks as at 1,000), never `performance.now()` with `toBeLessThan`; the timings are `bench:crdt`'s `scale` workload (`bench/lib/scale.js`, `pnpm bench:scale`; remote admission, the undo manager and encode/load scaling are checked only there, a report that fails nothing), a browser row reports its time as an annotation. A trace compared across runs records nothing the wall clock decides (the command schedules' final drain waits for every timer, `quiesce(Infinity)`). A row waits for the fact it needs, never for a delay: the room lane's `vi.waitFor` defaults to 10 s (`tests/do/setup.ts`), a seeded `RawClient` waits for `stored()` (an ack covering its state; the room acknowledges its Step1 before storing anything), a "never relayed" row counts `syncFrames()`, and a browser row that samples the page right after a protocol input waits for the page to have handled it (Chromium answers a drag move before the page sees it: `dragTo` in `block-handles.spec.ts`). A key after a press reads the press's caret even before its `selectionchange` (`sel.key.before-adoption`: `projector.unobserved()` in `events/onKeyDown.ts`); no row quarantines itself on CI.
- The JSX fixture DSL (`src/tests/jsx/`) turns `<root><paragraph>Hello <bold>world</bold></paragraph></root>` into `JSONDoc`; `|` marks cursor positions. `createTestEdytor()` (`src/tests/test.utils.ts`) is the headless view for model operations; `renderDomEdytor()` (`src/tests/dom/test.utils.ts`) mounts a real editor in jsdom.
- Every vitest lane (unit, `test:crdt`, `test:dom`) runs with the index's self-checks on (`indexChecks`, exported by `crdt/text/runs.ts`, the checks in `crdt/text/index/checks.ts`, set by `src/tests/setup/index-checks.ts`; `EDYTOR_INDEX_CHECKS=0` turns them off): after every fold each fact the index maintains incrementally must equal its rebuild from the replicated state, or the fold throws.
- The random corpus runner and the replica harness check every replica after every step against named `wellFormed` invariants (`src/tests/crdt/harness/assert/well-formed.ts`: registered-type, merge-order, void-children, seed-displacement, island-kind, promotion-hidden; `DST_PROMOTION_ORACLE=0` turns the last off). The corpus runs the `raw`, `model`, `doc` and `roles` adapters (`CRDT_ADAPTER`, default all); `roles` is the `doc` facade with block roles over a seed holding an island and a void. A break is a hard `ill-formed` violation; causally incomplete states are skipped; the replica harness checks after facade writes, deliveries and history, never from the engine `update` event. A history step never leaves a block or atom type, data or `lastChangedBy` undefined (`repairAttrs` in `createUndoManager`).
- Oracles live in `src/tests/oracles/` (`truth.ts`: every content equals its cell; `doc-change.ts`, `fresh-view.ts`, `runs.ts`, `model-ops.ts`). Expected results come from contracts, never from production output.
- `docs/editor-delete-contract.md` names the deletion, flow, seam and anchor rows; tests cite them.
- Real browser behaviour (selection, IME, Android drift) is proven only in the Playwright and cdp lanes; jsdom rows are necessary, not sufficient.

## Practical rules

- Change behaviour in its owner. If a change needs a flag, timer, retry or a second place that decides the same thing, stop: a contract row or an owner rule is missing.
- Timers are named, counted browser rules only (`pnpm census` reports them); no `tick()` polling, no re-assert loops.
- Keep `src/lib/crdt` Worker-safe; run `pnpm check:worker` when touching it.
- Verify engine APIs in the vendored source (`src/lib/crdt/vendor/yjs/src`), not from Yjs v13 examples; fork changes go through `UPSTREAM.md`.
- Public API and behavior changes update the site in the same change: the page that documents it, and `reference/migration.mdx`, the user changelog: a note under `### Unreleased` (right after `## Upgrading between pre-releases`; a release sorts its notes into `#### Breaking changes`, `#### New` and `#### Fixed` under `### From <previous version>` and opens a new, empty `### Unreleased` ("Nothing yet.") above it, a note that asks apps or tests to act under breaking changes), and the "Complete list of changes", the canonical record by area (the README links it and keeps no copy). The changelog is written for users: no ticket code, contract row id or repository path (`src/tests/docs-drift.test.ts` rejects them). Importing v13 documents is its own guide, `reference/v13-import.mdx`. The ledger records gates and measurements.
- Engine privates (`_map`, `_start`, `_length`, `store`, `gc`/`gcFilter`, transaction events, undo stacks) and engine functions called with edytor's structural views (`EngineDoc`, `StoreStruct`, `IdSetLike`) go through the typed accessors of `src/lib/crdt/structs.ts` (`asEngineDoc`, `attrItems`, `firstItem`, `keepFromCollection`, `onTransaction`, `engineOps(Y)`, …): a new reach into the engine is an accessor there, never a cast at the call site (`pnpm census` counts `as unknown as` and `as never`). Each edytor document carries the fork's keep-replaced rule (`keepingReplaced`, `crdt/incarnations.ts`) before it integrates anything; the engine's class default stays upstream's. `.github/workflows/upstream.yml` diffs and tests a newer `@y/y` weekly.
- The public surface is curated: `src/lib/index.ts` lists every name (no `export *`), the wire vocabulary lives only in `edytor/protocol` (`src/lib/crdt/protocol.ts`), and a member only the editor's own layers call carries `@internal` in its JSDoc (`stripInternal` drops it from the published `.d.ts`). The committed report `api/*.api.md` (`pnpm api:report`) is the reviewed surface: `src/tests/api/public-surface.test.ts` (unit lane) fails until a change to it is regenerated, so review its diff like code. It also fails when a reported declaration's JSDoc names an internal ticket code (`R4`, `UW-22`): public JSDoc says what a code means instead. A deprecated alias lives one release, then goes, with its row in the changelog's Breaking changes. A removed view option or prop an untyped caller still passes is ignored and warns in development, naming its replacement (`RETIRED` in `edytor.svelte.ts`).
- The composition root's `readonly edytor = this` is load-bearing: `batch()` binds operations onto the `Edytor` too. `edytor.container` is gone; the host element is `edytor.node`. Focus and pointer ownership listeners live in `events/onFocus.ts` (`attachFocus`), the press among them (the chrome press included): a `pointerdown`, or a trusted primary `mousedown` no `pointerdown` came before (WebKit sends none for the first press after a native drag, bugs 202287/222632/279749), a pair counted once. A press inside the host is handled there, not by a `pointerdown` listener of its own. Chrome outside the host reads the same fact, never a second classification: a press listener installed after the attach (a menu's press outside) is `onPress(edytor, target, listener)`, and an overlay element's own `mousedown` asks `isLonePress(edytor, event)` (the column resize band starts its drag from it, tracking the mouse on the window).
