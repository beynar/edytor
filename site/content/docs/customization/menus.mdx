Edytor's chrome is headless: the slash menu, the mention and page link menus, the block menu, the selection toolbar and its link card, the menu a pasted URL opens, the image toolbar, the empty image and media blocks, a table's grips, menus and `+` bars, a code block's header and language list, the callout icon picker, the equation editor, the comment cards, the suggestion bar, the version history, the block handles and the marquee's rectangle are drawn by your snippets. The package ships the behavior: when the UI opens, where it is placed, the keys it claims, the commands it runs, and the keyboard and ARIA your markup takes through a few attachments its controller hands you. It ships no markup for them.

**Without its snippet, a surface renders nothing**, and its controller still works: with `createSlashMenuPlugin()` and no `menu`, typing `/divider` and <kbd>Enter</kbd> still inserts a divider, and nothing shows. A plugin whose main job is a kind (code, table, image, the media kinds, equations) keeps its blocks; only its chrome is yours.

The examples below are the short version of each surface. The complete Notion-style markup of every surface, with its styles, is the demo's: [`src/routes/chrome`](https://github.com/beynar/edytor/tree/master/src/routes/chrome) in the repository (`chrome.svelte` holds the snippets, `plugins.ts` passes them to each factory). Copy what you need.

## The pattern

Every element is customized the same way:

- **Where.** A snippet option in the plugin's factory options (`createBlockMenuPlugin({ menu })`). The version history is a controller you make in your component (`new VersionHistory(…)`).
- **Naming.** A whole surface is named by what it is: `menu`, `toolbar`, `card`, `bar`, `empty`, `header`, `panel`, `box`, `picker`; a control by what it is: `grip`, `add`, `handle`. One surface, one snippet: your snippet draws its rows.
- **Typing.** A snippet takes one object argument whose type is exported from `edytor`: `Snippet<[BlockMenuController]>`. A whole surface receives its controller: its state, its actions, `readonly`, and a way to close it; the words are your markup's. A controller that builds its rows hands them in the shape every list shares, `MenuItemPayload`: `{ item, id, selected, run, select, option }` (a table menu's `items`, a code language list's `items`).
- **Accessibility.** The keyboard and the ARIA live on the controller as [attachments](https://svelte.dev/docs/svelte/@attach) and row attributes: a snippet that uses them gets the keys and the ARIA the accessibility tests prove (the demo's markup is the one they run).

| Attachment | Put it on | What it does |
| --- | --- | --- |
| `{@attach controller.popup}` | The list (`listbox` or `menu`), or the toolbar | Gives the element its id, and its role and name unless you set them; keeps the focus where it is on a press; publishes the popup to the editor's root (`aria-controls`, `aria-haspopup`, `aria-activedescendant` when the root holds the keyboard) while it is in the page, and withdraws it when it goes |
| `{@attach controller.keys}` | The element that holds the keyboard: the block menu's or the `+` menu's field (or the `+` menu itself), the toolbar, a table's grip menu, the code language list's search field, the callout icon picker | Takes the menu's keys (arrows, <kbd>Home</kbd>, <kbd>End</kbd>, <kbd>Enter</kbd>, <kbd>Escape</kbd>, …), focuses the element when it mounts, and makes it name the list and its highlighted row |
| `{...controller.option(index)}` | Each row | Its id, `role`, `aria-selected` (or `aria-checked`), `tabindex="-1"`, `data-selected`, and scrolls the keyboard's row into view. A row payload carries it as `option` |
| `{@attach controller.flyoutMenu}` | The block menu's open flyout | Its id, role, name and placement beside the menu |
| `{@attach controller.linkField}` | The toolbar's link field | Its id (unique per editor, for a `label`'s `for`), the focus when the panel opens, <kbd>Enter</kbd> applies, <kbd>Escape</kbd> closes |
| `{@attach controls.bar}`, `{@attach controls.altField}` | The image toolbar and its alt field | The toolbar's role and name; the alt field's focus, keys, and closing when the focus leaves |
| `{@attach empty.field}` | An empty block's link field | <kbd>Enter</kbd> embeds the link |
| `{@attach payload.grip}` | A table's row or column grip | The drag (the row or the column moves where it is dropped), the click that opens its menu, <kbd>↓</kbd> opens it too and <kbd>Escape</kbd> gives the keys back to the editor; its name, `aria-haspopup`, `aria-expanded` and `aria-controls` |
| `{@attach header.button}` | A code block's language button | Opens the language list on a click, <kbd>↓</kbd> or <kbd>↑</kbd> (<kbd>Alt</kbd>+<kbd>F10</kbd> at a caret in the block reaches it), <kbd>Escape</kbd> gives the keys back to the code; its name, `aria-haspopup`, `aria-expanded` and `aria-controls` |
| `{@attach editor.field}` | The equation editor's source field | The focus when the editor opens, the caret at the end; <kbd>Enter</kbd> and <kbd>Escape</kbd> close the editor (<kbd>Shift</kbd>+<kbd>Enter</kbd> is a newline in a block equation), and so does the focus leaving the panel |
| `{...history.option(index)}`, `onkeydown={history.keys}` | A version's row, the versions list | The row's `role="option"`, id, `aria-selected` and the list's one tab stop; the list's arrows, <kbd>Home</kbd> and <kbd>End</kbd> move the selection and the focus |

Two rules hold for every snippet:

- **Keep the selection.** A press on a menu must not move the caret. `popup` cancels the `mousedown` of every press in its element but on a field; on anything else that acts on the text (a `+`, a button outside the list), call `preventDefault` on `mousedown`. The toolbar's host does it for every press but in a field.
- **Mark the element to place** when it is not your snippet's first element: the block menu measures `[data-edytor-block-menu]`; the toolbar's `popup` marks the bar `data-edytor-toolbar-bar` for you.

Your markup writes its own words and names its menus, bars and fields (`aria-label`): the controllers carry no words and name none of your elements; the words the package itself shows are the view's `labels` ([Localization](/docs/customization/localization)). Your markup renders in the plugin's host, placed by the plugin; its look is all yours.

A snippet declared at the top level of a component's markup can be used in its `<script>`, so you build the plugins there, as every example below does.

## Slash menu

`menu` draws the menu while `controller.isOpen`. It opens on `/` (the editor's root keeps the keyboard: its <kbd>↑</kbd>/<kbd>↓</kbd>, <kbd>Enter</kbd> and <kbd>Escape</kbd> are the plugin's) or from a block handle's `+` (`controller.addition` is set: the menu holds the keyboard, through the element you give `keys`). `controller.commands` are the rows, in their groups' order (`command.group`, named by `controller.groupName`). See [Slash menu](/docs/plugins/slash-menu#markup).

```svelte title="SlashMenuEditor.svelte" check
<script lang="ts">
	import { Edytor, createSlashMenuPlugin, type SlashMenuController } from 'edytor';

	const plugins = [createSlashMenuPlugin({ menu })];
</script>

{#snippet menu(slash: SlashMenuController)}
	<div class="menu">
		{#if slash.addition}
			<!-- The `+` menu: this field holds the keyboard. -->
			<input
				role="combobox"
				aria-expanded="true"
				aria-controls={slash.listId}
				aria-label="Filter block commands"
				placeholder="Type to filter…"
				value={slash.query}
				oninput={(event) => slash.search(event.currentTarget.value)}
				{@attach slash.keys}
			/>
		{/if}
		<ul {@attach slash.popup}>
			{#each slash.commands as command, index (command.id)}
				<li
					{...slash.option(index)}
					onmousemove={() => (slash.selectedIndex = index)}
					onclick={() => void slash.run(command)}
				>
					{command.label}
					{#if command.hint}<kbd>{command.hint}</kbd>{/if}
				</li>
			{:else}
				<li role="presentation">No results</li>
			{/each}
		</ul>
	</div>
{/snippet}

<Edytor {plugins} />
```

In a `+` menu, `keys` goes on the element that holds the keyboard: your field, as above, or the menu element itself (give it `tabindex="-1"`): then typing and <kbd>Backspace</kbd> edit `controller.query`. `controller.commands` holds only the commands that can run in the block being added; `controller.dismiss()` closes the menu with the selection given back.

## Mention, page link and other trigger menus

A [trigger](/docs/plugins/input-rules#triggers) (`@` for [mentions](/docs/plugins/mention), `[[` for [page links](/docs/plugins/page-link), or your plugin's own) takes `menu`, the whole menu: a `TriggerMenuController<T>` whose `items` are the rows (`labelOf(item)` their words, `pick(item)` picks one). The editor's root keeps the keyboard; `popup` names the list and its highlighted row from it.

```svelte title="MentionEditor.svelte" check
<script lang="ts">
	import {
		Edytor,
		createMentionPlugin,
		type MentionItem,
		type TriggerMenuController
	} from 'edytor';

	const people: MentionItem[] = [
		{ id: 'ada', label: 'Ada Lovelace' },
		{ id: 'alan', label: 'Alan Turing' }
	];
	const plugins = [
		createMentionPlugin({
			items: (query) => people.filter((person) => person.label.toLowerCase().includes(query)),
			menu
		})
	];
</script>

{#snippet menu(mentions: TriggerMenuController<MentionItem>)}
	<ul {@attach mentions.popup} aria-busy={mentions.loading}>
		{#each mentions.items as person, index (person.id)}
			<li {...mentions.option(index)} onclick={() => void mentions.pick(person)}>
				{person.label}
			</li>
		{:else}
			<li role="presentation">{mentions.loading ? 'Searching…' : 'No results'}</li>
		{/each}
	</ul>
{/snippet}

<Edytor {plugins} />
```

## Block menu

`menu` renders while `controller.isOpen`, beside the grip that opened it. Its field holds the keyboard: `keys` gives it the menu's keys (<kbd>↑</kbd>/<kbd>↓</kbd>, <kbd>Home</kbd>/<kbd>End</kbd>, <kbd>→</kbd> opens a row's flyout and <kbd>←</kbd> closes it, <kbd>Enter</kbd> runs the row, <kbd>Delete</kbd> removes the blocks while the query is empty, <kbd>Escape</kbd> closes the flyout, then the menu) and makes it name the menu, or the open flyout, and its highlighted row. `controller.rows` are the keyboard's rows (the actions, then the kinds and the colours a query names); `runSelected()` runs the highlighted one, `runFlyout()` the flyout's. See [Block menu](/docs/plugins/block-menu#markup).

```svelte title="BlockMenuEditor.svelte" check
<script lang="ts">
	import { Edytor, createBlockMenuPlugin, type BlockMenuController } from 'edytor';

	const plugins = [createBlockMenuPlugin({ menu })];
</script>

{#snippet menu(blockMenu: BlockMenuController)}
	<div class="panel" data-edytor-block-menu>
		<input
			aria-label="Search actions"
			placeholder="Search actions…"
			value={blockMenu.query}
			oninput={(event) => blockMenu.search(event.currentTarget.value)}
			{@attach blockMenu.keys}
		/>
		<div {@attach blockMenu.popup}>
			{#each blockMenu.rows as row, index (`${index}:${row.id}`)}
				<button
					type="button"
					{...blockMenu.option(index)}
					onmousemove={() => (blockMenu.selectedIndex = index)}
					onclick={() => {
						blockMenu.selectedIndex = index;
						blockMenu.runSelected();
					}}>{row.label}</button
				>
			{/each}
		</div>
		{#if blockMenu.flyout}
			<div class="flyout" {@attach blockMenu.flyoutMenu}>
				{#each blockMenu.flyoutRows as row, index (row.id)}
					<button
						type="button"
						{...blockMenu.option(index, true)}
						onclick={() => {
							blockMenu.flyoutIndex = index;
							blockMenu.runFlyout();
						}}>{row.label}</button
					>
				{/each}
			</div>
		{/if}
	</div>
{/snippet}

<Edytor {plugins} />
```

`option(index)` gives each row its role: `menuitem`, a kind's switch `menuitemcheckbox`, a colour `menuitemradio` with its ✓ as `aria-checked`, and a row that opens a flyout `aria-haspopup` and `aria-expanded`. Every action closes the menu and returns the caret to the block (a block holding no text stays selected).

## Toolbar and link card

`toolbar` renders while `controller.isVisible`, above the selection. On the bar, `popup` publishes it to the root (with <kbd>Alt</kbd>+<kbd>F10</kbd> as its shortcut) and marks it for the placement; `keys` makes it one tab stop: <kbd>Alt</kbd>+<kbd>F10</kbd> focuses it, <kbd>←</kbd>/<kbd>→</kbd>, <kbd>Home</kbd> and <kbd>End</kbd> walk its buttons, <kbd>Escape</kbd> gives the focus back to the editor over the same selection. `linkField` is the link panel's field. `card` draws the card shown under a hovered link (without it, no card). See [Toolbar](/docs/plugins/toolbar#markup).

```svelte title="ToolbarEditor.svelte" check
<script lang="ts">
	import { Edytor, createToolbarPlugin, type ToolbarController } from 'edytor';

	const plugins = [createToolbarPlugin({ toolbar, card })];
</script>

{#snippet toolbar(bar: ToolbarController)}
	<div class="frame">
		<div class="bar" {@attach bar.popup} {@attach bar.keys}>
			{#each bar.marks as { mark, label, icon } (mark)}
				<button aria-label={label} aria-pressed={bar.isActive(mark)} onclick={() => bar.toggleMark(mark)}
					>{icon}</button
				>
			{/each}
			<button aria-expanded={bar.panel === 'link'} onclick={() => bar.togglePanel('link')}
				>Link</button
			>
		</div>
		{#if bar.panel === 'link'}
			<label for={bar.linkFieldId}>Link URL</label>
			<input
				placeholder="Paste link"
				value={bar.linkUrl}
				oninput={(event) => bar.setLinkUrl(event.currentTarget.value)}
				{@attach bar.linkField}
			/>
		{/if}
	</div>
{/snippet}

{#snippet card(links: ToolbarController)}
	<div class="card" role="toolbar" aria-label="Link">
		<span>{links.hoveredHref}</span>
		<button onclick={() => links.editHovered()}>Edit</button>
		<button onclick={() => links.removeHovered()}>Remove</button>
	</div>
{/snippet}

<Edytor {plugins} />
```

No press on the toolbar or the card takes the editor's focus (their hosts cancel each `mousedown` but in a field), so your buttons need no `mousedown` handler.

## URL paste menu

With the [embed](/docs/plugins/embed) or [bookmark](/docs/plugins/bookmark) plugin, a bare URL pasted on an empty line becomes a link and opens a menu: Link, Embed, Bookmark. `menu` draws it (the view's one menu takes the first `menu` its embed and bookmark plugins pass; without one, the link stays and nothing shows). It renders while `controller.open`, under the line; the editor keeps the keyboard (<kbd>↑</kbd>/<kbd>↓</kbd>, <kbd>Enter</kbd> picks, <kbd>Escape</kbd> keeps the link).

```svelte title="PasteMenuEditor.svelte" check
<script lang="ts">
	import { Edytor, createEmbedPlugin, type UrlPasteController } from 'edytor';

	const plugins = [createEmbedPlugin({ menu })];
</script>

{#snippet menu(paste: UrlPasteController)}
	<ul {@attach paste.popup}>
		{#each paste.open?.options ?? [] as option, index (option.id)}
			<li
				{...paste.option(index)}
				onmousemove={() => (paste.index = index)}
				onclick={() => paste.pick(option)}
			>
				{option.icon} {option.id}
			</li>
		{/each}
	</ul>
{/snippet}

<Edytor {plugins} />
```

## Image toolbar

`toolbar` draws the alignment buttons and the alt text field over the hovered (or selected) image; it renders at the image's top right while the chrome shows and no resize handle drags. The resize handles are the plugin's. `bar` marks it so a press on it keeps the alt field open (its Alt button toggles it); `altField` focuses the field when it opens, closes it on <kbd>Enter</kbd> or <kbd>Escape</kbd> (the editor takes its keys back) and when the focus leaves it. See [Image](/docs/plugins/image).

```svelte title="ImageEditor.svelte" check
<script lang="ts">
	import { Edytor, createImagePlugin, type ImageControls } from 'edytor';

	const plugins = [createImagePlugin({ toolbar })];
</script>

{#snippet toolbar(image: ImageControls)}
	<div class="image-toolbar" {@attach image.bar}>
		<button aria-pressed={image.box?.align === 'left'} onclick={() => image.align('left')}
			>Align left</button
		>
		<button aria-pressed={image.box?.align === 'center'} onclick={() => image.align('center')}
			>Align center</button
		>
		<button aria-expanded={image.editing !== null} onclick={image.toggleAlt}>Alt text</button>
		{#if image.editing !== null && image.editing === image.box?.id}
			<input
				aria-label="Alt text"
				placeholder="Describe the image…"
				value={image.alt}
				oninput={(event) => image.setAlt(event.currentTarget.value)}
				{@attach image.altField}
			/>
		{/if}
	</div>
{/snippet}

<Edytor {plugins} />
```

## Empty image and media blocks

`empty` draws an empty block: the image's "Add an image" and its link panel, and the same for the [embed](/docs/plugins/embed), [bookmark](/docs/plugins/bookmark), [file](/docs/plugins/file), [video](/docs/plugins/video) and [audio](/docs/plugins/audio) blocks, a readonly view's placeholder included: one snippet shape, one controller (`MediaEmptyController`) per empty block of any of these kinds: `kind` (`image`, `embed`, `bookmark`, `file`, `video`, `audio`: your words for it), `icon`, `open`, `draft` (bind your field to it), `failed` (why the last link or upload was not embedded: `invalid`, `inline` for an inline image over `MAX_INLINE_IMAGE_BYTES`, `upload`), `embed(value?)`, `upload(file)` (with the plugin's `upload`, `canUpload`, the picker's `accept`), `pending`, the upload of a pasted or dropped file (`status`, `progress`, an image's `preview`), and `readonly` (no control may write: show a placeholder).

```svelte title="EmptyBlocks.svelte" check
<script lang="ts">
	import {
		Edytor,
		createImagePlugin,
		createVideoPlugin,
		MAX_INLINE_IMAGE_BYTES,
		type MediaEmptyController
	} from 'edytor';

	const plugins = [
		createImagePlugin({ empty: emptyImage }),
		createVideoPlugin({ upload: (file) => upload(file), empty: emptyMedia })
	];
</script>

{#snippet emptyImage(image: MediaEmptyController)}
	{#if image.readonly}
		<p>Image</p>
	{:else}
		<input aria-label="Image link" bind:value={image.draft} {@attach image.field} />
		<button onclick={() => image.embed()}>Embed image</button>
		{#if image.failed === 'inline'}
			<small>Inline images are limited to {MAX_INLINE_IMAGE_BYTES} bytes.</small>
		{:else if image.failed}
			<small>That doesn't look like an image link.</small>
		{/if}
	{/if}
{/snippet}

{#snippet emptyMedia(media: MediaEmptyController)}
	{#if media.pending?.status === 'uploading'}
		<progress value={media.pending.progress ?? undefined} max="1"></progress>
	{:else if media.readonly}
		<p>{media.icon} Embed a {media.kind}</p>
	{:else}
		<input aria-label="Paste the link…" bind:value={media.draft} {@attach media.field} />
		<button onclick={() => media.embed()}>Embed</button>
		{#if media.canUpload}
			<input
				type="file"
				accept={media.accept}
				onchange={(event) => {
					const file = event.currentTarget.files?.[0];
					if (file) void media.upload(file);
				}}
			/>
		{/if}
		{#if media.failed}<small>{media.failed === 'upload' ? 'The upload failed.' : 'That link is not one.'}</small>{/if}
	{/if}
{/snippet}

<Edytor {plugins} />
```

`upload` here is your own upload function. The markup renders inside the block (the block's own `contenteditable="false"` region), so its fields keep their keys and presses.

## Table grips, menu and `+`

The [table](/docs/plugins/table) plugin's chrome shows over the hovered table (its column resize bands are the plugin's). `grip` draws the grip of the hovered row (left of the table) and of the hovered column (above it): the plugin renders it centered where the grip stands, and `{@attach payload.grip}` gives it the drag, the click that opens its menu and the keys (<kbd>↓</kbd> opens the menu, <kbd>Escape</kbd> gives the keys back to the editor). A press on a grip is never prevented: that would stop the native drag.

`menu` draws the grip's menu, under the grip while `chrome.menu` is set: `popup` and `keys` on its element make it a `menu` that takes the focus, its <kbd>↓</kbd>/<kbd>↑</kbd> walk the rows that can run, <kbd>Home</kbd>/<kbd>End</kbd> reach the ends, <kbd>Enter</kbd> runs the row, <kbd>Escape</kbd> closes it. `chrome.items` are the rows (Insert above, Insert below, Move up, Move down, Delete row, or the column's), each a `MenuItemPayload` with `disabled` (Move up on the first row, `aria-disabled`) and `danger`; `item.item.id` names the row (`insert-above`, `move-down`, `delete-column`, …) for your icons.

`add` draws the `+` under the table (a row at its end) and beside it (a column): the plugin lays it along that edge, as wide (tall) as the table shows, and keeps the editor's selection on a press.

```svelte title="TableChrome.svelte" check
<script lang="ts">
	import {
		Edytor,
		createTablePlugin,
		type TableAddPayload,
		type TableChrome,
		type TableGripPayload
	} from 'edytor';

	const plugins = [createTablePlugin({ grip, menu, add: plus })];
</script>

{#snippet grip(handle: TableGripPayload)}
	<button type="button" class="grip" {@attach handle.grip}>{handle.kind === 'row' ? '⋮⋮' : '⋯'}</button>
{/snippet}

{#snippet menu(table: TableChrome)}
	<div class="menu" {@attach table.popup} {@attach table.keys}>
		{#each table.items as item (item.item.id)}
			<button
				type="button"
				{...item.option}
				class:danger={item.danger}
				onmousemove={item.select}
				onclick={item.run}>{item.item.id}</button
			>
		{/each}
	</div>
{/snippet}

{#snippet plus({ kind, add }: TableAddPayload)}
	<button type="button" class="add {kind}" aria-label="Add a {kind}" onclick={add}>+</button>
{/snippet}

<Edytor {plugins} />

<style>
	.grip {
		width: 20px;
		height: 20px;
		cursor: grab;
```

## Code header and language list

The [code](/docs/plugins/code) plugin's `header` draws the header above each code block (the language's button and Copy), inside the block's non-editable part (the plugin places it at the block's top). It receives the block's `CodeHeader`: `language` (its id) and `label`, the plugin's `languages`, `editable` (false in a readonly view and a suggestion's preview: show the label only), `expanded`, `setLanguage(id)`, `toggle()`, `copy()` and `copied` (true for a moment after a copy), and `labels`. `{@attach header.button}` makes your button open the view's language list under it, with the keys and the ARIA.

`menu` draws that list (the first code plugin listed in a view owns it). It renders under the button while `menu.open` is set; `keys` on its search field makes it the `combobox` that holds the keys (<kbd>↓</kbd>/<kbd>↑</kbd> move the highlighted row, <kbd>Enter</kbd> picks it, <kbd>Escape</kbd> closes: the keys go back to the button when they opened the list, else to the editor), `popup` on the list makes it the `listbox` the root names, and each row of `menu.items` spreads its `option` (`current` marks the block's language).

```svelte title="CodeChrome.svelte" check
<script lang="ts">
	import { Edytor, createCodePlugin, type CodeHeader, type LanguageMenu } from 'edytor';

	const plugins = [createCodePlugin({ header, menu })];
</script>

{#snippet header(code: CodeHeader)}
	{#if code.editable}
		<button type="button" {@attach code.button}>{code.label} ▾</button>
	{:else}
		<span>{code.label}</span>
	{/if}
	<button type="button" onmousedown={(event) => event.preventDefault()} onclick={() => void code.copy()}
		>{code.copied ? 'Copied' : 'Copy'}</button
	>
{/snippet}

{#snippet menu(languages: LanguageMenu)}
	<div class="languages">
		<input
			placeholder="Search for a language…"
			value={languages.query}
			oninput={(event) => languages.search(event.currentTarget.value)}
			{@attach languages.keys}
		/>
		<ul {@attach languages.popup}>
			{#each languages.items as item (item.item.id)}
				<li {...item.option} onmousemove={item.select} onclick={item.run}>
					{item.item.label}{#if item.current}&nbsp;✓{/if}
				</li>
			{/each}
		</ul>
		{#if languages.items.length === 0}<p role="status">No results</p>{/if}
	</div>
{/snippet}
```


## Comment cards

`card` draws a card of the comments sidebar; the plugin places each card beside its text (under it, on a narrow screen). It receives a `CommentCardPayload`: the `thread` (its `comments`, `quote`, `resolved`), or `null` for the comment being written (its text `comments.draft.quote`: post it with `comments.submit(body)`, give it up with `comments.cancel()`), the view's `comments` controller (`reply`, `resolve`, `reopen`, `remove`, `mayDelete`, `userOf`) and whether the thread is the `active` one. `header` draws the top of the margin (Notion's "Resolved (2)" toggle: `comments.resolved`, `comments.showResolved`); the cards stack under it. Without `card`, no sidebar shows: the threads are still highlighted and kept. See [Comments](/docs/plugins/comments).

```svelte title="CommentsEditor.svelte" check
<script lang="ts">
	import {
		Edytor,
		createCommentsPlugin,
		createMemoryCommentsClient,
		type CommentCardPayload
	} from 'edytor';

	const plugins = [
		createCommentsPlugin({ client: createMemoryCommentsClient({ user: 'ada' }), user: 'ada', card })
	];
</script>

{#snippet card({ thread, comments, active }: CommentCardPayload)}
	{#if thread}
		<article class:active>
			<blockquote>{thread.quote}</blockquote>
			{#each thread.comments as comment (comment.id)}
				<p><strong>{comments.userOf(comment.author).name ?? comment.author}</strong> {comment.body}</p>
			{/each}
			{#if thread.resolved}
				<button onclick={() => void comments.reopen(thread.id)}>Re-open</button>
			{:else}
				<button onclick={() => void comments.resolve(thread.id)}>Resolve</button>
			{/if}
		</article>
	{:else}
		<form
			onsubmit={(event) => {
				event.preventDefault();
				const field = new FormData(event.currentTarget).get('body');
				void comments.submit(String(field ?? ''));
			}}
		>
			<textarea name="body" aria-label="Add a comment…"></textarea>
			<button type="button" onclick={() => comments.cancel()}>Cancel</button>
			<button>Comment</button>
		</form>
	{/if}
{/snippet}
```


## Version history

The [version history](/docs/server/history-panel) is a controller you make in your component: `new VersionHistory({ client, document })` lists the room's versions (`versions`, newest first), previews one (`select(key)`, `selected`, `preview`, `previewPlugins`, `diff` against the live `document`), restores it (`restore()`, `undo()`, `busy`, `undoable`, `status`, `failed`) in your words (`status` is a code; `dateOf(version)` and `timeOf(version)` format a version's day and time, `version.slot` its half of the day, `version.editors` who edited it). Each row spreads `option(index)`: an `option` of your listbox, its one tab stop when selected; the list's `onkeydown={history.keys}` walks them (<kbd>↑</kbd>/<kbd>↓</kbd>, <kbd>Home</kbd>, <kbd>End</kbd>). Make it in the component's script: its effects list the versions and follow the document.

```svelte title="Versions.svelte" check
<script lang="ts">
	import { untrack } from 'svelte';
	import { Edytor, VersionHistory, createHistoryClient, type EdytorDocument } from 'edytor';

	let { room, document }: { room: string; document: EdytorDocument } = $props();
	const client = createHistoryClient({ server: 'https://example.com/history', room });
	const history = untrack(() => new VersionHistory({ client, document }));
</script>

<ul role="listbox" aria-label="Versions" onkeydown={history.keys}>
	{#each history.versions ?? [] as version, index (version.key)}
		<li role="presentation">
			<button type="button" {...history.option(index)} onclick={() => void history.select(version.key)}>
				{history.dateOf(version)} <small>{version.editors.join(', ')}</small>
			</button>
		</li>
	{/each}
</ul>
{#if history.preview}
	{#key history.previewKey}
		<Edytor readonly value={history.preview} plugins={history.previewPlugins} />
	{/key}
{/if}
<button disabled={history.busy || !history.shown} onclick={() => void history.restore()}>
	Restore version
</button>
<p role="status">{history.status}</p>
```

## Block handle

`handle` draws the `+` and the grip beside each block: list `createBlockHandlesPlugin({ handle })` (without a `handle`, no handle shows). `use:grip` gives any element the grip's behavior: dragging (every block the selection covers when it covers this one, with the count preview), a click that selects the block and opens the block menu (its `edytor-block-activate` event), and the <kbd>Alt</kbd>+arrow moves. `add(alt?, anchor?)` is what the `+` does: it opens the slash menu under `anchor` (pass your button, `event.currentTarget`; else under the block), and adds nothing until a row is picked. `expanded`, `controls` and `haspopup` say which menu the `+` or the grip opened while it is open (their `aria-expanded`, `aria-controls` and `aria-haspopup`), `beside` that Alt+click adds a column (a block in a column); name the buttons in your words after `label`. Placement beside the block's first line and the hover fade are the plugin's.

A drag's drop indicator is placed by the plugin too: style `[data-edytor-drop-indicator]` (the 4px bar where the blocks land) and `[data-edytor-drop-backdrop]` (the future parent's row; `data-shown` while the drop nests). See [Block handles](/docs/plugins/block-handles#the-handle).

```svelte title="Handles.svelte" check
<script lang="ts">
	import { Edytor, createBlockHandlesPlugin, type BlockHandleSnippetPayload } from 'edytor';

	const keep = (event: MouseEvent) => event.preventDefault();
	const plugins = [createBlockHandlesPlugin({ handle })];
</script>

{#snippet handle({
	label,
	grip,
	add,
	readonly,
	expanded,
	controls
}: BlockHandleSnippetPayload)}
	{#if !readonly}
		<button
			class="add"
			aria-label={`Add a block below ${label}`}
			aria-expanded={expanded.add || undefined}
			aria-controls={controls.add}
			onmousedown={keep}
			onclick={(event) => add(event.altKey, event.currentTarget)}>+</button
		>
		<button
			class="grip"
			use:grip
			aria-label={`${label} block`}
			aria-expanded={expanded.grip || undefined}
			aria-controls={controls.grip}>⠿</button
		>
	{/if}
{/snippet}

<Edytor {plugins} />

<style>
	:global([data-edytor-drop-indicator]) {
		background: rgba(35, 131, 226, 0.43);
	}
</style>
```
