# Adversarial review — edytor (arch-v2)

**Repository:** `/Users/arnaud/code/edytor-arch-v2`, branch `arch-v2` · **Date:** 2026-09-29

## Executive summary

The arch-v2 engine is in better shape than its age suggests: convergence is fuzzed hard and held in every race the reviewers threw at it, the room protocol and providers have hand-authored tests for the happy paths, the lib is cleanly partitioned, the editing core passes the Notion-parity suite it names, and the docs are accurate on ~80 spot-checked claims. Of 54 findings, 50 were independently confirmed, 4 refuted, none left uncertain.

The bugs that remain are _convergent-but-wrong_ outcomes and _failure-path_ holes that no oracle looks at. Do these first: **(1)** undo of a raced type/data write leaves the attr undefined and throws inside `Block.svelte` for the whole room (UW-01); **(2)** compaction runs inside the room's `update` observer, and one throw silently inverts store-before-ack for the rest of the object's life (UW-02); **(3)** a late seed with shared ids, reachable through the 1 s readiness bound on a cold Durable Object, erases every edit since the snapshot for everyone (UW-03, UW-04); **(4)** the restore path (`onLoad`) is wrong three ways — generation row before `onLoad`, refused payloads crash-loop the object, and registrations are dropped so returning clients are locked out forever (UW-05/06/07); **(5)** the documented SSR path leaks a document per request (UW-09). Everything else is P1/P2 polish: Notion divergences on Backspace/Enter/divider, the dispatcher not owning undo policy, and docs drift (README vs site).

What is solid: placement LWW and text ownership under concurrency, the 150-seed corpus and p1 harness, identity forwarding and forged-header defence, the join rule / chunking / generation gates, the one-owner-per-fact module layout, the two-phase facade, and the site's collaboration and server pages.

**UW-01 · Undo/redo of a raced type/data write leaves the attr undefined and crashes rendering on every replica** — CRDT · critical · M

- _Files:_ `src/lib/crdt/edytor-doc.ts:916-929, 968-972, 986-997, 1228-1231`, `src/lib/crdt/document.ts:782-786`, `src/lib/crdt/text/runs.ts:509, 755`, `src/lib/components/Block.svelte:75`, `src/lib/edytor.svelte.ts:482-493`, `src/tests/crdt/arch-v2/p1-harness.ts:180-205`, `src/lib/attribution/block.ts:256-267`.
- _Failure:_ Alice (larger clientID) retypes a block to heading while Bob retypes it to quote; both sync; Alice presses Cmd+Z. The `type` item chain is all-deleted on every replica, `blockTypeOf` reads `undefined`, `toJSON` emits `type: ''`, `getBlockDefinition` throws inside a `$derived` with no boundary — the room stops rendering, persistently. Same for `setBlockData`, `setInlineData`, and redo.
- _Fix:_ Recovery must be a **write**, not a read (non-tip map items are deleted and GC'd at integration; a read-side `liveAttr` walk returns `undefined` too and would diverge across replicas because the undoer keeps content the peers don't). Make `blockJSON` assert in DEV instead of emitting `type: ''`.
- _Done when:_ p1 scenarios for `setBlockType`/`setBlockData`/`setInlineData` × undo and redo × both client-id orders assert a defined, registered type on both replicas and after binary reload; `wellFormed` fails on `type === ''`/`'unknown'`; a sibling probe checks `lastChangedBy` after undo when the undoer won LWW.
- _Depends on:_ none. UW-17 is defence in depth, not a substitute.

**UW-02 · Compaction runs inside the room's `update` observer; one throw permanently silences the doc (acked but never stored or relayed)** — Durable Object · critical · M

- _Files:_ `src/lib/cloudflare/DocumentRoom.ts:458-475, 479-481, 496-505, 519-533, 717-733`, `src/lib/crdt/vendor/yjs/src/utils/Transaction.js:316-345`.
- _Failure:_ `compact()` throws once (torn record, SQLite fault, CPU on a multi-MB merge) inside `doc.on('update')`; the engine's `_transactionCleanups` never drains and no further `update` fires. Every later edit from every client integrates, is acked `saved:true` via state vector and served to joiners, but no row is inserted and nothing is relayed. - _Done when:_ workerd test with small `EDYTOR_COMPACT_AFTER` and a `BEFORE DELETE ON rows` (or snapshot INSERT) `RAISE(ABORT)` trigger: next update present in `rows`, relayed to a second RawClient, acked only after the row exists, sender socket open, `refusals` has a `storage` entry; small engine-lane vitest pins "an observer throw wedges later `update` emits" so the guard has a stated reason.

**UW-03 · A late seed of a non-identical value with shared block ids replaces live registry nodes (erases edits since the snapshot for everyone)** — CRDT · high · M

## Per-area notes
