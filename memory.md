# Procedural memory

- When asked to integrate a capability already present in a pinned dependency, inspect its implementation and examples before expanding the discussion into product feature discovery. Separate the supplied mechanism from application lifecycle and persistence wiring. Verify the distinction with a small executable probe; do not propose a replacement merely because the current application does not expose it.
- Treat comments explaining historical workarounds as hypotheses about the current version. Test the current artifact through a representative consumer before preserving or retiring a workaround. Keep the scope of that proof explicit: a narrow type-check does not establish compatibility for the whole application.
- Keep deterministic-test replay artifacts outside runner-owned output directories, because test runners can clean those directories before replay starts. Write a pending artifact before reduction so the original schedule survives timeout or interruption.
- A deterministic browser result must identify the code that actually ran. Start a fresh isolated preview for the run and record a hash of tracked changes plus relevant untracked inputs; never reuse a mutable preview while claiming a source revision.
- When evaluating simulation coverage, distinguish seeded input generation from deterministic execution. Inventory controlled randomness, time, delivery, persistence and callbacks, then verify fresh-process trace replay before claiming execution determinism. Assess oracle independence separately: more seeds cannot detect a correctness rule that is never asserted.
- Browser assertions for visible editor text must join every serialized text part in a block. Attribution and mark boundaries can split one logical string into several parts, so reading only `content[0]` can report a false product failure.
- When an async selection restore loses a race, trace the competing `setAt*` call to the operation that owns it. Suppress the competing repair with the existing command-ownership signal when possible; do not weaken the generic stale-write guard to force the desired call through.
- When a rich-text editor shows the intended DOM caret but typing changes another block, inspect the model's atomic selection before changing focus timing. Verify both the DOM anchor and the model selection, then test an actual keystroke against the intended block and its previous neighbor.
- For visual editor changes, verify hover, post-menu selection, and nested drag results in a real browser. Static alignment checks can pass while an interaction leaves a bad color, selection state, or child layout.
- When a high-level browser drag misses a small or collapsed drop target, inspect the indicator during a scrolled-into-view mouse drag before diagnosing the move command. Verify that the proposed position appears and that the drop commits; a missed synthetic target is not evidence of a model defect.
- When estimating replicated metadata size, separate current logical state, encoded CRDT history, and update traffic. Measure a fresh single-writer case and an actor-switching case with equivalent payloads and history settings; replacing one map value can retain old CRDT entries, so a constant-size visible field does not prove bounded serialized storage. Label encoding prototypes separately from concurrency and migration qualification.
- A mocked dependency clock controls only the time reads that demonstrably reach that import; it does not control timers or pending callbacks automatically. Test the seam and inventory remaining scheduling sources. Fresh-process trace equality is evidence only for what the trace records: include action arguments, message identity/order/payload, and observable outcomes before treating a digest as a replay proof.
- Verify headless selection limits against the installed runtime before declaring a browser-only case. A helper that constructs a backward DOM Range can collapse it even when Selection.setBaseAndExtent preserves anchor/focus direction. Keep layout-derived visual lines and native target-range generation distinct from logical range support.
- Probing production output is discovery, not a correctness oracle. Establish intended semantics independently before writing expected states; hand-copying an unexpected result can canonize a defect. Keep behavioral expectations free of production decision helpers and assert identity, structure, unselected content, and continuation where they matter.
- Shared runner helpers do not guarantee shared assertions: when a validation step (e.g. input-intent verification) lives in a per-action wrapper, check every runner that calls the wrapper rather than assuming the lane inherits it.
- When successive reviews expose neighboring variants of the same failure, consolidate the behavioral contract and its semantic owner before requesting more isolated patches. Preserve active work, specify a bounded boundary-case matrix independently of production, and agree on a finite qualification gate. Stop after that gate passes instead of expanding adversarial scope indefinitely.
- For a first-principles redesign, separate required behavior and environmental constraints from inherited mechanisms before proposing layers or data types. Inventory each fact's authority and lifetime, then require candidate representations to name the decisions they eliminate, the invariant replacing them, and an independent counterexample. Make the execution plan definite while leaving untested representation choices subject to bounded experiments; verify compression in a second placement and a composed extension.
- In concurrency tests, distinguish observation checkpoints from settlement barriers. Keep ordinary command-result checks settled, but deliberately interleave deliveries and newer user intent with pending callbacks in race programs, then assert their specified combined result. Across alternative implementations, replay equivalent logical actions and targets; a shared RNG seed or packet index does not guarantee equivalent stimuli when generation depends on live state.
