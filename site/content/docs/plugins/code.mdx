`codePlugin` adds code blocks. A code block is an island that holds one `codeLine` child per line of code, in a language its header picks; each line is highlighted with TanStack Highlight (`@tanstack/highlight`, a dependency of `edytor`), whose grammars load the first time a line of their language renders.

```svelte title="Editor.svelte" check
<script lang="ts">
	import { Edytor, codePlugin } from 'edytor';
</script>

<Edytor plugins={[codePlugin]} />
```

`codePlugin` is `createCodePlugin()`. Importing it also imports its stylesheet, which gives code blocks Notion's look.

```ts check title="plugins.ts"
import { createCodePlugin, CODE_LANGUAGES } from 'edytor';

// Python by default, and only the languages this app writes.
export const code = createCodePlugin({
	defaultLanguage: 'python',
	languages: CODE_LANGUAGES.filter((language) =>
		['plaintext', 'python', 'sql', 'bash'].includes(language.id)
	)
});
```

## What it adds

| Definition | Kind  | Details                                                                                          |
| ---------- | ----- | ------------------------------------------------------------------------------------------------ |
| `code`     | block | An island that renders only its children, under a header with the language and a Copy button.   |
| `codeLine` | block | One line of code. The default child of `code`.                                                   |
| `codeToken`| mark  | A highlighting token, rendered as `<span class="th-…">`. Computed on render, never stored.       |

A code block has one preset, "Code", with the command id `block.code`, the markdown shortcut ` ``` ` (three backticks typed at the start of an empty block) and the slash menu section `Media`. <kbd>Mod</kbd> + <kbd>Alt</kbd> + <kbd>8</kbd> converts to it when the rich text plugin is loaded, as it is by default. An empty block converts in place, into a code block of one empty line. A block with text or children stays as it is: the command (the slash menu, the chord) inserts an empty code block after it instead, and the caret moves to its line. See [Presets](/docs/customization/blocks#presets).

A stored code block looks like this:

```json
{
	"type": "code",
	"data": { "language": "javascript" },
	"children": [
		{ "type": "codeLine", "content": [{ "text": "const idea = \"start somewhere\";" }] },
		{ "type": "codeLine", "content": [{ "text": "console.log(idea);" }] }
	]
}
```

## Languages

A code block's language is its `data.language`, an id from the plugin's `languages` (`code.language`). A block without one, as every code block stored before the picker was, is in the default language, JavaScript. The header names the language by its label (`code.language.label`): a language the plugin does not list shows its id as stored, and its lines are plain text.

The header's language is a button (`button[data-edytor-code-language]`, named "Code language: JavaScript", with a chevron) that opens the language list under it, in the overlay, as in Notion (`code.language.picker`): a search field over the languages by label, the block's own marked with a check and highlighted. Typing filters the rows by label or id (`script` keeps JavaScript and TypeScript, `cpp` keeps C++); a click on a row, or <kbd>Enter</kbd> on the highlighted one, sets `data.language`. A pick is one `patchData` command, so it is one undo step, refused in a readonly view, and seen by hooks; a collaborator's concurrent edits of the block's other data are kept. The block's lines render again in the new language, its grammar loaded if it is the first of its kind. A readonly view and a suggestion's preview show the label only, as a `<span data-edytor-code-language>`.

The keyboard reaches it all:

| Keys | Where | Action |
| --- | --- | --- |
| <kbd>Alt</kbd> + <kbd>F10</kbd> | At a caret in a code line | Move the focus to the block's language button (as to a toolbar) |
| <kbd>Enter</kbd>, <kbd>Space</kbd>, <kbd>ArrowDown</kbd>, <kbd>ArrowUp</kbd> | On the language button | Open the list, its search field focused |
| <kbd>Escape</kbd> | On the language button | Give the keys back to the code, the caret where it was |
| Typing | In the search field | Filter the languages; the first one left is highlighted |
| <kbd>ArrowDown</kbd>, <kbd>ArrowUp</kbd> | In the search field | Move the highlighted row, around the ends |
| <kbd>Enter</kbd> | In the search field | Pick the highlighted language |
| <kbd>Escape</kbd> | In the search field | Close the list, the language as it was |

The search field is a `combobox` naming the highlighted row (`aria-activedescendant`) of a `listbox`; the button carries `aria-haspopup="listbox"` and `aria-expanded`. A list the keys opened gives them back to its button; one a click opened, to the editor, its caret where it was. A press or a focus outside the list closes it, as does the view turning readonly.

`CODE_LANGUAGES` holds the default list, after Notion's:

| `id`         | Label      | Grammar                                    |
| ------------ | ---------- | ------------------------------------------ |
| `plaintext`  | Plain text | none: no tokens                            |
| `bash`       | Bash       | `shell`                                    |
| `cpp`        | C++        | `cpp`                                      |
| `css`        | CSS        | `css`                                      |
| `diff`       | Diff       | `diff`                                     |
| `docker`     | Docker     | `dockerfile`                               |
| `go`         | Go         | `go`                                       |
| `html`       | HTML       | `html`, with `css`, `js` and `ts` for its style and script elements |
| `javascript` | JavaScript | `jsx` (also covers plain JavaScript)       |
| `json`       | JSON       | `json`                                     |
| `markdown`   | Markdown   | `markdown`                                 |
| `mermaid`    | Mermaid    | `mermaid`                                  |
| `php`        | PHP        | `php`                                      |
| `python`     | Python     | `python`                                   |
| `sql`        | SQL        | `sql`                                      |
| `svelte`     | Svelte     | `svelte`, with `css`, `js` and `ts`        |
| `toml`       | TOML       | `toml`                                     |
| `typescript` | TypeScript | `ts`                                       |
| `vue`        | Vue        | `vue`, with `css`, `js` and `ts`           |
| `xml`        | XML        | `html`                                     |
| `yaml`       | YAML       | `yaml`                                     |

A `CodeLanguage` is `{ id, label, grammar?, load? }`: `grammar` names the TanStack Highlight grammar its lines are tokenized with, and `load` resolves to that grammar and the ones it embeds. Add a language by passing your own row:

```ts check title="languages.ts"
import { createCodePlugin, CODE_LANGUAGES, type CodeLanguage } from 'edytor';

const nginx: CodeLanguage = {
	id: 'nginx',
	label: 'Nginx',
	grammar: 'nginx',
	load: () => import('@tanstack/highlight/languages/nginx').then((m) => [m.nginx])
};

export const code = createCodePlugin({ languages: [...CODE_LANGUAGES, nginx] });
```

## Highlighting

Grammars load lazily (`code.language.lazy`): JSX, the default language's, ships with the plugin; every other grammar is a chunk of its own, loaded the first time a line of its language renders. Until it lands, those lines show as plain text; then they render again, highlighted. A grammar is loaded once per page and shared by every editor. `loadCodeLanguage(language)` starts a load ahead of time and resolves once it is there (a failed load is tried again at the next render).

Each `codeLine` declares a `transformText` that tokenizes its text with its code block's language. Tokens become `codeToken` marks carrying the token's class name. For `const idea = "x";` the tokenizer answers a `keyword` token, plain text, a `string` token and plain text, rendered as:

```html
<span data-edytor-mark="codeToken"><span class="th-keyword">const</span></span> idea = <span data-edytor-mark="codeToken"><span class="th-string">"x"</span></span>;
```

The tokens are decorations: they exist only in the rendered DOM, never in the document, so collaborators and the clipboard see plain text. Each line is tokenized on its own, so a construct spanning lines (a block comment) is highlighted line by line.

The bundled stylesheet colors the `th-*` classes with Notion's light syntax theme:

| Classes                                      | Color     |
| -------------------------------------------- | --------- |
| `th-comment`, `th-meta`                      | `#708090` |
| `th-keyword`, `th-link`                      | `#0077aa` |
| `th-string`, `th-attr`, `th-selector`, `th-inserted` | `#669900` |
| `th-function`, `th-type`                     | `#dd4a68` |
| `th-number`, `th-literal`, `th-tag`, `th-property`, `th-deleted` | `#990055` |
| `th-variable`                                | `#ee9900` |
| `th-operator`                                | `#9a6e3a` |

Override those classes to theme it.

## Editing

Inside a code line:

| Keys                                   | Action                                                                             |
| -------------------------------------- | ---------------------------------------------------------------------------------- |
| <kbd>Enter</kbd>, <kbd>Shift</kbd> + <kbd>Enter</kbd> | Start a new line. <kbd>Enter</kbd> in the empty last line (not the only one) leaves the block: the line is removed and a paragraph after the block takes the caret, one undo step |
| <kbd>ArrowDown</kbd>                   | In the last line, go below the block; with nothing after it, a new paragraph there takes the caret |
| <kbd>Tab</kbd>                         | At a caret, insert a tab character, or accept the line's `end` [suggestion](/docs/editor/suggestions). Over a selection, add a tab at the start of every line it touches, as one undo step; the selection keeps its characters |
| <kbd>Shift</kbd> + <kbd>Tab</kbd>      | Remove one leading tab, or up to two spaces, from the caret's line or every line the selection touches |
| <kbd>Mod</kbd> + <kbd>A</kbd>            | Select the text of the whole code block; press again to select the code block      |
| <kbd>Escape</kbd>                      | Discard the line's `end` suggestions                                               |

- Typing `(`, `[`, `{`, `"` or `'` at a caret also inserts the closing character. A quote pairs only at a word boundary: the apostrophe in `don't` stays single.
- Typing a closing character (`)`, `]`, `}`, `"`, `'`) right before the same character steps over it instead of inserting another: `f(a)` types as `f(a)`, not `f(a))`.
- A line break inside a line splits it: each code line holds exactly one line of text.
- <kbd>Backspace</kbd> at the start of the first line and <kbd>Delete</kbd> at the end of the last line do nothing: a line never merges out of its block.
- <kbd>Delete</kbd> at the end of the block right before a code block removes that block if it is empty, and does nothing otherwise. The caret goes to the end of the text before the removed block, or to the start of the code when nothing comes before it.
- <kbd>Backspace</kbd> in an empty block right after a code block removes that block and puts the caret at the end of the last line. In a block with text it moves the caret to the end of the code and merges nothing.
- Deleting or cutting the whole code text (<kbd>Mod</kbd> + <kbd>A</kbd>, then <kbd>Backspace</kbd>, <kbd>Delete</kbd> or cut) leaves the code block with one empty line and the caret in it.
- A selection that ends at the start of a line leaves that line out of <kbd>Tab</kbd> and <kbd>Shift</kbd> + <kbd>Tab</kbd>, as code editors do.
- <kbd>Tab</kbd> and <kbd>Shift</kbd> + <kbd>Tab</kbd> over several lines change each line with its own command (`insertText` or `deleteContentAtRange`): a line a plugin vetoes stays as it is and the others still change, together one undo step ([Refusing an edit](/docs/plugins/operations#refusing-an-edit)).
- The Copy button, shown while the block is hovered, writes the block's text, lines joined with newlines, to the clipboard, and reads "Copied" for a moment.

A code block is an island: merges never cross its edge, and a block selection walked with the arrow keys does not enter it from outside. It is also not convertible, so the slash menu and markdown shortcuts do not apply inside it.

## Styling

The stylesheet draws the block like Notion's: a `#f7f6f3` panel rounded 10px, padded `34px 16px 32px 32px`, with the language at the top left (a button with a chevron, shaded when hovered or open, ringed when focused from the keyboard) and the Copy button at the top right. The code is set in an `SFMono-Regular`, Menlo, Consolas stack at 85%, with a tab size of 2. No utility classes are involved; everything goes through attributes and classes you can override:

| Selector                        | Element                                        |
| ------------------------------- | ---------------------------------------------- |
| `[data-edytor-type='code']`     | The block panel                                |
| `[data-edytor-code-header]`     | The header, void chrome the caret never enters |
| `[data-edytor-code-language]`   | The language button (`button`, `[aria-expanded='true']` while its list is open), or its label (`span`) in a readonly view |
| `[data-edytor-code-copy]`       | The Copy button                                |
| `[data-edytor-code-language-menu]` | The language list, in the overlay: its search field (`input`) and its rows (`[data-edytor-code-language-option]`, the block's own `[data-current]`, the highlighted one `[aria-selected='true']`); `[data-edytor-code-language-empty]` when no language matches |
| `pre.th-code`                   | The code area                                  |

The panel's colors are custom properties a theme or an app sets on the editor or the block: `--edytor-code-background` and `--edytor-code-color` (the panel and its text), `--edytor-code-chrome-color` (the language and Copy), `--edytor-code-chrome-hover` (their hovered background) and `--edytor-code-accent` (the focus ring and the search field's border).

```css
[data-edytor-type='code'] {
	background: #1f1f1f;
	color: #e6e6e6;
}
[data-edytor-type='code'] pre.th-code {
	font-size: 14px;
}
```

The [Notion theme](/docs/customization/styling#notion-theme) reads the panel color from `--notion-code-panel`.
