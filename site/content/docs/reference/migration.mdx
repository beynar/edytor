Edytor is pre-1.0: a release keeps no compatibility shim beyond the deprecated aliases it names.

- **Upgrading from one pre-release to a later one?** Read [Upgrading between pre-releases](#upgrading-between-pre-releases), from the section named after your current version up. Each section lists what the next release changed: breaking changes first, then what is new, then what was fixed.
- **Upgrading from 0.0.11?** Start with [Upgrading from 0.0.11](#upgrading-from-0011). The [complete list](#complete-list-of-changes) names every public change since, by area.
- **Documents stored by 0.0.11's v13 engine** import through [Importing v13 documents](/docs/reference/v13-import).

## Upgrading between pre-releases

### Unreleased

- **Table rows and columns drag by their grips.** Drag a row's grip up or down, or a column's grip left or right: a blue line shows where it lands, and the drop moves it (its cells with it) in one undo step. A click on a grip still opens its menu, whose Move items stay the keyboard's way. A grip no longer keeps the focus in the editor while pressed (that would stop its drag): <kbd>Escape</kbd> on it, or in its menu, gives the keys back. See [Table](/docs/plugins/table#rows-and-columns).
- **A table stays inside the page.** Resizing a column stops where the table would get wider than the room at its place (the text column, or a layout's column), in the preview and in the width written. A table already wider (widths set on a wider screen) keeps its widths and scrolls sideways in its own box, which no longer widens a page that sizes the editor by its content; its column edges, grips and `+` show only over the part in view. The new `--edytor-table-drop-color` sets the drop line's colour.
- The room logs `size` once when a document reaches 80 % of its quota (`EDYTOR_DOCUMENT_WARNING`, `documentWarning`), and `metrics()` reports the quota as `documentLimit`: watch for documents nearing the maximum size you chose.

### From 1.0.0-rc.1

#### Breaking changes

- **`document.facade` is gone.** Deprecated in `1.0.0-rc.1`, it is no longer in the published types: call the operations on the document itself (`document.insertBlock(…)`, `document.toJSON()`).

#### New

- **An API reference.** The docs list every name each entry point exports, with its declaration and documentation, generated from the published types: [`edytor`](/docs/reference/api/edytor), [`edytor/cloudflare`](/docs/reference/api/edytor-cloudflare), [`edytor/protocol`](/docs/reference/api/edytor-protocol) and [`edytor/crdt/edytor`](/docs/reference/api/edytor-crdt-edytor).

### From 0.1.0-next.44

`1.0.0-rc.1` is the 1.0 release candidate, published under `latest` (`pnpm add edytor`; the `next` tag keeps the pre-releases). Its API is frozen: the published types are the 1.0 contract, and a change to them before 1.0 comes with a note under Breaking changes. `document.facade`, deprecated here, is the one exception: it goes in the next release.

#### Breaking changes

- **`selection.select(value)` takes the value only.** Its second argument named an internal cause (how the projector should treat the change); pass the value alone. The `SelectCause` type is no longer exported.
- **The document's operations are its own; `document.facade` is deprecated.** Call them on the document: `document.insertBlock(…)`, `document.toJSON()`, `document.prepare.splitBlock(…)`, `document.onChange(…)` (the `DocumentOperations` interface). `document.facade` returns the same operations and goes in the next release. What it held besides them (the index, the engine hooks, the history factory) is internal. `edytor` no longer exports `EdytorDoc` (the full binding, still in `edytor/crdt/edytor`): name `DocumentOperations` instead. A room's `transact` callback, its `facade` and `validate`'s `facade` are typed `DocumentOperations` too.
- **The dispatcher's plumbing is internal.** `edytor.dispatcher` keeps `last`, `permits()`, `run`, `each`, `dispatch`, `lead`, `caret` and `outside`; its normalization queue (`defer`, `request`, `drain`, `write`), its undo cut (`cut`), its prevention scopes (`scope`, `intercept`), `authoring` and `pendingLead` are no longer in the published types. `permits()` is now documented: whether the view accepts writes.

#### New

- **`DocumentOperations`, and the document's vocabulary exported.** `edytor` exports `DocumentOperations` (with `DocumentWrites` and `DocumentReads`) and the types its operations take and answer: `BlockId`, `BlockSpec`, `ContentItem`, `Destination`, `InlineSpec`, `ProjectedBlock`, `ProjectedDoc`, `SplitTail`, `DocPosition`, `RangeView`, `FlowView`, `ContentRun`, `DataTarget`, `OrderPolicy`, `PlanEffect`, `PlanStep`, `DocBlock`, `NodeRef`, `MarkEdge`, the semantics' (`DocumentSemanticsConfig`, `KindRecord`, `MergedSemantics`, `SchemaProblem`), the awareness's (`Awareness`, `AwarenessStates`, `AwarenessUpdate`, `MetaClientState`) and the chrome's (`Overlay`, `Measure`, `Cells`, `Cell`, `Popups`, `Popup`, `PopupOpener`, `Announcer`, `Handles`). `document.transact(fn, origin?)` takes an origin.

#### Fixed

- **A drag released where the page cannot see it ends.** Releasing a text selection drag over an embed (a frame of another site) left the editor waiting for the release, so it stopped showing its selection until the next click. The next pointer move ends it.
- **Typing on a very long page does less work.** The block handles found the blocks near the screen by watching every block, which the browser rechecked after each keystroke (about 6 ms a key at 10,000 blocks). They now look up the few blocks near the screen directly.

### From 0.1.0-next.43

#### New

- **Pasted and dropped files become their blocks.** With an `upload`, the video, audio and file plugins take pasted and dropped files as the image plugin does: one block per file, each of the kind that takes it (the file block takes what no other kind does), in order, as one undo step, each showing its upload. `upload` receives a second argument, `report`, whose `progress(fraction)` fills the block's bar (the image block's too); an `upload` that ignores it keeps working. The `Uploader` and `UploadReport` types are exported. See [Pasted and dropped files](/docs/editor/clipboard#pasted-and-dropped-files).
- **Pasting markdown makes blocks.** A plain-text paste (no HTML) with a line of block markdown (a heading, a list or to-do item, a quote, a fence, a divider) becomes the blocks it reads as, with its inline bold, italic, code and links, as one undo step, as in Notion. Text with no block markdown, a paste into a code block and <kbd>Shift</kbd>+paste are unchanged. See [Pasting markdown](/docs/editor/clipboard#pasting-markdown).

### From 0.1.0-next.42

`0.1.0-next.42` was never published to npm: upgrading from `0.1.0-next.41`, read the notes of both sections.

#### Breaking changes

- **Single-owner state is read-only.** `edytor.selection.value`, `selection.selectedBlocks`, `selection.focusedBlocks` and `edytor.dispatcher.last` can no longer be assigned (the sets are `ReadonlySet`s). Assigning `selection.value` used to leave the selected blocks behind; use `selection.select(value)` or a setter (`setCaret`, `setAtTextOffset`, …), which keep them in step.

#### New

- **`edytor.focus()`.** Focuses the editor without scrolling, keeping its selection, or with none putting the caret at the start of the first text. It replaces `edytor.node?.focus()` after setting a selection from a menu button.

- **The types you meet are exported.** `edytor` now exports the types its props, options, members and callbacks use, so an app can name them: `EdytorProps`, `EdytorOptions`, `Snippets`, every plugin's labels type (`RichTextLabels`, `TableLabels`, …), `Dispatcher`, the selection's (`SelectionValue`, `SelectionPoint`, `SelectionSegment`, `SelectionProjection`, `SelectionState`, `SelectCause`, `PresenceSelection`, `TextAnchor`), a hotkey's `Key`, `Modifier` and `Modifiers`, the plugin author's (`BlockView`, `InlineBlockView`, `BlockElement`, `InitializedPlugin`, `PluginDefinitions`, `PluginOperations`, `TextOperations`, `BlockOperations`, `BlockBeside`, `TriggerRange`, `TextInsertionPayload`, `RichTextLink`, `RichTextMark`), the document's (`EdytorDoc`, `DocumentOptions`, `DataPatch`, `TextRange`, `BlockRole`, `DocAnchor`, `AnchorAffinity`, `Flow`, `FlowLine`, `FlowTarget`, the attribution types) and the sync's (`PrefetchOptions`, `PrefetchResult`, `LastUpdatedOptions`, `EdytorSyncCleanup`, `WebsocketTarget`, `ProtocolMismatch`, `SchemaMismatchDetail`, `CommentMessage`, `AwarenessLike`, `PresenceWriter`).

### From 0.1.0-next.41

#### Breaking changes

- **Comments have quotas.** Comments are on in every room, so the room now bounds them: their stored bytes (`maxBytes`, `EDYTOR_MAX_COMMENT_BYTES`, 4 MiB by default; past it a new thread or reply answers `413`) and their request rate (`maxRequestsPerSecond`, `EDYTOR_MAX_COMMENT_REQUESTS_PER_SECOND`, 2 a second with a ten-second burst, per user over HTTP: past it `429`; per socket for its subscribes, which are dropped past it). A subscribe on a socket already subscribed no longer sends a second snapshot, and `routeDocumentComments` reads a body no further than 64 KiB even without a `Content-Length`. Raise the limits if your pages hold more; a client that posts in bursts should retry a `429`. See [Server comments](/docs/server/comments#quotas).

#### New

- **Comment quota exports.** `edytor/cloudflare` exports `DEFAULT_MAX_COMMENT_BYTES`, `DEFAULT_MAX_COMMENT_REQUESTS_PER_SECOND`, `COMMENT_ROW_BYTES` and `commentBytes`; `decideComment` takes `bytes` and `maxBytes`; the refusal reason `comments` is logged and counted in `refusalCounts`.

#### Fixed

- **Typing in a table no longer slows down with its size squared.** Each cell worked out its column by reading every cell of the table, so a keystroke re-rendered every cell, each reading every other one. A cell now reads only its table's column list; a keystroke costs the cell and one pass of the table's chrome.

### From 0.1.0-next.40

#### Breaking changes

- **The handles' raw write primitives are internal.** `Text.insertAt`, `deleteAt` and `formatAt`, and `Block.insertChildren`, `deleteChildren` and `insertParts`, wrote to the shared document directly: no hooks, no undo step of their own, and they wrote even on a readonly view. They are no longer in the published types, and on a view that refuses writes (readonly, a read-only document) they write nothing. Use the commands instead (`text.insertText`, `text.markText`, `block.deleteContentAtRange`, `block.insertBlockAfter`…), or `edytor.document.facade` for a deliberate raw write outside every view.

No package change: 0.1.0-next.39 was tagged but not published (a test of its CI run failed); this release carries it. Upgrading from 0.1.0-next.38, read the section below.

### From 0.1.0-next.38

#### Breaking changes

- **The deprecated aliases are gone.** Each had its release; rename before you upgrade:

  | Removed | Use |
  | --- | --- |
  | `hotKeys` (the `<Edytor>` prop and the `Edytor` option) | `hotkeys` |
  | `blockDnd` (the `<Edytor>` prop) | `blockHandles` (`blockHandles={false}` hides the handles) |
  | `serverUrl`, `roomName` (`createWebsocketSync`, `prefetch`, `lastUpdated`, `documentSnapshot`) | `server`, `room` |
  | `attachDocument(this, options)`, `AttachDocumentOptions` (`edytor/cloudflare`) | `attachRoom(this, options)`, `AttachRoomOptions` |
  | `moveBlocks(namespace, move)` (`edytor/cloudflare`) | `moveBlocksBetweenRooms(namespace, move)` |
  | A KV namespace itself as `history.store` | `kvHistory(namespace)` |
  | `block.suggestText({ value })`, `block.suggestions`, `block.acceptSuggestedText()` | `edytor.suggestions.add({ end: block.id }, content)`, `edytor.suggestions.at(block.id).end`, `suggestion.accept()` |
  | `MigrateOptions.leaseMs`, `waitMs`, `pollMs`, `owner` and `waitForSettled(name, options)`'s options (no-ops) | nothing: leave them out |

  - A `hotKeys` or `blockDnd` prop (or a `hotKeys` option to `new Edytor`) is ignored, whatever its value: no binding is registered and the handles stay. In development it warns, naming the replacement.
  - `createWebsocketSync({ serverUrl, roomName })` throws a `TypeError` that names `server` and `room`.
  - A room whose `history.store` is a bare KV namespace keeps no history: it notes a `history` refusal (`history.store: not a HistoryStore`) at its first use of the history, listing versions answers `404` and a restore throws. Nothing else fails, so check the room's refusals after upgrading. The `EDYTOR_HISTORY` binding is unchanged: the room still wraps a KV binding in `kvHistory` itself. `kvHistory` writes what earlier releases wrote, so their versions list, preview and restore as before.

- **Pre-release stored formats still load (nothing to do).** Documents stored by 0.1.0-next.6 (atomic array leaves, the whole-`data` attribute), containers written by 0.1.0-next.22 (no storage format) and alarms armed by 0.1.0-next.23 all load as before. They are all schema generation 4, so they reach this release through the generation cutover, which reads them with this build's reader: that reader is kept.

### From 0.1.0-next.37

#### Fixed

- **Chrome follows the blocks when they move with no edit.** Block handles and the other chrome were measured again only on an edit, a scroll or a resize of the editor or the window. A block laid out again without one (a font or a stylesheet that loads late, an equation KaTeX draws after the first render, an editor whose height the page fixes) left every handle beside its block's old place. The overlay now also measures again when a block's element changes size. Nothing to change in your code.
- **<kbd>↑</kbd> at the end of a wrapped cell's first line stays in the table's column.** Where a cell's first line wraps, the caret at that line's end is also the next line's start, and the browser does not say on which line it shows it. The arrow was left to the browser there, which moved the caret to the row's other cell (the line before it in the page's order), not the cell above; <kbd>↓</kbd> at the start of the last line did the same with the next cell. The key now moves the caret to that edge line: the next press leaves the cell. Nothing to change in your code.

### From 0.1.0-next.36

#### Breaking changes

- **`Doc.keepReplaced` is per document.** Binding the engine no longer sets the engine's class default: `Y.Doc.keepReplaced` stays `null` (upstream's behavior) for every other document of the engine in your app. Each edytor document carries the rule on itself (`doc.keepReplaced`): `createDocument`, `attachDocument`, `bindCrdt(Y).createDoc()`, the new `bindEdytorDoc(Y).newDoc()`, and any document a facade binds (`create(doc)`; a rule you set yourself stays).
  - A document must carry it before it integrates edytor content. A server or a script that built its document with `new Y.Doc()` and applied stored updates before binding builds it with `createDoc()` instead ([Protocol](/docs/server/protocol)).
- **`DocChange` is read-only.** Its collections are typed `ReadonlyMap`/`ReadonlySet`: the report is one object shared by every subscriber of the document (each view over it, its cells included). Code that changed it in place copies it first (`new Map(change.added)`).
- **New bundled roles: `table`, `tableRow`, `tableCell` and `equation`.** They are in `defaultSemantics`, so the room and headless documents read tables and equations as views with the plugins do. An app that defined its own kind of one of these names with other roles gets a `SemanticConflictError` against `defaultSemantics`: rename the kind, or give the document its own `semantics`.
- **The `comment` mark has a bundled edge.** `defaultSemantics` gives the `comment` mark the `exclusive` edge (`commentMarks`, a new export of `edytor/crdt/edytor`). A `comment` mark record of your own (the earlier recipe) that declares another `edge` now conflicts with it when the view mounts (`SemanticConflictError`): remove its `edge`, or use the comments plugin.
- **The history panel's count words are functions.** `added`, `removed`, `changed` and `moreEditors` were `'{n} added since'`-style templates and are now `(count) => string`, so a language inflects them. Replace a template with a function: `added: (count) => \`${count} ajoutés depuis\``.
- **A complete label dictionary has new sections.** A dictionary of your own typed `Labels` (`satisfies Labels`) adds the `comments`, `table`, `mention`, `history` and `equation` sections, the `editor` section's `triggerMenu`, `searching` and `noResults`. The slash menu's `groups` labels have two new keys to translate, `Color` and `Inline`. See [Localization](/docs/customization/localization).

#### New

- **Comments (opt-in).** `createCommentsPlugin({ client, user, users?, onComment?, card?, labels? })` adds Notion's comment threads: select text, press Comment in the toolbar (or <kbd>Mod</kbd> + <kbd>Shift</kbd> + <kbd>M</kbd>), and the thread shows in a sidebar beside the text (under it on a narrow screen), with replies, Resolve and Re-open. See [Comments](/docs/plugins/comments).
  - A thread's text is highlighted while it is open. Its anchor is a `comment:<id>` mark (one `addComment` command and undo step), kept through splits and merges, `exclusive` at its edges, and not copied.
  - Threads are kept by a client: `createCommentsClient({ server, room, socket?, params?, fetch? })` over the room, or `createMemoryCommentsClient({ user })` in memory (`client.as(user)` for another user of the same threads).
  - The room stores threads in two new tables, `threads` and `comments`, and the last change's sequence number in `meta` (`comments`). `routeDocumentComments(request, rooms, id, authorize, options?)` answers `GET` (every thread) and `POST` (`add`, `reply`, `resolve`, `reopen`, `delete`), authorized like `routeDocumentHistory`; `listComments()` and `comment(request, { user, readOnly?, moderator? })` are the same over RPC. See [Server comments](/docs/server/comments).
  - The room removes a removed thread's anchor marks. Override `onComment(change)` (or pass `attachRoom(this, { comments: { onComment, maxLength } })`) for notifications; `EDYTOR_COMMENTS=off` (or `comments: false`) keeps none.
  - A new message type, `messageComments` (`6`), carries a socket's subscribe and the room's snapshot and changes. The room sends it only to a socket that subscribed, so the generation is unchanged and older clients are unaffected. The shipped provider subscribes while a listener watches its room ([the protocol](/docs/server/protocol#comments)).
  - A room of an earlier pre-release closes a socket that subscribes (`1008`): upgrade the room before listing the plugin.
  - New exports: `createCommentsPlugin`, `commentsController`, `createCommentsClient`, `createMemoryCommentsClient`, `CommentRequestError`, `commentAnchors`, and the types `CommentsPluginOptions`, `CommentsController`, `CommentDraft`, `CommentNotice`, `CommentUser`, `PlacedThread`, `CommentsClient`, `CommentsClientOptions`, `MemoryCommentsClient`, `MemoryCommentsClientOptions`, `CommentDocument`, `CommentFeed`, `CommentResult`, `CommentChange`, `CommentRequest`, `CommentRun`, `CommentSnapshot`, `CommentThread`, `ThreadComment`.
  - From `edytor/cloudflare`: `routeDocumentComments`, `CommentOptions`, `COMMENT_STATUS`, `MAX_COMMENT_LENGTH`, `MAX_COMMENTS_PER_THREAD`, `MAX_THREADS`, `commentAnchors`, `decideComment` and the comment types (`CommentActor`, `CommentOutcome`, `CommentRefusal`).
  - From `edytor/protocol`: `messageComments`, `commentsSubscribe`, `commentsSnapshot`, `commentsChange`, `writeCommentsSubscribe`, `writeCommentsSnapshot`, `writeCommentsChange`, `readCommentsMessage`, `CommentMessage`, `CommentSnapshot`, `CommentChange`, `CommentThread`, `ThreadComment`.
- **Marks.** A mark record's new `copy: false` leaves the mark out of copy and cut; `toolbar.run` makes its toolbar button call `run` instead of toggling it.
- **Tables (opt-in).** `tablePlugin`, `createTablePlugin({ rows, columns, columnWidth, minColumnWidth, labels, keywords })`, `isTablePlugin`, `TablePluginOptions`: Notion's simple table, a `table` of `tableRow`s of `tableCell`s, each cell a text island whose lines are line breaks. See [Table](/docs/plugins/table).
  - Keys: <kbd>Tab</kbd> and <kbd>Shift</kbd>+<kbd>Tab</kbd> walk the cells (Tab in the last one adds a row; Shift+Tab in the first leaves the caret), <kbd>↑</kbd>/<kbd>↓</kbd> go up and down a column from a cell's first or last line as it wraps on screen, <kbd>Enter</kbd> is a line break in a cell and <kbd>Backspace</kbd> at a cell's start does nothing.
  - Hovering a table shows a `+` under it (a row) and beside it (a column), a row's and a column's grip with their menus (insert, move, delete) and a resize band on each column's edge. The table's block menu inserts and deletes rows and columns at the caret's cell and has Header row and Header column switches.
  - Undoing a column insert keeps a cell holding another person's text, in a column shown last. HTML `<table>` paste and copy. An empty cell shows no placeholder, whatever the editor's `placeholder`.
  - `tableBlock(options)` (root and `edytor/crdt/edytor`) builds a table as JSON with ids derived from its value; `TableBlockOptions` is its type.
- **The `table` role.** `BlockRole.table` and `BlockDefinition.table`: a kind displays only its rows (its `defaultChild`), a row only its cells (the row's `defaultChild`), in the order of the table's `data.columns` (`{ id, width? }`, each cell naming its column in `data.column`). `tableKinds` and `tableSemantics` are on `edytor/crdt/edytor`.
  - A cell of no listed column, a second cell for one, a row showing no cell and a table showing no row do not show; a row showing no cell for a column is padded by the view.
- **Table operations on the document.** `prepare.insertTableRow`, `deleteTableRows`, `insertTableColumn`, `deleteTableColumn`, `moveTableColumn`, `moveTableRows`, `fillTableCell` (and their applied forms), and the reads `isTable`, `isTableRow`, `isTableCell`, `tableOf`, `tableColumns`, `tableGrid` (the listed columns, then any shown unlisted: an undone insert's, holding someone's text).
  - A cell never moves as a block, never merges and never splits (`canPlace`, `canMerge`, `splitBlock` refuse it); a row moves only within its table.
  - A text range with an end in a cell deletes each crossed cell's covered text and removes no cell; a flow pasted into a cell joins its text.
  - Hooks see the view's table commands under the same names (`BlockOperations`).
- **Kind rows in the block menu.** `BlockDefinition.menu(block)` returns rows (`KindMenuAction`: `id`, `label`, `icon?`, `checked?`, `isEnabled?`, `run`) the block menu shows for a block of that kind opened alone, after Color. A row with `checked` is a switch (`menuitemcheckbox`, the menu stays open); any other row closes the menu after it runs (a caret its action placed stays). `BlockMenuAction` gained `checked`.
- **Equations (opt-in).** `createEquationPlugin({ katex, macros, labels, keywords })` adds Notion's block equation (`equation`, void, its TeX in `data.expression`) and inline equation atom (`inlineEquation`), drawn by KaTeX. See [Equation](/docs/plugins/equation).
  - Your app loads KaTeX lazily (`katex: () => import('katex')`); `katex` is an optional peer dependency, and its stylesheet is yours to import.
  - A click, or <kbd>Enter</kbd> on a selected equation, opens its source in an editor under it, the equation the live preview. "Block equation" and "Inline equation" are slash commands; `$$…$$` typed in text and <kbd>Mod</kbd>+<kbd>Shift</kbd>+<kbd>E</kbd> make inline equations.
  - Copy writes MathML with a TeX annotation, and HTML import reads KaTeX's markup and `<math>` back.
  - `equationKinds` and `equationSemantics` are on `edytor/crdt/edytor`. New root names: `createEquationPlugin`, `EquationPluginOptions`, `EquationData`, `KatexLike`, `KatexLoader`.
- **Inline atoms in HTML.** `InlineBlockDefinition` takes `html(data)` (its clipboard HTML; the default is still the empty `data-edytor-inline-block` span) and `parse(element)` (HTML import claims an element inside a line as the atom, its contents not read as text). HTML import also offers a kind's or an atom's `parse` hook elements outside the HTML namespace, such as MathML's `<math>`.
- **Dragging selected text moves it.** A text range dragged inside the editor used to drop nothing; it now moves to the drop point as one command, `moveText` (`{ from: { start, end }, to, copy }`), and one undo step. See [Dragging text](/docs/editor/clipboard#dragging-text).
  - Its content is placed at the drop point as a paste places it, then the range is deleted, both prepared before any write: hooks see the steps of both, and a drop either refuses writes nothing. The moved text is selected after.
  - <kbd>Alt</kbd> at the drop copies instead, and a drop inside the range changes nothing.
  - The drag carries the range as a copy does (the Edytor fragment, HTML and plain text) for a drop elsewhere. Block-handle drags are unchanged; an internal drag with no selected range still drops nothing.
- **Colours by name.** With the block menu listed, the slash menu offers Notion's colours once a query names one: `/red` lists "Red text" and "Red background" (group `Color`, commands `color.<name>` and `background.<name>`), painting the caret's block and removing `/red` in one undo step.
  - The block menu's search lists them too, after the kinds (`controller.matchingColors`; `rows` may now hold `BlockMenuColor` rows, and `runSelected()` paints one).
  - New `EditorCommand.searchOnly`: a command listed only once a query names it.
- **Block colours in copied HTML.** A copy's `text/html` names a block's colours as Notion's export does, a class on the block's element (`block-color-red`, `block-color-red_background`), and a paste of HTML reads them back on its text blocks (Notion's `teal` as `green`).
- **Opening a page block.** `createPagePlugin({ open })` is called as `open(pageId, { newTab })`: `newTab` is true for a modified click (Mod, Shift) or a middle click without an `href` (with one, those clicks stay the browser's), so your app can open a new tab as Notion does. <kbd>Enter</kbd> over a page block selected alone opens it. An `open` that takes only the id keeps working.
- **Localized history panel, mentions and trigger menus.** `Labels` has a `history` section (`englishLabels.history`; `defaultHistoryLabels` is the same object) and `<HistoryPanel labels>` takes `PartialLabels<'history'>`. `createMentionPlugin({ labels })` takes the new `mention` section (`menu`, `searching`, `noResults`; English `People`, `Searching…`, `No results`). A trigger that names no `name`, `empty` or `searching` says the view's new `editor` labels `triggerMenu`, `noResults` and `searching` (`<Edytor labels>`), English as before.
- **`onDocChange`.** New `<Edytor onDocChange>` prop, `EdytorOptions.onDocChange` and plugin hook: each commit's change report (`DocChange`), with no whole-document export, where `onChange` exports the document every commit. Each `onDocChange` and `onChange` consumer (the prop, each plugin) is isolated: one that throws is logged and the others still run.
- **Handle getters are reactive.** A template, `$derived` or `$effect` that reads a `Block`, `Text` or `InlineBlock` getter (`block.type`, `block.children`, `block.content`, `block.parent`, `block.index`, `block.isInTree`, `text.stringContent`, `atom.type`, …) re-runs when a commit changes it, as `block.data` already did. Read elsewhere, a getter is the same plain read of the document. A template that read `edytor.cells` only to make a handle getter update can read the getter. See [Handles](/docs/concepts/editor-instance#handles).
- **Presence within a budget.** The room relays presence within `EDYTOR_MAX_PRESENCE_FANOUT` frames a second over all its sockets (`maxPresenceFanout` with `attachRoom`, 2,000 by default, `DEFAULT_MAX_PRESENCE_FANOUT`, a new export of `edytor/cloudflare`). See [the room's presence](/docs/server/room#identity-and-presence).
  - Within it nothing changes: each entry goes out at once. Past it, the entries wait per recipient, the newest of each client, and go out together in one frame per recipient at the end of a later message. A departure still goes out at once.
  - In the soak's worst case (50 clients all at 20 Hz) acknowledgements went from p99 16 s to 43 ms.
- **The purge drops merged blocks' attribution.** A block merged into another before the purge horizon keeps its structure but loses its own attribution record (who created it, its contributors, its lineage); the block it merged into already holds its contributors. `PurgeReport` and `metrics().purge` have a new `merged` count. In documents 50 people edited, the purge gives back 12 to 17 % of the stored size instead of 5 %. See [The purge](/docs/server/history#the-purge).

- **Snapshots are stored in the v2 encoding, compressed.** The room's compaction snapshot and the IndexedDB store's are v2 (`encodeStateAsUpdateV2`) and gzip-compressed where the platform has `CompressionStream` (on the `automerge-paper` trace: 224 KB stored instead of 6.7 MB). Update rows stay v1, and the wire is unchanged (v1).
  - Each container's generation record says `storage: 'v2'`; containers written by 0.1.0-next.22 load as they are and are rewritten by their next compaction.
  - The room's `records()` marks a v2 snapshot (`v2: true`) and returns it inflated, takes an optional kind, and `compressed()` resolves once a compaction's compression is stored.
- **Validate client edits on the server.** A `validate` option (`attachDocument`) or a `validate(frame)` override (`DocumentRoom`) is asked after each client frame that changed blocks, with the blocks it touched and their state before and after; `false` makes the room undo that frame as its own edit, which every client receives. See [validate edits](/docs/server/extending#validate-edits) (per-block locks as the example).
- **Large offline backlogs are delivered.** The provider sends a frame larger than 32 MiB (its new `maxFrameBytes` option, also on `createWebsocketSync`) as chunks, which the room reassembles: an offline backlog of 40 MB reaches the room at reconnect, where it used to be undeliverable. A room of an earlier release refuses such chunks (`refused: malformed`): deploy the room first.
- **Room metrics and log.** `metrics()` (also over RPC) returns the room's counters: document and stored bytes, records and rows, sockets, compaction and fold times, fan-out, quota hits and validation denials. The room logs one JSON line per compaction, quota hit, denial and fault (`EDYTOR_LOG=off` silences it). See [metrics and log](/docs/server/room#metrics-and-log).
- **Offline coverage.** See [prefetch and last updated](/docs/collaboration/persistence#prefetch-and-last-updated) and [require hydration](/docs/collaboration/documents#require-hydration).
  - `prefetch({ server, room, params })` syncs a document's local copy with its room once and closes (keep documents fresh before going offline).
  - `lastUpdated({ server, room, params })` asks the room when it last stored a change with one HTTP request that `routeDocumentSocket` answers (`GET <room>?lastUpdated`, authorized like a dial).
  - `createDocument({ requireHydration: true })` and `<Edytor requireHydration>` seed nothing, and keep the view read-only, until the document was fetched once.
  - The room keeps a third table, `meta` (`edytor_meta`).

#### Fixed

- **The room stores its live document when it compacts.** `DocumentRoom` (and `attachDocument`) used to merge its stored updates into one snapshot, which kept every keystroke's struct and every deleted character; it now stores the live document's state, healed and with deleted content collected (on the `automerge-paper` trace, 1.6 MB instead of 6.7 MB, and a woken room loads it about six times faster). No API change; rows written by 0.1.0-next.22 load as before.
- **A joining client gets restorable text.** The room's document also keeps text a peer's undo may copy back, as an editing replica does: before, a client that joined a room was sent such a deleted copy without its text.
- **Per-writer block marks are the writer's.** The room strips a frame that writes another client's per-writer block mark (`del.<n>`, `wd.<n>`) and drops a delete of another user's mark: no client can delete or restore a block under someone else's name.

### From 0.1.0-next.2

#### Breaking changes

- **Nested blocks sit in one indented container.** Every kind that renders children puts them in a `div[data-edytor-children]`, indented by `--edytor-nest-indent` (24px). A block nested under a paragraph, heading or quote is now indented, as in Notion. CSS that indented children itself should target `[data-edytor-children]` or set the variable (see [Styling](/docs/customization/styling)).
- **Drop zones follow Notion.** The top half of a block's row drops before it and the bottom half after it; a drop nests only when the pointer is also more than one nest step right of the block's text.

#### New

- **Every drag shows a preview of the blocks it moves**, a scaled-down copy of them as rendered, with a count badge when several move.

### From 0.1.0-next.1

#### Breaking changes

- **Heading and quote text sits in its own `h1`/`h2`/`h3`/`blockquote`.** The block element is now a `div`, and its nested blocks render beside the heading tag instead of inside it, so a page's heading styles no longer reach them. Selectors written against the old markup (`h2[data-edytor-type='heading']`) now match nothing: target `[data-edytor-type='heading'] > h2` instead (see [Styling](/docs/customization/styling)).
- **The block handle's <kbd>+</kbd> inserts nothing until a pick.** It opens the insert menu with its own filter field; a block is added only when a row is picked, and <kbd>Escape</kbd> leaves the document and the undo history as they were. Without a slash menu, <kbd>+</kbd> adds an empty block as before.

#### New

- **Dragging a handle moves the whole selection.** When the dragged block is part of a block selection or of a text range across blocks, every block the selection covers moves, as one undo step; a block outside the selection moves alone.
- **A nest drop tints its future parent.** The backdrop is themed with `--edytor-drop-backdrop-color`.

### From 0.1.0-next.0

#### Breaking changes

- **`block.isEmpty` and `block.hasContent` count inline atoms.** A block holding only a mention is no longer empty; 0.0.11 and 0.1.0-next.0 counted text only. To test for text only, use `block.content.every((part) => !(part instanceof Text) || part.isEmpty)` (the old `!hasContent`; add `&& !block.children.length` for the old `isEmpty`), with `Text` from `edytor`.
- **`onDeleteSelectedBlocks` runs whenever a block selection is replaced.** Typing, a composition or a paste over a block selection now runs it first, as <kbd>Backspace</kbd>, <kbd>Delete</kbd>, a cut and the block menu's Delete do: `prevent()` keeps the blocks and inserts nothing.
  - A word or line delete (<kbd>Alt</kbd>, <kbd>Mod</kbd> or <kbd>Ctrl</kbd> with <kbd>Backspace</kbd> or <kbd>Delete</kbd>) over a block selection now deletes the blocks as <kbd>Backspace</kbd> does, hook first and children promoted.
  - It used to skip the hook and delete them as a text range in Chromium (a selected parent alone kept its block and lost its text), and did nothing in Firefox and Safari.
- **<kbd>Enter</kbd> or <kbd>Shift</kbd>+<kbd>Enter</kbd> over a block selection edits the text, as in Notion.** It leaves the selection and puts the caret at the end of the first selected block's line, as <kbd>Escape</kbd> does; nothing changes, nothing is removed and `onDeleteSelectedBlocks` does not run.
  - <kbd>Enter</kbd> used to empty the first selected block, keep it and remove the others (a checked to-do became an empty paragraph, a heading an empty heading), and <kbd>Shift</kbd>+<kbd>Enter</kbd> replaced the blocks with an empty paragraph holding a line break.
  - Over selected dividers alone either key inserts a line after them (<kbd>Enter</kbd> did before; <kbd>Shift</kbd>+<kbd>Enter</kbd> replaced them).
  - Over a selected image the caret now goes to the end of its caption (the image's line), so text typed right after <kbd>Enter</kbd> goes into the caption and a second <kbd>Enter</kbd> adds the line; <kbd>Enter</kbd> used to insert a line after the image.
- **<kbd>Mod</kbd>+<kbd>Enter</kbd> never splits.** As in Notion, it only modifies the blocks it is in: a toggle opens or closes, and with the rich text plugin a to-do checks or unchecks: each shown block among the selected ones (a to-do in a collapsed toggle stays), or the caret's. Elsewhere it now does nothing, where it used to split the block at the end of the caret's text node (moving a container's children out, or an inline atom and the text after it to a new block). To keep a Mod+Enter action of your own, bind `mod+enter` in `hotKeys`.
- **Room ids are percent-encoded.** A 0.1.0-next.0 client put the room id into the URL unchanged; since 0.1.0-next.1 the provider sends it through `encodeURIComponent`, so `a:b` dials `…/rooms/a%3Ab`.
  - **A Worker that decodes the segment**, as the [quick start](/docs/server/quick-start) does, routes both forms of an id to the same room unless it holds `/`, `\`, `%`, `?`, `#`, a tab or a line break.
  - **Those ids never reached their room from 0.1.0-next.0**, as the URL rewrote them: `/` and `\` (a `ws:` or `wss:` URL reads it as `/`) split the path (the quick start's route answers 404), `?` and `#` cut the id short (`q?x` opened room `q`), `%` read as an escape (`a%41b` opened `aAb`, and `50%off` does not decode, so it is refused `4400`), and a tab, LF or CR was stripped (`a<tab>b` opened `ab`).
  - Upgraded clients reach the full id, so for those ids the two groups edit different rooms whatever the Worker does: reload every client onto the new version, then move what 0.1.0-next.0 clients wrote under the cut, decoded or stripped name to the full id.
  - **A Worker that routes on the raw segment** (the last path segment, not decoded) sends an id holding `$`, `%`, `&`, `+`, `,`, `:`, `;`, `=`, `@`, `[`, `]` or `|` (what `encodeURIComponent` escapes and a URL path keeps, so `50%off` dials `50%25off`; a space or a non-ASCII letter is escaped alike by both, and Chromium already escaped `|`) to a different, empty Durable Object, while clients still on 0.1.0-next.0 keep editing the old one. No edit is lost, but the two groups stop seeing each other's edits.
  - **What to do.** Decode the segment in your Worker, closing one that does not decode with `closedSocket(4400, 'invalid document id')`, and deploy the Worker together with the upgraded clients. A raw-routing Worker stored an id the URL itself escapes (a space arrives as `%20`) under its escaped form, so after you add the decode those rooms open under the plain id: map the old names in the Worker, or move those documents.
- **User ids reach the room as `authorize` returns them.** `routeDocumentSocket` now percent-encodes the `userId` into `X-Edytor-User`, so an id with a non-Latin-1 character (which a header could not carry) gets in, spaces around an id are kept (a header dropped them) and an id with a lone surrogate is closed `4403`. An id `authorize` returned with spaces around it is now another user than the trimmed one its client ids were bound to, so those clients are refused (`4409`, or `1008` `refused: replica` when `authorize` passes no `replica`): trim the id in `authorize` to keep them.
- **`<Edytor server room actor>` names its local store without the trailing slashes of `server`.** A view with an `actor` named its IndexedDB store from `server` as written, so `wss://x/rooms/` and `wss://x/rooms` kept two stores (and two cross-tab channels, which the store carries); the socket, `createWebsocketSync` and a view without `actor` already removed them.
  - An app whose `server` ends in `/` now opens a new store, `edytor:<actor.id>@wss://x/rooms/<room>`: what the room stored comes back from the room, but an edit made offline that never reached it stays in the old store.
  - To keep the old store, build the sync with its old name: `` sync={createWebsocketSync({ server, room, params: dialParams, onExpired: (state) => refreshToken(state), persistName: `edytor:${actor.id}@${server}/${room}` })} ``, with `server` still ending in `/`. Once `sync` is passed, the view wires nothing itself: `onSyncExpired` does not apply (pass `onExpired`, which puts a fresh token in `dialParams`), `params` is read at each dial from the object you pass (keep one object and change its fields, as `dialParams` here; a new object is never seen), and a room id no URL can carry throws a `TypeError` instead of reaching `onSyncRefused`.
- **`.`, `..` and lone surrogates are refused.** A URL collapses those segments, and turns a lone surrogate into U+FFFD, so those ids never reached their room; the provider and `createWebsocketSync` now throw a `TypeError` for them (and for an empty id or one over 256 characters), and `routeDocumentSocket` closes them `4400`. `<Edytor server room>` does not throw: an editable view gets the `4400` refusal through `onSyncRefused` without dialing, and a readonly view renders its `value`.

#### Fixed

- **Formatting keys keep a block selection.** <kbd>Mod</kbd>+<kbd>B</kbd> and the other mark keys over selected blocks format their text and leave the blocks selected, as in Notion; they used to turn the selection into a text range.
  - Over selected dividers alone, the mark keys, <kbd>Home</kbd>, <kbd>End</kbd> and the word keys keep the dividers selected, and <kbd>Escape</kbd> puts the caret at the start of the next line (else the end of the line before); each used to put the caret inside the divider, where typing wrote hidden text into it.
  - The word keys over a block selection that starts or ends in a divider, a list or a code block now land on its first or last shown line; they used to put the caret in that block's hidden text too.
- **A composition over a block or inline-atom selection replaces it.** An IME composition (Japanese, Chinese or Korean input) over selected blocks now starts in the one empty block that takes their place (a paragraph; inside a list, an item), and over a selected mention in its place, as typing does; it used to write its text at the start of the document's first paragraph.
- **`edytor.moveBlocks` with `direction: 'in'` or `'out'` keeps the text in order.** Siblings with another block between them now move as separate runs of adjacent siblings, as <kbd>Tab</kbd> and <kbd>Shift+Tab</kbd> do: `[a, c]` out of a list `a` to `e` leaves `b` between them, where it used to read `b a c`. A run that cannot move stays, and the result lists only the blocks that moved. The headless `unNestBlocks(ids)` still moves its blocks together ([document API](/docs/reference/document-api)).
- **A throwing `edytor.transact(fn)` normalizes the writes it keeps.** The normalization the writes before the throw requested now runs before the error leaves `transact`; it used to be skipped, leaving those writes committed and synced unnormalized.

## Upgrading from 0.0.11

The current release rewrites the editor's internals around one owner per fact. The changes most apps hit first are summarized here; the [complete list](#complete-list-of-changes) below names every public change. Documents stored by 0.0.11's v13 engine import through [Importing v13 documents](/docs/reference/v13-import).

### Editor and plugins

- `value` is the initial content and is no longer bindable: `bind:value` fails type-checking. Follow edits with `onChange` or `edytor.value`.
- `Block`, `Text` and `InlineBlock` are non-reactive handles over the document, and their constructors are gone. Snippets receive a `BlockView` (`{ id, type, data, selected, focused, handle, void }`), not a `Block`: commands go through `block.handle`.
- Selection is a value set with `selection.select()`, `setAtRange` or `setAtTextOffset`. The marks at the caret are `selection.projection.marks` (was `selection.state.currentMarks`); marks for the next insertion are `selection.stage(marks)` / `selection.pending` (`text.markOnNextInsert` is gone).
- The `hotkeys` module and the `HotKeys` class are gone. Declare bindings in the `hotkeys` prop or a plugin's `hotkeys` (see [Hotkeys](/docs/customization/hotkeys)); `HotKey` and `HotKeyCombination` come from the package root. The editor's keymap is internal (`edytor.hotKeys` is gone) and its `Keymap` class is not exported. Unknown chord tokens (`cmd`, `esc`, …) fail type-checking.
- Block kinds declare `defaultChild`; the `defaultBlock` hook, `Edytor.getDefaultBlock` and `Edytor.defaultType` are gone (use `edytor.defaultChild(parent)`). `Edytor.getBlockDefinition` is replaced by `edytor.definitionOf(type)`, which never throws: a kind no plugin registers renders as a plain block.
- Plugin hooks run on the prepared command before anything is written; a veto refuses the whole command (a gesture over several blocks issues one command per part, see [Refusing an edit](/docs/plugins/operations#refusing-an-edit)). Several operation names changed, errors are reported as `refused` instead of thrown, and the first definition of a kind wins.
- Marks render by `tag` (`<strong data-edytor-mark="bold">`), which changes CSS selectors. `placeholder` is a string or a function. HTML paste is built in.
- A block selection holds exactly its members, and an emptied document shows a [virtual paragraph](/docs/collaboration/concurrent-editing#an-emptied-document-shows-a-virtual-paragraph).

See the [editor](/docs/editor/edytor-component) and [plugins](/docs/plugins) sections for the current APIs.

### Collaboration and providers

- `attachDocumentSync` is removed: use `document.attachSync`. The presence format changed (one entry per view in `selections`), so old and new clients do not see each other's carets.
- `createWebsocketSync` takes `{ server, room }`, the names of the `<Edytor server room>` props (`serverUrl` and `roomName` were removed after a deprecation). It keeps a local IndexedDB copy by default (`persist`, `persistName`) and syncs tabs by default (`disableBc`). It no longer takes `connect`, `protocols` or `resyncInterval`; pass tokens in `params`.
- The provider sends the room id percent-encoded as one path segment (`acme/roadmap` dials `…/rooms/acme%2Froadmap`): a server that routes on the path must decode it. The ids `.` and `..` throw, as a URL collapses those segments, and so do an empty id, one over 256 characters and one with a lone surrogate.
- `WebsocketProvider` lost the `protocols` option, the `sync` event (use `synced`) and `wsconnecting` (use the `status` event). It gained `saved`, `unsaved`, `readOnly` (the room's read-only notice), the `'saved'` event, the `refused`, `expired` and `unreachable` events, and the `connectTimeout` option.
- `IndexeddbPersistence` lost `get`, `set` and `del`.
- The document decides readiness itself: `syncFailed`, `onSyncSettled` and `EdytorDocSyncPendingError` are gone; see [readiness](/docs/collaboration/documents#readiness). A document keeps one provider per target.
- Content with a foreign schema makes the document read-only (`document.writable`) instead of throwing on every edit.
- `edytor/cloudflare` is new: the [Durable Object room](/docs/server/quick-start) replaces a coordinator you wrote yourself.

### Document API

- Every facade operation returns an [`OpResult`](/docs/reference/document-api#results) (`applied`, `noop` or `refused`) instead of a boolean. Operations on deleted or missing blocks are refused.
- Operations have a two-phase form: `facade.prepare.<op>()`, `facade.apply(plan)`, `facade.compose(...plans)`. New operations: `deleteRange`, `replaceRange`, `deleteBlocks`, `insertFlow`, `insertBlocks`, `liftOut`. `toBlockSpec(json)` turns canonical JSON into the `BlockSpec` that inserts take.
- New queries: `order`, `compare`, `next`, `previous`, `canPlace`, `canMerge`, `defaultChild`, `fits`, `nestParent`.
- `facade.onChange` reports one `DocChange` per commit. The per-block subscription API (`subscribeBlock`, `subscribe`, `blockVersion`, `snapshot`), `decorateRuns` and the `bind*` building blocks are no longer exported: use `onChange` with `runs(id)`, a block kind's `transformText` for decorations, and `bindCrdt(Y)` for engine injection.
- `deleteBlock(id)` and `deleteBlocks(ids)` delete only the named blocks; children take their place. Pass `{ keepChildren: false }` for the old whole-subtree delete.
- Undoing a block's creation keeps the block while it holds another person's content; `hasBlock(id)` stays `true`, and re-creating an undone id is refused.
- A document edited without a view adopts the bundled block roles (`defaultSemantics`) unless you pass other `semantics`.
- Selection anchors are `{ b, a }`; `toJSON()` gives inline blocks `data: {}` when they have none.
- `duplicateBlock(id, freshId)` and `block(id).duplicate(freshId)` call `freshId(oldId, kind)` for every copied block (`kind` `'block'`) and inline atom (`'inline'`). A callback that returns nothing for an atom gets a fresh atom id; returning nothing for a block refuses the copy.

### Stored documents

- Documents, IndexedDB stores and peers from earlier development builds of the v14 engine are refused (`GenerationMismatchError`, `'schema-mismatch'`): re-import them from JSON. v13 documents [import](/docs/reference/v13-import) instead.
- Seeding a `value` is deterministic, so replicas seeding the same template converge. `BOOTSTRAP_BLOCK_ID` is gone, and seeded blocks have no `createdBy`.

### Migration API

- `MigrationRecord` no longer has `owner` or `leaseUntil`, and is never stored as `pending`. The `leaseMs`, `owner`, `pollMs` and `waitMs` options are gone (they were ignored).
- `force` restores the v13 content in place instead of overwriting, and a store of another generation makes `migrate` throw `GenerationMismatchError`.

## Complete list of changes

Every public change since 0.0.11, by area.

### Stored documents

- **Properties are stored per leaf.** A block's, an inline block's and the document's (root `docdata`) data is one attribute per leaf, `d/` and its JSON pointer; a block's older whole `data` attribute is read under the leaves and split into them by the first write it would show through (a delete or a replace). No generation bump: an older client reads only the whole attribute, so upgrade every client together.
- **Array items are stored per item.** An array is a `[]` leaf and its items: item `id`'s value under `~id`, its position (a rank) in `~id#`, or in `~id>` once moved. An array of the previous pre-release is read as items with ids derived from their indexes and split into them by the first write that removes one. A client of that pre-release reads such an array as an object, so upgrade every client together.
- **Schema generation 5** (wire word `14005`): paired marks, shorter ranks, a v2 SyncStep2. A generation-4 container, browser store and peer convert through JSON, as [the upgrade notes](#from-010-next24) describe; the generation-4 browser database (`edytor-v14:<name>`) is left beside the new one (`edytor-v14-g5:<name>`).
- **Schema generation 4** (wire word `14004`). Documents, IndexedDB containers and peers of earlier v14 development generations (1–3) are refused by the generation gate (`GenerationMismatchError`, `schema-mismatch`); re-import them. Behind the bumps: per-writer delete marks (a deleted block is not read as live), the replicated block nonce `n` (attribution records keyed by it), and text ownership as streams delimited by boundary items (the `slices` attribute is gone; merge claims live on `claims`).
- v13 (`yjs`) documents still [import](/docs/reference/v13-import).
- **Deterministic seeds.** `createDocument({ value })` and `<Edytor {value}>` write the value under a writer id hashed from it, so two replicas seeding the same template converge and a late identical seed never erases an edit. See [deterministic seeds](/docs/collaboration/documents#deterministic-seeds).
  - Missing ids are derived from that hash. Seed writer ids sit below 2^26, so a seed never displaces a block a live replica wrote.
  - Seeded blocks carry no attribution stamp (`createdBy` is absent). `BOOTSTRAP_BLOCK_ID` is gone.

### Document and CRDT API (`edytor`, `edytor/crdt/edytor`)

- **Operation results.** Every facade op and every `document.block(id)` mutator returns `OpResult` `{ status: 'applied' | 'noop' | 'refused', ids, reason? }` instead of a boolean. An empty op (`insertText('')`, an empty range, `moveBlocks([])`, a same-value format) is `noop` and writes nothing; a reused child id is `refused` (`id-collision`); an absent target is `refused`. `moveBlocks` answers the moved ids in request order.
- **Two-phase operations.** `facade.prepare.<op>(…)` returns a plan (steps, effect, ids) or the refusal without writing; `facade.apply(plan)` writes it in one transaction; `facade.compose(...plans)` joins plans prepared at one version. A plan applied at another version throws. Positions are `DocPosition { block, offset }`. See [the document API](/docs/reference/document-api).
  - New ops: `prepare.deleteRange(start, end, view?)`, `replaceRange(start, end, view?)`, `deleteBlocks(ids)`, `insertFlow(target, flow, view?)`, `insertBlocks`, `setInlineData`, `liftOut(id, kind, { keep?, after? })` (places a block where a kind fits, out of every list it does not fit, as Turn into does).
  - The optional `view` (`{ hidden(id, removed?) }`, `RangeView`) names the blocks a view hides, such as a closed toggle's body, which a range leaves alone and a paste keeps with its first line. `insertFlow`'s (`FlowView`) also takes `itemKind(parent)`, a list's flat item kind, whose pasted lines become the list's items. The editor passes it.
  - New helper: `toBlockSpec(json, { freshIds? })`.
- **Liveness.** Deleting a block that is not live (already deleted, merged away, under a deleted parent) is refused (was `true`); `blockText` of a block under a deleted parent is `null`.
- **Order and capability.** New `facade.order()`, `compare(a, b)`, `next(id, policy?)`, `previous(id, policy?)` (one document order; `{ sealed: true }` never enters an island it did not start in), `canPlace(ids, parent?)`, `canMerge(from, into)`, `defaultChild(parentId)`, `rendersContent(type)`, `fits(parent, kind)` (the container rule: may a block of `kind` sit directly under `parent`) and `nestParent(ids, parent)` (where Tab nests them: `parent`, or a container's last item).
  - A list holds only its items: `canPlace` answers `false` and `moveBlocks` (and the `moveBlock` command) is refused where blocks would sit directly in a container they are no items of (a block already in it, such as an image a merge left there, still reorders among its items).
  - `nestBlock` into a list nests under its last item (refused when the list ends with a block that holds no children, such as an image).
  - A paragraph stored directly in a list (an explicit write, a concurrent race) shows as its item.
- **Block roles as data.** `createDocument({ semantics })` takes block roles, content-less kinds and default children; views still adopt roles from their plugins. See [the document API](/docs/reference/document-api).
  - `defaultSemantics`, `richTextSemantics`, `codeSemantics`, `imageSemantics` and `layoutSemantics` hold the bundled plugins' rows (`defaultSemantics` the other four: the columns plugin's layout rows too, though it is not a default plugin; `layoutKinds` is the columns plugin's kind table) and are deeply frozen.
  - `semanticsOf(...tables)` (with the `KindSemantics` row type) builds a config from kind rows. To extend a bundled config, merge `roles`, `rendersContent` and `defaultChild` field by field, since a top-level spread drops the bundled rows.
- **Properties.** One data operation, `patchData(target, ops)`, which only writes the properties and array items it changes; `setBlockData` and `setInlineData` are patches of the root. See [Properties](/docs/concepts/properties).
  - `target` is a block id, `{ block, atom }`, or `null` for the document; `ops` are `{ path, value? }`, `{ path, splice }` and `{ path, order }`, a path naming array items by index or id and a key that starts with `~` as `~0…`; `facade.dataItemIds` lists the ids.
  - `facade.docData()` reads the document's own data, `JSONDoc.data` holds it (seeded, exported by `toJSON` only when present), and `SerializableContent` includes arrays.
- **Atomic data paths.** A kind's role (`BlockRole`, a block definition, a `semanticsOf` row) may declare `atomic` paths: a write there writes the whole value as one property, so concurrent assignments never merge into a mix of both. Roles compare their `atomic` sets when adopted.
- **A retype keeps the properties.** `setBlock` with `data` (Turn into, a markdown shortcut, the slash menu, Backspace at the start of a kind) sets the properties it names, one `patchData` patch each, and removes none: a to-do turned into a heading keeps `checked` and gains `level`. It used to replace the whole object. Use `setBlockData`/`block.setData` to replace it.
- **Block runs.** A block inserted right after a block this replica ranked (`insertBlocks`, Duplicate, a whole-line paste; never a move) is ranked in the replica's run there (the rule data arrays use, now one segment per run), so concurrent Enters at the end of one line never interleave the two people's lines.
- **History limit.** The undo stack keeps the newest `history.limit` steps (`DEFAULT_HISTORY_LIMIT`, 200; `Infinity` keeps every step); a dropped step releases the deleted content it kept. `document.historyLimit` reads it; a reattach naming another limit is a `SemanticConflictError`.
- **Change report.** `facade.onChange(cb)` delivers one `DocChange` per commit that changed the visible document or its data: `{ added, removed, moved, meta, content, order, data?, origin, local, version }` (`data`: the document's, when it changed). A block that moves into a subtree added in the same commit is reported in `moved`/`meta`/`content`, not folded into the subtree. A write made while another transaction's change is being reported (in an `update` listener or an observer) is folded before the report reads the document, so it shows in that report too.
- **Retired exports.** Use `bindCrdt(Y)` (`.doc`, `.providers`, `.migration`, `.sync`, `.admission`, `.attribution`) for engine injection, `facade.onChange` + `facade.runs(id)` for reads, and a kind's `transformText` for local decorations. Gone:
  - the per-block subscriber API (`subscribeBlock`, `subscribe`, `blockVersion`, `snapshot` on the facade and the index), `decorateRuns` and its types (`LocalDecoration`, `DecoratedRun`);
  - the "advanced internals" tier: `bindEdytorDoc`, `bindDocument`, `bindNodes`, `bindModel`, `bindRuns`, `bindIndexeddbProvider`, `bindWebsocketProvider`, `bindProviders`, `bindSync`, `bindAdmission`, `bindAttribution`, `bindBlockAttribution`, `bindMigration`, `bindLegacyReader`, `setDocRand`/`randOf`, the rank functions;
  - the constants and helpers `REGISTRY_KEY`, `SCHEMA`, `SCHEMA_NAME`, the attribution root constants, `migrationBcRoom`, `PREFERRED_TRIM_SIZE`, `GENERATION_PREFIX`, `generationDbName`, `GENERATION_KEY`, `writeProtocolVersion`, `removeAwarenessStates`, `outdatedTimeout`, `readAuthMessage`, and their types.
- **Kept for a server coordinator** (see [the protocol](/docs/server/protocol)): `bindCrdt(Y)`, `SCHEMA_VERSION`, `META_KEY`, `GENERATION`, `generationWord`, `frame`, `PROTOCOL_VERSION`, `readProtocolVersion`, `GENERATION_RECORD`, `GenerationMismatchError`, the message types, the lib0 frame helpers, the awareness codec (`readAwarenessEntries`, `writeAwarenessEntries`, `applyAwarenessUpdate`, `encodeAwarenessUpdate`, `modifyAwarenessUpdate`) and `messagePermissionDenied`/`writePermissionDenied`. New: `messageReadOnly`/`writeReadOnly`, `messageSaved`, `messageChunk`, `MAX_FRAME_BYTES`, `chunkFrame`, `createChunkReader`.
- **Raw engine exports pruned** (`edytor/crdt`). Edytor never called these; they are removed from the vendored engine:
  - the renderers (`AttributionsRenderer`, `createAttributionsRenderer`, `DiffRenderer`, `createDiffRenderer`, `SnapshotRenderer`, `createSnapshotRenderer`; `AbstractRenderer` and `$renderer` stay);
  - snapshots (`Snapshot`, `snapshot`, `createSnapshot`, `emptySnapshot`, `createDocFromSnapshot`, `encodeSnapshot` and `encodeSnapshotV2`, `decodeSnapshot` and `decodeSnapshotV2`, `equalSnapshots`, `snapshotContainsUpdate`, `nodeMapGetSnapshot`, `nodeMapGetAllSnapshot`, and the `snapshot` argument of `node.getAttrs`);
  - update helpers (`logUpdate` and `logUpdateV2`, `obfuscateUpdate` and `obfuscateUpdateV2`, `diffUpdate` (`diffUpdateV2` stays), `encodeStateVectorFromUpdate` and `encodeStateVectorFromUpdateV2`, `convertUpdateFormatV1ToV2`, `createContentIdsFromUpdate` and `createContentIdsFromUpdateV2`, `intersectUpdateWithContentIds` and `intersectUpdateWithContentIdsV2`, `readUpdate`, `createDocFromUpdate` and `createDocFromUpdateV2`, `cloneDoc`, `diffDocsToDelta`, `logNode`);
  - the delta-position helpers (`createRelativePositionsFromDeltaPositions`, `createDeltaPositionsFromRelativePositions`, `createRelativePositionFromDeltaPosition`, `createDeltaPositionFromRelativePosition`);
  - the binary relative-position codec and comparison (`encodeRelativePosition`, `decodeRelativePosition`, `compareRelativePositions`; use `relativePositionToJSON`/`createRelativePositionFromJSON`);
  - id-set and id-map algebra (`gcIdSet`, `createInsertSetFromStructStore`, `encodeIdSet`, `decodeIdSet`, `mergeIdMaps`, `diffIdMap`, `intersectMaps`, `filterIdMap`, `createIdMapFromIdSet`, `createIdSetFromIdMap`, `$idMap`);
  - content-id helpers (`createContentIds`, `createContentIdsFromContentMap`, `createContentIdsFromDoc`, `createContentIdsFromDocDiff`, `excludeContentIds`, `excludeContentMap`, `mergeContentIds`, `mergeContentMaps`, `createContentMapFromContentIds`, `intersectContentIds`, `intersectContentMap`, `filterContentMap`, `writeContentIds`, `readContentIds`, `encodeContentIds`, `decodeContentIds`);
  - and `getNodeChildren`, `$node`, `getPathTo`, `tryGc`, `undoContentIds`.
  - A document built with `createDocFromUpdate(u)` is a new document + `Y.applyUpdate(doc, u)` (for edytor content, `bindCrdt(Y).createDoc()`, see `Doc.keepReplaced` under Unreleased); `attribution.legacy()` still returns a `ContentMap` (`encodeContentMap`/`decodeContentMap`, `encodeIdMap`/`decodeIdMap` stay) for a renderer you supply.
- **Anchors** are `{ b, a }`: the `o` owner facet and the `a: -2` form are gone from the selection value, the presence wire and history entries.
- **Attribution.** Undo and redo keep a block's record (`createdBy` survives an undo/redo of its creation on every replica). A forced re-migration (`force`) gives a block whose stream started at a boundary a new nonce without moving its record, so its `createdBy` is replaced at the next attributed write.
- `facade.toJSON()` inline atoms carry `data: {}` when they have no data (the shape `edytor.value` already had).
- **Block deletes promote children.** `deleteBlocks(ids)` and `deleteBlock(id)` delete only the named blocks: each one's unselected children take its place (a deleted island's children take the default child type). `deleteBlock(id, { keepChildren: false })` is the whole-subtree delete (was the default). Promotion is read-time: a block a peer adds, moves or splits off under a concurrently deleted block also takes that block's slot, so nothing is hidden with a deleted subtree.
- **Void blocks hold no children.** Retyping a block to a void kind moves its children right after it; a child that still lands under a void block (a concurrent nest) is shown in its slot.
- **Undo of a creation withdraws.** The history no longer deletes a block node it created: it writes a per-writer withdraw mark `wd.<writer>` (the `UndoManager` option `withdraw(item, stackItem, transaction)`), and the block is shown while it holds another writer's content. `hasBlock(id)` stays `true` for a withdrawn block, and re-creating an undone id is refused.
  - Old clients of the same schema generation ignore the marks and show a withdrawn block (empty, or with the other writer's text); an old client's own undo still deletes the node.
  - A withdrawn block costs its node in storage (about 100 bytes) instead of a tombstone. A history created directly with `new Y.UndoManager` over the registry does not follow the rule.
- **Text delete marks.** Every text delete writes a record naming its writer (root `textdel`, in the history's scope) and every undo that brings text back writes a restoration record (root `restored`, never removed). `document.history` is created by `facade.createUndoManager` as before.
  - Old clients of the same schema generation ignore both and keep the previous undo behavior (a double delete undone by both peers can show the character twice).
  - A text delete update is about 21 bytes larger and a stored document about 12 bytes per delete. A history created directly with `new Y.UndoManager` over the registry does not follow the marks.
- **Conflicting type changes.** An undo returns a block to the type you replaced, never to no type.
- **Paired marks.** A mark write is one operation; overlapping marks of one value union, a later mark wins where it covers, no end clears another mark's tail; a mark's `edge` decides where a concurrent insert at its ends lands. `DocumentSemanticsConfig.marks` holds mark edges for a document without a view (`richTextMarks`, in `defaultSemantics`); views adopt their mark records' `edge`. A key `name:<id>` reads the `name` record (one mark per comment). `markName`, `MarkEdge`, `facadeConfigOf`.
- **The generation cutover** (generation 4 to 5). `bindCrdt(Y).generations` reads a generation-4 state as JSON (`previousJSON`, `previousJSONWith`) and seeds it (`seedOf`); `PREVIOUS_SCHEMA`, `isPreviousGenerationRecord`; `IndexeddbPersistence`'s `convertPrevious` option (set by `createIndexeddbSync`); `bindCrdt(Y).sync.step2Update` converts a v2 SyncStep2.
- **Layouts.** A kind whose role says `layout` (`BlockRole.layout`) shows its items side by side and is shown by read-time rules on every replica: only its items show (another block stored in it shows right after it), an empty item does not show, a layout showing one item or none shows as that item's blocks, an item outside a layout shows as its blocks. Edits write the same in the same step (an emptied item goes, a one-item layout dissolves).
  - New `placeBeside(ids, target, side, kind?)`, `wrapInLayout(ids, kind?, columns?)`, `isLayout(id)`, `isLayoutItem(id)` and `besideAt(id, kind?)`.
  - `mergeBackward` of an item's first block merges into the previous shown line in reading order and `mergeForward` crosses items; deleting an item puts its blocks after the layout, deleting a layout keeps its blocks in its place with their kinds.
  - `fits`: a container holds containers of its items only when the item renders content (a layout holds no layout).

### Editor view, selection and commands

- **The document's own operations.** `EdytorDocument` carries `DocumentOperations` (`document.insertBlock(…)`); `document.facade` is deprecated; the types the operations use are exported from `edytor`.
- **`selection.select(value)`** takes the value only; the dispatcher publishes `last`, `permits()`, `run`, `each`, `dispatch`, `lead`, `caret` and `outside`, the rest is internal.
- **`edytor.focus()`** focuses the editor, keeping its selection or putting the caret at the start; `selection.value`, `selectedBlocks`, `focusedBlocks` and `dispatcher.last` are read-only.
- **Pasted and dropped files.** The video, audio and file plugins with `upload` take their files (`media.files`); `upload(file, report)` reports progress (`Uploader`, `UploadReport`); the media labels gain `uploading` and `uploadFailed`.
- **Markdown paste.** A `text/plain` paste holding block markdown is placed as its blocks (`textToBlocks`); see [Pasting markdown](/docs/editor/clipboard#pasting-markdown).
- **Exported types.** The types the root entry's props, options, members and callbacks use are exported from `edytor` (`EdytorProps`, `EdytorOptions`, the labels types, `Dispatcher`, the selection, hotkey, plugin, document and sync types); see the note of the release that added them.
- **`value` is not bindable.** `<Edytor value>` is the initial content; `bind:value` fails type-checking. Read edits with `onChange` or `edytor.value`.
- **Component props.** New: `document` (an `EdytorDocument` to render; several views can share one), `actor` (the local author), `room`, `server` and `params` (the view builds its IndexedDB copy and its websocket sync from them), `onSyncExpired` (the room closed with `4401`; refresh `params` before the redial) and `onSyncRefused` (a refusal standing at mount, then each new one), `blockHandles`, `defaultPlugins`, and the root attributes `translate`, `spellcheck`, `autocorrect`, `autocomplete`, `autocapitalize`, `inputmode` and `enterkeyhint`. `sync` takes an `EdytorSync` (a factory from `createIndexeddbSync`/`createWebsocketSync`, or your own) and overrides `room`/`server`. `hotkeys` is typed (see Keymap below). See [the component](/docs/editor/edytor-component).
- **Handles.** `Block`, `Text` and `InlineBlock` are id-only handles over the document index: getters read the document (inside a command they see its writes); they are **not reactive** (except `data`, a reactive proxy). Templates read the snippet's view object or `edytor.cells`.
  - `new Block({block})`, `new Text({…content})` and `new InlineBlock({block})` are gone: use `block.insertChildren(index, JSONBlock[] | Block[])` (a handle moves) and `block.insertParts(index, (JSONText | JSONInlineBlock)[])`; `deleteParts` is removed (use `deleteContentAtRange`).
  - A `Text` is the `ordinal`-th segment of its block (`text.id` = `t:<block>:<ordinal>`) with no identity across commits; key extension state by block id and anchor.
  - Liveness: `block.isInTree`, `text.isInDocument`, `atom.isInDocument` (`_live`, `_bound`, `_blockId`, `_segOrd`, `_items` are gone; a dead block's `parent` is `undefined`).
  - `edytor.idToBlock` is the handle registry (`get(id)`, `block(id)`, `text(blockId, ordinal)`, `atom(blockId, atomId)`, `parts(id)`); `edytor.idToText`, `edytor.idToInlineBlock`, `Edytor.getTextById`, `Block.partOffsetOf`/`atomOffsetOfPartIndex`/`projectedParts` are removed (a text's display offset is `text.segStart`, a block's parts `edytor.idToBlock.parts(id)`).
  - `InlineBlock.type` has no setter. `Block.firstText`/`lastText` are `undefined` for a kind that renders no content.
  - New getters: `Block.isContainer` (a block that shows only its children, such as a list), `Block.isListItem` and `Block.list` (the list an item shows in); `Block.convertible` is `false` for a list container (its items convert).
- **Emptiness counts inline atoms.** `block.isEmpty` (no content and no children) and `block.hasContent` count inline atoms as content, so a block holding only a mention is not empty (0.0.11 counted text only). To test for text only, use `block.content.every((part) => !(part instanceof Text) || part.isEmpty)` (the old `!hasContent`; add `&& !block.children.length` for the old `isEmpty`).
- **Data writes are commands.** `block.data.x = …`, `edytor.data.x = …`, `atom.data.x = …`, `block.setData(data)` and `atom.setData(data)` are the `patchData` command (`{ ops, atom? }`; the document's on the root block), and `block.type = …` is `setBlock`: refused on a readonly view, shown to `onBeforeOperation`, recorded in `dispatcher.last`, and each is its own undo step (writes typing into the same string properties join one within the capture window; a string set to another value does not). `block.model.setData` is the raw write. `block.data`, `atom.data` and `edytor.data` are live, reactive proxies (see [Properties](/docs/concepts/properties)); an array method or an index write is one command that writes only the items it changes.
- **Definitions.** `edytor.definitionOf(type)` is the one lookup and never throws (`getBlockDefinition` is removed). A kind no plugin registers renders as a plain block (its text and children), with one development warning per kind, instead of throwing. `edytor.container` is removed: use `edytor.node`.
- **Op results inside transactions.** `splitBlock`, `insertBlockAfter/Before`, `mergeBlock*`, `addInlineBlock` and `addChildBlock(s)` answer handles of what they created, also inside an outer `edytor.transact`. A vetoed `insertFlow` answers `[null, 0]`.
- **Selection is a value.** `selection.value` (`none`, `text { anchor, focus, pending? }`, `atom { blockId, atomId, from }`, `blocks { ids }`), `selection.select(value, cause)` (the only writer), `projection`, `epoch`, `cause`, `textValue`, `stage(marks)`/`pending`. `onSelectionChange` fires only when the value changed (a remote edit that moves the projection does not emit).
  - `selection.state` is a read-only view of the projection (assigning it fails; use `setAtRange`, `setAtTextOffset` or `select`): `startText`, `endText`, `yStart`, `yEnd` (offsets inside the text segments), `startBlock`, `endBlock`, `texts`, `blocks`, `isCollapsed`, `isReversed`, `isBlockSpanning`, `isVoidEditableElement` and `edge` (new).
  - The projection facts moved to `selection.projection`: `content` (and its `length`), `marks` (was `state.currentMarks`), `isAtStartOfText`/`isAtEndOfText`/`isAtStartOfBlock`/`isAtEndOfBlock`, `isTextSpanning`, `islandRoot`/`voidRoot` (block ids; `isIsland`/`isVoid` are `!== null`).
  - The caret anchors are the value's (`relativePosition`/`endPosition` → `selection.value.anchor`/`focus`); `contentParts`, `startNode`, `endNode` and `yTextContent` are gone.
  - `setRangeStateAtTextOffsets` → `setAtRange` (same arguments); `setCollapsedStateAtTextOffset` → `setAtTextOffset` (the old name is removed). `setAtTextOffset` takes a `Text` (not an id) and selects in the caller's turn.
  - Removed: `hasSelectedAll`, `focusBlocks`, `deadEndpointRecoveryPending`, `notifyTextMounted`, `Edytor.getTextNode`, `ignoreNextSelectionChange`, `Edytor.mirrorRevision`.
- **Pending marks** are `selection.pending` / `selection.stage(marks)` (`Text.markOnNextInsert` is gone); a move clears them, an insertion at the caret consumes them, and they hold valued marks (links, colors) as a full set.
- **Default children.** The plugin `defaultBlock` hook, `Edytor.getDefaultBlock` and `Edytor.defaultType` are removed: a kind declares `defaultChild`; `edytor.defaultChild(parent)` answers.
- **Deletion and paste** follow one rule each:
  - blocks after the range end inside a dying container, and a dying tail's children, survive; an emptied list container dies;
  - a range from inside an island never merges out of it, and a range inside one `lines` island never removes it (its first line stays, emptied: a code block's Mod+A, then Backspace, Delete or cut);
  - a list or a table row never merges as a whole (`canMerge` refuses it): Delete at the end of the block above a list pulls the first item's text up and the list keeps the rest, and Backspace at the start of a list's first item lifts it out of the list, as its new parent's default child;
  - multi-line plain paste and drop split the block per line; copied fragments keep their ids and paste always mints fresh ones.
- **Moves.** `BlockMoveRequest` is `{ blocks } & ({ target, position } | { direction: 'up' | 'down' | 'in' | 'out' })`; `BlockMoveDirection` and the move types come from the package root (the deep import of the old block-move module is gone).
  - A move is its own undo step, and a move that lands in or under a closed toggle opens it (`edytor.moveBlocks` and the block commands `nestBlock`, `unNestBlock`, `moveBlock`, `moveBlocks` too, as the handles and keys do).
  - Arrow-move never nests; `Mod+↑` moves a selected group; the handle claims every Alt+arrow key.
  - Outdent (Shift+Tab, `unNestBlock`, direction `out`) hands the following siblings to the outdented block, as in any outliner; an item of a list container leaves the list instead, without the items after it (a middle item splits the list).
  - `BlockMovePosition` gains `left` and `right`: beside the target, in a new column of the layout it is in, else in a new layout wrapping it (`prepare.placeBeside`; refused without a layout kind); hooks see `moveBlock`/`moveBlocks` with a `beside: { target, side }` payload (`BlockBeside`).
- **Keymap.** The `hotkeys` module is deleted: the types move to the package root (`HotKey`, `HotKeyCombination`; `HotKeyModifier`, `Single/DoubleModifierCombination` removed). `HotKeys` → the editor's internal keymap, whose `Keymap` class is not exported (`isHotkey` → `handle`, `run(chord)`, `offered`; no `init`).
  - A `HotKey` payload's `event` is optional. A key binding runs once per occurrence.
  - Chords take up to three modifiers in any order, plus punctuation and `f1`–`f12`; `space` matches the space bar. Unknown tokens (`cmd`, `esc`, `return`, …) fail type-checking and warn in development.
  - The `hotkeys` prop is typed `Partial<Record<HotKeyCombination, HotKey>>`.
- **Navigation.** Shift+Home/End/PageUp/PageDown, Shift+↑/↓ and Mod+Shift+↑/↓ move the focus and keep the anchor (Mod+Shift+↑/↓ only where the default [arrow move](/docs/plugins/arrow-move) plugin has no block to move; otherwise it moves the caret's block); word keys are visual under RTL; arrows skip a collapsed toggle's body; an atom selection carries the side it was anchored on (`from`).
- **Input and IME.** `edytor.attempts` (the input attempts) and `edytor.composition` (the session: `live`, `phase`, `host`, `owns(node)`, `ended(fn)`, `restructured(change)`) are new; `edytor.isComposing` is read-only.
  - Removed: `compositionState`, `compositionStartReplacementState`, `hasHandledCompositionInput`, `compositionText`, `resolveCompositionRegion`, `shouldIgnoreCompositionKeyDown`, `Text.toCompositionDomOffset`, and the input-fallback flags and timers on `Edytor`.
  - A composition is one undo step with its ending; no timer ends it; a commit that re-places the composing block (a peer deletes, retypes, moves or re-parents it) commits what the IME shows first.
  - `onBeforeInput` no longer sees fabricated paste, drop or keydown-fallback events. `preventUnsupportedDrop(event, edytor?)`.
- **History.** `edytor.historyUndo()`/`historyRedo()` restore the selection each step recorded for this view (before on undo, after on redo); the undo-snapshot queue and its helpers are gone. See [history](/docs/editor/history).
  - The dispatcher owns undo grouping: structural edits, deletions, menu, toolbar and `+` actions, and markdown or slash conversions are each their own step, however soon they follow typing.
  - Typing joins the step before only when that step was typing or a text deletion (typing right after a column resize, a data change, a paste or a conversion is its own step).
- **Nothing selected, nothing written.** With the selection `none`, typing, <kbd>Backspace</kbd>, <kbd>Delete</kbd>, <kbd>Enter</kbd> and an IME composition write nothing (`dispatcher.last` is `refused`; `edytor.composition.targetless`), even over a caret the browser parks; the navigation keys do nothing (<kbd>PageUp</kbd>/<kbd>PageDown</kbd> scroll) and <kbd>Mod</kbd>+<kbd>A</kbd> selects every block. After a drop or a column resize the editor's root takes the focus without a caret, so <kbd>Mod</kbd>+<kbd>Z</kbd> works at once. A paste over a block selection lands at a collapsed DOM caret only when a press or a script put it there. `edytor.selection.dragging` is reactive.
- **Block selection is exactly its members.** Select-all selects every block (was the root's children); Shift+↑/↓ adds each block it passes; a block copy or cut carries the selected blocks only, a selected list or code block with everything in it (`selection.selectedMembers`; `selectedBlocks` holds the blocks as clicked).
  - Deleting or cutting a block selection, or the block menu's Delete, puts the caret at the start of a child promoted into its place, else at the end of the nearest line before it (else at the start of the nearest line after it).
  - Escape, <kbd>Enter</kbd> or <kbd>Shift</kbd>+<kbd>Enter</kbd> (which remove nothing) put it at the end of the first selected block's line in document order.
  - <kbd>Mod</kbd>+<kbd>Enter</kbd> only opens or closes toggles and checks to-dos (Notion); it no longer splits.
  - `Block.removeBlock()` promotes the children (`removeBlock({ keepChildren: false })` deletes the subtree).
- **Virtual paragraph.** A view reads its document through a lens: `edytor.facade` is a per-view object whose prototype is `document.facade`, and `edytor.facade.virtual()` names the virtual paragraph while the document shows no block (`edytor.root.children` then holds its handle; `edytor.value.children` is empty). Every facade op the view issues on it creates it first, in the same plan. An emptied root no longer gets a replacement paragraph written by normalization.
- **Dragging text (`moveText`).** Selected text dragged inside the editor moves to the drop point, one command and one undo step (<kbd>Alt</kbd>: a copy); the drag carries the range's fragment, HTML and plain text.

### Plugins and the extension API

- **Hooks run on the prepared command before any write.** `onBeforeOperation` sees the command, then each planned step under its documented name (`removeBlock`, `mergeBlockBackward`, `deleteContentAtRange`, `addChildBlocks`, `moveBlock(s)`, `splitBlock`, `setBlock`, `insertText`, `addInlineBlock`), with `effect` on the payload. `onAfterOperation` fires once per command. See [Refusing an edit](/docs/plugins/operations#refusing-an-edit).
  - A veto of any step refuses the whole command (no write, no undo step); a gesture over several blocks (Turn into, <kbd>Tab</kbd>, formatting, Duplicate) issues one command per part, so a veto skips only its part.
  - `prevent(cb)` or a returned command replaces it once per extension; a payload returned for a nested step is ignored with a development warning.
  - Nested operations and normalization are not shown as operations. Commands the document refuses are still shown (no steps), so an extension may replace them.
- **`onDeleteSelectedBlocks`** runs before every gesture that removes a block selection: <kbd>Backspace</kbd> or <kbd>Delete</kbd> (a word or line delete too), a cut, the block menu's Delete, and typing, a composition or a paste over it (<kbd>Enter</kbd>, <kbd>Shift</kbd>+<kbd>Enter</kbd> and a drop remove nothing, so they never run it). `prevent()` keeps the blocks (a cut still writes the clipboard; typing and paste insert nothing) and `dispatcher.last` reports `refused`.
- **Operation names.** New `deleteBlocks` (`{ blocks }`), `insertFlow` (`{ flow, target }`, paste and drop), `insertDivider`, `setInlineData`; `deleteContentWithinSelection` takes `{ replace }` (was `{ preserveStartBlock }`); Enter's lift is `splitBlock`; markdown and slash conversions are `setBlock` with a `deleteContentAtRange` step; word deletes are `deleteContentAtRange`; handle in/out are `moveBlock`. Browser-typed text is adopted as `insertText`/`deleteContentAtRange` and can be vetoed (the text re-renders).
- **Errors.** Top-level operations report `refused` (`edytor.dispatcher.last.status`) instead of throwing `PreventionError`; text operations refuse in readonly; a read-only (quarantined) document refuses instead of throwing `SchemaMismatchError`; async handler errors are reported, not swallowed. `edytor.clear()` is a command (one undo step, refused on a readonly view) and answers whether it applied; `historyUndo()` and `historyRedo()` set `dispatcher.last` too: `applied`, `noop` on an empty stack, `refused` on a readonly view.
- **Normalization** (`normalizeContent`/`normalizeChildren`) runs at the end of the command's transaction, inside it, with handles that read the command's writes (at most 51 passes per normalizer and block); its work is part of the same update and undo step.
- **Definitions: first wins** (was last): an extension that extends another's definition lists itself first.
- **Kind records.** `BlockDefinition` gains `element`, `contentElement`, `viewState`, `lines`, `layout`, `rendersContent`, `defaultChild`, `itemKind`, `continues`, `container`, `presets`, `empty`, `html`, `plain`, `parse`; `snippet` is optional (`schema` is removed). One label per kind (`Text`, `To-do list`, `Toggle list`).
  - `element` and `contentElement` take a tag, `{ tag, attributes }`, or a function `(data, id) => …` of the block's data and id (for view state a kind keeps per block; reactive state it reads re-renders the element).
  - `lines: true` (with `island` and `defaultChild`) makes an island of lines, like the code block: its direct children show as its line kind and hold no children. A custom island of lines needs it, and an island without it keeps its children's kinds and nesting (block roles in `semantics` take `lines` too).
  - `layout: true` (with `defaultChild`, its column kind) makes a layout, like the columns plugin's `columns`: it shows its columns side by side, an empty column does not show, and a layout showing one column shows as that column's blocks (block roles in `semantics` take `layout` too: `layoutSemantics`).
  - `itemKind` on a list container names the flat kind its items show as (`numbered-list-item` for `ordered-list`): the menus name an item by it, and turning an item into it keeps the item in its list.
  - With `empty`, a conversion turns only a block that holds nothing into the kind; a block with text or children stays and the new block is inserted after it.
  - `MarkDefinition` gains `edge`, `toolbar`, `tag`, `attributes`, `parse`; `InlineBlockDefinition` gains `plain`. `convertToKind`, `KindRow`, `KindPreset` are exported; `edytor.kinds` is the catalogue the slash menu, markdown shortcuts and menus read.
- **Snippets render inner markup.** The core renders, registers and marks void the block element (`use:block.attach` and `BlockView.attach`/`InlineBlockView.attach` are removed; `use:block.void` still marks inner chrome). Block snippets receive `block: BlockView` = `{ id, type, data, selected, focused, handle, void }`; inline-atom snippets `block: InlineBlockView` = `{ id, type, data, selected, handle }` (`handle` is `undefined` for a suggested atom). Commands and document reads go through `block.handle`. `onBlockAttached` runs once per element, and the attach hooks may return a cleanup. Identity attributes are declarative (present in server-rendered HTML).
- **`transformText`** receives declared values `{ text: { stringContent, value }, block: { id, type, data }, content }`, not handles.
- **Marks at insertion** follow one rule (explicit → a replaced range's common marks → pending → the neighbour → the mark's `edge`); `insertText` without marks resolves them by that rule; plain paste inherits the caret's marks; Mod+B at the start of a bold run toggles bold off.
- **Suggestions.** `edytor.suggestions` proposes content at a position, session-only until `accept()` (one command, `acceptSuggestion`, one undo step), with the default `suggestionsPlugin` bar and keys and `textToBlocks` ([Suggestions](/docs/editor/suggestions)); `BlockView.handle` is `undefined` in a suggestion's preview. An `{ end }` suggestion survives selection changes. `block.suggestText`, `block.suggestions`, `block.acceptSuggestedText`, `edytor.selection.suggestions`, `rawSuggestions` and the readonly Proxy wrappers are removed.
- **HTML import is core.** The HTML paste plugin (never exported) and its hand-written parser are gone; external HTML paste and drop are imported by the core through the browser's parser and the records (`parse` hooks on kind and mark records; see [clipboard](/docs/editor/clipboard)). A plugin's `onPaste` still runs first. The code plugin highlights through TanStack Highlight, and the package declares `sideEffects` so it (and its CSS) ships only in apps that import `codePlugin`.
- **Notion behavior.** See [Enter and Backspace by role](/docs/customization/hotkeys#enter-and-backspace-by-role).
  - Markdown `> ` makes a toggle and `" ` a quote; `+ `, `a. `, `i. ` and inline markdown are new, and a prefix converts at the caret, keeping the text after it.
  - The to-do checkbox writes `data.checked`. The callout's default icon is `💡` (was `!`). Headings are `h1`–`h3`; a missing level is `h1` and any other renders and copies as `h3`.
  - Lists, to-dos and toggles continue on Enter; toggles, callouts and quotes are containers; Backspace at the start of a kind other than its parent's default child turns it into that default first.
  - The paragraph and code block elements no longer carry Tailwind classes. `KindPreset.group` and `EditorCommand.hint` are new; `richTextOperations(edytor).removeMarkAtRange(mark)` is new.
- **Columns (opt-in).** `columnsPlugin`, `createColumnsPlugin({ minWidth })`, `isColumnsPlugin` and `ColumnsPluginOptions`: Notion's multi-column layouts (the kinds `columns` and `column`, a column's `data.width` a weight), not a default plugin; see [Columns](/docs/plugins/columns).

  - `EditorCommand.turnsInto(blocks)` makes a command a row of the block menu's Turn into over those blocks (`KindRow.command`; `turnCommands`, `wrappable` and `wrapBlocks` are exported; the operation hooks see `wrapBlocks`, `{ blocks, kind, columns }`): "2 columns" to "5 columns" over one block, or "N columns" over N sibling blocks.
  - A block selection covering every block of a layout stands for it (drag, Alt and Mod+Shift arrows, Duplicate, Delete, cut, copy).
  - A drop's beside bands (right edge, left page margin, a column's gap) place blocks in a new column or wrap the target in a new layout; resizing is live, view-only until the release, which writes two weights in one undo step.

- **`BLOCK_ACTIVATE_EVENT` is cancelable**: a menu that answers a grip click and takes the keyboard calls `preventDefault()`; unanswered, the editor takes the focus after the click, so <kbd>Backspace</kbd> and <kbd>Shift</kbd>+arrows act on the selected block.
- **Default plugins.** `<Edytor>` appends `arrowMovePlugin`, `suggestionsPlugin`, `imagePlugin` and `richTextPlugin`, in that order, after your `plugins` unless the list already has them, and prepends block handles; `defaultPlugins={false}` opts out. Your plugins therefore win over all four; to let a default win over one of yours, list it yourself before your plugin. Passing `plugins={[richTextPlugin]}` still works.
- **Image plugin.** `imagePlugin`, `createImagePlugin({ upload })` and `ImagePluginOptions` are exported. The `image` kind stores `data.src`, has an "Image" preset in the `Media` group, and exports and imports `<figure><img><figcaption>`.
- **Block colours, toggle headings, page block, table of contents.** Blocks store `data.color` and `data.background` (palette names the block menu's Color sets, rendered as `data-edytor-color`/`data-edytor-background` and painted from `--edytor-color-<name>`/`--edytor-background-<name>`; `BLOCK_COLORS`, `setBlockColor`); the rich text `toggle-heading` kind (Toggle heading 1 to 3, markdown `> ` in a heading and `# ` in a toggle, through `KindPreset.markdownFrom`); `createPagePlugin`/`pagePlugin` (a void `page` linking to another document) and `tocPlugin`/`createTocPlugin` (a void `toc` listing the headings), their roles in `defaultSemantics`.
- **Tables.** `tablePlugin`/`createTablePlugin` (opt-in): rows and columns added from the table's edges, moved by dragging their grips or from the grips' menus, deleted from those menus; columns resized within the room at the table's place, a wider table scrolling sideways in its own box ([Table](/docs/plugins/table)).
- **Media plugins.** `embedPlugin`/`createEmbedPlugin({ providers })`, `bookmarkPlugin`/`createBookmarkPlugin({ unfurl })`, `filePlugin`/`createFilePlugin({ upload })`, `videoPlugin`/`createVideoPlugin({ upload })` and `audioPlugin`/`createAudioPlugin({ upload })` add void `embed`, `bookmark`, `file`, `video` and `audio` kinds (opt-in, `Media` presets, roles in `defaultSemantics`/`mediaSemantics`).
  - Exports: `EMBED_PROVIDERS`, `embedSourceOf`, `EMBED_SANDBOX`, `EMBED_ALLOW`, `safeWebUrl`, `safeMediaSrc` and the types `EmbedProvider`, `EmbedPluginOptions`, `BookmarkPluginOptions`, `BookmarkPreview`, `MediaPluginOptions`.
  - An embed's frame plays only an allowlisted provider's `https:` player, sandboxed, never `srcdoc`. With the embed or bookmark plugin, a URL pasted on an empty line is a link and a menu offers Embed or Bookmark.
  - HTML import maps `iframe`, `video` and `audio` when one of them claims them; a void kind with a `parse` hook is found by its hook only and takes only its `figcaption`'s text.
- **UI snippets.** `createSlashMenuPlugin({ item, menu })`, `createToolbarPlugin({ toolbar })`, `createBlockMenuPlugin({ menu })` and `BlockHandlesOptions.handle` are new, with the types `SlashMenuOptions`, `SlashMenuItem`, `SlashMenuController`, `ToolbarOptions`, `ToolbarController`, `BlockMenuController`, `BlockMenuAction`, `BlockHandleSnippetPayload` (its `addable` is always `true`: every handled block has its `+`, a block in a column too, whose Alt+click adds a column right of its column) and `BlockHandleController`. The toolbar and block menu place the element marked `data-edytor-toolbar-bar` / `data-edytor-block-menu` (was their `data-testid`). A press in the toolbar's host never takes the editor's focus (its `mousedown` is cancelled but in a field), so a toolbar snippet's buttons need no `mousedown` handler.
- **Heading and quote block elements are `div`s.** The rich text `heading` and `quote` used to render as the block element itself (`<h2 data-edytor-block … data-edytor-type="heading">`, `<blockquote data-edytor-block …>`), with nested blocks inside the tag. The block element is now a `div`; the `h1`–`h3` or `blockquote` is the kinds' new `contentElement`, which wraps only the block's own text, and nested blocks follow it in a sibling `div`. The copied HTML is unchanged.
  - Rewrite selectors: `h2[data-edytor-type='heading']` becomes `[data-edytor-type='heading'] > h2`, `blockquote[data-edytor-block]` becomes `[data-edytor-type='quote'] > blockquote`; drop resets for a `div` inside a heading, and a test locating `h1[data-edytor-id=…]` locates `[data-edytor-id=…] > h1`.
  - A `headingBlock` or `quoteBlock` snippet override keeps the tag: `content()` renders inside it.
- **Slash menu, hotkeys and the code plugin.**
  - The slash menu opens only at the start of a text or after whitespace, matches word prefixes of labels and keywords, claims Enter only with a match, and closes when a non-empty query matches nothing or the query starts with a space.
  - A replacing kind (divider, image, code) converts a block in place only when the block holds nothing but the slash query, and is otherwise inserted after it.
  - A hotkey whose value is not a function is skipped with a development warning.
  - The code plugin's Shift+Enter runs `insertParagraph` as an intent, its auto-pair is a returned payload (after-hooks see the typed character), and a typed closer steps over the same character.
- **Links.** A URL typed before a space, or pasted at a caret, becomes a link as an undo step of its own; <kbd>Mod</kbd>+click opens a link in a new tab; <kbd>Mod</kbd>+<kbd>K</kbd> opens the toolbar's link panel, and hovering a link shows the toolbar's link card (Open, Edit, Remove; `createToolbarPlugin({ linkCard })`). `richTextOperations` gains `linkText` and `unlinkText`; `ToolbarController` gains `openLinkPanel`, `closePanel`, `takeFieldFocus` and `hovered`. See [links](/docs/plugins/rich-text#links).
- **Code languages.** `createCodePlugin({ languages, defaultLanguage })`, `CODE_LANGUAGES`, `loadCodeLanguage`, `CodeLanguage` and `CodePluginOptions` are exported; a code block's language is its `data.language` (JavaScript when unset), picked in its header, and its lines are highlighted with that language's grammar, loaded the first time one renders. See [languages](/docs/plugins/code#languages).
- **Equations.** `createEquationPlugin({ katex, macros, labels, keywords })`: a block equation (`equation`, void, in `defaultSemantics` as `equationKinds`) and an inline equation atom (`inlineEquation`), TeX drawn by KaTeX loaded on demand (an optional peer dependency), edited in a field under the equation with a live preview; slash commands, `$$…$$`, <kbd>Mod</kbd>+<kbd>Shift</kbd>+<kbd>E</kbd>; MathML on copy, KaTeX and MathML read by HTML import. `InlineBlockDefinition` takes `html` and `parse`.

### Rendering, placeholder and chrome

- `placeholder` (prop, option, plugin) is a string or `(view: { type, data, focused, empty }) => string | null`; the snippet form is gone. It renders as `data-placeholder` on the empty text element with a shipped `::before` rule (style `[data-placeholder]::before`); `[data-edytor-text-placeholder]` and its click handlers are gone. `edytor.placeholderRepair` is removed.
- Chrome lives in `[data-edytor-overlay]`, a sibling after the host: block handles (in document order), the drop indicator (`position: absolute`, not in `document.body`), menus (`position: fixed` inside the layer) and layer-relative remote carets. `--edytor-handle-offset-y` is gone. `edytor.overlay` (`layer`, `add(measure)`, `mount(…)`, `invalidate()`) is new.
- Typing, formatting, Tab and block moves never remount the element under the caret; a moved block's element is re-created where it moved. `edytor.cells` is new (the view's render cells); `refreshEditorDom`/`editorDomRevision` are removed.
- The DOM observer restores what the editor owns and leaves an extension's markup around the slots alone: a foreign node inside a block's text run is removed, a node beside it stays; foreign text inside a content is adopted; attributes the core does not own (an extension's `id` on a block element, `open` on a toggle) are never reverted.
- A kind's own control (any form control or nested editable inside a block) owns its keys, `beforeinput`, paste, copy, cut and drops, even over a block selection; the editor never writes its caret over a focused form control. `patchData` writes join one undo step only when they type into the same string properties (one run inserted or deleted); a string set to another value, such as a status, is its own step.
- A "`[data-edytor-block]` exists" check no longer means hydrated; wait for a registered text element.
- A block suggestion's preview renders inside the host as `[data-edytor-suggestion]` (non-editable, `data-status`), its blocks with `data-edytor-block` and `data-edytor-type` but no `data-edytor-id` or text elements. Select live blocks with `[data-edytor-id]`. The Notion theme styles them (`--edytor-suggestion-*`).
  - A `replace` marks its blocks `data-edytor-suggestion-replaced` (`="empty"` when they all hold nothing: folded, the preview in their place) and a replaced text range with `[data-edytor-suggestion-range]` rectangles in the overlay, where the default bar (`[data-edytor-suggestion-bar]`) lives too.
- **Block handles in layouts.** Layouts and columns have no handle; a block in a column has its `+` and grip in the gap, right of the column resize band (the gap's left 10px, the layout's height, above the handles). A handle's box covers its block's row. The handle column left of the blocks' text reorders (before or after the row at the pointer's height, never inside; a container list is one row there). While a text selection is dragged, handles and resize bands take no pointer (`data-selecting`). The block menu's Turn into flyout stays in the viewport (`[data-edytor-block-menu-flyout]`).
- A kind's element (`element`) is the block element and wraps its children; `contentElement` wraps only its own text (`content()`), and a snippet override keeps both. The rich text heading is a `div` holding an `h1`–`h3`, a quote a `div` holding a `blockquote`, their nested blocks after that tag: style `[data-edytor-type='heading'] > h2`, not `h2[data-edytor-type='heading']`.
- **Marks by tag.** A mark record declares `tag` (and `attributes` from its value); the core renders the tag itself as the mark element (`<strong data-edytor-mark="bold">`, was `<span data-edytor-mark="bold"><b>`), and the clipboard exports the same element. `MarkDefinition.html` is replaced by `tag`/`attributes`; `snippet` is optional (a snippet still renders inside a core `<span data-edytor-mark>`). Selectors such as `[data-edytor-mark="link"] a` become `a[data-edytor-mark="link"]`.
  - Built-ins: bold `strong`, italic `em`, underline `u`, strike `s`, code `code`, link `a` (sanitized `href`, `target`), superscript `sup`, subscript `sub`, color and highlight `span` with a sanitized `style`.
- **Notion theme `--edytor-block-visibility`.** Top-level blocks under `.edytor-notion` take `content-visibility: var(--edytor-block-visibility, visible)` and `contain-intrinsic-block-size: auto 32px`; the block handles and remote carets measure a skipped block through its nearest rendered ancestor.

### Collaboration and providers

- **Presence wire.** `selections[viewKey] = { start, end, collapsed, reversed, t }` for text (`DocAnchor`s), `{ blocks, t }` for a block set, `{ atom, block, t }` for an atom; the legacy `selection` mirror, `startTextId`/`yStart` fields and numeric fallbacks are gone. A view writes only its own key and clears it on destroy. `publishPresence` replaces `createAwarenessSelection`/`publishAwarenessSelection`/`clearAwarenessSelection`; `attachDocumentSync` is removed (use `document.attachSync`). A lost socket clears remote carets in that tab only.
- **Presence throttle default.** A view writes its presence at most once every 50 ms (`DEFAULT_PRESENCE_THROTTLE`; it was `0`, every change): `presence={{ throttle: 0 }}` restores every write.
- **Presence cost.** The `presence` prop (`{ share: 'caret' | 'block' | 'none', throttle }`, `edytor.presence`, `PresenceWriter`) throttles a view's presence writes and can share only the focused block or nothing; peers sharing blocks are drawn as a bar beside them (`[data-edytor-remote-block]`), and a client's freshest entry wins whatever its kind ([presence](/docs/collaboration/presence#sharing-less-at-scale)).
- **`createWebsocketSync`** takes `server`, `room`, `params`, `maxBackoffTime`, `connectTimeout`, `onExpired`, `WebSocketPolyfill`, `disableBc`, `persist` and `persistName` (`connect`, `protocols`, `resyncInterval`, `serverUrl` and `roomName` are removed).
  - It persists locally by default: an IndexedDB store beside the socket (`persist: false` opts out, `persistName` renames it from `edytor:<server>/<room>`; the returned sync's `persistName` is the name to pass to `clearDocument`), skipped where there is no `indexedDB`, attached through the new `EdytorSyncPayload.attach`. While the store exists it carries the cross-tab channel; `disableBc` turns both off (`IndexeddbPersistence` gains a `disableBc` option).
  - `connectTimeout` (default 10 000 ms, `Infinity` for no limit) closes a dial that neither opens nor fails, like a failed one.
  - The room name is percent-encoded into one path segment of the URL (`encodeURIComponent`), so a server that routes on the raw path must decode it: `acme/roadmap` dials `…/rooms/acme%2Froadmap`. An id a URL cannot carry (`''`, `.`, `..`, over 256 characters, or with a lone surrogate) throws a `TypeError` at construction.
  - `onExpired(state)` runs on each `4401` close (`{ reason, attempts, nextRetryMs }`): put a fresh token in `params` before the redial.
- **`WebsocketProvider`**: removed the `protocols` option and field (pass tokens in `params`, read at every dial), the `sync` event (use `synced`), `wsconnecting` (the `status` event carries it) and the settle window (`syncSettleMs`). `resyncInterval` stays a provider option only. The BroadcastChannel leg stays and is on by default (`disableBc` opts out); it relays other tabs' edits to the server. New:
  - `saved`, `unsaved` and the `'saved'` event (the room's `messageSaved` acknowledgements), and `readOnly` (`true` once the room's read-only notice arrives, with no event; a read-only socket counts nothing as unsaved, so check `readOnly` to learn that edits were never stored: see [saved state](/docs/collaboration/websocket#saved-state));
  - `messageChunk` reassembly;
  - the `refused` event (a `SyncRefusedError` on a `1008` close or a `4xxx` close other than `4401`, after which it stops dialing), the `expired` event (a `4401` close: expired credentials; the provider redials after the backoff with the re-read `params`) and the `unreachable` event (the backoff cap grows to 30 s after 8 dials that never synced);
  - the `connectTimeout` option.
  - A room fault (`1011`) after a sync also grows the backoff, until the room acknowledges every local update again. The provider sends a text `ping` after 15 s of silence, and a text `pong` counts as liveness.
- **Readiness.** The document decides readiness itself: `syncFailed`, `onSyncSettled` and `EdytorDocSyncPendingError` are gone; `whenSynced` exists on both providers and `synced` is the lifetime claim.
  - A lone first client is ready after `DEFAULT_READINESS_BOUND` (1 s, per factory `EdytorSync.bound`; `createWebsocketSync` arms it from the socket's open or first failed dial through the new `EdytorSyncPayload.armBound`); `history` refuses while `pending`.
  - A refusal never seeds: `document.syncRefusal` and `document.onSyncRefused(fn)` are new. A refusal belongs to the provider that reported it: releasing that provider, or its next sync, lifts it.
  - A sync factory's payload carries `EdytorSyncPayload.failed(error, provider)` beside `synced`: the provider's terminal failure, reported once when it never synced (destroyed before any handshake, refused, or denied).
  - `EdytorSyncPayload.holdBound()` stops a provider's bound until the next `armBound()`: a `4401` before the first sync holds it, so an empty document waits for a dial that gets in instead of seeding.
- **One provider per target.** `EdytorSync.target` (`indexeddb:<name>`, `websocket:<server>/<room>`); attaching a target already attached is a no-op returning nothing; attaching on a destroyed document throws `DocumentDestroyedError`.
- **Admission.** Unversioned content is not refused at ingress: the document is read-only and quarantined until admission accepts it (`document.writable`, `onWritableChange`).
- **`IndexeddbPersistence`**: `get`/`set`/`del` are removed (the `custom` store holds only the generation record).
- **SSR.** `<Edytor>` releases the document it created in `onDestroy`, which also runs after a server render.
- **First paint from a snapshot.** `EdytorProps.snapshot` (`JSONDoc`, rendered read-only inside `[data-edytor-snapshot]` while the document is pending); `documentSnapshot(options: LastUpdatedOptions): Promise<JSONDoc | null>` (package root, `edytor/collaboration` and `bindCrdt(Y).providers`); `routeDocumentSocket` answers `GET <room>?snapshot` and the room's `PROBE_HEADER` takes `snapshot` (`{ lastUpdated, document }`, `503` while the room has no document).
- **Offline coverage.** `prefetch(options: PrefetchOptions): Promise<PrefetchResult>` and `lastUpdated(options: LastUpdatedOptions)` (package root and `bindCrdt(Y).providers`); `DocumentOptions.requireHydration`, `EdytorDocument.requireHydration`, `EdytorOptions.requireHydration` and the `<Edytor requireHydration>` prop; the room's `lastUpdated()` (RPC), its `meta` table and `PROBE_HEADER`; `routeDocumentSocket` answers `GET <room>?lastUpdated`.
- **Outbound chunking.** `WebsocketProvider` and `createWebsocketSync` take `maxFrameBytes` (default `MAX_FRAME_BYTES`) and chunk larger frames; the room reads `messageChunk` inbound (closing `1011` `chunk sequence lost` on a part without a start). The image plugin exports `MAX_INLINE_IMAGE_BYTES`, `oversizedInlineImage` and `storableImageSrc`, and marks its panel error `[data-edytor-image-error]`.

### The room (`edytor/cloudflare`)

- **`edytor/cloudflare` (new).** `DocumentRoom`, `attachRoom` and `routeDocumentSocket(request, namespace, documentId, authorize)` replace the coordinator you wrote yourself; see [the room](/docs/server/room).
  - The entry also exports `AttachedDocument` (what `attachRoom` returns: the socket handlers plus `transact`, `read`, `compact`, `dropWaitingDeletes`, `reset` and the diagnostics; forward the ones you call over RPC), `SOCKET_TAG`, `noTimers`, `ROOM_ORIGIN` (the origin of the room's own edits), `IDENTITY_HEADERS`, the defaults `DEFAULT_MAX_ROW_BYTES`, `DEFAULT_COMPACT_AFTER` and `DEFAULT_SAVE_AFTER`, and the caps `MAX_REFUSALS` and `MAX_WAITING_DELETES` (the delete ranges the room keeps waiting for items it does not hold).
  - Its types: `AttachRoomOptions`, `Attachment`, `DocumentRoomEnv`, `LoadedDocument`, `Refusal`, `ReplicaOwner`, `SavedDocument`, `SocketIdentity`, `AuthorizeDocumentSocket`, `ExpiredCredential`, `DocumentNamespace` and `DocumentIdentity`.
  - `requestedReplica(request)` reads the dial's client id for `authorize`, and `closedSocket(code, reason)` turns a dial away from your own Worker with a close the provider understands (an HTTP error reaches the browser as `1006`, which it redials forever).
  - The room binds `{ user, replica, readOnly }` to each socket, strips the content of updates under another user's client ids, and applies `defaultSemantics` to server edits.

**Close codes** the room and its router send (the `CLOSE` table; see [the room](/docs/server/room#admission) for each reason), and what the provider does:

| Code | When | The provider |
| --- | --- | --- |
| `4400` | An empty document id, `.`, `..`, one over 256 characters or one with a lone surrogate (`authorize` is not called). | Stops. |
| `4401` | `authorize` returns `{ expired: true }` (`ExpiredCredential`), or the `expiresAt` it returned passed. | Redials, reading `params` again. |
| `4403` | `authorize` returns `null` or an invalid identity (a `userId` empty, not a string, over 256 characters or with a lone surrogate, an invalid `replica`), the page's origin is not in `allowedOrigins`, or the room revoked the user's access (`closeUser`, `setAccess(user, 'none')`). | Stops. |
| `4409` | A replica id another user holds. | Stops. |
| `4413` | A room quota (`quota: document`, `quota: rate`, `quota: frame`): the write is not applied. | Stops. |
| `1008` | `refused: <reason>`: a frame of another generation (`generation`), a replica the dial does not own (`replica`), a forged schema stamp (`schema`), undecodable bytes (`malformed`), a socket the room holds no user for (`identity`), or a stored document the room refuses (`container`). | Stops. |
| `1011` | A fault of the room itself (`storage failure`, `internal error`, `room busy`, `room unavailable`). | Retries, backing off while it repeats. |
| `1012` | `access changed`: the room granted write access to a read-only socket (`setAccess(user, 'write')`). | Redials at once. |

- **Room compaction.** The room's compaction stores the live document (`encodeStateAsUpdate` without what waits), never a merge of the stored updates, and the room's document applies the text-delete `gcFilter` from its creation (`bindCrdt(Y).doc.keepCopies`, new), so it keeps a deleted restoration copy's text. `bindCrdt(Y).admission.admitUpdate` takes several updates (applied in one transaction, `{ v2: bytes }` for one in the v2 encoding) and `{ prepare }`.
- **Storage format v2.** Snapshots (room compaction, the IndexedDB store's `storeState`) are v2 and gzip-compressed where `CompressionStream` exists; update rows stay v1. The generation record gains `storage` (`GenerationRecord.storage`, `STORAGE_FORMAT`, `STORED_GENERATION_RECORD`); a record without it is v1, and an unknown format is a `GenerationMismatchError`. An IndexedDB snapshot row is the object `{ v2 }`. The room's `records(kind?)` returns `StoredRecord`s, `{ kind, record, bytes, v2 }` (a compressed snapshot inflated) and `compressed()` is new (also over RPC).
- **Room quotas.** `maxDocumentBytes`, `maxUpdatesPerSecond` and `maxInboundFrameBytes` (`EDYTOR_MAX_DOCUMENT_BYTES`, `EDYTOR_MAX_UPDATES_PER_SECOND`, `EDYTOR_MAX_INBOUND_FRAME_BYTES`; defaults `DEFAULT_MAX_DOCUMENT_BYTES`, `DEFAULT_MAX_UPDATES_PER_SECOND`, `DEFAULT_MAX_INBOUND_FRAME_BYTES`); a write past one closes its socket `4413` (`CLOSE.quota`; the close-code table `CLOSE` is now exported from `edytor/crdt/edytor`), refusal reason `quota`. `createChunkReader(maxBytes?)` throws `ChunkLimitError` for a sequence announcing more.
- **Document size warning.** `documentWarning` (`EDYTOR_DOCUMENT_WARNING`, default `DEFAULT_DOCUMENT_WARNING`, 0.8): the room logs `{ edytor: 'size', bytes, limit, share }` once when the document reaches that share of `maxDocumentBytes`; `metrics()` reports `documentLimit`.
- **Room validation.** `AttachRoomOptions.validate(frame)` and `DocumentRoom.validate`, with a `FrameValidation`: `{ user, replica, touched, dataChanged, before, after, facade }`, `before`/`after` returning a `ValidatedBlock` (`{ id, type, data, content, parent }`) or `null`; `false` or a throw denies, and the room undoes the frame (refusal entry `denied`). Per-writer marks of another writer are stripped (refusal reason `mark`). `facade.releaseHistory(um)` drops every step of a history `createUndoManager` made and releases what they kept, by the history limit's rule.
- **Room metrics and log.** `metrics()`, `RoomMetrics` and `Timing`; the `log` option, `DocumentRoom.log`, `RoomLogEntry` and `EDYTOR_LOG`.
- **Version history.** The room keeps two versions a day (first in a KV namespace; see the history stores below): the `history` option of `attachDocument` (`HistoryOptions`: `{ store, retentionDays, timeZone, maxValueBytes }`), `DocumentRoom.history()` (the `EDYTOR_HISTORY` binding with `EDYTOR_HISTORY_RETENTION_DAYS` and `EDYTOR_HISTORY_TIME_ZONE` by default); `DEFAULT_RETENTION_DAYS` and `HISTORY_MAX_VALUE_BYTES`. See [History and purge](/docs/server/history).
  - The room's `listHistory()` (`HistoryEntry[]`), `readHistory(key)`, `restoreHistory(key, { user })` (`RestoreResult`, origin `RESTORE_ORIGIN`), `undoRestore({ user })` and `historyWritten()`, also over RPC, and `routeDocumentHistory(request, namespace, documentId, authorize)` for HTTP.
  - Refusal reason `history`; `RoomMetrics.history`; log entries `history` and `restore`. `bindCrdt(Y).doc.restoreTo(doc, facade, json)` is the restore itself.
- **History stores.** `HistoryOptions.store` takes a `HistoryStore` (`maxValueBytes`, `nativeTtl`, `put(key, value, { expiresAt, metadata })`, `get(key)`, `list(prefix, cursor)` of `HistoryStoreRecord`s, `delete(key)`), or a `HistoryStoreFactory` over the room's storage (`HistoryRoomStorage`); a KV namespace (`KVLike`) goes through `kvHistory`.
  - Adapters `kvHistory(namespace)`, `r2History(bucket)` (an `R2BucketLike`) and `roomHistory({ maxBytes, maxValueBytes })`, with `R2_HISTORY_MAX_VALUE_BYTES`, `ROOM_HISTORY_MAX_BYTES` and `ROOM_HISTORY_MAX_VALUE_BYTES`; `HistoryMetadata` is exported; `HistoryEntry.expiresAt`.
  - `EDYTOR_HISTORY` takes a KV or R2 binding or `"room"`; the alarm's `retention` task deletes expired versions.
- **Concurrent creations of one id.** The losing node of a concurrent creation of one block id keeps its subtree (`isKeptReplaced` exported from `edytor/crdt`, `Doc.keepReplaced`), and its text shows at the end of the winner's (an implicit merge claim); `insertBlock`, `splitBlock` and pastes refuse an id holding U+0000.
- **Anchored merges.** A merge claim stores the end of the block it joins (`MergeClaim.a`, `MergeClaim.r`; `Claim.holder` names the block that stores a claim shown in another); a concurrent split moves it to the split's last piece. `TextBlockRec.listClaims` is a record's stored list, `claims` its effective claims.
- **Comment quotas.** `CommentOptions.maxBytes` and `maxRequestsPerSecond` (`EDYTOR_MAX_COMMENT_BYTES`, `EDYTOR_MAX_COMMENT_REQUESTS_PER_SECOND`; defaults `DEFAULT_MAX_COMMENT_BYTES`, `DEFAULT_MAX_COMMENT_REQUESTS_PER_SECOND`), `COMMENT_ROW_BYTES`, `commentBytes`, `decideComment`'s `bytes` and `maxBytes`, the refusal reason `comments` and the `429` of `routeDocumentComments`.
- **Per-block locks.** `lockedBlocks(options)` and `LockOptions` (`key`, `subtree`, `bypass`); the `locks` option of `attachDocument`, `DocumentRoom.locks()` and the `EDYTOR_LOCKS` variable.
- **Cross-document moves.** `moveBlocksBetweenRooms(namespace, move)` and `forwardLateEdits(namespace, from)`; the `rooms` option, `DocumentRoom.rooms()` and the `EDYTOR_ROOMS` binding; `DEFAULT_MOVE_GRACE_DAYS`. See [moving blocks between documents](/docs/server/moves).
  - The room's `exportBlocks(ids)`, `importBlocks(request)`, `commitMove(moveId, receipt)`, `abortMove(moveId)`, `lateEdits()`, `ackLateEdits(moveId, seq)` and `applyLateEdits(batch)`, also over RPC.
  - The types `MoveNamespace`, `MoveRoom`, `MoveDestination`, `ExportedBlocks`, `ImportRequest`, `ImportReceipt`, `CommitResult`, `LateEdit`, `LateEditBatch` and `MovedState`.
  - Log entries `move` and `late`; the alarm's `forward` task; tables `moves` and `late`.
- **Purge.** The room purges content deleted before its horizon (`purgeAfterDays`, `EDYTOR_PURGE_AFTER_DAYS`; default the retention, else 30 days) as its own transaction (origin `PURGE_ORIGIN`). A document's histories drop the steps below the horizon.
  - `bindCrdt(Y).doc.purge(doc, facade, horizon)` (`PurgeReport`) and `bindCrdt(Y).doc.horizonOf(doc)`; the room's `purge()` (also over RPC), `RoomMetrics.purge` and the `purge` log entry.
  - The room's alarm runs `onSave`, the history and the purge, each due time stored; `attachDocument` installs `alarm` unless none applies; the `now` option and `DocumentRoom.now()` set the room's clock.

### Migration

- `MigrationRecord` loses `owner` and `leaseUntil` and is never stored `pending`; `MigrateOptions` has no lease options and `waitForSettled` takes only the name (a crash-released `navigator.locks` lock arbitrates; `status()` reports `pending`, `wait: false` returns `busy`).
- `MigrationPhase` loses `activate`/`announce`; there are no BroadcastChannel migration announcements.
- `force` restores legacy ids in place instead of overwriting a snapshot row; `result.update` is the full migrated state; a foreign-generation container makes `migrate` throw `GenerationMismatchError`. `bindCrdt(Y).doc.restore` is new.
