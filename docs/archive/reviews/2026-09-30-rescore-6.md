## Open units of work

### ZW-01 — Non-item blocks land directly inside a list container

- **Area:** Editing behaviors (the CRDT facade is involved) · **Severity:** medium · **Effort:** M
- **Where:**
  - `src/lib/crdt/edytor-doc.ts:1882`: `mergeUnnesting` moves the kids with no `fits` check.
  - `edytor-doc.ts:1935-1947`: the pull-up returns early without `emptying` when the item has children.
  - `edytor-doc.ts:1137-1144`: `canPlace` has no container rule.
- **Failure:** this happens with the documented structural `unordered-list`/`ordered-list` kinds, which are also what HTML paste produces.
  - Delete at the end of `p` above `ul > [li 'a' > [p 'child'], li 'b']` gives `ul > [paragraph 'child', li 'b']`. The paragraph renders as a bullet-less `<p>` inside the `<ul>`.
  - With a one-item list, the result is `ul > [paragraph]`, a list with no item that nothing removes.
  - Tab on a paragraph right after a list gives `ul > [li a, paragraph q]`.
  - Backspace at the start of a middle item that has a paragraph child leaves that paragraph in the list.
- **Fix:**
  - In `mergeUnnesting`, send children that fail `fits(from, kids, pos.parent)` to the merge target as its children, as Notion does.
  - Run `emptying()` after the pull-up whether or not the item had children.
  - In `canPlace` or the moves destination, refuse a non-item under a list container, or retarget `in` to the list's last item.
  - This fix depends on ZW-14. The contract sentence "a block never lands directly in a container it is no item of" contradicts the pinned DR-crdt-1 columns outdent row. Decide its scope first (lists: yes; columns last-paragraph outdent: as pinned), then make the code and the contract agree.
- **Done when:**
  - rescore5-crdt-view has rows for the pull-up (first item with a paragraph child, and a one-item list), the middle-item merge, and Tab after a list. They pass, and no list container ends up holding a non-item or no item.
  - The DR-crdt-1 row still passes or has been deliberately re-decided.
  - `pnpm test:dom` and `pnpm test:crdt` are green.

### ZW-02 — Turn into over a block selection converts the list container itself

- **Where:**

### ZW-03 — Splitting a list on Shift+Tab moves a peer's concurrent Enter or append into the upper list

- **Area:** CRDT correctness · **Severity:** medium · **Effort:** M
- **Where:** `src/lib/crdt/edytor-doc.ts:1778` (container branch of `unNestBlocks`). The code computes `after = childrenIds(from).slice(pos.index+1)` at plan time, then moves those blocks into a new list `rest`.
- **Failure:** start from `[P, U[I1 'a', I2 'b', I3 'c']]`. Ada outdents I2 while Bob, at the same moment, presses Enter at the end of I3 and types 'd'.
  - All replicas converge to `U[I1, I4 'd'] I2 'b' NEW[I3 'c']`. Bob's bullet jumps above Ada's paragraph and his caret moves with it.
  - Running the same two edits one after the other gives `NEW[I3, I4]`, the order the user intended.
  - Case D (both peers outdent) can leave `c` before `b` plus an empty list.
  - No text is lost, and every replica converges.
- **Fix:** split the other way. Keep the trailing items in `from` and move the leading items into a new list inserted before the outdented block, so a concurrent append at the end stays in the correct list. If that trade is rejected, document the ordering residual in `del.merge.container` instead.
- **Done when:** a p1 converge row (Ada outdents a middle item, Bob splits the last item and types) puts Bob's item after I3 on every replica and delivery order. Case D has a pinned, documented expectation. `pnpm test:crdt` is green.

### ZW-04 — A writer can push waiting deletes past MAX_WAITING_DELETES without limit

- **Area:** Durable Object server · **Severity:** low · **Effort:** S
- **Where:** `src/lib/cloudflare/DocumentRoom.ts:517` (`unheldDeletes` and `carriedClocks` at :493-521; the cap check at :1465-1467).
- **Failure:**
  - One frame that carries a struct of the writer's own id at a high clock, plus N deletes of that id below it, gets all N stored as a `pending` record and acknowledged, with no `waiting` refusal for the sender. This was reproduced with 200,000 ranges and again independently with 5,000.
  - Afterwards, every honest relayer delete is dropped as `waiting` and logged against the relayer, and every update in the room pays a cost proportional to N.
  - `compact()` keeps the ranges because the id is registered. `dropWaitingDeletes()` clears them, but the same frame refills the queue.
  - This breaks the stated bound at room.mdx:40 ("at most MAX_WAITING_DELETES (1,024) ranges wait").
- **Fix:** count as carried only the exact IdSet that the frame's non-stripped structs cover, or re-check `added` against `MAX_WAITING_DELETES` in `settleDeletes` and drop the excess, logging `waiting` for the sender.
- **Done when:** a workerd row (one high-clock struct plus more than 1,024 deletes below it) shows at most 1,024 ranges waiting, a `waiting` refusal attributed to the sender, and a relayer delete still stored and acknowledged afterwards. `pnpm test:do` is green.

### ZW-05 — The empty-container rule exists twice, and a text range deletes a container's hidden text

### ZW-07 — A Tab over several sibling groups reports `dispatcher.last = refused` although blocks moved

### ZW-10 — Room ids `.` and `..` never reach their room

- **Areas:** Collaboration, Durable Object server, Documentation (one unit covering all three) · **Severity:** low · **Effort:** S
- **Where:**
  - `src/lib/crdt/providers/websocket.ts:687`: `encodeURIComponent` leaves `.` alone, and the constructor does not check the room name.
  - The docs claim "any string": websocket.mdx:20, authorization.mdx:40, limitations.mdx:52, edytor-component.mdx:32.
- **Failure:** WHATWG URL parsing collapses dot segments. The id `.` dials `/rooms/` and `..` dials `/`, so the documented route answers 404. The browser reports 1006 and the provider redials forever as `unreachable`, with no refusal ever shown.
- **Fix:** refuse `''`, `.` and `..` at provider construction with a clear error, and name the exception in the four doc pages. Note that escaping the dots as `%2E` does **not** work, because WHATWG also normalizes a segment made entirely of `%2E`.
- **Done when:** the YW-05 row covers `.` and `..` and asserts the clear refusal. The docs name the exception, and docs-drift passes.
