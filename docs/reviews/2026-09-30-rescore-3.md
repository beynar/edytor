### FW-01: Undo of an island delete or merge seals a peer's nested block inside a codeLine
- **Area:** CRDT
- **Severity:** medium
- **Effort:** M
- **Where:** `src/lib/crdt/placement/model.ts:449` (displaySlotOf, lines 449-470). Also `src/lib/plugins/code/CodePlugin.svelte:191-193` and `tests/crdt/harness/assert/well-formed.ts:105-117`.
- **Failure:**
  1. The document has a code block C with line L1, followed by a paragraph N.
  2. Ada deletes C, or merges it with Backspace. L1 becomes a paragraph.
  3. Bob nests N under L1. canPlace allows this, because L1 is no longer inside an island.
  4. Ada presses Undo.

  Every replica now converges to `C:code[L1:codeLine[N]]`. The codeLine snippet renders only its own content, so N disappears from both screens, and `canPlace(['N'])` returns false, so N cannot be selected or moved. Neither wellFormed nor the island-kind check flags it. The content is still in toJSON. It comes back only through Bob's undo or Ada's redo.
- **Fix:** At read time, as UW-21b does for voids, treat a block that sits strictly inside an island without being the island's direct child as having no children for display. Its children then take its slot outside the island, with the reset. Alternatively, have undo re-home a foreign subtree that would land inside an island. Also extend the island-kind check so that two cases count as violations: a child under the island's default child kind, and a kind other than the default directly under an island.
- **Done when:**
  - A p1 row exists for the sequence above (delete or merge C, the peer nests N under L1, undo).
  - That row leaves N visible and movable for every client-id order.
  - The island-kind check flags the sealed shape.
  - The roles corpus is still 162/162.

### FW-02: Backspace, Delete and Tab next to a collapsed toggle act on its hidden body
- **Area:** Behaviors
- **Severity:** medium
- **Effort:** M
- **Where:** `src/lib/events/beforeInputDeleteCommands.ts:118` (Backspace, lines 118-126) and lines 36-42 (Delete). The HIDDEN rule is at `src/lib/selection/selection.svelte.ts:136`. Toggles render closed by default (`RichTextPlugin.svelte:393`).
- **Failure:** The document is `[toggle 'title'->[p 'body'], p 'after']` with the toggle closed.
  - Backspace at the start of 'after' gives `toggle->[p 'bodyafter']`. The caret ends up in the hidden block, so the next keystrokes also go into invisible content.
  - Delete at the end of 'title' pulls the hidden child into the header, giving 'titlebody'.
  - Tab on 'after' nests it as a hidden child, and the toggle stays closed.

  Enter already handles closed toggles and has tests for it. These three keys do not.
- **Fix:**
  - Resolve the previous and next block as the nearest block that is displayed, using the same HIDDEN test that arrow navigation uses.
  - Backspace after a closed toggle merges into the toggle's header.
  - Delete at the end of a closed header merges the block that comes after the toggle.
  - Tab into a closed toggle opens it, or keeps the nested block visible.
- **Done when:**
  - notion-parity has rows for all three keys next to a collapsed toggle, and they pass.
  - hotkeys.mdx states the rule.

### FW-04: Tab over several code lines damages the first line, and Shift+Tab never dedents
- **Area:** Behaviors
- **Severity:** medium
- **Effort:** S
- **Where:** `src/lib/plugins/code/CodePlugin.svelte:68`. Also `src/lib/text/text.utils.ts:57-58`.
- **Failure:** The Tab handler calls `insertText('\t')` without passing start or end, so it picks up an end offset that belongs to another line. On the lines `['if (a) {','run();','}']`:
  - Selecting l1:0 to l3:1 gives `'\tf (a) {'`.
  - Selecting l2:5 to l3:1 gives `'run()\t;'`.
  - Selecting l2:0 to l3:0 replaces 'run();' with a tab.

  In every case the selection collapses. The code plugin has no Shift+Tab binding, and the built-in unnest refuses the move.
- **Fix:**
  - When a range spans code lines of the same island, insert '\t' at offset 0 of each line in one run, and keep the range, shifted.
  - Pass an explicit start and end for the single-line case.
  - Add a Shift+Tab binding that removes one leading tab (or up to tab-size spaces).
  - Update code.mdx.
- **Done when:**
  - DOM rows pass for multi-line Tab, Shift+Tab, and a partial single-line selection.
  - code.mdx's Editing table documents both keys.

### FW-05: Block-menu Delete puts the caret past the children that take the block's place
- **Area:** Code
- **Severity:** medium (raised from low)
- **Effort:** S
- **Where:** `src/lib/plugins/blockMenu/BlockMenuController.svelte.ts:195`
- **Failure:** `remove()` computes the next caret position from the deleted block's deepest last descendant. But `removeBlock()` keeps the children, which are promoted into the block's place.
  - `[a, b->[b1,b2], c]`, deleting b: the caret lands at `['c',0]`.
  - When b is the last block: the caret lands at `['a',1]`.

  In both cases it should land at b1, which is what block-menu.mdx promises.
- **Fix:** `const after = this.editable(block, 'blockAfter', 'firstEditableText')`
- **Done when:** An editing-lows row for a block with children expects `['b1',0]`, both with and without a following block.

### FW-06: Tab or Shift+Tab over a block selection holding a parent and its child does nothing
- **Area:** Behaviors
- **Severity:** medium (raised from low)
- **Effort:** S
- **Where:** `src/lib/session/bindings.ts:171`. Also `src/lib/session/moves.ts:27`.
- **Failure:** Shift+Down from a parent always adds its first child as its own member of the selection, for example `[b, b1, c]`. `nest()` passes all members to one `moveBlocks`, and `placement()` refuses a group whose members are not siblings. The key is swallowed and the tree is unchanged.
- **Fix:**
  - Drop members that have a selected ancestor, as `rangeBlocks` and `duplicateAll` already do.
  - Group the rest by parent and move each group in one `run('moveBlocks')`.
  - Reselect the moved roots.
- **Done when:** An editing-lows row for `[a, b->[b1], c]`, with b selected and Shift+Down pressed twice, nests b (with b1) and c under a with Tab, and one Undo reverts it.

### FW-07: `saved` never becomes true after a reload when the local copy holds edits the room stripped
- **Areas:** Collaboration, Durable Object, Docs
- **Severity:** low
- **Effort:** S
- **Where:** `src/lib/crdt/providers/websocket.ts:464-471`, `src/lib/crdt/providers/index.ts:218` and `indexeddb.ts:128-131`. The docs claims are at `authorization.mdx:136-138` and `websocket.mdx:184`.
- **Failure:** The IndexedDB replay, and the constructor's `_track(stateVector(doc))`, record every client's clocks, including a peer's content that the room lost and keeps stripping. A workerd repro gave `saved=false`, `unsaved=1` with no end. The effects:
  - "Saving…" and the unload warning stay until the author's own client returns, or for good if her device is lost.
  - `_faults` never resets, so the reconnect delay keeps growing after 1011 closes.
- **Fix:** Count as pending only the clocks of this replica's own client id and ids registered to the same user. Do not simply ignore the store's origin: offline edits the user made before the reload must still count as unsaved. As a stopgap, qualify both doc sentences with "within the session that heard them".
- **Done when:**
  - The RW-10 workerd test has a reload case: a provider on a hydrated doc reaches `saved=true` once its own edits are stored.
  - The docs match the behavior.

### FW-08: An onSyncExpired or onExpired callback that throws synchronously stops the provider and seeds the draft
- **Area:** API
- **Severity:** low
- **Effort:** S
- **Where:** `src/lib/crdt/providers/websocket.ts:325` (emits before the redial at :329), `src/lib/crdt/providers/index.ts:183/211` (the consumer listener runs before the hold listener), and `Edytor.svelte:197`.
- **Failure:** A callback written without `async` that throws means the redial is never scheduled and holdBound never runs. The armed bound then seeds the draft. The repro showed 1 dial and readiness 'local', against 5 dials and 'pending' when the callback does not throw. The provider stops silently, and the seeded draft can later merge into the room.
- **Fix:**
  - Schedule the redial before emitting, or emit through a guarded emit that logs and continues.
  - Register the hold listener before the consumer's listener, or wrap `onExpired(state)` in try/catch.
- **Done when:** A row with a throwing onSyncExpired still redials, and the document stays pending.

### FW-11: An alarm that fires during a retryable failure silently skips onSave
- **Area:** Durable Object
- **Severity:** low
- **Effort:** S
- **Where:** `src/lib/cloudflare/DocumentRoom.ts:582` (alarm, lines 580-592). Also start() at :515 and scheduleSave at :669-673.
- **Failure:** `alarm()` returns normally while the doc is null, which consumes the platform alarm. After the room recovers, `start()` finds no alarm and nothing re-arms the save. The external mirror lags until the next edit, so a restore after a storage loss would come from a stale mirror.

### FW-13: history.mdx overstates what `dispatcher.run(kind, body)` makes one undo step
- **Areas:** API, Docs
- **Severity:** low (two findings, one sentence)
- **Effort:** S
- **Where:** `site/content/docs/editor/history.mdx:53`. Also `src/lib/session/commands.ts:207-223`, :141 and :456.
- **Failure:** The claim fails in two cases:
  1. With an async body, `running` is reset before the promise settles, so commands after an `await` cut into their own steps (a stack of 3 instead of 2).

- **Done when:** The docs are qualified. Optionally, H-G7 gains rows that pin the documented behavior for an async body and for `captureTimeout: 0`.
