## New units of work

### Medium

**NW-01: A restore from a lagging snapshot locks out clients that relay another user's edits**
- **Area:** Durable Object server
- **Severity:** medium (lowered from high)
- **Effort:** M
- **Location:** `src/lib/cloudflare/DocumentRoom.ts:788`, in `claim()`; the refusal is at `onSync` :948-950.
- **Failure:** The room's storage is lost and `onLoad` restores an onSave snapshot from before some collaboration. Two outcomes, depending on the restore shape:
  - With `{update, replicas}`, a client holding another user's post-snapshot structs is closed with 1008 `refused: replica`. The provider treats 1008 as terminal, and the frame carrying the client's own edits is dropped. After a reload, IndexedDB resends the same foreign structs, so the client is refused again until the original author reconnects first.
  - With a bare update, the first client to relay those structs takes over the author's orphaned id. The author's next dial then gets 403.
- **Fix:**
  - Split `newWriters` into ids the sender may write under (its own, its bound replica, or ids already registered to it) and ids it is only relaying.
  - Only the dialed or bound replica may claim an orphan or a fresh id.
  - For relayed structs: accept them without changing ownership, logged as `relayed`, when the room holds none of those clocks. Otherwise strip them from the frame. Never refuse the whole frame.
  - Document the relay case in extending.mdx#load and authorization.mdx.
- **Done when:** a workerd test with two clients and a lagging restore passes for both restore shapes. Bob stays connected, his own edits are stored, and Ada keeps her id and can dial.

**NW-02: Server and storage exceptions in the message path are refused as `malformed` 1008, which clients treat as terminal**
- **Area:** Collaboration and Durable Object server (reported by both; merged)
- **Severity:** medium
- **Effort:** S
- **Location:** `src/lib/cloudflare/DocumentRoom.ts:882`, the catch-all in `webSocketMessage`; related code in `claim()` :771-802 and in `rebuild()`→`load()` :591-593.
- **Failure:** A transient SQLite fault (SQLITE_FULL, an I/O error) while registering a client id in `claim()` closes the socket with 1008 `refused: malformed`. This is reproduced in workerd with a `BEFORE INSERT ON replicas` trigger. The provider then stops dialing for good, and unsent edits are stranded until a reload. Operators see a "malformed" refusal and blame the client.
  - Separately, a transient read failure inside `rebuild()` calls `fail(error, false)`, which is non-retryable. Every socket then gets a terminal 1008 container refusal.
  - The append path, by contrast, correctly closes 1011 so the client redials.
- **Fix:**
  - Keep 1008 `malformed` only for errors from decoding the client's bytes: wrap just the decode step, or tag decoder errors.
  - Route claim SQL errors, engine errors and send errors to `note({reason:'storage'|'internal'})` and close 1011, calling `rebuild()` first where the document may be inconsistent, as `recover()` does.
  - Make a `load()` failure inside `rebuild()` retryable.
- **Done when:** a DO test with a replicas-INSERT RAISE trigger passes. A fresh-client update and an unbound presence frame both close 1011 with a `storage` refusal. After the trigger is dropped, the provider redials, the edit is stored, and no `refused` event fires. A second test covers a load failure during rebuild, which must close 1011.

**NW-03: The slash menu hijacks Enter in ordinary prose**
- **Area:** Editing behaviors
- **Severity:** medium (lowered from high)
- **Effort:** S
- **Location:** `src/lib/plugins/slashMenu/SlashMenuController.svelte.ts:23`, where matching is done at :18-24 and the menu opens at :61.
- **Failure:** The menu opens on any `/`, including mid-word. The query is matched with `includes()` against the command id (which starts with `block.`), the label and the keywords. So Enter right after common text runs a command:
  - `see 1/2` + Enter produces an h2 "see 1".
  - `a/b` + Enter produces "a", with no new line.
  - `w/o` + Enter produces "w".
  - `and/or` + Enter matches the divider keyword "separator", produces a divider and erases "and".
  - Undo recovers the text.
- **Fix:**
  - Open the menu only when `/` is at offset 0 or follows whitespace.
  - Match labels and keywords by word prefix, and stop matching the `block.` id.
  - Update slash-menu.mdx:30 and :48 to match.
- **Done when:** notion-parity rows for `see 1/2`, `a/b` and `and/or` + Enter each keep their text, add a new paragraph and leave the menu closed. The existing `/zzqq` rows still pass.

**NW-04: Slash commands for replacing kinds erase a non-empty block's text and children**
- **Area:** Editing behaviors
- **Severity:** medium (lowered from high)
- **Effort:** M
- **Location:** `src/lib/kinds.ts:97`, in `kindCommand.run` → `convertToKind`.
- **Failure:** Replacing kinds are those that convert the block to an empty shape: /divider, /code and /image. Each wipes the block it runs in:
  - `keep me /divider` + Enter gives `[divider, paragraph]`, and the text is gone.
  - `/code` in the same block gives an empty code block.
  - An empty paragraph with a nested child, then `/divider`, deletes the child subtree.
  - The markdown path guards against this with `alone` (markdownShortcuts.ts:103-105); the slash path has no guard.
- **Fix:** When the row replaces and the block has text other than the slash query, or has children, insert the new kind after the block in one plan and put the caret there. The divider case can reuse `insertDividerAtSelection`. Convert in place only when the block is empty and has no children.
- **Done when:** s6 rows for `/divider` and `/code` on a block with text and on a block with children keep the original block intact, insert the new kind after it, and undo in one step.

**NW-05: Enter in the middle of a container header moves the container's body to a new block**
- **Area:** Editing behaviors
- **Severity:** medium
- **Effort:** M
- **Location:** `src/lib/events/beforeInputCommands.ts:307`, which reaches `prepareSplit` (block.utils.ts:283-293) and the facade's `splitBlock` (edytor-doc.ts:1636-1664).
- **Failure:** In each case below the container starts as `title` with a child `body`, and the caret is between "ti" and "tle":
  - Callout gives `[callout "ti", paragraph "tle" → [body]]`. The body leaves the callout.
  - Quote behaves the same way.
  - An open or closed toggle gives `[toggle "ti", toggle "tle" → [body]]`. The closed case contradicts the documented rule that "children stay".
- **Fix:** Add a mid-header branch in `insertParagraph` for a container that has children or is an open toggle. The tail becomes child 0 of the head, of its defaultChild kind, and the children stay with the head. For a closed toggle, create a sibling toggle holding the tail and leave the children on the head; this needs a split variant that does not move children, still in one plan. Document where children go in hotkeys.mdx.
- **Done when:** notion-parity rows pass for mid-header Enter in a callout, a quote, an open toggle and a closed toggle. Each keeps the body with the original header and undoes in one step.

**NW-06: The CUT table is incomplete, so direct operations and `+` on an empty block merge with earlier typing**
- **Area:** Code organization
- **Severity:** medium
- **Effort:** S
- **Location:** `src/lib/session/commands.ts:60` (the CUT table), `policyOf` :89-91, and `BlockHandleController.svelte.ts:165-183`.
- **Failure:**
  - `markText`, `removeMarksFromText`, `addChildBlock(s)`, `setInlineData`, `pushContentIntoBlock` and `setText` default to 'continue' outside `run()`. A plugin calling any of them joins the undo step of typing done in another block.
  - `+` on an empty block reduces to a bare `insertText('/')`. Type 'a', click `+` on an empty paragraph, press Cmd+Z once, and both the 'a' and the '/' are undone. This contradicts history.mdx:44 and :53.
- **Fix:**
  - Wrap `addBlock` in `dispatcher.run('insertBlock', …)`, using `dispatcher.caret` and no `tick()`.
  - Add the missing operations to CUT as 'before'. Or flip the default: outside `run`, only `insertText`/`addInlineBlock` continue, and only when `history.continues` holds.
  - Confirm that `run('format')` wrapping `markText` still gives one step.
- **Done when:** arch-v2-history-grouping.test.tsx gains two rows:
  - an H-G5 row for `+` on an empty paragraph after typing (stack depth 2);
  - an H-G7 row for direct `markText`, `addChildBlock` and `setInlineData` calls (each starts a new step).

**NW-07: A readonly view offers the image panel and runs `upload(file)` before the write is refused**

### Low

**NW-08: A SyncRefusedError sticks to the document, so an empty document never becomes ready after a re-attach**
- **Area:** CRDT and Collaboration (reported by both; merged)
- **Severity:** low (lowered from medium)
- **Effort:** S
- **Location:** `src/lib/crdt/document.ts:878`, in `_decide`; the only write is at :932.
- **Failure:** The sequence is: refused (4401 or 4403), then `release()`, then a fresh provider attaches and syncs with an empty room. The document stays `pending` for good, and only `document.sync()` recovers it. This contradicts the documents.mdx rule that a document decides once each provider has "settled, failed, been removed". Related inconsistency: Edytor.svelte:190 does seed a refused document when mounted as a view with no provider.
- **Fix:**
  - Scope the refusal to the target that reported it. Either clear it in that target's `release()`, or stop blocking once a later provider reports `synced`.
  - Keep the public `syncRefusal` getter.
  - Update the documents.mdx wording and the 4403 row in websocket.mdx.
- **Done when:** a test that refuses, releases, then re-attaches to an empty room reaches `local` with the draft seeded. A second test does the same through `connect()`. The existing "refusal alone stays pending" test still passes.

**NW-09: A dial that neither opens nor fails never arms the readiness bound or emits `unreachable`**
- **Area:** Collaboration
- **Severity:** low (lowered from medium)
- **Effort:** S
- **Location:** `src/lib/crdt/providers/index.ts:174` and `websocket.ts:288-323` (`setupWS`, which has no connect timeout).
- **Failure:** On a first visit behind a network that silently drops the connection, the document stays `pending` for about 75-240 s, until the browser gives up. No `unreachable` event fires during that time. This is documented as a residual in limitations.mdx:35.
- **Fix:** Start a connect timer (for example 10 s) in `setupWS`. If `onopen` has not fired, close through the existing `closeWebsocketConnection` path, which arms the bound, advances the backoff and emits `unreachable`. Clear the timer on open, close and destroy.
- **Done when:** a fake socket that never opens, with fake timers, sees `unreachable` fire and readiness leave `pending` after the timeout plus `DEFAULT_READINESS_BOUND`. limitations.mdx:35 is updated.
