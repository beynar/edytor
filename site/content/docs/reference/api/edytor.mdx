## AnchorAffinity

Selection-endpoint affinity — which side of a position the anchor binds
to (see `T.atomAnchorAt`):

- `'left'` — bound to the atom BEFORE the position; resolves right after
  it, so a concurrent insert exactly at the position lands to the
  anchor's right. Used for carets and range ENDS.
- `'right'` — bound to the atom AT the position; resolves right before
  it, so a concurrent insert lands to the anchor's left — outside a
  range starting here. Used for range STARTS.

```ts
export type AnchorAffinity = 'left' | 'right';
```

## Block

An id-only, read-only block handle: every getter reads the document index
(transaction-aware). Writes are the view's operations, with the block's id
(`edytor.splitBlock(block.id, …)`). The view keeps one handle per id
(`edytor.idToBlock`); `node` is the element the core renders for it.

A reactive reader (a template, a `$derived`, an `$effect`) of a getter
depends on the cells the answer comes from (this block's, its parent's,
the root's list), so it re-runs when a commit changes them, as `data`
does; a read anywhere else is a plain read of the document.

```ts
export declare class Block {
    #private;
    readonly: boolean;
    readonly edytor: Edytor;
    readonly id: string;
    node?: HTMLElement;
    constructor(edytor: Edytor, id: string);
    get isRoot(): boolean;
    get parent(): Block | undefined;
    get children(): Block[];
    get content(): (Text | InlineBlock)[];
    get type(): string;
    get data(): Record<string, any>;
    get definition(): BlockDefinition;
    get selected(): boolean;
    get focused(): boolean;
    get movable(): boolean;
    get convertible(): boolean;
    get index(): number;
    get depth(): number;
    get path(): number[];
    get isInTree(): boolean;
    get nextBlock(): Block | null;
    get previousBlock(): Block | null;
    get closestPreviousBlock(): Block | null;
    get closestNextBlock(): Block | null;
    get hasChildren(): boolean;
    get hasContent(): boolean;
    get isEmpty(): boolean;
    get isNested(): boolean;
    get value(): JSONBlock;
    isChildOf(block: Block): boolean;
    get rendersContent(): boolean;
    get isContainer(): boolean;
    get isListItem(): boolean;
    get list(): Block | undefined;
    get firstText(): Text | undefined;
    get lastText(): Text | undefined;
    void: (node: HTMLElement) => void;
    textAtOffset: (offset: number) => {
        text: Text;
        offset: number;
    } | null;
}
```

- `parent`: The display parent (the root for a top-level block); none for the root or a dead block.
- `content`: Text segments and inline atoms, alternating, starting and ending with a text.
- `data`: The block's `data` as plain state: reactive at any depth (through the block's cell), and writable (`block.data.color = 'red'`, `block.data.tags.push('x')`, `delete block.data.color`).
- `movable`: May this block move at all: `canPlace` without a destination (drag handles).
- `convertible`: May text-level structural commands (convert, markdown shortcut, slash menu) apply: the block is movable — or the virtual paragraph of an emptied document, which a conversion creates with its kind — has no role of its own and renders its own content — a container (a list) is never converted, its items are.
- `isInTree`: The block is visible in the document (a dead handle answers false).
- `hasContent`: It shows content: text or an inline atom (a block holding only a mention is not empty).
- `isEmpty`: It holds nothing: no content and no children (the emptiness Turn into reads, `holdsNothing`).
- `value`: This block's JSON — the document's one serializer (`facade.blockJSON`).
- `rendersContent`: Whether this kind renders its own content slot — the adopted capability.
- `isContainer`: A container: it shows only its children (a list), neither void nor an island — the document's container rule.
- `isListItem`: An item of a list: its parent is a container whose items are a kind of their own (a `list-item` in an `unordered-list`), not the document's default — a column of paragraphs is no list.
- `list`: The list this block shows in: its container when it is an item (`isListItem`), or — an item outdented out of a nested list into the item holding it — the list of the items of its kind it sits under.
- `firstText`: The first text of this block's own content — none for a kind that does not render its content (a list container, a divider): its slot is never displayed, so no caret or endpoint may land there.
- `lastText`: The last text of this block's own content (see `firstText`).
- `void`: Mark an element inside the block's markup as non-editable chrome (a header, a caption bar).
- `textAtOffset`: The text segment that displays block offset `offset`, and the offset in it — the one offset → segment mapper over the committed parts (a boundary before an atom reads the text before it; past the end, the last text's end).

## BlockDefinition

Defines the structure and behavior of a block type.

```ts
export type BlockDefinition = {
    snippet?: Snippet<[
        BlockSnippetPayload<any>
    ]>;
    element?: BlockElement | ((data: Record<string, any>, id?: string) => BlockElement);
    contentElement?: BlockElement | ((data: Record<string, any>, id?: string) => BlockElement);
    viewState?: string[];
    void?: boolean;
    island?: boolean;
    lines?: boolean;
    layout?: boolean;
    table?: boolean;
    menu?: (block: Block) => KindMenuAction[];
    atomic?: readonly (string | readonly string[])[];
    rendersContent?: boolean;
    upload?: KindUpload;
    continues?: boolean;
    container?: boolean;
    body?: boolean;
    defaultChild?: string;
    itemKind?: string;
    presets?: KindPreset[];
    empty?: Pick<JSONBlock, 'content' | 'children'>;
    html?: string | ((block: JSONBlock, content: string, children: string) => string);
    plain?: (block: JSONBlock, content: string, children: string) => string;
    markdown?: (block: JSONBlock, content: string, children: string, context: MarkdownContext) => string;
    parse?: (element: HTMLElement) => Record<string, SerializableContent> | undefined;
    transformText?: TextTransform;
    onFocus?: (payload: {
        block: Block;
    }) => void;
    onBlur?: (payload: {
        block: Block;
    }) => void;
    onSelect?: (payload: {
        block: Block;
    }) => void;
    onDeselect?: (payload: {
        block: Block;
    }) => void;
    normalizeContent?: (payload: {
        block: Block;
    }) => (() => void) | void;
    normalizeChildren?: (payload: {
        block: Block;
    }) => (() => void) | void;
};
```

- `snippet`: The markup inside the block element; a kind whose element takes no content (`hr`) has none.
- `element`: The element the core renders for the block: a tag, or tag and attributes, possibly from the block's data and id (the second argument: view state the kind keeps per block, such as a column's width while a resize drags; reactive state it reads re-renders the element; absent when HTML import reads a kind's tag for data alone).
- `contentElement`: The element the core wraps around the block's own text (`content()`), possibly from the block's data and id: a heading's `h1`–`h3`, a quote's `blockquote`.
- `viewState`: Attributes of the block element the browser or the user own (`open` on a `details`): declared view state, never inverted.
- `void`: A void kind (an image, a divider): one unit the editor never edits as text and never merges.
- `island`: An island kind (a code block, a table): editable inside, structurally sealed.
- `lines`: An island of lines (the code block): each direct child shows as this kind's `defaultChild` and holds no children, even when an undo or a peer's edit puts another kind or a nested block there.
- `layout`: A layout (the columns plugin's `columns`): its `defaultChild` is its item kind (a column, a container that holds any block), shown side by side.
- `table`: A table (the table plugin's `table`): its `defaultChild` is its row kind, a container whose own `defaultChild` is the cell kind (a text island).
- `menu`: Rows the block menu adds for a block of this kind, when it is opened on that block alone (a table's Header row switch), after Turn into and Color.
- `atomic`: Data paths written as one value (`data.atomic`): a top-level key, or an array of keys for a nested one.
- `rendersContent`: Whether the snippet renders the block's own content (`content()`).
- `upload`: The files the kind takes (the image's `image/*`, the file block's any) and who sends them (`send`: the media plugins set it from their `upload` option): an empty block's Upload sends one, and a pasted or dropped file becomes a block of this kind (`media.files`).
- `continues`: A list-like kind (Notion's bullets, numbers, to-dos, toggles): Enter at the start or end of a non-empty block opens another block of this kind (with its first preset's data), and Enter in an empty one ends the run — it outdents under a parent of a continuing kind, else turns into the parent's default child in place (at the top level, in a callout).
- `container`: A container kind (Notion's toggles, callouts, quotes): its content is a header over its children.
- `body`: A container whose children are a body that shows even while it is empty (Notion's callout: a title over its content): Enter at the end of its header opens its first child, as an open toggle's does, and a paste there leads that body.
- `defaultChild`: The type a new child of this block takes by default (Enter inside a child, a split, an island merged out into it).
- `itemKind`: A list container's flat counterpart (`numbered-list-item` for an `ordered-list`): its items show as this kind, so the menus name them by it and turning one into it keeps it in the list.
- `presets`: Catalogue rows: one per way to create this kind — the slash menu, markdown shortcuts and block menus are generated from them (`edytor.kinds`).
- `empty`: The content and children a conversion into this kind creates (a void has none; an island starts with a first child).
- `html`: Clipboard HTML form: a tag wrapping content then children, or a function of the block and its serialized content and children.
- `plain`: Clipboard plain-text form; default content then children, one per line.
- `markdown`: Markdown form (`toMarkdown`): `content` is the block's text as inline markdown (marks by their own `markdown` forms), `children` its children's markdown, blocks apart by a blank line (indent them yourself: `MarkdownContext.indent`).
- `parse`: HTML import: the block's data when `element` is this kind, else `undefined`.
- `transformText`: Transform text content within the block
- `onFocus`: Called when the block receives focus
- `onBlur`: Called when the block loses focus
- `onSelect`: Called when the block is selected
- `onDeselect`: Called when the block is deselected
- `normalizeContent`: Normalize block content Called at the end of the transaction of each operation that wrote the block's content: the block is an id-only handle whose reads show the operation's writes.
- `normalizeChildren`: Normalize block children Called at the end of the transaction of each operation that changed the block's children: the block is an id-only handle whose reads show the operation's writes.

- `block`: The block whose grip opened the menu.
- `blocks`: The blocks the actions apply to, in document order: the block selection when it holds `block` (Notion), else `block` alone — as clicked, so a grip-selected list is one block (Move, Duplicate, Copy link, the caret after).
- `anchor`: Where the menu stands: the handle that opened it (a `ChromeAnchor`: your `menu` places itself beside it, its flyout beside the menu); `null` while closed.
- `index`: The keyboard's row.
- `flyout`: The open flyout: the kinds (`turn`), the colours (`color`), or none.
- `flyoutIndex`: The keyboard's row in the open flyout.
- `readonly`: The editor is readonly: the menu closes.
- `menuId`: The menu's and the Turn into flyout's element ids (page-unique), for `aria-controls`.
- `rowId`: A row's element id (page-unique; a flyout's with `flyout`), for `aria-activedescendant`.
- `popup`: The menu element (`{@attach controller.popup}`, the one with the rows): it takes the menu's id, its `menu` role and name unless it has its own, keeps the focus where it is on a press (a field takes its own), and is published to the view's root (`edytor.popups`) while it is in the page, the grip that opened it told so.
- `flyoutMenu`: An open flyout (`{@attach controller.flyoutMenu}`, named by your markup): its id, `menu` role, the overlay's placement beside the menu, and presses that keep the focus.
- `keys`: The element that holds the keyboard (`{@attach controller.keys}`: the search field): focused when it mounts, it takes every key of the menu (the arrows, Home and End walk the rows, → opens a row's flyout and ← closes it, Enter runs the row, Delete removes the blocks while the query is empty, Escape closes the flyout, then the menu), and names the open menu and its highlighted row (`aria-controls`, `aria-activedescendant`, once that row is in the page).
- `option`: The attachment of the row at `index` (of the open flyout's rows with `flyout`): `{@attach controller.option(index)}` on its element.
- `search`: The search field typed in: the rows match `query`, the first one highlighted, no flyout open.
- `members`: What Delete and Turn into act on: `blocks`, a list or a code block with its subtree (`selectedMembers`).
- `kinds`: The Turn into rows: the kinds, then the commands that turn `blocks` into something (`turnCommands`).
- `colorable`: The blocks the Color flyout paints: the `members` that take a colour (`colorable`).
- `colors`: The Color flyout's rows: Notion's text colours, then its backgrounds.
- `isCurrentColor`: Whether every block the flyout paints holds `row`'s colour (its ✓).
- `flyoutRows`: The rows of the open flyout.
- `currentKind`: The row naming the open block.
- `matchingColors`: With a query, the colours it names join the list after the kinds (Notion's "Color" results: `red` lists "Red text" and "Red background"), when the blocks take one (`colorable`).
- `rows`: Every keyboard row: actions, then the matching kinds, then the matching colours.
- `turnInto`: Convert the open block, or every member (a list's items) as one undo step (they stay selected); one block's conversion places the caret (refused: the caret returns).
- `paint`: Paint the open blocks (`colorable`, a list's items too) with `row`'s colour or background as one undo step (`setBlockColor`); the menu closes and the blocks stay selected, as in Notion.
- `duplicate`: Duplicate `blocks` as one undo step, each copy after its block (a block inside another of them is copied with it; a vetoed one is skipped, `dispatcher.each`); the copies are selected (`select`), else the first copy takes the caret (refused: its block keeps it).
- `remove`: Delete the open blocks' `members` (a list with its items) as the keyboard's block delete does (`deleteSelectedBlocks`): `onDeleteSelectedBlocks` may keep them, then one command (`deleteBlocks`, one plan, so a veto keeps them all), unselected children taking their parent's place, the caret where that delete puts it (kept or refused: the caret or the selection returns).
- `linked`: The one block "Copy link" names: the open block, or the layout its block selection covers whole (`liftLayouts`); none for several.
- `run`: Run a row of the menu or of its open flyout (a click; Enter runs the keyboard's): paint a colour, convert to a kind, open an action's flyout or run it.
- `openFlyout`: Open a flyout on its first row (keyboard or mouse): the "Turn into" kinds (default) or the colours; that flyout already open stays as it is.

## BlockRole

Structural role of a block type (plugin-side policy, resolved per op).


## Commands

The view's commands that are no single document write, each one prepared
plan of them, with their payloads: a hook sees each by its name, then its

```ts

    acceptSuggestion: {

            id: string;
            at: ResolvedAt;
            content: readonly JSONBlock[];
        };

    replaceMatches: {

            offset: number;
            length: number;

    };
    addComment: {
        thread: string;
        runs: {
            block: string;
            offset: number;
            length: number;
        }[];
    };
    moveText: {
        from: {
            start: {
                block: string;
                offset: number;
            };
            end: {
                block: string;
                offset: number;
            };
        };
        to: {
            block: string;
            offset: number;
        };
        copy: boolean;
    };
    inlineMarkdown: {
        value: string;
        start: number;
        end: number;
    };
    insertDivider: Record<string, never>;
    insertTableRow: {
        index: number;
    };
    deleteTableRows: {
        rows: Block[];
    };
    insertTableColumn: {
        index: number;
        width?: number;
    };
    deleteTableColumn: {
        column: string | number;
    };
    moveTableColumn: {
        column: string | number;
        to: number;
    };
    moveTableRows: {
        rows: Block[];
        to: number;
    };
    fillTableCell: {
        row: string;
        column: string | number;
    };
}
```

- `acceptSuggestion`: A suggestion placed in the document (`edytor.suggestions`, `suggestion.accept()`).
- `replaceMatches`: Find and replace (`plugins/find`): each match's text replaced by `replacement`, one plan, one undo step.
- `addComment`: A comment thread's anchor (`plugins/comments`): its `comment:<thread>` mark over each run of the text it was made on, one plan, one undo step.

- `insertDivider`: A divider at the caret: its steps are the conversion, insertion or split it plans.
- `insertTableRow`: A table's row at `index`, one empty cell per column (`table.insert-row`).
- `deleteTableRows`: A table's rows, with their cells (`table.delete-row`).
- `insertTableColumn`: A table's column at `index`, an empty cell in every row (`table.insert-column`).
- `deleteTableColumn`: A table's column, by id or position, with its cells (`table.delete-column`).

- `moveTableRows`: A table's rows moved to position `to` among its rows (`table.move-row`).

## CommentsController

The comments plugin's state and actions (`plugins/comments`): the
threads the client hears (merged by their newest change), each thread's
anchor read from the document (its `comment:<id>` mark), the thread being
written, the active one (the caret's, or the one clicked), and the
requests. The anchor mark is written by one dispatcher command
(`addComment`) once the server accepted the thread; a removed thread's
marks are its store's to remove (the room, or the memory client).

```ts
export declare class CommentsController {
    #private;
    private edytor;
    private options;
    active: string | null;
    draft: CommentDraft | null;
    showResolved: boolean;
    error: string | null;
    readonly client: CommentsClient;
    readonly user: CommentUser;
    constructor(edytor: Edytor, options: CommentsControllerOptions);
    readonly anchors: Map<string, CommentRun[]>;
    readonly threads: PlacedThread[];
    readonly open: PlacedThread[];
    readonly resolved: PlacedThread[];
    readonly shown: PlacedThread[];
    readonly anchor: import("../chrome.js").ChromeAnchor;
    get canComment(): boolean;
    thread(id: string): PlacedThread | undefined;
    userOf: (id: string) => CommentUser;
    mayDelete: (thread: CommentThread, comment: {
        author: string;
    }) => boolean;
    connect: () => void;
    destroy: () => void;
    start: () => boolean;
    cancel: () => void;
    draftRuns: (draft?: CommentDraft | null) => CommentRun[];
    submit: (body: string) => Promise<boolean>;
    reply: (thread: string, body: string) => Promise<boolean>;
    resolve: (thread: string) => Promise<boolean>;
    reopen: (thread: string) => Promise<boolean>;
    remove: (thread: string, comment?: string) => Promise<boolean>;
    focus: (thread: string | null) => void;
    follow: () => void;
    readonly css: string;
}
```

- `active`: The thread the caret is in, or the one picked in the sidebar.
- `draft`: The thread being written, before it is posted.
- `showResolved`: The sidebar also shows the resolved threads.
- `error`: The last request that failed (its message), until the next one succeeds.
- `anchors`: Every thread's anchor runs, in document order (maintained per commit).
- `threads`: Every thread, in the order of its anchor in the document (threads with none last).
- `open`: The open threads whose text shows (what the sidebar places by default).
- `resolved`: The resolved threads.
- `shown`: The threads the sidebar shows: the open ones, the resolved ones on demand, the active one.
- `anchor`: Where the thread being written, else the active one, stands (`ChromeAnchor`): the first line of its text, by which a card may place itself (the sidebar places its cards in the margin).
- `canComment`: The view may write: it may start, answer, resolve and delete comments.
- `thread`: One thread, by id.
- `userOf`: A user as the sidebar shows them: their name (else their id), avatar and color.
- `mayDelete`: Whether the current user may delete `comment` of `thread` (its author).
- `connect`: Start hearing the threads: the client's list, its changes, the document's commits.
- `destroy`: Stop hearing them (the editor is going away).
- `start`: Start a thread on the selected text (the toolbar's Comment button, Mod+Shift+M): each selected run, held by anchors while it is written; at a caret, its block's whole text.
- `cancel`: Drop the thread being written; the editor takes the focus back.
- `draftRuns`: The runs the draft's anchors cover now.
- `submit`: Post the thread being written: the server keeps it, then its anchor mark is written over the draft's text (one `addComment` command, one undo step).
- `remove`: Delete one comment; without `comment` (or its first), the whole thread.
- `focus`: Make `thread` the active one (a click on its card); its text scrolls into view.
- `follow`: The caret moved (`onSelectionChange`): the thread whose text holds it becomes the active one (an open one first), or none.
- `css`: The highlight of the threads' text: open threads, the active one stronger.

```ts
    each: <T, R>(kind: string, parts: readonly T[], part: (item: T) => R) => (R | undefined)[];
    dispatch: <P, R>(operation: string, payload: P, context: {
        block: unknown;
        text?: Text;
    }, body: (payload: P, plan?: Prepared) => R, prepare?: (payload: P) => Prepared) => R | undefined;
    plan: <P>(operation: string, payload: P, prepare: (payload: P) => Prepared, block?: Block, text?: Text) => OpResult;
    lead: <T>(lead: Prepared, body: () => T) => {
        out: T | undefined;
        taken: boolean;
    };
    caret: (caret: Caret | DocPosition | null | undefined, ops?: () => OpResult) => OpResult | undefined;
    private policy;
    private decide;
    private settle;
    private replace;
    private steps;
}
```

- `last`: The last operation's result (read-only: the dispatcher records it).
- `outside`: Run `body`'s commands outside the undo history (one transaction of their own, under an origin no history tracks): admitted, shown to hooks and recorded in `last` as any command, but they cut no step and enter none.
- `permits`: Whether this view accepts writes now: not readonly, its document writable, and decided when it requires hydration.
- `run`: A user command: admission, the undo policy around it, and one prevention scope.
- `each`: A user command over several parts (Turn into over several blocks, Tab over several runs of siblings): each part is its own prevention scope, so a part the document refuses or an extension vetoes is skipped and the others still run, as one undo step.
- `dispatch`: Dispatch one operation.
- `plan`: Dispatch `operation` as the plan `prepare` makes of `payload` (a hook's replacement payload is prepared again), about `block` (the root by default): hooks see it and each planned step before any write; one transaction; the blocks it touched normalized and the blocks it moved shown (closed toggles open); the caret it decides (`plan.at`: a range deletion, a placed flow) selected.
- `lead`: Run `body` with `lead` (a plan prepared now) composed into the first operation it dispatches: one plan, so a veto of any step, or a refusal, refuses both (a slash or markdown trigger removal with its conversion).
- `caret`: A command's result caret, `{ block, offset }` in block offsets (an inline atom counting 1): selected once and recorded on the result; the projector displays it after the flush.

## DocumentReadiness

How the document's content state was decided — the distinction the
readiness contract requires:
- `pending` — undecided (created without a value or attached before
  `sync()`; a provider may still hydrate — nothing bootstrapped,
  nothing broadcast). Reads/attaches/`sync()` legal, `history`
  refuses;
- `local` — seeded locally (`createDocument({value})`, or `sync()` on a
  still-fresh doc — seed-if-empty bootstrap included). Full surface
  legal;
- `hydrated` — the doc was already initialized when `sync()` ran:
  provider-applied remote state or a `loadDocument` restore (schema
  asserted, content untouched). Full surface legal.

`sync()` is the only transition out of `pending`, and it is the
document-side admission re-check: a doc that arrived in a problem
state (unversioned/unsupported/foreign — e.g. via raw
`applyUpdate` bypass writes) refuses there with a typed error, stays
`pending`, and preserves the state — never silently becoming `local`.

```ts
export type DocumentReadiness = 'pending' | 'local' | 'hydrated';
```

- `doc`: The underlying engine doc — raw reads/providers borrow it; they never own it.
- `awareness`: One shared awareness instance for every view/provider of this document.
- `actor`: The local actor identity (anonymous opaque id when none was supplied).
- `attribution`: The attribution surface — compact per-block records and the replicated actor dictionary (`u/` profiles, `c/` replica bindings).
- `transaction`: The document's own local-edit transaction origin — headless edits via `transact` carry it so history capture attributes them.
- `requireHydration`: `DocumentOptions.requireHydration`: an empty document waits for a provider's `synced`.
- `data`: The document's properties as a live object (`crdt/props`): a read follows the document, and a write at any depth (`document.data.title = 'Notes'`, `document.data.tags.push('x')`, `delete …`) is the raw `patchData` operation at once, as `document.patchData(null, …)`.
- `clientID`: The replica id (`doc.clientID`) — identifies the replica, not the actor.
- `ready`: `true` once the document's content state is decided — seeded locally or hydrated then synced.
- `readiness`: `pending` | `local` | `hydrated` — distinguishes a locally-seeded ready from a provider-hydrated/restored ready (the contract consumers need to tell "I decided this content" from "sync brought it").

- `onWritableChange`: Subscribe to `writable` transitions — the visible signal that the document turned read-only (once per transition, not per refused edit).
- `historyLimit`: The undo steps this document's history keeps: the configured `history.limit`, else `DEFAULT_HISTORY_LIMIT`.
- `semantics`: The document-level semantic configuration (snapshot).
- `defaultChild`: The default child type under a parent of `parentType` (`null` = the root) — the one answer split, paragraph insert, merge-unnest, clear and root normalization apply against the new block's actual parent.
- `rendersContent`: Whether kind `type` renders its own content slot (undeclared kinds do).
- `adoptSemantics`: Contribute document-level semantics — the seam views use to seed the structural roles implied by their plugin block definitions.
- `sync`: The readiness transition — decide the document's content state.
- `history`: The default local history (the registry-scoped undo manager — `undo`/`redo`/`stopCapturing`/stacks).
- `trackOrigin`: Track a local-edit transaction origin for history capture — the seam views use to enroll their own `TRANSACTION` instance in this document's history.
- `untrackOrigin`: Release a previously-tracked origin — the view-teardown counterpart of `trackOrigin`.
- `clearHistory`: Drop the undo/redo stacks.
- `transact`: Local document transaction — headless edits, one undo step per call (`origin`: another origin, which the document's history tracks only when it is tracked).
- `onReady`: Subscribe to the readiness transition — fires once, synchronously, inside `sync` when `_readiness` leaves `'pending'` (every decision path goes through `sync()`: provider `synced`, local seed, explicit call).
- `syncPending`: Whether an attached provider has neither settled nor reached its bound.
- `syncRefusal`: The server's refusal of a provider (a `1008`/`4xxx` close — see `SyncRefusedError`), the latest still standing: that provider stopped.
- `onSyncRefused`: Subscribe to provider refusals (`syncRefusal`).
- `attachSync`: Attach a provider sync factory to this document (headless `EdytorSync` path — the same contract views use).
- `encode`: Full replicated state as a v14 update — `loadDocument` restores it on a fresh replica.
- `retain`: Acquire one more attach reference and return its ONE-SHOT release capability.
- `destroy`: Release ONE attach reference.

- `historyUndo`: Undo/redo through THIS view: the only history entry points that restore a view's selection (its recorded `before`/`after`); sibling views and a headless `document.history.undo()` restore none (their carets ride the change, as for a remote undo).
- `definitionOf`: The definition of block kind `type` — the one lookup (render, surface, handles).
- `value`: Full-document JSON export — memoized on `facade.version` (the model-state token the facade bumps on every write and every committed update) + the root wrapper identity, so repeated reads inside one version share the one computed tree.
- `defaultChild`: The adopted default type for a new child of `parent` — its actual parent.
- `focus`: Focus the editor, as a click in it would, without scrolling: the selection it has stays, and with none the caret goes to the start of the first text.
- `clear`: Replace the whole document with one empty block and put the caret in it, as one undo step.
- `presence`: This view's presence writer: what it shares (`share`) and how often (`throttle`, ms); both settable.
- `destroy`: Edytor-lifetime teardown.

## Overlay

```ts
export declare class Overlay {
    #private;
    layer: HTMLElement | null;
    observe: (node: Element) => () => void;
    add: (measure: Measure) => () => undefined;
    invalidate: () => void;
    mount: <Props extends Record<string, unknown>>(component: Component<Props>, props: Props, name: string, zIndex: number, measure: (host: HTMLElement, origin: DOMRect) => (() => void) | void) => () => void;
```

## SchemaProblem

A document's relationship to this build's schema:

- `unversioned` — registry state exists but `meta.v` is absent. Someone
  wrote replicated content without running the schema path (a rogue or
  v13-era write). This state must NEVER be persisted/broadcast as a
  document update by a provider.
- `unsupported` — `meta.v` names a version this build does not speak
  (e.g. `99` written by a future build). Content still applies (a replica
  cannot refuse structs it already shares a protocol with), but providers
  surface a `schema-mismatch` signal so operators can detect skew.
- `foreign` — `meta.v` is the supported version but `meta.schema` is
  missing or names a DIFFERENT manifest (`'not-edytor'`, a next-gen name,
  an app-local doc kind). A valid version number alone does not make the
  payload an edytor document — the manifest name is part of the contract
  (the version-only check let foreign `meta.schema` values
  cross the staging boundary).

```ts

    kind: 'unversioned' | 'unsupported' | 'foreign';
    version?: number;
    schema?: unknown;
};
```

- `version`: The observed `meta.v` (undefined for `unversioned`).
- `schema`: The observed `meta.schema` (undefined when absent).

## Text

An id-only, read-only text handle: the `ordinal`-th text segment of block
`blockId` — no identity across commits beyond that position. Getters read
the document index; writes are the view's operations in block offsets
(`edytor.insertText(text.parent.id, text.segStart + offset, …)`). `node`
is the element that renders the segment (a Surface fact). A reactive
reader of a getter depends on the block's cell, so it re-runs when a
commit changes the block's content.

```ts

    get parent(): Block;
    get index(): number;
    get value(): JSONText[];
    get stringContent(): string;
    get isEmpty(): boolean;
    get endsWithNewline(): boolean;
    get length(): number;
    get segStart(): number;
    get isInDocument(): boolean;
    refreshFromModel: () => void;
    getMarksAtRange: (start: number, end: number) => JSONText[];
}
```

- `ordinal`: The segment's position among its block's text segments.
- `index`: Position among the block's content parts.
- `stringContent`: The segment's text.

- `getMarksAtRange`: The runs of `[start, end)` (segment offsets), each with a copy of its marks: the MODEL runs (`value`), never the rendered ones — a kind's `transformText` decorations (code tokens) are no marks of the text.

## Trigger

A character typed at a text's start or after whitespace opens a menu at
the caret (`@` for people, `[[` for pages); the text typed after it is
the query. Picking a row replaces the trigger and its query (`onPick`).
The menu's keys are the editor's while it is open: &lt;kbd>↑&lt;/kbd>/&lt;kbd>↓&lt;/kbd>
move, &lt;kbd>Enter&lt;/kbd> picks, &lt;kbd>Escape&lt;/kbd> closes it and keeps the text.

```ts
export type Trigger<T = any> = {
    char: string;
    name?: string;
    items: (query: string, ctx: TriggerContext) => readonly T[] | Promise<readonly T[]>;
    onPick: (item: T, ctx: TriggerContext) => unknown;
    label?: (item: T) => string;
    key?: (item: T) => string;
    menu?: Snippet<[
        TriggerMenuController<T>
    ]>;
    enabled?: (block: Block) => boolean;
};
```

- `char`: The text that opens the menu (one or two characters: `@`, `[[`).
- `name`: The menu's name, read by its markup as `controller.trigger.name` (the mention plugin's `kind`: one menu snippet can serve several triggers).
- `items`: The rows for `query`, at once or as a promise (a search); the newest query wins.
- `onPick`: Write the picked row: the trigger and its query (`from` to `to`) are removed in the same plan as the first operation it runs (one undo step; a refusal keeps them).
- `label`: A row's label: default the item itself when it is a string, else its `label`, `title` or `name`.
- `key`: A row's key, which keeps its markup across queries: default its `id`, else its label.
- `menu`: The menu's markup and its words; it renders while `controller.isOpen`, placed at the caret (without it, nothing shows).
- `enabled`: Whether the menu may open in `block` (default: a block that is not void and not in a code block).

```ts
    constructor(options: VersionHistoryOptions);
    diff: import("./diff.js").VersionDiff | null;
    preview: JSONDoc | null;
    previewKey: string | null;
    changes: ReadonlyMap<string, VersionChange>;
    previewPlugins: Plugin[];
    selectedVersion: HistoryVersion | null;
    refresh: () => Promise<void>;
    select: (key: string | null) => Promise<void>;
    restore: () => Promise<void>;
    undo: () => Promise<void>;
    dateOf: (entry: HistoryVersion) => string;
    timeOf: (entry: HistoryVersion) => string;
    option: (index: number) => Attachment<HTMLElement>;
    keys: Attachment<HTMLElement>;
}
```

- `versions`: The versions, newest first (`null` while the first list loads).
- `selected`: The previewed version's key.
- `shown`: The previewed version's JSON, once read (`null` while it loads or when it is gone).
- `reading`: The previewed version is being read.
- `busy`: A restore or an undo is in flight.
- `undoable`: A restore this view applied, which `undo` can take back.
- `status`: The last outcome, to announce (`aria-live`) in your words.
- `failed`: The last outcome failed.
- `highlight`: Highlight the blocks added, removed and changed since the version.
- `diff`: The previewed version against the live document: its counts and the changed blocks.
- `preview`: What the preview renders: the version, with the blocks removed since when highlighting.
- `previewKey`: A key for the preview: it remounts when what it renders changes (`value` is read once).
- `changes`: The blocks changed since the version, by id, while highlighting (else none).
- `previewPlugins`: The preview's plugins: the highlights of the changes (read live), then the app's.
- `selectedVersion`: The previewed version, as listed.
- `refresh`: List the versions again; keeps the selection when it is still listed, else selects the newest.
- `select`: Preview the version `key` (`null`: none).
- `restore`: Restore the previewed version (the room writes it as one change).
- `undo`: Take back the restore this view applied.
- `dateOf`: A version's day (`Oct 8, 2026`), in `locale`; its half of the day is `entry.slot`.
- `timeOf`: When a version was saved, in `locale`.
- `option`: The attachment of the version at `index`'s row (`{@attach history.option(index)}`, on its focusable element): `role="option"`, its id, `aria-selected`, the list's one tab stop when it is selected, else the first.
- `keys`: The list's attachment (`{@attach history.keys}`): the arrows, Home and End move the selection and the focus.

## VersionHistoryOptions

```ts
export type VersionHistoryOptions = {
    client: HistoryClient;
    document?: EdytorDocument;
    plugins?: Plugin[];
    locale?: string | string[];
    id?: string;
    onRestore?: (result: HistoryRestoreResult) => void;
    onUndo?: (result: HistoryUndoResult) => void;
    onError?: (error: unknown) => void;
};
```

- `client`: Where the versions come from: `createHistoryClient(…)`, or any object with `list`, `read`, `restore` and `undo`.
- `document`: The live document the preview is compared with.
- `plugins`: The preview's plugins: the ones the live view uses, so every kind renders as it does there.
- `locale`: The locale dates and times are written in (default the browser's).
- `id`: The id prefix of the list's rows (page-unique: `$props.id()`).
- `onRestore`: After a restore the room answered.
- `onUndo`: After an undo the room answered.
- `onError`: A request failed (`status` is `denied` or `failed`).

## VersionHistoryStatus

The last outcome to announce (`''`: none): a restore in flight or done
(`unchanged`: the page already matched), the previewed version gone
(`unavailable`), an undo done or with nothing to undo, a request refused
(`denied`: a `401` or `403`) or failed. Your panel says it in its words.

```ts
export type VersionHistoryStatus = '' | 'restoring' | 'restored' | 'unchanged' | 'unavailable' | 'undone' | 'nothingToUndo' | 'denied' | 'failed';
```

## withRulesAndTriggers

## wrapBlocks

Wrap `blocks` in a new layout of `columns` items (default one per block),
at the first one's place (`layout.wrap`, Notion's Turn into N columns): the
blocks one per item, then one empty block per further item; the document's
`wrapInLayout`, one undo step. The blocks stay selected. Answers whether
it applied.

```ts
declare const wrapBlocks: (edytor: Edytor, blocks: Block[], kind?: string, columns?: number) => boolean;
```

## wrappable

Whether `blocks` may be wrapped in a new layout of `columns` items

block, at least two).

```ts
declare const wrappable: (edytor: Edytor, blocks: Block[], kind?: string, columns?: number) => boolean;
```
