`richTextPlugin` defines the everyday document: paragraphs, headings, lists, to-dos, toggles, toggle headings, callouts, quotes, dividers, and ten marks, with Notion's shortcuts. The core defines no block kinds, so `<Edytor>` includes it by default, after your plugins:

```svelte title="Editor.svelte" check
<script lang="ts">
	import { Edytor } from 'edytor';
</script>

<!-- Rich text, with no plugins listed. -->
<Edytor />
```

`createRichTextPlugin({ labels, keywords, callout })` builds it in another language or with other callout icons (see [Toggles and callouts](#toggles-and-callouts)): `labels` (a `PartialLabels<'richText'>`) names the presets, the toolbar's mark buttons and the to-do checkbox, and `keywords` replaces a preset's slash keywords by command id (see [Localization](/docs/customization/localization)); `richTextPlugin` is the English one. A listed instance replaces the default. List it yourself to translate it, to place it elsewhere in the order, or with `defaultPlugins={false}` (see [Default plugins](/docs/plugins#default-plugins)). To change one of its kinds, define a kind with the same name in any of your plugins, since they come before it, or override only its snippet (see [Blocks](/docs/customization/blocks#override-a-snippet)).

## Block kinds

| Kind                 | Element                    | Data                           | Presets (markdown)                                         |
| -------------------- | -------------------------- | ------------------------------ | ---------------------------------------------------------- |
| `paragraph`          | `div` with a `p` inside    | none                           | Text                                                       |
| `heading`            | `div` with an `h1` to `h3` | `{ level: 'h1' }`              | Heading 1 (`# `), Heading 2 (`## `), Heading 3 (`### `)    |
| `bulleted-list-item` | `li`                       | none                           | Bulleted list (`- `, `* `, `+ `)                           |
| `numbered-list-item` | `li`                       | none                           | Numbered list (`1. `, `a. `, `i. `)                        |
| `todo-item`          | `div` with a checkbox      | `{ checked: boolean }`         | To-do list (`[ ] `, `[] `)                                 |
| `toggle`             | `details`, content in `summary` | none                      | Toggle list (`> `)                                         |
| `toggle-heading`     | `details`, an `h1` to `h3` in `summary` | `{ level: 'h1' }` | Toggle heading 1, 2, 3 (`> ` in a heading; `# `, `## `, `### ` in a toggle) |
| `callout`            | `div`: icon, title, content | `{ icon: string }`            | Callout (icon `💡`)                                        |
| `quote`              | `div` with a `blockquote`  | none                           | Quote (`" `)                                               |
| `divider`            | `hr`, void, no content     | none                           | Divider (`---`)                                            |

The kinds are listed in catalogue order, which the menus follow. Presets feed the [slash menu](/docs/plugins/slash-menu) (all under `Basic blocks`), [markdown shortcuts](/docs/plugins/markdown-shortcuts) and block menus. Their command ids are `block.paragraph`, `block.heading1` to `block.heading3`, `block.bulleted-list-item`, `block.numbered-list-item`, `block.todo-item`, `block.toggle`, `block.toggle-heading1` to `block.toggle-heading3`, `block.callout`, `block.quote` and `block.divider`.

The plugin also defines kinds without presets, for content that arrives from stored documents, the API or an Edytor fragment (an HTML paste gives flat bulleted and numbered items):

- `ordered-list` and `unordered-list`: `ol` and `ul` containers that render only their children. A new child takes the `list-item` kind, and so does a pasted line of the list's own flat kind (a numbered item in an `ordered-list`, a bulleted one in an `unordered-list`, their `itemKind`); any other kind keeps its kind.
- `list-item`: an `li`.
- `details`: the same as `toggle`.
- `horizontalRule`: the same as `divider`.

Behavior worth knowing:

- Bulleted and numbered items, to-dos and toggles are [continuing kinds](/docs/customization/blocks#continuing-kinds): <kbd>Enter</kbd> opens another of the same kind (an unchecked to-do), and in an empty one ends the list. Toggles, callouts and quotes are [containers](/docs/customization/blocks#containers): <kbd>Enter</kbd> at the end of one with children, or of an open toggle, opens a first child, and in the middle of the header moves the rest of the text into that first child. <kbd>Backspace</kbd> at the start of any kind but a paragraph turns it into a paragraph first. [Enter and Backspace by role](/docs/customization/hotkeys#enter-and-backspace-by-role) has the full rules.
- Headings have Notion's three levels. A `heading`'s tag follows `data.level`, `h1` to `h3`, and so does its copied HTML. Without a level it is `h1`; any other level (a stored `h5`, say) renders and copies as `h3`, as pasting `h4` to `h6` gives a level `h3` heading.
- The `h1`–`h3` of a heading and the `blockquote` of a quote wrap the block's own text only. The block element is a `div`, and nested blocks render after the tag, in a sibling `div`: the page's heading styles do not reach them, and a screen reader does not read them as part of the heading. Style the text through `[data-edytor-type='heading'] > h2`, the block through `[data-edytor-type='heading']`. The tag is the kinds' `contentElement`, so a `headingBlock` or `quoteBlock` snippet override keeps it around `content()`.
- A `toggle` is a native `<details>`. The browser owns its `open` attribute, so opening and closing it is not an edit and is never reverted. Arrow keys skip the body of a closed toggle. A toggle you create (the slash menu, `> `, Turn into a block without children) opens, so you can write its content right away (see [Toggles and callouts](#toggles-and-callouts)).
- A `toggle-heading` is Notion's toggle heading: a heading's text as a toggle's header, `data.level` as on a heading. It is a `<details>` whose `summary` holds the `h1`–`h3`, and behaves as a toggle: a container, whose closed body is hidden and skipped; <kbd>Enter</kbd> at the end of an open one opens a first child, of a closed one a paragraph after it (it does not continue itself, as a heading does not). Turn into moves between a heading, a toggle heading and a toggle keeping the text, the children and the level. As in Notion, `> ` typed at a heading's start makes it a toggle heading of its level, and `# `, `## ` or `### ` at a toggle's (or a toggle heading's) start a toggle heading of that level, so `> # ` on a new line is a toggle heading 1 ([markdown shortcuts](/docs/plugins/markdown-shortcuts)). Its HTML is `<details><summary><h2>…</h2></summary>…</details>`, which pastes back as a toggle heading. The [table of contents](/docs/plugins/table-of-contents) lists it with the headings.
- Every block that shows its own text takes a colour and a background from the [block menu](/docs/plugins/block-menu#block-colors) (`data.color`, `data.background`).
- The `todo-item` checkbox (`data-edytor-todo-checkbox`) shows `data.checked`. Clicking it, or <kbd>Mod</kbd> + <kbd>Enter</kbd> in the to-do (or over selected blocks, each shown to-do, while the toggles among them open or close), flips `checked` as one undo step. It does not change in a readonly editor.
- A `callout` is an icon, a title and a content: see [Toggles and callouts](#toggles-and-callouts).
- The `paragraph` element carries no classes of its own: style it through `[data-edytor-type='paragraph']`.
- Pasted `ol > li` becomes a numbered item and other `li` a bulleted item.

## Toggles and callouts

A toggle's and a callout's own text is a header; their children are a body that holds any blocks, nested any way. In an open toggle, and in a callout, an empty body shows a hint ("Empty toggle. Click or drop blocks inside.", "Empty callout. Click or drop blocks inside."). Clicking it starts the body: an empty paragraph as its first child, the caret in it, one undo step. A block dragged by its handle onto the hint goes inside. From the keyboard, <kbd>Enter</kbd> at the end of the header goes into the body. The hint is not content: it is not editable, not copied, not read by assistive technology, and a readonly editor does not show it (`[data-edytor-empty-body]` styles it).

A callout is Notion's: an icon, a title and a content.

- Its title is its own text, semibold (`[data-edytor-callout-title]`), with the placeholder "Callout title" while empty ([placeholders](#placeholders)). <kbd>Enter</kbd> at the end of the title, or in the middle of it, goes into the content, whether or not it has blocks yet.
- Its content is its children, any blocks. Copied, a callout is `<div data-edytor-callout="💡"><p>Title</p>…</div>`, which pastes back as the callout, its icon kept; as plain text, its title then its content.
- Its icon is `data.icon`: the editor's default when the callout has none (`💡`, or the `callout.icon` option), no icon when it is `''`. A new callout takes the default. Set it from code as any data, `block.data.icon = '🔥'`.
- Clicking the icon (`[data-edytor-callout-icon]`, a button named "Change icon", "Add icon" when the callout has none) opens a picker under it. Picking an icon, or Remove icon, is one undo step; Escape, <kbd>Tab</kbd> or a click elsewhere closes it unchanged. The arrows move through the icons (up and down by a row), Home and End go to the ends, <kbd>Enter</kbd> or <kbd>Space</kbd> picks, and the editor gets the keys back with its caret. The block menu of a callout has a Change icon row, the keyboard's way to the picker. A readonly editor shows the icon only.

```svelte title="CalloutIcons.svelte" check
<script lang="ts">
	import { CALLOUT_ICONS, Edytor, createRichTextPlugin } from 'edytor';

	// New callouts take 📌; the picker offers the default icons and a unicorn.
	const richText = createRichTextPlugin({
		callout: { icon: '📌', icons: [...CALLOUT_ICONS, '🦄'] }
	});
</script>

<Edytor plugins={[richText]} />
```

`callout.picker` replaces the picker's markup with your snippet. It receives the picker (`CalloutIconPicker`): the callout it is open on (`block`), the choices (`icons`), the icon the callout shows (`current`), `set(icon)`, `remove()` and `close()`, its words (`labels`) and `readonly`. Put `{@attach picker.keys}` and `{@attach picker.popup}` on its element, which then takes the focus and the keys and is announced to assistive technology, and spread `picker.option(i)` on each row: its id, role, state (`data-active` on the keyboard's row, `aria-checked` on the current icon) and handlers; `picker.option(picker.icons.length)` is Remove icon. The editor places it under the icon.

```svelte title="IconPicker.svelte" check
<script lang="ts">
	import { Edytor, createRichTextPlugin, type CalloutIconPicker } from 'edytor';

	const richText = createRichTextPlugin({ callout: { picker: iconPicker } });
</script>

{#snippet iconPicker(picker: CalloutIconPicker)}
	<div class="icons" {@attach picker.keys} {@attach picker.popup}>
		{#each picker.icons as icon, index (index)}
			<button type="button" {...picker.option(index)}>{icon}</button>
		{/each}
		<button type="button" {...picker.option(picker.icons.length)}>{picker.labels.remove}</button>
	</div>
{/snippet}

<Edytor plugins={[richText]} />
```

## Marks

| Mark          | Element                      | Value                          | Toolbar button |
| ------------- | ---------------------------- | ------------------------------ | -------------- |
| `bold`        | `strong`                     | `true`                         | B              |
| `italic`      | `em`                         | `true`                         | I              |
| `underline`   | `u`                          | `true`                         | U              |
| `strike`      | `s`                          | `true`                         | S              |
| `code`        | `code`                       | `true`                         | `</>`          |
| `link`        | `a` with `href` and `target` | `{ href, target? }`            | Link panel     |
| `superscript` | `sup`                        | `true`                         |                |
| `subscript`   | `sub`                        | `true`                         |                |
| `color`       | `span` with `color`          | a CSS color                    | A ⌄ (text)     |
| `highlight`   | `span` with `background-color` | a CSS color                  | A ⌄ (background) |

Marks nest in this order, `bold` innermost. Typing at the end of a link extends it only when the caret is inside the link; typing at the edge of any other mark extends it.

Values are sanitized when rendered and copied. A link `href` keeps only `http:`, `https:`, `mailto:`, `tel:` and scheme-less URLs; any other scheme, such as `javascript:`, drops the `href` and leaves the text. A color that could inject CSS (it contains `;`, braces, quotes, `url(` and similar) drops the `style`.

Pasted HTML maps `b`, `i`, `u`, `strike` and `del` to their marks, reads Google Docs' styled spans for bold, italic, underline, strike, color and highlight, and turns `mark` into a yellow highlight.

## Links

Links work as in Notion. Everything below applies where the [toolbar](/docs/plugins/toolbar) offers a link: a text selection or caret outside code blocks and void blocks. A URL here means one URL and nothing else: `http:` or `https:` with a host, or `mailto:`. Words, several URLs, a bare domain such as `svelte.dev` and a scriptable URL are not URLs.

### Pasting a link

**Over selected text**, pasting a URL (spaces around it ignored) sets the `link` mark with that URL on the selected text, across several blocks too, instead of replacing it. The text stays selected, and one undo gives the plain text back. A copied page link pastes the same way, since its plain text is the URL.

**At a caret**, pasting a URL inserts it as a link, the caret after it (`link.autolink.pasted`). The paste and the link are two undo steps: the first undo gives the plain URL back, the second removes it. A caret inside a link or inline code pastes the URL as plain text.

Anything else pastes as usual, and so does <kbd>Shift</kbd>+paste.

### Autolink

A URL typed before a space becomes a link when you type the space (`link.autolink.typed`): `see https://svelte.dev ` links `https://svelte.dev`. The URL is the word before the space; trailing `.`, `,`, `;`, `:`, `!` and `?` stay out of the link, so `https://svelte.dev.` links `https://svelte.dev`. The space and what you type after it are plain text. The link is an undo step of its own after your typing: one undo gives the plain text back, the space kept. A word that already carries a link or inline code is left as it is, and nothing is linked in a code block.

### Opening a link

Links are not followed by a plain click while you edit: a click places the caret. <kbd>Mod</kbd>+click opens the link in a new tab (`link.mod-click`; <kbd>Mod</kbd> is read as the keymap reads it: <kbd>Meta</kbd>, or <kbd>Ctrl</kbd> off a Mac). The tab opens with `noopener` and `noreferrer`, and an unsafe `href` opens nothing. The [toolbar](/docs/plugins/toolbar#link-card) adds a card with Open, Edit and Remove over a hovered link, and <kbd>Mod</kbd>+<kbd>K</kbd> to link a selection.

## Hotkeys

| Keys                                           | Action                        |
| ---------------------------------------------- | ----------------------------- |
| <kbd>Mod</kbd> + <kbd>B</kbd>                    | Toggle bold                   |
| <kbd>Mod</kbd> + <kbd>I</kbd>                    | Toggle italic                 |
| <kbd>Mod</kbd> + <kbd>U</kbd>                    | Toggle underline              |
| <kbd>Mod</kbd> + <kbd>E</kbd>                    | Toggle inline code            |
| <kbd>Mod</kbd> + <kbd>Shift</kbd> + <kbd>S</kbd>, <kbd>Mod</kbd> + <kbd>Shift</kbd> + <kbd>X</kbd> | Toggle strikethrough |
| <kbd>Mod</kbd> + <kbd>Shift</kbd> + <kbd>H</kbd>   | Toggle red text color         |
| <kbd>Mod</kbd> + <kbd>Enter</kbd>                  | Check or uncheck the to-do (in a to-do, or the selected to-dos) |

With a collapsed caret, a mark hotkey sets the mark for the next characters you type instead.

Notion's "turn into" chords convert the block holding the caret, or, as in Notion, every block of a block selection or of a text range across blocks, as one undo step that keeps the selection (Code converts only the first):

| Keys                                              | Turns into      |
| ------------------------------------------------- | --------------- |
| <kbd>Mod</kbd> + <kbd>Alt</kbd> + <kbd>0</kbd>    | Text            |
| <kbd>Mod</kbd> + <kbd>Alt</kbd> + <kbd>1</kbd>    | Heading 1       |
| <kbd>Mod</kbd> + <kbd>Alt</kbd> + <kbd>2</kbd>    | Heading 2       |
| <kbd>Mod</kbd> + <kbd>Alt</kbd> + <kbd>3</kbd>    | Heading 3       |
| <kbd>Mod</kbd> + <kbd>Alt</kbd> + <kbd>4</kbd>    | To-do list      |
| <kbd>Mod</kbd> + <kbd>Alt</kbd> + <kbd>5</kbd>    | Bulleted list   |
| <kbd>Mod</kbd> + <kbd>Alt</kbd> + <kbd>6</kbd>    | Numbered list   |
| <kbd>Mod</kbd> + <kbd>Alt</kbd> + <kbd>7</kbd>    | Toggle list     |
| <kbd>Mod</kbd> + <kbd>Alt</kbd> + <kbd>8</kbd>    | Code (with the [code plugin](/docs/plugins/code)); a block with text or children keeps them, and the code block is inserted after it |

Each runs the kind's command (`block.paragraph`, `block.heading1`, …, `block.code`) and is claimed only when that command is registered.

The plugin also handles the formatting input types browsers send from their own menus and from iOS: bold, italic, underline, strikethrough, superscript, subscript, remove formatting, text and background color, insert link, ordered and unordered list (converts the block), and horizontal rule (inserts a divider at the caret, splitting the block when the caret is inside it; a block that holds nothing becomes the divider; in a list's item, the divider goes out of the list as Turn into puts one: in the place of an item that holds nothing, else after the item, whose text stays whole; an inline block such as a mention counts as content, so a block holding only one keeps it; in an emptied document it creates the divider and a paragraph after it). `insertDividerAtSelection()` below does the same.

## Formatting from code

`richTextOperations(edytor)` returns the helpers the hotkeys and the toolbar use. They act on the current selection:

```ts title="src/lib/format.ts" check
import { richTextOperations } from 'edytor';

const format = richTextOperations(edytor);

format.setMarkAtRange('bold'); // toggle, or stage at a caret
format.setMarkValueAtRange('highlight', '#fff3a3'); // set, never toggle
format.removeMarkAtRange('highlight'); // remove one mark
format.setLinkAtRange({ href: 'https://svelte.dev', target: '_blank' });
format.removeLinkAtRange();
const text = block.firstText!; // a Text handle
format.linkText(text, 0, 4, 'https://svelte.dev'); // a range of one text, its own undo step
format.unlinkText(text, 0, 4); // one undo step; the selection stays
format.removeAllMarksAtRange();
format.insertDividerAtSelection();
```

`setLinkAtRange` and `linkText` ignore an unsafe `href`. `setMarkValueAtRange` ignores an unsafe color. `removeMarkAtRange` does nothing at a collapsed caret. `linkText` and `unlinkText` take a [`Text`](/docs/concepts/editor-instance#handles) and offsets within it, and leave the selection alone; autolink and the link card use them.

## Placeholders

`richTextPlaceholder` gives the kinds Notion's placeholders ("Heading 1", "Toggle heading 1", "List", "To-do", "Type '/' for commands" in a focused paragraph…). Pass it to `<Edytor placeholder={richTextPlaceholder} />`. See [Placeholder](/docs/customization/placeholder#notion-placeholders).
