# Selection, input and the surface

The session (`src/lib/session/`: the selection value, the dispatcher, input attempts, composition, history, handles) and the surface (`src/lib/surface/`, `src/lib/components/`, `src/lib/events/`: cells, the observer, the projector), with the selection contracts that must not regress. Read it before changing anything in `session/`, `surface/` or `events/`.

## Session

- **Selection value** (`SelectionValue`, by `kind`): `none`, `text {anchor, focus, pending?}`, `atom {blockId, atomId, from}`, `blocks {ids}`. Everything a command reads (endpoints as (block, display offset), direction, collapsed, covered blocks, edge flags, marks, content) is `project(value, doc)`, memoized per (value, index version). `selection.state` is a read-only compatibility getter over the projection. Pending marks are `value.pending` (`selection.pending`, `selection.stage(marks)`).
- With the value `none` and no caret a gesture placed (`untargeted` in `session/attempt.ts`), the navigation keys do nothing: claimed (`stayWithoutTarget` in `session/navigation.ts`; the page keys keep scrolling), and Mod+A selects every block.
- **A drag's release** (`sel.drag.unseen-release`): the projector does not display under a pointer drag (`selection.dragging`, armed by the press in `events/onFocus.ts`), so the drag must end even when the page never sees its `pointerup` (released over a frame of another origin; Playwright's Firefox outside the window): the next document `pointermove` with no button down ends it, as a `pointerup` or `pointercancel` does.
- **`commit(value, cause)`** is the one writer (`@internal`; the public `select(value)` is it with cause `model`). No text endpoint rests in a block that renders no content (a divider, a list, a code block): `select` moves it to the nearest shown line (`#shown`: a container's first item, else the next line, else the one before; none: the value stays), and the post-flush repair does the same after a peer's change. Over a block selection the navigation keys (`move` in `session/navigation.ts`) and Escape/Enter (`selectedBlocksLine`) read each member's own line, a line-less member's (list, code block) subtree, never an unselected child's (`shownText` in `selection/replaceSelection.ts`); voids alone stay selected except under the document keys; never patch a key instead. It applies the effects once (selected/focused sets and hooks, suggestions), emits `onSelectionChange` and publishes presence only when the value changed, and asks the projector to display (causes `model`/`history`), or not (`dom`).
- **Dispatcher** (`edytor.dispatcher`): admission (readonly, `document.writable`) → prepare → `onBeforeOperation` on the command and on each planned step under its documented name, all before any write → one transaction → normalization requests drained once inside it (also when the transaction threw: its writes stay) → `last` (`CommandResult`: `status` `refused | noop | applied | failed`) → `onAfterOperation` once (`AfterOperationPayload`, a distributive `Omit`, narrows by `operation`) → a handle mutator's return `value` on that result (`dispatcher.answer`, only on the result its own `dispatch` produced: a vetoed call whose `prevent(cb)` ran the same operation leaves the replacement's result and value). A veto refuses the whole command; `prevent(cb)` replaces it. A hook's `prevent` records and returns: every hook and key binding is called through `vetoable` (`utils.ts`), which throws the recorded veto after the hook returns, so it is caught only in the dispatcher's scopes (a hook that throws a `PreventionError` itself vetoes the same way). Never call `stopCapturing()` or catch `PreventionError` elsewhere. Plugin command API: `dispatcher.dispatch`, `lead` (a markdown or slash trigger removal leading a conversion in one plan) and `caret` (the command's result selection); `Plan`/`Prepared` are exported types.
- **Undo policy is the dispatcher's.** Do not hand-place `dispatcher.cut(…)` before block or text operations.
  - An operation outside a user command is its own step (it cuts before it writes) unless it is `insertText` or `addInlineBlock` continuing at the caret the last step left, when that step was text editing (`history.continues`: the dispatcher records per step, as it writes, whether it was an insertion, a composition or a text deletion, `inserts` → `history.wrote`; a resize, a data write, a paste or a conversion ends it); a led operation (markdown or slash conversion), the first operation `dispatcher.alone(body)` dispatches (an input rule's replacement, internal) and `inlineMarkdown` are always their own step and end an insertion's, so undo gives back the typed trigger.
  - To make a multi-operation gesture one step, wrap it in `edytor.transact` (always one step) or `dispatcher.run(kind, body)` (also a prevention scope; it cuts no step between its synchronous commands, but each commits alone, so the capture window groups them: `captureTimeout: 0`, a slow body or commands after an `await` split it).
  - `dispatcher.cut` remains only for writes the dispatcher never sees: raw facade writes, browser-owned attempts, a composition's first write.
  - A command that completes a step already taken, whose undo that step's undo covers, runs in `dispatcher.outside(body)`: admitted, shown to hooks, recorded in `last`, but under an origin no history tracks, so it starts and joins no step (an upload's URL filling the image block its paste placed: the paste's undo withdraws the block, URL included, and its redo shows it whole; a URL answered while the block is undone is held and written when it shows again); it throws inside another transaction, whose origin and step its writes would take.
- **Data writes are commands.** `block.data.x =` (the proxies), `block.setData`, `atom.setData` (all `patchData`) and `block.type =` (`setBlock`) go through the dispatcher: refused when readonly, shown to hooks, recorded in `last`, their own undo step. `block.model.setData` is the raw write. `edytor.clear()`, `historyUndo()` and `historyRedo()` check the same admission (`dispatcher.permits()`): a readonly view never wipes or rewinds the shared document.
- **Selection-touched blocks and hidden bodies.** `src/lib/selection/replaceSelection.ts` owns `getSelectionBlocks` (blocks a selection touches; a closed toggle's hidden body is not touched), `outermost`, `revealing` (a move never hides a block the user saw) and `revealed` (wraps the block move commands `nestBlock`/`unNestBlock`/`moveBlock`/`moveBlocks`, so every caller reveals); caret walkers use `shown(block, step, { removed })`, which skips hidden bodies unless their toggle is being removed. The visibility rule itself (`HIDDEN`, `hidden`, `shown`, `viewOf`, `rangeCovers`, `selectedTextSpans`) has one owner, `src/lib/selection/visibility.ts`; editor code imports it from there, and `selection.hidden`/`selection.shown` re-expose the same functions to extensions. Keep one definition of each here; plugins import them from these modules.
- **Input attempt** (`edytor.attempts`): one per occurrence (a `beforeinput`, a keydown whose `beforeinput` never came, paste, drop, a native line break). Intent, anchored target (the selection value) and owner (model performs, or browser performs and the model adopts) are fixed at admission. An intent with no target is refused there (`targetless`: a text, delete or break intent while the value is `none` and the host holds no caret a gesture placed, `projector.placed`): prevented at its keydown and at its `beforeinput`, never adopting the declared range (Chromium's parked caret at the host's start), and that caret stays parked (`projector.parked`) until a press or a focus from outside the host, an adopted move or a display: a key (Mod+Z, Escape) never ends it, and a value that becomes `none` under the host's focus (a history step, a closing menu) parks again. A model-owned attempt owns the DOM drift around it until its deadline.
- **Composition session** (`edytor.composition`): one IME composition, `live → tail → gone`. The start target is replaced by an ordinary command at the first write (over a block or atom selection, which shows no DOM range, at `compositionstart`, with the DOM caret parked in its place by `projector.park`); the pin keeps the host's render as the IME found it until the first preview (a write before it collapses the IME's range to the node's start; before it `imeBuffer()` reads nothing, so an abandon writes nothing), and a range across texts (across blocks, or across an inline atom in one block) shows the rest its first write merged into the host, with the host's new segments, after the IME's own write (`pin.merge`); previews are mechanical tracked writes in one capture group (one undo step); it ends exactly once (`commit`, `cancel`, `abandon`, or the re-placement end when a commit re-places the host's block). No timer ever ends a session. A session that starts with no target (`composition.targetless`: the value is `none` and the IME's caret is the browser's parked one, the attempt's `untargeted`) refuses: it adopts no caret, writes nothing, its occurrences are refused at admission (`targetless`), and the observer restores what the IME wrote (its pinned host through the tail). While live, the host's segment list is frozen by the pin and the projector writes no DOM selection.
- **History**: `edytor.historyUndo()/historyRedo()` are the view's only history API (`edytor.history` and `undoManager` are internal; `History.replay` checks `dispatcher.permits()`, so no view path rewinds a readonly view) and the bare engine calls — never inside a transaction and with no tracked write after them (that would empty the redo stack), so nothing normalizes after them. The issuing view restores its recorded value, and each call sets `dispatcher.last` (`applied`, `noop` on an empty stack, `refused`). The undo stack keeps the newest `history.limit` steps (`DEFAULT_HISTORY_LIMIT`, 200; `createUndoManager({ limit })`): a dropped step releases the items it kept for its undo once every step that deleted part of an item fell off (never splitting the store's merged items; leaf items only: a kept container may guard a newer step's items) and the engine collects their content under the doc's `gcFilter`.
- **Handles**: `Block`, `Text`, `InlineBlock` are id-only handles (`edytor.idToBlock` is the `Handles` registry). Getters read the document index (inside a command they see its writes); mutators issue commands. Under a reactive reader (`$effect.tracking()`) a getter also reads the cells its answer comes from (the block's, its parent's for `parent`/`index`, the root list; `value` every commit), so `{block.type}` follows commits as `data` does; anywhere else it is a plain read and costs nothing more. The view's commit report reaches consumers as `onChange` (the whole-document export) or `onDocChange` (the `DocChange` itself, no export; one shared, read-only report per commit, each consumer isolated: a throw is logged, never starves the others). A `Text` is the `ordinal`-th segment of its block and has no identity across commits; key extension state by block id and anchor. Liveness is `block.isInTree`, `text.isInDocument`, `atom.isInDocument`.

## Surface

- **Cells** (`edytor.cells`): one frozen cell per visible block, patched from each change report; a patch replaces exactly the cells it names. Components render from cells only (`Edytor` → `Block` → `Content` → `Text`/`Mark`/`InlineBlock`). The core renders the block element from the kind's `element`; snippets render inner markup and receive view objects (`BlockView`, `InlineBlockView`), not handles. The block element wraps the children too, so a kind that holds children never declares a heading or text-level `element`; it declares `contentElement`, which the core wraps around `content()` (snippet overrides keep it): the rich text heading and quote are `div`s whose `h1`–`h3`/`blockquote` holds only their text, children in a sibling `div` (`heading-children-structure.test.tsx`).
- **Nesting indent.** Every kind that renders children puts them in ONE `div[data-edytor-children]` (a rich text snippet's `nested`; the unknown-kind fallback in `Block.svelte`), indented once by `padding-inline-start: var(--edytor-nest-indent, 24px)` (`Block.svelte`'s global style, `themes/notion.css`); a kind that indents through a marker column (Notion theme: lists, to-dos, callouts) zeroes it, a toggle aligns it with its text — never add a second indent (`children-container.test.tsx`, `nest-indent.spec.ts`). Text segments are keyed causally (by the atom before them), so typing never remounts the caret's node.
- **Compare-to-truth observer** (`edytor.surface`): records carry no provenance; they only say what to compare. The pre pass (root `$effect.pre`) inverts a record that removed registered elements and snapshots an edit the flush would overwrite; the compare pass (root `$effect`, after every DOM write) compares each named content with its cell. Text inside a content is adopted through the dispatcher unless an expectation claims its host (the composition tail, a pending structural key, a model-owned drift — then the cell is restored); structure is restored; the live IME host is the IME's; read-only divergence is inverted at the flip back. The root, text elements and core mark elements are strict containers. **Strict regions:** a block's own text/atom run is a strict region only the editor writes; tolerance covers only a kind's own markup around the content and children slots (and attributes the table does not own).
- **Projector** (`edytor.projector`): the only DOM-selection writer. After every flush it writes the current value when asked, or when the render epoch moved, and only if the live DOM selection differs. It never takes focus from outside the editor (a form control or foreign editable focused in a kind's chrome counts as outside: a field bound to `block.data` keeps its focus while each keystroke commits) and never writes while a composition is live, except `park`: the one caret a composition over a block or atom selection gets before the IME writes. It classifies every `selectionchange` (echo, drift, composition, foreign, intent). Two named, time-bounded browser rules are the only signatures: the Android post-delete snap-back and the IME post-commit jump. The caret a browser parks when the editor focuses its own host (`takeKeys` in `events/onFocus.ts`, after a block drop, a column resize release or a grip click no menu answers, so the history and block-selection keys act at once) is drift until the next gesture, never adopted; so is the one Chromium parks at the host's start for a press an inline atom took (`InlineBlock.attach` calls `projector.parked()` through `edytor.ports.surface.parked`; reported a frame later, after the release marked a gesture): under an atom or no selection a parked caret stays drift until a press inside, a focus from outside, an adopted move or a display; a `none` value asked for (a history step) shows no DOM range.
- **View state** (a kind's declared `viewState`, `open` on a toggle's `details`): the browser and the user own it; `Block.attach` carries it to a re-rendered element (a moved toggle stays open). A collapsed toggle is one unit: `hidden(block)`/`shown(block, step)` let Backspace, Delete, Tab and the block-selection arrows skip its hidden body; never walk `blockBefore`/`blockAfter` alone for a key the user sees. A text range never reaches a hidden body either: `prepareDeleteContent` passes `{ hidden(id, removed?) }` to `prepare.deleteRange`/`replaceRange`, and range deletion asks it with the blocks that die, so a dying head's body goes and a dying tail's revealed body can take the caret (`del.range.hidden-body`, which Backspace/Delete next to a closed toggle reuse as one plan), and copy, marks, the toolbar and typed-over marks ask `rangeCovers`/`selectedTextSpans` (`src/lib/selection/visibility.ts`: a hidden block is covered exactly when the range's delete removes it; the live block selection covers exactly its members, a selected list or code block with its shown subtree: `selectedMembers`), never `state.texts` directly. Cut deletes like Backspace (not a replacement), and `prepare.insertFlow` takes the same `viewOf(edytor)` so a split closed header keeps its body.
- **Placeholder** is the `data-placeholder` attribute on the empty text element, drawn by a shipped `::before` rule.
- **DOM selection exceptions.** Besides the projector (`post`, `park` and its own clear when focus leaves), only these write the DOM selection directly: `selection/domSelection.ts` replaces a multi-range selection (in practice Firefox's) with its bounding range when a snapshot reads it, and these clear it: `events/onFocus.ts` (focusout after focus moved outside), `edytor.svelte.ts` (attach teardown), `selection/selection.svelte.ts` (two sites), `block/inlineBlock.svelte.ts` (atom selection, through `edytor.ports.surface.clear`). Do not add more.
- **Host-writer lint**: DOM mutation calls in `src/lib` are allowed only in the host writers (`components/`, the handles' attachments, `surface/observer`, `surface/attributes`, `surface/overlay`, `plugins/`, `collaboration/`). Never write imperatively into owned text or mark elements.

## Selection contracts that must not regress

(Normative spec: `docs/editor-delete-contract.md`, "Anchor contract", "Selection ownership and lifecycle", "Responsibility map".)

- A caret anchor is `{b, a}`: `b` the home block of the backing text, `a.i` the bound item (causal identity), `a.a`'s sign the insert affinity. Text ownership is streams delimited by boundary items: a left caret at a split-born block's start binds that block's boundary item, so the containing stream and the side are two facts in two fields (no owner facet since architecture v2). Never let a caret migrate into a surviving neighbour block because that neighbour received text at the shared gap.
- Logical recovery destination and DOM readiness are separate: a live destination with no mounted node stays the selection value and is displayed by the projector's pass after the flush that mounts it (a value that no longer projects runs the seam repair; a text mount or the observer's records re-run a waiting pass). Do not "fix" this by treating unmounted text as unrecoverable, or by weakening `firstEditableText`'s mounted-node requirement (container phantom slots must stay skipped).
- `surface/projector.svelte.ts` is the only DOM-selection writer (`post`, and `park` under a live composition; the named exceptions are under Surface): after every Svelte flush it writes the current value, so no older request can overwrite a newer gesture. Commands and input attempts decide the value and `select()` it in their own turn (`edytor.attempts.caret` only records the drift-repair caret); the three named writes that still select after a wait (the adoption caret, the root-heal redisplay, the drift repair's caret) check the gesture serial after it and yield to a newer gesture. Do not bring back tick/timeout re-assert loops. While a requested display has not landed, a `selectionchange` with no intent gesture since the request (`Edytor.intentSerial`, the one gesture serial; `input` events do not bump it) is not adopted.
- **The pointer** (`selection.pointer`, `selection/pointer.svelte.ts`): a press and its drag (`dragStart`, `capture`, `release`), the normalization a drag holds back (`hold`), a drag across columns (`dragAcross`, `across`), a press on a block's chrome, a triple click, a drag over inline atoms and `selectstart` on chrome. It writes the selection only through the selection's setters; the DOM adoption in `selection.svelte.ts` reads `dragging` and `across`.
