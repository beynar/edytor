# Room and protocol

The Worker-safe CRDT boundary, the shipped room (`edytor/cloudflare`, `src/lib/cloudflare/`) and the sync layer (`src/lib/crdt/{providers,protocols,migration}/`, `src/lib/collaboration/`). The owners table of [AGENTS.md](../../AGENTS.md) names who writes each fact.

## Worker-safe CRDT boundary

The CRDT engine and the sync layer also run server-side in a Cloudflare Durable Object that coordinates clients over WebSockets (a central coordinator, not P2P). `src/lib/crdt/**` (vendor included), `src/lib/utils/json.ts`, `src/lib/utils.ts` and `src/lib/constants.ts` must stay importable and runnable without Svelte and without browser globals:

- never import `svelte`, `$app/*`, `*.svelte(.ts|.js)` or a view layer (`components`, `selection`, `surface`, `session`, `events`, `block`, `text`, `plugins`, `clipboard`, `collaboration`, `edytor*.ts`) from there;
- feature-detect browser APIs (IndexedDB, `navigator.locks`, `BroadcastChannel`, page events); no module-level timers.

Three checks enforce it: `pnpm lint` (`WORKER_SAFE` + `edytor/worker-safe-imports` in `eslint.config.js`), `pnpm check:worker` (bundles `src/lib/crdt/index.ts`, `src/lib/crdt/protocol.ts` and `src/lib/cloudflare/index.ts` for a Worker target) and `src/tests/crdt/arch-v2/do-coordinator.test.ts` (a reference coordinator with the browser globals removed and timers forbidden). The coordinator's public surface — `bindCrdt(Y)` (`.sync` readers/writers and `applyRemote`, `.admission`, `.doc`), the frame contract, the message types (incl. `messageSaved`, `messageChunk`), the chunk codec, the lib0 frame helpers and the instance-free awareness codec (`readAwarenessEntries`/`writeAwarenessEntries`), the admission gates and the raw provider classes — is `src/lib/crdt/protocol.ts`, the `edytor/protocol` entry (never `edytor` or `edytor/crdt/edytor`). Do not remove anything that test or the room imports. The site's `server/protocol` and `server/room` pages have the contract.

## The room (`edytor/cloudflare`)

- The shipped room is `edytor/cloudflare` (`src/lib/cloudflare/`): `DocumentRoom` (the Durable Object) and `routeDocumentSocket` (authorize before the upgrade, forward only `X-Edytor-User/Replica/Access/Expires`, the user percent-encoded; a denied dial (`null`, or an invalid identity: a `userId` empty, not a string, over 256 characters or with a lone surrogate, or an invalid `replica`) is accepted and closed `4403`, an invalid document id `4400` (empty, `.`/`..`, over 256 characters, a lone surrogate: `validRoomId`, which the provider and `createWebsocketSync` enforce by throwing at construction; `<Edytor server room>` never throws: the server render builds no provider, a view (editable or readonly) reports `4400` through `onSyncRefused` without dialing), so the provider stops; the provider sends the room id percent-encoded as one path segment, and a host Worker decodes it, closing a segment that does not decode `4400`; a host Worker refusing a dial itself answers `closedSocket(code, reason)`, never an HTTP error, which the browser reports as `1006`).
- Its code: `DocumentRoom.ts` declares the public types and constants and wires `AttachedDocument`; the room's parts are one module each under `cloudflare/room/`, sharing one explicit context (`room/context.ts`: the options, the live document and its facade, the running flags, the counters, the socket primitives, and every part): `storage.ts` (rows, restore, `onLoad` seed, append, compaction, the `onSave` mirror), `admission.ts` (frames, chunks, quotas, waiting deletes, store-before-ack; with `replicas.ts`, the replica registry and attribution, `forged.ts`, forged marks and attribution entries, and `validation.ts`), `scheduler.ts` (the alarm's due tasks), `history.ts` (slots, versions, restores), `purge.ts`, `moves.ts`, `presence.ts` and `access.ts` (the door: identity, upgrade, probes, revocation, expiry); a part reaches another only through the context, and a fact keeps one owner among them.
- It is in the Worker-safe set and is the only module allowed to import `cloudflare:workers`; `src/cloudflare-workers.d.ts` (outside `src/lib`, never shipped) types that runtime for `pnpm check`, while `tests/do` checks it against `@cloudflare/workers-types`.
- Rules it owns:
  - identity bound in the socket attachment
  - a client id belongs to the user whose socket dials or binds it as its `replica` (another user's dial is closed `4409`)
  - new structs under another user's id, or an id the room holds part of, are stripped from the frame and the sender stays (an id the room holds nothing of is stored unowned, `relayed`; the frame's deletes are kept except those of map entries the stripped structs replace, held or not (`replacedEntries` resolves an unheld origin through the frame; unknown counts as an entry); a delete of an item the room lacks is stored as a `pending` row (capped at `MAX_WAITING_DELETES` ranges: a frame past it has those deletes dropped, a `waiting` refusal, left out of its ack; `settleDeletes` re-checks after applying, so deletes of the frame's own waiting items and in-memory replaced entries are capped too; compaction keeps only the ones still waiting, apart, and reclaims those of ids no user registered and no socket holds, in memory too (deletes of a registered id's items are kept, so a writer can still fill the cap: `dropWaitingDeletes()`, also over RPC, empties it, in-memory ones too; a stored waiting delete arms `onSave`, and a seed from the `onSave` copy stores the ones it carries as a `pending` row again), applied when the item arrives, echoed to the sender that released it, all dropped when a frame's release discards a forged stamp), except the entry a rewrite of the same frame that still waits replaces (it waits with it, in memory; a struct the engine left a Skip for counts as waiting))
  - only undecodable bytes are `1008 malformed`, room faults close `1011`
  - `authorize` may return `{ expired: true }` (close `4401`, retried), or an identity with `expiresAt` (`X-Edytor-Expires`; past at the dial: `4401`), which the room closes `4401` at the socket's first message past it or on the alarm (`expiry` task)
  - revocation (`room.access`): `closeUser(user, code = 4403)` and `setAccess(user, 'read' | 'write' | 'none')` walk the open sockets' attachments (read: downgraded in place with the read-only notice; write: read-only sockets closed `1012` `access changed`, redialed; none: `closeUser`), logged `access`
  - `closeUser` throws a `RangeError` on a code `ws.close` rejects or a reason over 123 bytes, before touching a socket
  - read-only sockets get the read-only notice (auth subtype `1`, `writeReadOnly`: no event, the provider's `readOnly` turns true) when they join and `permission-denied` (`read-only`) per refused write, and stay (the provider then tracks nothing, so `saved`, and sends the socket only its document's own local edits, never what a tab or a store delivered; that denial never emits `failed`)
  - every sync message is answered with `messageSaved` after the write (the provider's `saved`/`unsaved`; its deletes are the message's stored ones, applied or in a `pending` row, and the provider settles a delete only when an ack names it), and a frame that releases waiting structs broadcasts one, with the deletes that waited, to the other sockets (a relayer's waiting rewrite, e.g. `lastChangedBy`, is stored when the author returns)
  - frames above `EDYTOR_MAX_FRAME_BYTES` go out as `messageChunk` sequences, both ways (the provider chunks over its `maxFrameBytes`; the room reassembles per socket, and a part with no start closes `1011` `chunk sequence lost`)
  - compaction stores the live document after `EDYTOR_COMPACT_AFTER` records (`room.compact.*`: `encodeStateAsUpdateV2` with the engine's pending store set aside, never a merge of the records; the room's doc keeps fork patch YP11 copies from its creation, `crdt.doc.keepCopies`), run after the message is acknowledged (a failure is logged as a `storage` refusal and retried; nobody is disconnected)
  - snapshots are v2 and gzip-compressed in place after they are stored (`room.store.v2`: the generation record says `storage: 'v2'`, update and pending records stay v1, a next.22 container loads and its next compaction rewrites it; `inflate` at start keeps the raw bytes for a rebuild's synchronous read)
  - quotas (`room.quota`: `maxDocumentBytes` 2 MiB and `maxInboundFrameBytes` 4 MiB by default, sized for a 128 MB isolate at up to 46 heap bytes per stored byte (`bench/room-memory.mjs`), `maxUpdatesPerSecond`) close a socket `4413`, its frame unapplied
  - a chunk sequence is one buffer of its announced size, allocated at its start, skipped for a read-only socket (denied `read-only`), counted against the rate, and the sequences of every socket share `maxBufferedBytes` (one past it closes `1011` `room busy`, redialed; `net.chunk.inbound`)
  - a client writing another client's `del.<n>`/`wd.<n>` mark is stripped and a delete of another user's mark dropped (`room.marks.writer`)
  - the attribution root is the verified user's (`room.attribution.trust`): a `c/<n>` written under another client or for another user's replica, and another user's `u/<id>`, are collected from the frame (a GC, the rest applied; a `c/<n>` naming `n`'s registered owner stands whoever wrote it, the room's own rebinding relayed; a relayed id's binding to another actor too), a delete of one dropped, logged `forged`
  - a `c/<own id>` naming another actor, or an id a writer claims (`orphan`, `bindOrphan`), is rewritten to the user by the room (`rebind`), and a relayed presence state's `actor` carries the user as its `id`
  - `allowedOrigins` (`RouteDocumentOptions`, both routers) refuses another `Origin` before `authorize` (`4403` `origin not allowed`, `403`)
  - an optional `validate` hook is asked after each frame that changed blocks and a denial is undone by the room's own transaction, the history undo of that frame (`room.validate.*`)
  - `metrics()` and a JSON log (`EDYTOR_LOG`) report sizes, timings, fan-out, quota hits and denials
  - `lastUpdated()` (a `meta` table, answered over HTTP by `routeDocumentSocket` for `GET <room>?lastUpdated`) serves the client's `lastUpdated` probe
  - every entry point runs under `noTimers`.
- Restore and registry: `onLoad` returns JSON, a bare v14 update or `{update, replicas}` (`LoadedDocument`); nothing is stored until it settles; `null` is provisional (asked again at every start); a throw closes sockets `1011 room unavailable` and is retried; a refused payload, a torn record or a container of another generation sets `failure` and refuses every socket `1008 refused: container` (`reset()` is the generation cutover).
- `onSave` receives `{value, update, replicas}` (`ReplicaOwner[]`; an alarm that finds the rows unreadable restarts the room, else re-arms with backoff); after a bare-update restore each id with content is claimed by its first dial (an `orphan` note).
- `refusals` keeps the newest `MAX_REFUSALS` (100), `refusalCounts` counts all.
- The room echoes an accepted presence entry to its sender, so a lone client is never silent for 30 s.
- Presence fan-out has a budget (`room.presence.fanout`, `maxPresenceFanout`/`EDYTOR_MAX_PRESENCE_FANOUT`, 2,000 frames a second over all sockets, in memory): within it an entry goes out at once; past it entries wait per recipient (the newest per replica, encoded once) and each recipient's go out in one frame at the end of a later message (no timer); a removal goes at once and drops the replica's waiting entries.
- A failed append rebuilds once per outage (`room.storage.outage`): until a probe append (rolled back) or an append succeeds, a frame that would write is closed `1011` unapplied, with no second rebuild.
- Presence quotas (`room.presence.quota`): an entry over `maxPresenceBytes` (16 KiB of JSON) is ignored, and presence messages draw from their own bucket (`maxPresencePerSecond`, 50): past it a query is dropped and the newest entry held, relayed (one frame for all released) at the end of a later message once the bucket refills (no timer), one `presence` log entry per burst; logged `presence`, the socket stays.
- Server `transact` edits obey the `semantics` option (default `defaultSemantics`; `semantics: {}` checks nothing) and are one transaction, not a rollback, like every client-side `transact`: a throw from `fn` keeps the writes made before it (stored and relayed; all or nothing is one `prepare.*` plan), a failed append throws the storage error and rebuilds from the rows keeping what the engine holds waiting (a rebuild replaces `doc` and `facade`: their subscriptions end); a room-side write straight through `facade` whose append failed is dropped (`heal`) at the next entry point or the next read of `facade` or `doc` while the room is idle (never mid-transaction, mid-frame or mid-event, `afterAllTransactions` included: the frame handler faults its sender); a room `transact` inside another transaction or its change events (a `facade.onChange` subscriber, of a client's frame or of the room's own `transact`; only a call inside `fn` joins) throws without writing, as its write could not be stored before it returns (defer it with `queueMicrotask`); client updates are relayed as they are.
- One alarm, six tasks (`room.alarm.tasks`): `save` (`onSave`), `history` (the open slot's end), `purge` (the daily tick), `retention` (the next version's expiry, for a store without its own TTL), `forward` (a move's late edits) and `expiry` (the sockets' earliest credential expiry; so `attachRoom` always installs `alarm`), each due time stored in `meta` (`due.<task>`), the alarm set to the earliest (the site's `server/internals` page holds the one table of these tasks and of the room's tables: update it with them); a task already due keeps its time (`schedule` `keep`, the purge tick `earlier`), and an alarm armed by next.23 with no due rows counts as a due save.
- History (`room.history.*`, `cloudflare/history.ts`): with `history: { store, retentionDays = 30, timeZone = 'UTC' }` (`DocumentRoom.history()`, `EDYTOR_HISTORY` by default: a KV or R2 binding, or `room`) — `store` a `HistoryStore` (`room.history.store`: `kvHistory`, `r2History`, `roomHistory()` over the room's own SQLite, or any object with `maxValueBytes`, `nativeTtl?`, `put`/`get`/`list`/`delete`; a KV namespace goes through `kvHistory`, the namespace itself is refused), expiry the room's (`room.history.retention`: nothing past `expiresAt` is listed or read; the `retention` task deletes it from a store without `nativeTtl`) — a change opens the half-day slot it falls in (`am` before local noon, `pm` until midnight, `Intl`), recording its writers' users (`editors` table); the slot closes at its end — the alarm, the first write past the boundary (captured before that write applies: `closeSlotIfPast` in `onUpdate`, `transact`, restore, purge) or a start past it — writing `history/<encodeURIComponent(room)>/<YYYY-MM-DD>-am|pm` = `packed(liveState)`, metadata `{ bytes, blocks, editors, more?, at }` (≤ 1,024 B), `expiresAt` = `at` + retention; a value past `maxValueBytes` (the store's, which the option only lowers) or a failed put is skipped (refusal `history`), never split.
- `restoreHistory(key, { user })` is one `RESTORE_ORIGIN` room transaction of `crdt.doc.restoreTo` (`crdt/restore.ts`: revive, unclaim, type/data per leaf, place by the longest kept run, rewrite only differing content between the common prefix and suffix through the per-stream ops, delete the rest with what it displays), recorded by the room's restore history; its step (insert/delete id sets, `restore` table) is undone by `undoRestore()` (one level), the content it deleted kept from collection by the room doc's `gcFilter` (`prepareRoomDoc`) until undone, replaced or past the purge horizon (`dropRestore` releases and collects it).
- `routeDocumentHistory` (GET list/`?key=`, POST `?restore=`/`?undo`) shares `routeDocumentSocket`'s one authorization path (`authorized`).
- Purge (`room.purge.*`, `crdt/purge.ts`): the tick records an epoch (state vector, `epochs` table) when the document changed, purges at the newest epoch ≥ `purgeAfterDays` old (default the retention, else 30; `false`/`off` never) newer than the last purged (meta `purged`), drops older epochs, compacts, re-arms at the next epoch's crossing (a change arms it a day out); the purge is one `PURGE_ORIGIN` transaction of real deletes (a dead block whose text family is all dead and nothing stays placed under it loses its registry entry, attribution record and the claims naming it; another dead block keeps its node, its stream's text, data leaves and claims deleted; old text delete marks and dead restoration records; runner-up candidates of an old accepted winner; the attribution record of a block merged away before the horizon, its registry node kept, `room.purge.merged`), ending with the horizon record (root `horizon`, attr `h` = `{ at, sv }`) that every history reads to drop the steps below it (`hist.purge.horizon`) and that `react` treats as a purge (no pending fork patch YP11 restoration).
- Only the room writes `horizon` (`isHorizon` in `forgedWriters`/`forgedDeletes`, refusal `mark`).
- A replica offline past the horizon has no close code: its structs under a collected parent integrate as GC, a move under a removed block resolves to the root (`room.purge.stale`).

## Sync

- Comment threads (`room.comments.*`): message type `6` (`messageComments`) carries a client's subscribe and the room's snapshot and changes, sent only to a socket that subscribed (the generation is unchanged); the provider subscribes at each open while `watchComments` has a listener for its `<serverUrl>/<room>` (the default comments client's `subscribe`). A room that predates it closes a subscribing socket `1008`. Their quotas (`room.comments.quota`) are the room's, apart from the document's: the stored bytes go through `decideComment` (`bytes`, `maxBytes`), the rate is a token bucket per user (HTTP) and per socket (`allowance` of `room/admission.ts`, on the room's clock), and the route reads at most 64 KiB of a body (`bodyWithin`).
- Every frame is `varuint GENERATION | varuint messageType | payload`; `GENERATION = PROTOCOL_VERSION * 1000 + SCHEMA_VERSION` (schema generation 5, wire word `14005`). Anything else is refused before decode; `applyRemote` refuses updates that forge the schema stamp. A SyncStep2 is v2 on the wire (`step2Update` converts it), an Update v1. Generation 4 converts through its JSON only (`crdt/migration/generation.ts`: a room at load, a local-only IndexedDB store at open; `room.generation.convert`); its bytes are never integrated.
- One room lifecycle and join rule (`providers/room.ts`): hello = Step1 + presence; a Step1 is answered with Step2, plus our own Step1 when the asker holds something we lack.
- `createIndexeddbSync(name)` / `createWebsocketSync({server, room, params?, maxBackoffTime?, connectTimeout?, onExpired?, WebSocketPolyfill?, disableBc?, persist?, persistName?})` are `EdytorSync` factories for `<Edytor {sync}>` or `document.attachSync` (the target is `{ server, room }`: `serverUrl`/`roomName` are refused by name); the document keeps one provider per transport target. `createWebsocketSync` attaches a local IndexedDB store by default (`edytor:<server>/<room>`, skipped without `indexedDB`) as a provider of its own through the payload's `attach`, so the document's readiness rules apply to each leg unchanged; while the store exists it carries the cross-tab channel (the socket's BroadcastChannel leg is off).
- Readiness bound: `createWebsocketSync` sets `bound: Infinity` and arms the 1 s bound through `EdytorSyncPayload.armBound()` from the socket's open or its first failed dial, so a cold room hydrates instead of racing the seed. Known gap: a server that opens and then takes over 1 s to send its state is read as empty. A dial that neither opens nor fails is closed after `connectTimeout` (10 s default, `Infinity` = no limit), which arms the bound (up to about 11 s). A `4401` before the first sync holds the bound (`armBound`'s counterpart `holdBound()`) until that provider syncs or is released.
- Refusals: a close with `1008` or `4xxx` is terminal: the provider stops dialing and emits `refused` (`SyncRefusedError {code, reason}`); an empty document never seeds over it and exposes `document.syncRefusal` / `onSyncRefused` until that provider is released or syncs again; one that already holds content is hydrated at the refusal.
  - `4401` (expired credentials) is not terminal: `expired` fires (`onExpired` option, `<Edytor onSyncExpired>`) and the provider redials with the re-read `params`; `<Edytor onSyncRefused>` reports refusals (the one standing at mount too, isolated like the later ones).
  - Releasing a refused provider decides with the providers still attached (none: stays pending), and a view never seeds a refused document on mount.
  - `1006` (an HTTP refusal looks the same) keeps redialing: backoff `100 ms × 2ⁿ` capped at `maxBackoffTime`, the cap doubling to 30 s after 8 dials that never synced, each emitting `unreachable`; the count resets when a connection syncs.
  - A room fault (`1011`) after a sync also grows the backoff and emits `unreachable` (`attempts`: faults in a row), until the room acknowledges every local update again (`saved`, which counts only clocks of client ids the actor dictionary binds to the document's actor, so another user's stripped edits never hold it).
  - Provider and awareness events isolate their listeners (`protocols/observable.ts`): a throwing one is logged and the provider keeps going.
  - A text `ping` goes out after 15 s of silence; a text `pong` counts as liveness.
- Version history UI: `HistoryPanel` (`collaboration/history/`, site `server/history-panel`) reads a room's versions through a `HistoryClient` (`list`/`read`/`restore`/`undo`; `createHistoryClient` speaks `routeDocumentHistory`'s requests and throws `HistoryRequestError`), previews one in its own `<Edytor readonly>` over the version's JSON (no handles), and highlights the blocks added, removed and changed since against the page's `document` (`versionDiff`, recomputed at each of its commits; tints over each block's own row in the preview's overlay, never on its blocks). Restore and Undo restore call the client; the page updates through its sync.
- Presence lost with a transport is removed under the `LOCAL_PRESENCE_LOSS` origin: that tab only, sibling tabs keep their remote carets. `beforeunload` only announces the departure (an unsaved-changes prompt may keep the page); `pagehide` of a page leaving for good destroys the providers.
- `<Edytor>` releases a view-owned document in `onDestroy`, which also runs after a server render.
- A readonly view is a live viewer: `<Edytor readonly>` attaches its `sync` (or the one `room`/`server` build) as an editable view does and waits for the same readiness (its server render shows `snapshot`, never `value`); `readonly` gates the view's commands only, so a flip keeps the connection (`readonly-live.test.tsx`, the hosted `live viewer` row). A user who may not write is the room's decision (`authorize` → `readOnly`).
- Presence: `selections[viewKey] = serialize(value) + t`, through the view's `PresenceWriter`: `share` (`caret`, `block`: `{ blocks: [focus block] }`, `none`) and `throttle` (ms, 50 by default, `DEFAULT_PRESENCE_THROTTLE`; leading write then one trailing write of the newest; a named timer cleared by `destroy()`; DOM rows about what is published pass `presence: { throttle: 0 }`). A view writes only its own key. Peers resolve the freshest valid entry per client, text (a caret) or a block set (a bar beside the blocks' own rows).
- The room's modules (`cloudflare/room/*`) read their shared constants and helpers (the router's headers, the transaction origins, `SOCKET_TAG`, the refusal caps, the comment defaults, `noTimers`, `closedSocket`) from the leaf `room/shared.ts`, never from `DocumentRoom.ts`, which re-exports them: the room forms no import cycle (`pnpm check:deps --all`).
